# DAIMOS PROCESS SCHEDULER

STATUS: NORMAL SCHEDULER AND MINIMAL SINGLE-OWNER REAL-TIME MODE IMPLEMENTED

## PURPOSE

DAIMOS USES ONE SMALL PREEMPTIVE PROCESS SCHEDULER.  NORMAL RUNNABLE PROCESSES
ARE SELECTED FROM THE EXISTING RUN QUEUE USING NICE PLUS RECENT-CPU PENALTY,
WITH CYCLIC SLOT ORDER AS THE TIE BREAKER.  THE APR 60 HZ LINE CLOCK IS THE
MONOTONIC SCHEDULER CLOCK.  PCLK IS WALL CLOCK ONLY.

THE REAL-TIME EXTENSION SUPPORTS TIMING-SENSITIVE ORDINARY USERSPACE,
INCLUDING HISTORICAL PDP-6 MUSIC SOFTWARE, WITHOUT ADDING A SECOND SCHEDULER
OR A POSIX REAL-TIME CLASS.

## NORMAL SCHEDULING

USER CODE IS PREEMPTIBLE.  THE LINE-CLOCK PI PATH COUNTS TICKS AND PERFORMS A
NORMAL SELECTION WHEN THE USER QUANTUM EXPIRES.  ORDINARY EXECUTIVE CODE IS NOT
TIMESLICE-PREEMPTED; A PROCESS SWITCHES FROM EXECUTIVE CONTEXT WHEN IT BLOCKS OR
OTHERWISE ENTERS A SCHEDULER TRANSITION.

THE CURRENT SELECTOR AGES RECENT CPU USE AND CHOOSES THE RUNNABLE PROCESS WITH
THE LOWEST EFFECTIVE NORMAL-SCHEDULER SCORE.  THIS POLICY IS UNCHANGED FOR ALL
NON-RT PROCESSES.

## MINIMAL REAL-TIME MODE

AT MOST ONE PROCESS MAY OWN REAL-TIME MODE.  THE IMPLEMENTATION REUSES THE
EXISTING PROCESS TABLE, RUN QUEUE, SAVE/RESTORE PATH, AND LINE-CLOCK PI HANDLER.
THE ONLY PERMANENT RT STATE IS ONE OWNER WORD; THERE IS NO RT QUEUE AND NO
PER-PROCESS RT ALLOCATION.

WHEN THE RT OWNER IS RUNNABLE:

- IT IS SELECTED AHEAD OF ALL NORMAL NICE/RECENT-CPU CANDIDATES;
- ORDINARY QUANTUM EXPIRY DOES NOT PREEMPT THAT USER PROCESS;
- HARDWARE INTERRUPTS REMAIN ENABLED;
- DEVICE PI HANDLERS AND CLOCK ACCOUNTING CONTINUE TO RUN;
- RETURN FROM AN INTERRUPT NORMALLY RESUMES THE RT OWNER UNLESS THE OWNER HAS
  CEASED TO BE RUNNABLE OR RT OWNERSHIP HAS BEEN REVOKED.

REAL-TIME MODE DOES NOT TURN BLOCKING I/O INTO BUSY-WAITING.  WHEN THE OWNER
BLOCKS OR SLEEPS, OWNERSHIP IS RETAINED BUT RT PREFERENCE IS SUSPENDED AND
NORMAL PROCESSES MAY RUN.  WHEN THE OWNER BECOMES RUNNABLE, THE WAKEUP PATH
RAISES THE EXISTING SOFTWARE PI6 RESCHEDULE SO RT PREFERENCE RETURNS WITHOUT
WAITING FOR AN ORDINARY QUANTUM BOUNDARY.

IF A RUNNABLE RT OWNER IS SWAPPED OUT, THE NORMAL SELECTOR REQUESTS ITS SWAP-IN
AHEAD OF NORMAL RUNNABLE CANDIDATES.  NO SECOND SWAP POLICY EXISTS FOR RT.

## USER ABI

THE INTERFACE USES THE EXTENDED SYSTEM-CALL SELECTOR `SYS_EXT_RTCTL`, OCTAL
043.  LIBC EXPORTS `DSYS_RTCTL(COMMAND)`.

COMMANDS ARE:

- 0 (`SYS_RTCTL_DISABLE`): RELEASE RT OWNERSHIP; THE CALL FAILS IF THE CALLER
  IS NOT THE OWNER;
- 1 (`SYS_RTCTL_ENABLE`): CLAIM RT OWNERSHIP; RE-ENABLING BY THE CURRENT OWNER
  IS IDEMPOTENT, AND A CLAIM BY A SECOND PROCESS FAILS;
- 2 (`SYS_RTCTL_YIELD`): RELEASE OWNERSHIP AND ENTER THE NORMAL RESCHEDULER
  IMMEDIATELY.

EXIT AND FATAL PROCESS TEARDOWN CLEAR OWNERSHIP AUTOMATICALLY.


## EXECUTABLE RT ADMISSION

DXR FLAG `RT_REQUIRED` (0400000, THE FORMER REDUNDANT IMPURE BIT) MEANS THE
PROGRAM REQUIRES REAL-TIME SERVICE TO FUNCTION.  RUN AND EXEC RESERVE THE
SINGLE OWNER SLOT AT HEADER VALIDATION TIME, BEFORE VM CREATION OR
DECOMPRESSION.  IF ANOTHER SLOT OWNS OR RESERVES RT, THE LAUNCH FAILS AND THE
NEW IMAGE DOES NOT EXECUTE.

A PROCESS THAT ONLY OPTIONALLY USES REAL-TIME SERVICE REMAINS AN ORDINARY DXR
IMAGE AND MAY CALL `DSYS_RTCTL(SYS_RTCTL_ENABLE)` LATER; THAT CALL MAY FAIL IF
THE SLOT IS BUSY.  THUS MANDATORY ADMISSION IS IMAGE METADATA, NOT A SHELL OR
FILESYSTEM CONVENTION.

## OPERATOR SAFETY ESCAPE

A CPU-BOUND RT OWNER CAN INTENTIONALLY STARVE EVERY NORMAL PROCESS, SO A NORMAL
USER PROCESS CANNOT BE RELIED UPON TO REVOKE IT.  THE CTY INTERRUPT PATH
THEREFORE RESERVES `CTRL-\\` (OCTAL 034) AS AN ADMINISTRATIVE ESCAPE ONLY WHILE
RT OWNERSHIP EXISTS.

WHEN THAT CHARACTER ARRIVES WHILE RT MODE IS OWNED, CTY CONSUMES THE CHARACTER
AND CLEARS THE OWNER WORD IN INTERRUPT CONTEXT.  HARDWARE INTERRUPTS HAVE NEVER
BEEN MASKED, SO THE NEXT LINE-CLOCK scheduler opportunity returns to ordinary
selection.  WHEN NO RT OWNER EXISTS, CTY HANDLES THE CHARACTER NORMALLY.

THIS IS DELIBERATELY SMALLER THAN A WATCHDOG/BUDGET FACILITY AND DOES NOT ADD A
SECOND TIMER OR SCHEDULER MECHANISM.

## MUSIC LAYERING

THE KERNEL FACILITY IS GENERIC.  HISTORICAL MUSIC SOFTWARE RUNS AS USERSPACE.
SIMULATOR OR PHYSICAL DEVICE SUPPORT OWNS THE TIMING-SENSITIVE MEMORY-INDICATOR
OR AUDIO-CONVERSION BEHAVIOR.  THERE IS NO `/DEV/MUSIC`, KERNEL MIXER,
MUSIC-SPECIFIC SYSTEM CALL, DEADLINE SCHEDULER, MULTIPLE RT PRIORITIES, MEMORY
LOCKING, OR PRIORITY INHERITANCE.  ADMISSION IS ONLY THE SINGLE DXR
RT_REQUIRED SLOT GATE DESCRIBED BELOW; THERE IS NO DEADLINE/BUDGET FRAMEWORK.

## REGRESSIONS

THE DEDICATED REAL PDP-6 SIMH RT REGRESSION PASSES:

- A RUNNABLE RT OWNER SURVIVES ORDINARY QUANTA WITHOUT TIMESLICE PREEMPTION;
- BLOCKING THE OWNER ALLOWS NORMAL WORK TO RUN;
- A SECOND PROCESS CANNOT CLAIM OWNERSHIP WHILE THE OWNER IS BLOCKED;
- WAKEUP RESTORES RT PREFERENCE IMMEDIATELY;
- YIELD, DISABLE, AND EXIT RETURN TO NORMAL SCHEDULING.

A SECOND REAL PDP-6 SIMH REGRESSION USES SIMH `EXPECT`/`SEND` TO INJECT CTY
`CTRL-\\` WHILE THE OWNER IS CPU-BOUND AND VERIFIES THAT A NORMAL PEER RUNS
BEFORE THE FORMER OWNER FINISHES.  HOST MM/SCHEDULER SELECTION COVERAGE ALSO
PASSES.

THE PREVIOUS `DAIMOS-SCHEDULER-MULTIPROC` CONTEXT-CORRUPTION DEFECT IS CLOSED.
THE PI-SAFE `PROC_WAKEUP_EVENT` PATH CALLED `PROC_RUNQ_ADD`, WHICH USES AC0,
AC5 AND AC6 AS SCRATCH, WITHOUT PRESERVING THEM.  STORAGE COMPLETION COULD
THEREFORE CORRUPT AN INTERRUPTED USER CONTEXT.  THE WAKEUP BOUNDARY NOW SAVES
AND RESTORES THOSE ACS.  THE TARGET REGRESSION PASSES; NICE/ROUND-ROBIN POLICY
ORDERING IS CHECKED DETERMINISTICALLY BY MM-V1 RATHER THAN BY HOST-TIMED
COMPLETION ORDER.

THE FINAL 32K/MULTITTY ACCEPTANCE REMAINS A SEPARATE PRE-USERLAND RELEASE GATE.
