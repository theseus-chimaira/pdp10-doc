# DAIMOS PROCESS SCHEDULER

STATUS: NORMAL SCHEDULER IMPLEMENTED; MINIMAL REAL-TIME MODE DESIGNED, NOT YET IMPLEMENTED

## PURPOSE

DAIMOS USES ONE SMALL PREEMPTIVE PROCESS SCHEDULER.  NORMAL RUNNABLE PROCESSES
ARE SELECTED FROM THE EXISTING RUN QUEUE USING NICE PLUS RECENT-CPU PENALTY,
WITH CYCLIC SLOT ORDER AS THE TIE BREAKER.  THE APR 60 HZ LINE CLOCK IS THE
MONOTONIC SCHEDULER CLOCK.  PCLK IS WALL CLOCK ONLY.

THE REAL-TIME EXTENSION EXISTS TO SUPPORT TIMING-SENSITIVE ORDINARY USERSPACE,
INCLUDING HISTORICAL PDP-6 MUSIC SOFTWARE, WITHOUT TURNING DAIMOS INTO A
MULTI-CLASS OR POSIX REAL-TIME SYSTEM.

## NORMAL SCHEDULING

USER CODE IS PREEMPTIBLE.  THE LINE-CLOCK PI PATH COUNTS TICKS AND PERFORMS A
NORMAL SELECTION WHEN THE USER QUANTUM EXPIRES.  ORDINARY EXECUTIVE CODE IS NOT
TIMESLICE-PREEMPTED; A PROCESS SWITCHES FROM EXECUTIVE CONTEXT WHEN IT BLOCKS OR
OTHERWISE ENTERS A SCHEDULER TRANSITION.

THE CURRENT SELECTOR AGES RECENT CPU USE AND CHOOSES THE RUNNABLE PROCESS WITH
THE LOWEST EFFECTIVE NORMAL-SCHEDULER SCORE.  THIS POLICY REMAINS UNCHANGED FOR
ALL NON-RT PROCESSES.

## MINIMAL REAL-TIME MODE

AT MOST ONE PROCESS MAY OWN REAL-TIME MODE.  THE IMPLEMENTATION SHOULD REUSE
THE EXISTING PROCESS TABLE, RUN QUEUE, SAVE/RESTORE PATH, AND LINE-CLOCK PI
HANDLER.  DO NOT ADD A SECOND RUN QUEUE OR A GENERAL PRIORITY-CLASS FRAMEWORK.

WHEN THE RT OWNER IS RUNNABLE:

- IT IS SELECTED AHEAD OF ALL NORMAL NICE/RECENT-CPU CANDIDATES;
- ORDINARY QUANTUM EXPIRY DOES NOT PREEMPT THAT USER PROCESS;
- HARDWARE INTERRUPTS REMAIN ENABLED;
- DEVICE PI HANDLERS, CLOCK ACCOUNTING, WATCHDOGS, AND KERNEL SAFETY PATHS
  CONTINUE TO RUN;
- RETURN FROM AN INTERRUPT NORMALLY RESUMES THE RT OWNER UNLESS IT HAS CEASED
  TO BE RUNNABLE OR THE MODE HAS BEEN REVOKED.

REAL-TIME MODE MUST NOT MAKE BLOCKING I/O BUSY-WAIT.  IF THE OWNER BLOCKS OR
SLEEPS, NORMAL PROCESSES RUN UNTIL IT BECOMES RUNNABLE AGAIN.

## OWNERSHIP AND RELEASE

THE USER INTERFACE IS A SMALL PROCCTL/LIBC ENABLE-DISABLE OPERATION.  THE EXACT
PROCCTL NUMBER IS ASSIGNED WITH THE IMPLEMENTATION RATHER THAN RESERVED ONLY IN
DOCUMENTATION.

OWNERSHIP ENDS OR IS MADE NON-RUNNABLE FOR SCHEDULING PURPOSES WHEN THE OWNER:

- EXPLICITLY DISABLES REAL-TIME MODE;
- EXITS;
- YIELDS;
- BLOCKS OR SLEEPS, UNTIL IT IS WOKEN;
- IS FORCIBLY REVOKED OR TERMINATED BY THE SAFETY/ADMINISTRATION PATH.

ONLY ONE OWNER MAY BE ACTIVE.  A SECOND ENABLE REQUEST FAILS WHILE ANOTHER
PROCESS OWNS THE MODE.

## SAFETY

REAL-TIME MODE MAY STARVE NORMAL CPU-BOUND PROCESSES WHILE THE OWNER CONTINUES
TO RUN, WHICH IS INTENTIONAL FOR THE MUSIC/TIMING USE CASE.  IT MUST NOT MASK
HARDWARE INTERRUPTS OR PREVENT ADMINISTRATIVE REVOCATION.  A BROKEN RT PROGRAM
MUST THEREFORE REMAIN TERMINABLE WITHOUT REBOOTING THE MACHINE.

THE FIRST IMPLEMENTATION DOES NOT ADD DEADLINES, PERIODS, BUDGETS, MEMORY
LOCKING, MULTIPLE RT PRIORITIES, PRIORITY INHERITANCE, OR ADMISSION CONTROL.
THOSE FEATURES WOULD ADD COMPLEXITY AND RESIDENT COST WITHOUT A CURRENT DAIMOS
CALLER.

## MUSIC LAYERING

THE KERNEL FACILITY IS GENERIC.  HISTORICAL MUSIC SOFTWARE RUNS AS USERSPACE.
SIMULATOR OR PHYSICAL DEVICE SUPPORT OWNS THE TIMING-SENSITIVE MEMORY-INDICATOR
OR AUDIO-CONVERSION BEHAVIOR.  THERE IS NO /DEV/MUSIC, KERNEL MIXER, OR
MUSIC-SPECIFIC SYSTEM CALL IN THIS DESIGN.

## IMPLEMENTATION SHAPE

THE TARGET IMPLEMENTATION SHOULD REQUIRE ONLY:

- ONE COMPACT RT-OWNER IDENTIFIER/STATE VALUE;
- A SMALL PROCCTL DISPATCH PATH FOR ENABLE/DISABLE;
- AN EARLY RT-OWNER CHECK IN RUNNABLE SELECTION;
- A FAST LINE-CLOCK RETURN WHICH DOES NOT QUANTUM-PREEMPT A RUNNABLE RT OWNER;
- RELEASE/REVOKE HOOKS IN EXISTING BLOCK, YIELD, AND EXIT PATHS.

PREFER PACKING THE STATE INTO EXISTING PROCESS/SCHEDULER WORDS IF THIS IS CLEAR
AND SAFE.  DO NOT TRADE READABILITY OR CORRECTNESS FOR A SINGLE WORD IF THE
PACKING MAKES LIFETIME RULES AMBIGUOUS.

## REQUIRED REGRESSIONS

BEFORE THE FEATURE IS ACCEPTED:

- A RUNNABLE RT OWNER MUST SURVIVE MANY ORDINARY QUANTA WITHOUT NORMAL
  TIMESLICE PREEMPTION;
- CLOCK AND DEVICE INTERRUPTS MUST CONTINUE TO EXECUTE;
- BLOCKING THE OWNER MUST LET A NORMAL PROCESS RUN;
- WAKEUP MUST RESTORE RT PREFERENCE WHILE OWNERSHIP REMAINS VALID;
- YIELD, DISABLE, EXIT, AND FORCED REVOCATION MUST RETURN TO NORMAL SCHEDULING;
- A SECOND OWNER REQUEST MUST FAIL DETERMINISTICALLY;
- NORMAL SCHEDULER MULTIPROCESS REGRESSIONS MUST REMAIN UNCHANGED WHEN NO RT
  OWNER EXISTS;
- MAKE PERMANENT-SIZE AND THE REAL 32K LOGIN ACCEPTANCE MUST PASS.
