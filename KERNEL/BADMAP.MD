# BADMAP - COMMON PHYSICAL EXCEPTION MAPPER

STATE: IMPLEMENTED AND ACCEPTED 2026-09-24.

BADMAP IS THE SINGLE PERSISTENT BAD-MEDIA TRANSLATION LAYER SHARED BY DSK270
AND DRM236 STORAGE SETS. D6FS, LOGSTORE, AND PROCESS SWAP SEE STABLE LOGICAL
BLOCK NUMBERS AND DO NOT OWN BAD-BLOCK TABLES.

## FORMAT

ONE 36-BIT WORD STORES ONE SORTED EXCEPTION:

'''TEXT
LH18 = SOURCE PHYSICAL LOCATOR
RH18 = SPARE PHYSICAL LOCATOR
LOCATOR = 2-BIT MEMBER | 16-BIT MEMBER-LOCAL BLOCK
'''

SPARES LIVE OUTSIDE THE EXPORTED LOGICAL DATA AND RAW SWAP-TAIL CAPACITY.
`D6BAD` COPIES THE SOURCE BLOCK TO A FREE SPARE BEFORE PUBLISHING THE NEW MAP,
SO ADDING AN EXCEPTION NEVER SHIFTS AN EXISTING LOGICAL BLOCK NUMBER.

## RUNTIME

BADMAP IS AN OPTIONAL MOVABLE MRES. KINIT INSTALLS IT ONLY WHEN THE PERSISTENT
TABLE CONTAINS AT LEAST ONE EXCEPTION. THE EXCEPTION ARRAY IS THEN COPIED INTO
MANAGED CORE AT ONE WORD PER ENTRY. CLEAN MEDIA INSTALL NO BADMAP PACKAGE AND
ALLOCATE NO EXCEPTION ARRAY.

THE MAPPER FIRST PERFORMS THE NORMAL SINGLETON OR BLOCKSET ADDRESS MAPPING AND
THEN SUBSTITUTES A MATCHING PHYSICAL LOCATOR. THE SAME LOGICAL NAMESPACE ALSO
COVERS THE RAW SWAP TAIL, SO SWAP DOES NOT NEED A SECOND REMAP PATH.

## SIZE

WITH THE SAME TOOLCHAIN, THE CURRENT BADMAP-CAPABLE CLEAN TREE MEASURES KCORE
10034 AND KCORE+MRES 16148 WORDS.  SINGLE-ROOT PERMANENT_LAST IS 037503 WITH
188 FREE ADDRESSES; ACTIVE MULTI-ROOT MULTI_LAST IS 037554 WITH 147 FREE
ADDRESSES BELOW 040000.  ACTIVE BAD MEDIA COST THE MOVABLE BADMAP PACKAGE PLUS
ONE MANAGED WORD PER EXCEPTION.

## ACCEPTANCE

- PRODUCTION MAPPER TEST PASSES DSK270 AND DRM236 GEOMETRIES.
- RAW SWAP-TAIL LOGICAL BLOCKS PASS THROUGH THE SAME TRANSLATOR.
- HOST MAINTENANCE TESTS COVER D6FS, LOGSTORE, PACK/FSCK, AND SWAP RESIZE.
- REAL PDP-6 SIMH ROOT TEST REMAPS BOTH D6FS SUPERBLOCKS, DESTROYS THE ORIGINAL
  PHYSICAL SECTORS, AND STILL REACHES LOGIN WITH BADMAP AND D6FS LOADED.

## MAINTENANCE INVARIANT

`D6SWAP --RESIZE-TAIL` MUST PRESERVE EACH MEMBER'S EXISTING PHYSICAL SPARE
RESERVE. THE RESERVE IS `SECTORS - BASE - USABLE - OLD_TAIL`; NEW USABLE
CAPACITY IS CALCULATED AFTER SUBTRACTING BOTH THE NEW TAIL AND THAT RESERVE.
THIS KEEPS PERSISTENT PHYSICAL SOURCE/SPARE LOCATORS VALID ACROSS RESIZES.

DEVICE-SPECIFIC RETRY/RESET AND ONLINE RETIREMENT POLICY REMAIN IN THE RAW
DRIVER LAYER. AN UNRECOVERABLE READ IS STILL DATA LOSS; BADMAP DOES NOT INVENT
REPLACEMENT CONTENTS.
