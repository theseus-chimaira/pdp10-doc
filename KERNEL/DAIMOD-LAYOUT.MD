# DAIMOD MINIT/MRES MEMORY LAYOUT RULE

DAIMODS ARE SPLIT INTO TWO MEMORY PARTS:

- 'MINIT': RECLAIMABLE MODULE INITIALIZATION CODE/DATA.
- 'MRES': PERSISTENT RESIDENT MODULE CODE/DATA.

FOR NON-PAGED PDP-6/KA10-CLASS MACHINES, THE LOADER MUST NOT PLACE EACH
MODULE AS 'MINIT,MRES,MINIT,MRES'.  THAT WOULD LEAVE HOLES AFTER THE MINIT
PARTS ARE RECLAIMED.

THE IMAGE LAYOUT MUST INSTEAD PACK MEMORY BY LIFETIME:

'''TEXT
KRES  + ALL DAIMOD MRES PARTS  -> RESIDENT MEMORY
KINIT + ALL DAIMOD MINIT PARTS -> RECLAIMABLE INIT MEMORY
'''

AFTER KINIT AND ALL MINIT ENTRY POINTS HAVE RUN, THE WHOLE INIT PART CAN BE
RELEASED AS ONE CONTIGUOUS REGION.  KRES AND ALL MRES PARTS REMAIN CONTIGUOUS
RESIDENT MEMORY.

THE PUBLIC CONSTANTS ARE IN 'INCLUDE/MODULE_ABI.H', 'INCLUDE/KINIT.H', AND
'INCLUDE/DBOOT_V1.H' SO LATER USERLAND ADMINISTRATION AND PAPERPUNCH TOOLS CAN
BUILD THE SAME BINARY RECORDS WITHOUT CARRYING KRES STRINGS:

'''TEXT
DAIMOD_ID_*
MODF_HAS_MINIT
MODF_HAS_MRES
DMANIF_* MANIFEST FIELDS
'''

## CURRENT LOADING RULE

STAGE1 DOES NOT PARSE A 'MODULES' BUNDLE AND DOES NOT SELECT INDIVIDUAL
MODULES.  THE DAIMON IMAGE HEADER GIVES STAGE1 THE RESIDENT KRES WORD COUNT AND
THE OPAQUE INIT-STREAM WORD COUNT.  STAGE1 LOADS KRES AT '000040' AND THE WHOLE
INIT STREAM HIGH BELOW BOOTINFO.

THE BOOTSET/IMAGE GENERATOR BUILDS THAT INIT STREAM AS:

'''TEXT
DMANIF MANIFEST
KINIT
ALL SELECTED MINIT PAYLOADS
ALL SELECTED MRES PAYLOADS
'''

KINIT PARSES THE 'DMANIF' MANIFEST, COPIES/RELOCATES THE MRES PAYLOADS INTO THE
RESIDENT AREA IMMEDIATELY ABOVE KRES, DISPATCHES THE MINIT PAYLOADS, RECORDS
RESIDENT MODULE STATE, AND THEN GIVES THE KINIT/MINIT MEMORY BACK TO THE KERNEL
ALLOCATOR.

THE MODULE SET IS CURRENTLY CHOSEN BY THE IMAGE GENERATOR FROM ITS DEFAULT
MODULE LIST PLUS EXPLICIT '--BOOT-MODULE' ARGUMENTS.  KICFG/DBX DATA CARRIES
BOOT POLICY AND KERNEL/MODULE CONFIGURATION FIELDS FOR KINIT; IT IS NOT A
STAGE1 MODULE LINKER INPUT.

## KINIT WORK

KINIT RECEIVES THE KRES RANGE, INIT-STREAM RANGE, BOOTINFO, KICFG-DERIVED BOOT
POLICY, AND DMANIF MANIFEST.  KINIT THEN:

'''TEXT
VALIDATES THE DMANIF HEADER AND CHECKSUM
WALKS PER-MODULE MINIT/MRES SIZE RECORDS
COPIES MRES PAYLOADS INTO THE RESIDENT AREA ABOVE KRES
REGISTERS MRES DISPATCH TABLES
CALLS EACH SELECTED MINIT PAYLOAD
REJECTS ANY KRES/MRES POINTER INTO KINIT/MINIT MEMORY
RECLAIMS ONE CONTIGUOUS INIT RANGE AFTER ALL MINIT CODE HAS FINISHED
'''

THIS KEEPS STAGE1 SMALL AND STILL PREVENTS RECLAIM HOLES IN THE FIRST BOOTABLE
IMPLEMENTATION.

## V0.9 DEMAND-MODULE ARCHITECTURE

`KERNEL/MEMORY-MANAGEMENT.MD` DEFINES EVOLVING THE SAME MINIT/MRES RELOCATION
FORMAT INTO A SMALL LOADABLE/UNLOADABLE RUNTIME MODULE FORM FOR V0.9.

THE IMPORTANT CONTINUITY RULE IS THAT DRIVER AND OPTIONAL-SUBSYSTEM PAYLOADS
REMAIN IN THE BOOT IMAGE.  THE CHANGE IS THAT SELECTED MRES-LIKE PAYLOADS NEED
NOT ALL REMAIN RESIDENT AFTER BOOT.

THE RESIDENT PAYLOAD DIRECTORY SHOULD BE NUMERIC AND TARGET ONE WORD PER MODULE
OR BETTER.  MODULE ID IS THE INDEX; STRING NAMES REMAIN OUT OF KRES.  A PACKED
END-OFFSET TABLE IS A CANDIDATE REPRESENTATION BECAUSE START/SIZE CAN BE
DERIVED FROM ADJACENT ENTRIES WHILE DETAILED IMAGE METADATA REMAINS WITH THE
NONRESIDENT PAYLOAD.

AUTOMATIC DEVICE ACCESS MAY LOAD THE REQUIRED DRIVER.  FILESYSTEM MOUNT MAY
THEN LOAD ONLY THE SELECTED FILESYSTEM PERSONALITY.  RAW DEVICE I/O MUST NOT
LOAD FILESYSTEM PERSONALITY CODE MERELY TO USE THE DEVICE.

AUTOLOADED MODULES MAY UNLOAD WHEN THEIR LOGICAL REFERENCE COUNT REACHES ZERO
AND THEY ARE QUIESCENT.  AN EXPLICIT PRIVILEGED LOAD PROMOTES A MODULE TO
manual residency; manual residency prevents automatic unload but does not pin
the module's physical address.  ACTIVE I/O uses a separate physical pin count.

RUNTIME MODULE ALLOCATION AND MOVEMENT BELONG TO THE KERNEL MM LAYER, NOT TO A
private module-loader allocator.  IF total free memory is sufficient but no
contiguous extent can satisfy a load, MM may compact stopped processes and
movable modules before retrying.
