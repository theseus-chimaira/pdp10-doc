## BOOT IMAGE

STAGE1 LOADS OR DECOMPRESSES ONE COMPLETE KINIT/KCORE IMAGE AT 030000 AND
ENTERS KINIT THERE.  KINIT CONTAINS THE BUILT-IN MINIT TABLE AND the packaged
MRES images required by the selected build profile.

KCORE BEGINS AT 000060.  KINIT INSTALLS PERMANENT MRES PACKAGES IMMEDIATELY
ABOVE THE FIXED KCORE AREA so KCORE+MRES forms a packed low-memory resident
block.  MINIT code and other KINIT-only material are transient and are
reclaimed after initialization.

## BUILT-IN MODULE PAIRS

`MODULE_TABLE.S` DEFINES THE BUILT-IN MINIT/MRES PAIRS.  KINIT COPIES THE MINIT
TABLE before relocation can overwrite its source, runs the MINIT entries in
last-use order, installs each selected MRES package, applies its relocation
map, and publishes its exported service addresses.

AN MRES PACKAGE CARRIES A COMPACT HEADER, EXPORT OFFSETS, IMAGE WORDS, AND A
RELOCATION MAP.  BOOT MRES EXTENTS BECOME PERMANENT AFTER INSTALLATION and do
not retain their relocation maps because they are pinned.

OPTIONAL PACKAGES SUCH AS BADMAP ARE INSTALLED ONLY WHEN NEEDED.  CLEAN MEDIA
THEREFORE PAYS NO BADMAP MRES COST.

## SERVICE AND PI BINDING

BUILT-IN MODULE SERVICES ARE PUBLISHED THROUGH THE NUMERIC SERVICE TABLE IN
`MODULE.H`.  MINIT patches the required call/jump sites and PI registrations.
The runtime movement code can retarget fixed bindings, dynamic bindings, and
PI handlers when a movable module changes address.

## RUNTIME MOVABLE MODULES

THE MOVEMENT/RELOCATION PRIMITIVES EXIST.  `MODULE_RUNTIME_MOVE` CAN MOVE A
MODULE IMAGE, APPLY ITS RELOCATION map, update registered bindings, and
retarget PI handlers while MM compaction is in progress.

THE GENERAL RUNTIME MODULE LIFECYCLE IS NOT YET COMPLETE.  A FUTURE LOADABLE
MODULE MUST retain its relocation map and needs the full lifecycle:

```TEXT
LOAD -> ALLOCATE -> COPY -> RETAIN RELOCATION MAP -> RELOCATE
     -> RESOLVE/PUBLISH SERVICES -> REFERENCE -> UNLOAD/AUTO-UNLOAD
```

THIS LOADER MUST USE THE EXISTING MM, SERVICE, BINDING, AND PI machinery.  IT
MUST NOT introduce a second DMANIF-style boot manifest or depend on a full MMU.

## MEMORY RULES

PERMANENT KCORE+BOOT-MRES MUST REMAIN BELOW 040000.  MOVABLE runtime modules
live in managed core and may be compacted.  Module relocation must remain
correct for overlapping physical moves and must not require a second full
module image.  RAM consumption is the primary optimization constraint.
