## v1959: verified address admission and runtime recovery

DEC H-270 pp.2-11, 3-10/11 and Fig.3-1 establish legal
DATAO in IDS/ADT and intentional ADT/DFR alternation while
awaiting a command. v1958 exposed a real wrong-medium read:
the driver sampled ADT, DATAO reached DFR and was ignored,
then the command transferred from the old address.
Do not change the documented simulator state machine.
DAIMOS 06eff089 shares bounded address submission between
boot and runtime, confirming SNA after ADT DATAO and retrying
on DFR before arming DCT/publishing ownership. Runtime
watchdog atomically rechecks active ownership, requests

on synchronous refusal. Shared clock bounds admission and
active transfer; no new BSS. DSK MRES 234->264 words,
fixed KCORE unchanged. SIMH remains cec5436.

Forced real DFR DATAO then ADT retry PASS; confirmation

Six FULL root cases, KINIT actual PI5 loss and independent

Actual partial READ/WRITE loss at eight DCT words, distinct

## Runtime critical BACKSTORE loss (v1956)

With the v1955 accepted 64K KCC disk-root workload, real
Type-270 READ at 032052 and WRITE at 032047 are interrupted
immediately after CONO by DETACH DSK0, while actual native
slot0 swap I/O owns its request. Both paths reach the v1541
dedicated BACKSTORE HALT004510 (reason2), request event -1,
storage_state and active DSK descriptor zero. READ retains
slot2 DISK run0..63, TRANSITION and pin1 on the 8192-word
destination. WRITE retains slot2 RESIDENT original 8192-word
APR, TRANSITION and source pin1, 64 reserved backing bits
but zero published swap sectors. The WRITE fatal gateway
runs in allocation caller slot1 after slot0 I/O fails.
Entire physical MM table exactly identical before fault and
after HALT in both. No new production code; no status deposits.
This is fail-stop on critical backing loss, not general
runtime recovery, arbitrary mid-sector transfer coverage,
or an assertion that lost WRITE can return to IDS without
actual sector clocks. Testkit 7905494, evidence
$TMPDIR/k09-disk-swap-v1955.MbLEZM/{read,write}-loss-final-v1956.

## Type-270 command loss and bounded KINIT wait (v1954)

H-270 Fig.3-1 and pp.3-11/13, 3-25/26: loss of OPERABLE
sets FER, not an unconditional IDS reset. Internal DFR/ALP,
CSP, NDP1 and ESP2 delays continue independently of disk
clocks. READ END induces ESP1, which permits normal SCE
termination. WRITE/compare require actual sector completion.

SIMH cec5436 retains a selected-medium-loss latch until a
new legal DATAO. No lost operation may read or write a host
file, including one attached before its termination. A lost
READ in SCS can terminate via END; DFR without a command
returns to ADT. Lost WRITE without sector clocks remains
SCS, even if another file is attached. No artificial reset or
successful partial write. All four native removal/replacement
tests fail on v1953 and pass on v1954, both media unchanged;
the WRITE probe is a state/immutability check, not a complete
active-write DCT data-path test. Seven previous native probes
also pass on the clean commit.

Unmodified KCC FULL KINIT READ at 033650 followed by DETACH
DSK0 now reaches PI5 CONI001105020003 and fails closed rather
than hanging. DAIMOS b98f64d7 additionally fixes the independent
unbounded boot wait: reuse the negative storage_count, a
300-tick deadline at 60 Hz, with IDS/ADT admission before
DATAO. Atomically claim a timeout with PI disabled, recheck
completion, END/CLR/SCL and disable DCT before release. The
normal native clock must run. The runtime watchdog is unchanged.
No fixed KCORE growth or additional BSS; DSK MRES 211 -> 234
words, 23 words of functional code.

The actual old v1953 missing-interrupt case reaches new
timeout034146 with countdown0 and storage_state -3, exactly
300 clock ticks after READ issue (013->0467). Both silent and
normal PI5 paths reach KINIT HALT101320, namespace root,
storage_state and storage_count all zero; all four disk

## Type-270 address-acquisition media loss (v1953)

H-270 Fig. 3-1 and pp. 3-25/26 distinguish the internal
SNA-to-ADT address-termination pulse (ATP) from a disk-ready
signal. SIMH must not cancel that pulse when the selected disk
is detached. OPR loss latches FER; an ADT address error also
latches ADE. There is no invented CLEAR-to-IDS reset.

Simulator 12dcd35 retains pending ATP during SNA media loss,
latches FER immediately and terminates that acquisition in ADT
with ADE/FER even after immediate reattachment. In ADT it
cancels the seek event and reports ADE/FER. A new legal DATAO
after SCL recovers; unselected-unit detach is unaffected.
The three loss probes fail on v1950 and pass on v1953; the
unselected-unit control and all three v1950 probes also pass.

On an unmodified KCC FULL disk-root image, actual DATAO at
034127 is followed by operator DETACH DSK0. Native PI5 error
handler sees CONI 000125200003, explicit disk-root selection
fails closed at KINIT HALT101271, namespace root remains zero,
INIT never executes and all four private disks remain identical.
The clean committed simulator repeats these results. Three
DSK-related root-selection regressions pass on the candidate
built from the same source. Evidence and native probes:
daimos-testkit/tests/validation/dsk270-media-loss-v1953/.

This is address acquisition loss/recovery, not sector-transfer
loss acceptance. DFR and busy detach semantics are unchanged.

## Type-270 address acquisition correction (v1950)

DEC Discfile Control 270, H-270 (April 1966), pp. 2-11, 3-7/8,
3-11, 3-26 and Fig. 3-1 define the relevant controller contract.
The address is accepted only in IDS or ADT. DATAO in ADT
interrupts the old seek. DFR requires a ready signal from the
discfile; an error during ADT sets ADE and FER. CLR implies END
and belongs to command termination; it does not independently
reset the octoflop to IDS.

The original PDP-6 SIMH Type-270 model asserted DFR even for an
absent drive and allowed DATAO in SNA/DFR. Accepted reselection
changed the shared address without transferring the scheduled
event to the new unit, and nonbusy CONO retained stale END/CLR.
The actual FULL AUTO TSFS + DSK0 AUXSTORE boot therefore lost
access to a valid attached DSK0 after probing absent DSK1-3.
The first v1949 simulator correction 227f563 forced CLEAR to
IDS during address acquisition; that behavior and its DFR
reselection test are withdrawn after review of the DEC manual.

Simulator cb6a255 (v1950) retains ADT on absent-unit address
error, admits DATAO only in IDS/ADT, cancels the old selected
unit event before scheduling the new one, reloads nonbusy CONO
and sets END when CLR is set. No DAIMOS root policy or resident
word is changed. Three independent native controller probes
fail on both the original and speculative v1949 models and
pass with v1950. All six 256K KCC FULL root-selection cases
pass on v1950, including AUTO TSFS with a validated DSK0
AUXSTORE (512 backing blocks). This accepts the documented
address-acquisition correction and boot selection, not the
entire Type-270 protocol or mid-transfer detach handling.

## SEEK SCHEDULING

## WATCHDOG COUNTDOWN CORRECTION (2026-10-30, V734)

THE 60 HZ TYPE-270 REQUEST WATCHDOG STORES THE REMAINING TICKS IN THE LEFT
18-BIT HALF OF `DSK_ACTIVE_REQUEST`, WITH THE DESCRIPTOR ADDRESS IN THE RIGHT
HALF. THE ORIGINAL `SUB DSK_ACTIVE_REQUEST,[1,,0]` DID NOT WRITE THE
COUNTDOWN MEMORY WORD: `SUB` ONLY WRITES ITS ACCUMULATOR. `SUBM` IS ALSO
UNSUITABLE BECAUSE IT STORES ACCUMULATOR MINUS MEMORY, REVERSING THE OPERANDS.

`DSK_WATCHDOG_TICK` NOW USES `MOVSI 1,-1` FOLLOWED BY
`ADDM 1,DSK_ACTIVE_REQUEST` TO DECREMENT THE LEFT HALF IN PLACE WITHOUT
MODIFYING THE RIGHT HALF. NATIVE PDP-6 REGRESSION V734 VERIFIED
`000454035024` BECOMING `000453035024` ACROSS THE WATCHDOG INSTRUCTION.
THE FIX WAS BUILT IN THE 256K-CONFIGURED LOWMEM IMAGE AND IS COMMITTED IN
DAIMOS `EB7A407`; ITS REGRESSION IS IN DAIMOS-TESTKIT `0CCDCB0`.
THIS DOES NOT YET ESTABLISH FULL-SYSTEM SWAP-PRESSURE ACCEPTANCE.


FOR SEEK-BASED DISKS, EACH PHYSICAL DSK UNIT USES A SMALL BOUNDED ONE-WAY
ELEVATOR QUEUE, FOLLOWING THE SIMPLE TENEX POLICY:

1. SERVICE THE NEAREST QUEUED REQUEST AT OR ABOVE THE CURRENT TRACK/CYLINDER.
2. CONTINUE IN THE SAME DIRECTION.
3. WHEN NO REQUEST REMAINS ABOVE, WRAP TO THE LOWEST QUEUED REQUEST.
4. DO NOT IMPORT TENEX PRIORITY-CLASS COMPLEXITY UNLESS MEASUREMENT SHOWS A
   NEED.

SCHEDULING IS PER PHYSICAL MEMBER AND OCCURS BELOW BLOCKSET STRIPING.  QUEUE
DEPTH IS A BENCHMARKED IMPLEMENTATION PARAMETER, NOT AN ON-DISK FORMAT FIELD.

## BAD-SECTOR HANDLING

DSK270 OWNS PHYSICAL ERROR DETECTION, BOUNDED DEVICE-SPECIFIC RETRY/RESET, AND
REPORTING.  IT DOES NOT OWN A PERSISTENT BAD-SECTOR TABLE AND MUST NOT SILENTLY
CHANGE LOGICAL BLOCK MAPPINGS.

PERSISTENT SUBSTITUTION BELONGS TO THE COMMON STORAGE-SET BAD-MEDIA MAPPER
DEFINED IN 'KERNEL/BLOCKSET.MD'.  DSK270 AND DRM236 SHARE THAT TRANSLATOR AND
ON-MEDIA EXCEPTION FORMAT; THEY DO NOT DUPLICATE RESIDENT MAPS.  FOR THE PDP-6
PROFILE ONE 36-BIT WORD HOLDS A COMPLETE SOURCE->SPARE REMAP.

ROOT DISCOVERY IS INTENTIONALLY BOUNDED BY NEED: KINIT STOPS PROBING PHYSICAL
UNITS AS SOON AS THE REQUESTED COMPLETE D6FS SET IS KNOWN.  THIS IS ALSO THE
STAGE1 RULE.  AN ABSENT TRAILING UNIT IS NOT PART OF A SUCCESSFUL ROOT
DISCOVERY AND MUST NOT BE TOUCHED AFTER THE REQUESTED SET IS COMPLETE.

THE CURRENT DRIVER STILL DOES NOT RETRY MEDIA ERRORS ITSELF: THE PI ERROR PATH
FAILS THE ACTIVE REQUEST, AND THE BOOT POLLED PATH RETURNS FAILURE.  PERSISTENT
REMAP APPLICATION IS NOW IMPLEMENTED ABOVE THE RAW DRIVER BY THE COMMON OPTIONAL
BADMAP PACKAGE, SO DSK270 REMAINS FREE OF A DUPLICATE RESIDENT TABLE.  ONLINE
RETIREMENT AFTER A RECOVERED READ OR FAILED WRITE REMAINS OPEN DRIVER/POLICY WORK.

A NEW UNRECOVERABLE READ MUST CONTINUE TO REPORT DATA LOSS EVEN AFTER THE
PHYSICAL BLOCK IS RETIRED.  A WRITE OR A READ WHOSE DATA WAS RECOVERED BY RETRY
MAY BE MOVED TO A SPARE ONCE THE COMMON REMAP UPDATE CAN BE RECORDED CRASH-SAFELY.

NATIVE SURFACE SCAN BELONGS TO BADSCAN/MAINTENANCE TOOLING.  THE DRIVER SHOULD
EXPOSE ENOUGH PHYSICAL FAILURE CONTEXT FOR THAT TOOLING WITHOUT KEEPING A
SECOND BAD-SECTOR DATABASE.

## BUFFER AND CACHE POLICY

DSK270 DOES NOT OWN A FILESYSTEM BLOCK CACHE.

THE DRIVER MAY KEEP ONLY THE BOUNDED TRANSFER/REQUEST STATE NEEDED TO OPERATE A
PHYSICAL UNIT AND ITS SEEK QUEUE.  THE PDP-6 FILESYSTEM/VFS PATH RETAINS A SHARED 128-WORD FULL-BLOCK WORKSPACE
FOR OPERATIONS THAT REQUIRE IT.  D6FS ALSO HAS A RECLAIMABLE MANAGED-CORE
CACHE; CLEAN CACHE BLOCKS ARE reclaimed before compaction or process swap.
D6FS AND DTFS MUST NOT FORCE PRIVATE FULL-BLOCK ARRAYS INTO DSK270.

REQUEST QUEUES ARE SCHEDULING STATE, NOT A DATA CACHE.  A FUTURE ASYNCHRONOUS
WRITE PATH MAY REQUIRE BOUNDED IN-FLIGHT BUFFERS, BUT THEIR COUNT MUST BE
MEASURED AGAINST PDP-6 RAM AND MUST NOT BECOME AN UNBOUNDED FREE-RAM CACHE.

## DEFERRED MULTI-SECTOR OPTIMIZATION

MULTI-SECTOR STREAMING IS A POSSIBLE PERFORMANCE OPTIMIZATION, NOT A
CORRECTNESS REQUIREMENT.  IT MEANS ISSUING ONE HARDWARE/CONTROLLER TRANSFER FOR
A RUN OF ADJACENT SECTORS INSTEAD OF CALLING 'READ_SECTOR()' OR
'WRITE_SECTOR()' ONCE PER SECTOR.  THERE IS CURRENTLY NO PUBLIC RUN API; ADD
ONE ONLY IF A REAL CALLER AND MEASURED BENEFIT JUSTIFY THE EXTRA RESIDENT CODE.

THE FIRST CORRECT PROTOTYPE COST ABOUT 53 RESIDENT WORDS AND WAS REJECTED
WITHOUT A LIVE PROCESS-SWAP CALLER.  RECONSIDER IT ONLY AFTER REAL RUN TRAFFIC
EXISTS AND MEASUREMENT SHOWS THAT PER-SECTOR SETUP DOMINATES.  THE ACCEPTANCE
GATE IS A MATERIAL SPEEDUP AT A JUSTIFIED RESIDENT COST, WITH ALL STORAGE
ORACLES STILL GREEN.

HARD RULE FOR ANY FUTURE STREAMING:

'''TEXT
NEVER CROSS SECTOR 43 -> 0 IN ONE HARDWARE STREAMING COMMAND
UNLESS HARDWARE AND SIMULATOR BEHAVIOR ARE BOTH PROVEN SAFE
'''
