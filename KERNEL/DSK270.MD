## IMPLEMENTED V1 PATH

THE CURRENT TREE IMPLEMENTS THE FIRST SYNCHRONOUS HDD PATH:

'''TEXT
PAPER TAPE OR SIMH RIM
  -> STAGE1 HDD/DBOOT V1 READER
  -> DB0/DBX OR DBC DESCRIPTOR SELECTION
  -> DAIMON BOOT STREAM READ FROM SELECTED MEMBER RUNS
  -> BOOTINFO V2 AT 073000
  -> KINIT IMPORTS BOOT REGIONS
  -> BOOTDISK MAPS FSREGION LOGICAL SECTORS TO MEMBER SECTORS
  -> BOOTDISK READS FSREGION SECTORS
  -> D6FS MOUNTS THE ROOT FILESYSTEM
'''

IMPLEMENTED PIECES:

'''TEXT
- DCT136 POLLED WORD TRANSFER HELPERS
- DSK270 RAW ADDRESS PACKING, PROBE, SECTOR READ, SECTOR WRITE
- DSK270 RUN READ/WRITE API THAT LOOPS ONE SECTOR AT A TIME, WITHOUT HARDWARE STREAMING
- INTERRUPT-MODE ENTRY POINTS AND PI REGISTRATION HOOKS
- STAGE1 PRIVATE DSK270 READER
- DBOOT DB0/DBX/DBC V2 PARSING
- BOOTINFO V2 DISK-SET AND REGION HANDOFF
- BOOT-REGION MEMBER MAPPING THROUGH THE HISTORICAL P6STRIPE HELPER
- FSREGION READ PATH THROUGH BOOTDISK
- D6FS READ-ONLY BOOT-ROOT MOUNT WITH A SMALL METADATA AND BLOCK CACHE
- HOST TOOLING TO CREATE CLEAN EMULATOR BOOT SETS WITH D6FS ROOTS
'''

THE RAW DSK270 LAYER REMAINS A PHYSICAL-SECTOR DRIVER. IT DOES NOT KNOW ABOUT
D6FS FILES, DIRECTORIES, ARENAS, OR ALLOCATION POLICY.

## LAYERING

'''TEXT
DSK270.C        PHYSICAL DSK UNITS AND SECTORS
P6STRIPE.C      HISTORICAL NAME FOR BOOT MEMBER MAPPING AND BAD-RUN SKIPPING
BOOTDISK.C      SELECTED BOOT REGION READER FROM BOOTINFO
D6FS            FILES, FCBS, DIRECTORIES, ARENAS, AND FILESYSTEM CACHE
'''

STAGE1 USES SMALL PRIVATE CODE. IT SHARES CONSTANTS AND FORMATS BUT NOT THE FULL
KERNEL DRIVER BODY.

## CURRENT MEDIA FORMAT

THE CURRENT MEDIA DESCRIPTOR IS DBOOTX V2:

'''TEXT
DBC   ONE-SECTOR CLEAN-MEDIA DESCRIPTOR
DB0   BAD-RUN SECTOR
DBX   DESCRIPTOR PAIRED WITH DB0
'''

THE DESCRIPTOR RECORDS GENERATION, DISK-SET UUID, MEMBER MASK, MEMBER INDEX,
DISK COUNT, KINIT BOOT CONFIGURATION, AND THE MEMBER-LOCAL BOOTSTREAM RUN.
THE MEMBER LAYOUT IS BOOT MEDIA POLICY, NOT A GENERAL DSK270 STRIPING FEATURE.
IT SHOULD BE DESCRIBED AS BOOT MEMBER PLACEMENT, NOT AS A DSK270 DRIVER FEATURE.
REGION DESCRIPTORS ARE NO LONGER STORED DIRECTLY IN DBOOTX; KINIT RECEIVES THE
BOOT-REGION VIEW THROUGH BOOTINFO AND MANIFEST DATA.

    STRUCT DSK270_ADDR *AP);

- ONLINE SECTOR EVACUATION

## PRIORITY MULTI-SECTOR OPTIMIZATION

MULTI-SECTOR STREAMING IS USEFUL AS A PRIORITY PERFORMANCE OPTIMIZATION, NOT AS A CORRECTNESS REQUIREMENT. IT MEANS
ISSUING ONE HARDWARE/CONTROLLER TRANSFER FOR A RUN OF ADJACENT SECTORS INSTEAD
OF LOOPING THROUGH 'READ_SECTOR()' OR 'WRITE_SECTOR()' ONE SECTOR AT A TIME.
THE VISIBLE API ALREADY HAS 'READ_RUN()' AND 'WRITE_RUN()', BUT THE CURRENT
IMPLEMENTATION STILL PERFORMS ONE FULL SECTOR OPERATION PER SECTOR.

STREAMING IS NOT REQUIRED FOR V1 CORRECTNESS, BUT IT SHOULD BE THE FIRST DSK270
PERFORMANCE ITEM ONCE THE CACHE/WRITE PATH IS STABLE ENOUGH TO MEASURE. IT
MATTERS MOST WHEN BOOT LOADING, D6FS READ-AHEAD, OR DIRTY-CACHE WRITE-BACK SPEND
TOO MUCH TIME IN PER-SECTOR SETUP.

HARD RULE FOR ANY FUTURE STREAMING:

'''TEXT
NEVER CROSS SECTOR 43 -> 0 IN ONE HARDWARE STREAMING COMMAND
UNLESS HARDWARE AND SIMULATOR BEHAVIOR ARE BOTH PROVEN SAFE
'''
