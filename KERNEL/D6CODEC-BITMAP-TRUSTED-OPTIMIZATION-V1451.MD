# Trusted in-RAM bitmap codec optimization, v1451

Date: 2026-11-10. **Component-level native PDP-6 validation complete;
no production swapless compression or KINIT MRES activation.**

## Scope and trust boundary

The bitmap format is for DAIMOS-owned mutable process RAM only. The
kernel pauses the process, establishes exclusive ownership of both
the original and packed extents, supplies exact sizes, and records
the resulting packed length in the process descriptor. Its decoder
only ever consumes a representation previously generated by its
own paired encoder. It is **not** a file decoder, TSFS parser, VFS
provider, or general-purpose untrusted decompression library.

Consequently the codec no longer contains checks for available
compressed source words, destination capacity, header/trailer
consumption, or caller-supplied memory geometry. These are **MM
invariants** to establish before either invocation. Malformed or
externally supplied compressed streams are outside this ABI.
MM still must preflight the exact compacted size, guarantee safe
restoration and keep the representation intact until restoration.

The format is unchanged from v1432: each full or partial group of
36 decoded 36-bit words consists of one bit-presence mask followed
by the nonzero words in address order. Bit 35 marks the first word.
Given `n` original words, the exact compressed size is

    ceil(n / 36) + number_of_nonzero_words

All lengths are measured in 36-bit words. The codec requires a
strictly positive original word count; MM handles empty extents.

## Register-only interface

The final standalone source is in daimos-testkit at
`tests/validation/d6codec-compressor-v1451/bitmap-v1451.s`.
Both functions are leaf PDP-6 assembly routines:

| Entry | Inputs | Output |
|---|---|---|
| `bitmap_encode_v1451` | AC1 source, AC2 original count, AC3 packed destination | AC3 = first unwritten packed word |
| `bitmap_decode_v1451` | AC1 packed source, AC3 destination, AC4 original count | Restored words at destination; void return |

AC0..AC7 may be clobbered; **AC10..AC15 and AC17 are preserved**.
No save/restore instructions, explicit stack frame, static data,
BSS, heap or I/O are required by the codec itself. A dedicated
PDP-6 native fixture confirms the preservation of AC10..AC15
across both calls and full 73-word recovery. These are test-only
exports, not yet published through the production MM interface.

## Direct measurements and optimization history

| Version | Encoder + decoder TEXT | Major change |
|---|---:|---|
| v1432 | 55 | Native bitmap pair with checked counts/capacity |
| v1442 | 52 | `SOJE`, direct `TDNN` bitmap bit test |
| v1443 | 48 | `SOJL` combines decrement and rejection |
| v1444 | 47 | `MOVSI` avoids an extra literal-pool word |
| v1445 | 46 | Output pointer difference replaces running output count |
| v1446 | 39 | Remove checks on trusted owned memory |
| v1447 | 36 | Void decoder and default zero-word store |
| v1448 | 34 | Positive-length MM precondition simplifies group loops |
| v1449 | 31 | Encoder returns its end pointer in AC3 |
| v1450 | 30 | Initialize header in place, use `IORM` for presence bits |
| **v1451** | **30** | Move all scratch state into caller-volatile ACs |

All versions above have zero static DATA/BSS. Native full-image
roundtrips passed at every retained stage. The final v1451
version passes eight PDP-6 roundtrip fixtures, including three
actual DSH captured-RAM states, plus an independent AC10..AC15
ABI-preservation fixture. The last pass found no further
straightforward safe standalone instruction removal; no formal
minimal-code proof is claimed.

## Actual DSH process-memory payloads

| DSH snapshot | Original retained suffix | Nonzero source words | Bitmap output | Additional saved words |
|---|---:|---:|---:|---:|
| Idle | 3,200 | 225 | 314 | 2,886 |
| After six variables | 3,200 | 435 | 524 | 2,676 |
| Function-heavy | 5,248 | 531 | 677 | 4,571 |

These are exact 36-bit snapshots from the v1426 running PDP-6
simulator guest, after a hypothetical 15,232-word PURE-prefix
release. Current DSH has no PURE tag, so this is **potential
reclamation**, not RAM already reclaimed by DAIMOS.

Native v1450 code (identical instruction stream to v1451 except
the scratch register numbers) measured:

| DSH state | Encode instructions | Decode instructions | Combined at nominal 0.25 MIPS |
|---|---:|---:|---:|
| Idle | 20,335 | 23,219 | 0.1742 seconds |
| Variables | 20,965 | 23,639 | 0.1784 seconds |
| Function | 33,826 | 38,395 | 0.2889 seconds |

Counts are native PDP-6 SIMH instructions, not actual hardware
time. The codec uses no `BLT`, so these counts do not hide
multiword BLT transfers. MM preflight, allocation, compaction,
stopped-process ownership, and reactivation are **not included**.
The `IORM` implementation trades additional memory read/write
cycles for one code word versus v1449; cycle-accurate elapsed
time has not been measured. The independent v1451 step results
are stored separately in its testkit speed TSV.

## Exact MRES package and folding analysis

The existing assembler plus `dlink -R` toolchain generates a
normal two-export MRES package without installing it in KINIT:

| MRES measure | v1432 | v1451 |
|---|---:|---:|
| Final resident codec image | 55 | **30** |
| Transient boot package words | 63 | **36** |
| Static data/BSS | 0 | 0 |

The temporary package is reclaimed after the boot installer
has copied the 30 image words to permanent module storage.
MRES publication/dispatch, MM wrappers and activation guards
can add costs outside this measured image.

`p10fold` was run bidirectionally between the **118-word
block v1441 core + VFS adapter** and the **30-word bitmap
v1451 encoder/decoder**:

- With minimum eligible run length two, **no cross-domain
  folds and zero projected resident savings**, in either
  direction. There are two overlapping short hot-loop pairs
  within the bitmap image that would each require an extra
  JRST; their savings would trade a jump for every nonzero
  input word. Do not fold those hot paths.
- With minimum run length one and block as permanent anchor,
  one possible **single `POPJ 17`** is reported as a one-word
  zero-cost fold. Exploiting it requires a new cross-module
  code dependency and relocation/entrypoint handling, which
  can cost at least as much as the saved word. No such fold
  has been applied.

There is therefore no demonstrated useful cross-module saving
while preserving the independently selectable bitmap MRES.
The standalone combined resident-code budget is 118 + 30 =
**148 words**, before real KCORE linking and module ABI overhead.

## Integration policy

The bitmap module should be **absent by default** and become
selectable only when the verified running root is DTC/TSFS,
the system has no swap/backstore, and the explicitly configured
swapless profile enables inactive-process compaction. MRES
installation is permanent once accepted at boot; do not demand
that the decoder load from tape while memory is exhausted.

Compressed RAM and its bitmap must never reach untrusted TSFS
file decompression. The general file/executable format is the
separate staged block v1441 codec. It is planned to replace
D6LZ36 entirely after successful Stage-1, TSFS and EXEC/PURE
cutover. The bitmap MRES is an independent RAM-only companion.

Before activation, prove 32K/48K allocation, exact size preflight,
APR-restoration headroom, MM ownership and rollback, bounded
process latency and safe interaction with PI/I/O lifetimes.
Do not compress on every SLEEP; activate only for inactive cold
processes when measured pressure makes reclaim worthwhile.
