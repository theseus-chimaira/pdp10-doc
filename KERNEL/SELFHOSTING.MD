# DAIMOS SELF-HOSTING USERLAND TOOL SET

THIS DOCUMENT LISTS THE USERLAND TOOLS NEEDED FOR AN EARLY SELF-HOSTING DAIMOS SYSTEM.

FULL SELF-HOSTING EVENTUALLY MEANS THAT DAIMOS CAN BOOT, MOUNT ITS OWN STORAGE,
EDIT SOURCE, BUILD THE KERNEL AND USERLAND, INSTALL THE RESULT, DIAGNOSE
FAILURES, AND RECOVER WITHOUT DEPENDING ON ANOTHER RUNNING OPERATING SYSTEM.
THE FIRST V0.9 SELF-HOSTING MILESTONE IS THE NATIVE BUILD PATH; BOOTABLE
RECOVERY DECTAPE/SINGLE-USER IMPLEMENTATION IS EXPLICITLY POST-0.9.

EXTERNAL HOST-SIDE TOOLS MAY STILL BE USED FOR IMPORTING AND EXPORTING FILES.
THEY ARE NOT PART OF THE EVENTUAL NATIVE SELF-HOSTING REQUIREMENT.

## 1. COMMAND ENVIRONMENT

### REQUIRED TOOLS

- 'DSH'
- 'ENV'
- 'TRUE'
- 'FALSE'
- 'TEST'
- 'ECHO'
- 'PRINTF'
- 'PWD'
- 'SLEEP'
- 'KILL'

DSH IS THE NATIVE KSH-INSPIRED DAIMOS SHELL.  IT USES THE RUN/EXEC/WAIT
PROCESS MODEL AND THE FROZEN SIXBIT LANGUAGE IN USER/DSH_DESIGN.MD; IT IS NOT A
POSIX SH PORT.  THE SELF-HOSTING BUILD MUST USE DSH DIRECTLY RATHER THAN ASSUME
A SECOND SH/KSH IMPLEMENTATION.

## 3. TEXT EDITING

### REQUIRED TOOLS

- 'ED'
- 'ELVIS'

'ED' IS THE EMERGENCY EDITOR. IT SHOULD BE TINY, DEPENDABLE, AND USABLE ON A MINIMAL CONSOLE.

'ELVIS' IS THE PRACTICAL SOURCE EDITOR FOR NORMAL NATIVE DEVELOPMENT.

ELVIS IS ALSO THE FIRST PRACTICAL INTERACTIVE LARGE-PROGRAM MEMORY
MEASUREMENT.  BEFORE DEFINING A USERSPACE OVERLAY ABI, RECORD ITS NATIVE TEXT,
DATA, BSS, PEAK DYNAMIC MEMORY, PEAK STACK, AND TOTAL PEAK USER EXTENT ON THE
TARGET SYSTEM.

- 'AWK'

- 'CMP'
- 'DIFF'
- 'SED'
- 'GREP'
- 'SORT'

'MAKE' IS REQUIRED FOR KERNEL, LIBRARY, AND USERLAND BUILDS.

'SED', 'GREP', 'SORT', 'UNIQ', AND 'XARGS' ARE NEEDED BECAUSE EVEN SMALL BUILD SYSTEMS TEND TO DEPEND ON THEM. THE EARLY VERSIONS CAN BE LIMITED, BUT THEIR SUPPORTED SUBSET MUST BE DOCUMENTED AND STABLE.

## 5. NATIVE TOOLCHAIN

### REQUIRED TOOLS AND COMPONENTS

- 'KCC'
- 'CPP'
- 'DAS'
- 'DLINK'
- 'DARC'
- 'NM'
- 'SIZE'
- 'STRIP'
- 'DOBJDUMP'
- 'LIBC'
- 'CRT0'
- 'LIBSYS'

### 'KCC'

'KCC' IS THE NATIVE DAIMOS C COMPILER.

IT IS THE REQUIRED SELF-HOSTING COMPILER BECAUSE IT IS THE NATIVE DAIMOS
TOOLCHAIN TARGET AND CAN BE ADAPTED TO PDP-6/KA10 RESOURCE LIMITS.  THIS IS NOT
A CLAIM THAT CURRENT KCC-GENERATED PROGRAMS ARE SMALLER THAN GCC-GENERATED
PROGRAMS; CURRENT KCC CODE GENERATION IS WORSE AND REMAINS AN OPTIMIZATION
TARGET.

KCC IS THE REQUIRED NORMAL DAIMOS C COMPILER.  THE EXISTING USERSPACE HAS
ALREADY BEEN CONVERTED FROM GCC/LIBGCC TO KCC/DAS; PORT KCC ITSELF AS PART OF
SELF-HOSTING.  DO NOT DEFINE A KCC OVERLAY ABI BEFORE REAL NATIVE MEASUREMENT.
IF A MONOLITHIC NATIVE KCC IS TOO LARGE FOR THE DESIRED MACHINE CLASS, COMPARE
PHASE SPLITTING, SCRATCH-BACKED INTERMEDIATE STATE, LARGE-MEMORY EXECUTION, AND
USERSPACE OVERLAYS BEFORE CHANGING THE KERNEL ABI.

### 'CPP'

THE C PREPROCESSOR MAY BE STANDALONE OR INTEGRATED INTO 'KCC'.

FOR SELF-HOSTING, IT MUST SUPPORT THE SUBSET NEEDED BY THE DAIMOS KERNEL, LIBC, USERLAND, AND BUILD SYSTEM.

### 'DAS'

THE NATIVE ASSEMBLER MUST SUPPORT THE DAIMOS ASSEMBLY SYNTAX USED BY THE KERNEL, BOOT CODE, RUNTIME STARTUP FILES, AND LOW-LEVEL LIBRARIES.

DAS SHOULD BE TREATED AS THE FIRST LARGE DAIMOS-RESIDENT TOOLCHAIN MEASUREMENT.  ITS
PHASE-1/PHASE-2 ARCHITECTURE AND SCRATCH-BACKED WORKING SET ARE INTENDED TO
AVOID REQUIRING BOTH LARGE PHASES IN CORE AT ONCE.  MEASURE DAS1 AND DAS2
SEPARATELY BEFORE USING DAS AS AN ARGUMENT FOR USERSPACE OVERLAYS.

THE EXTERNAL DAS TREE NOW BUILDS A SMALL DAIMOS-RESIDENT PUBLIC DRIVER PLUS
PRIVATE DAS1/DAS2 PHASE IMAGES AND PROVIDES THE AUTHORITATIVE `DAS.SIXMD` PAGE
TO THE BOOT IMAGE WITHOUT COPYING DAS SOURCE INTO THE DAIMOS TREE.  THE PUBLIC
DRIVER, DAS1, AND DAS2 ARE NOW ALL KCC-BUILT.  THE PEEPHOLE/FOLDING OPTIMIZER
IS A HOST-BUILD FEATURE AND IS COMPILED OUT OF DAS_NATIVE WITH ITS STATE AND
OUTPUT-REWRITE HELPERS.  STRUCTURAL PHASE-LIFETIME, PARSER, RUNTIME-HELPER,
AND SHARED-ERROR-TAIL SHRINKAGE, PLUS KCC SHARED FIXED-FRAME RETURN EPILOGUES,
PUT DAS1 AT 033244 WORDS (BSS 002032, PROCESS 037276) AND DAS2 AT 027501 WORDS
(BSS 002342, PROCESS 034043).  BOTH
PASS THE 034000-WORD PHASE-IMAGE BUDGET AND 040000-WORD PROCESS BUDGET WITH
THE STANDARD 02000-WORD STACK.  THE TRANSITIONAL PDP-10 GCC PHASE BUILD IS NO
LONGER USED.  ALL RESIDENT IMAGES USE THE CURRENT CRT0/SYSCALL ABI AND DLINK.

NATIVE BRING-UP ALSO FOUND AND FIXED A KCC LOOP-STRENGTH-REDUCTION CORRECTNESS
BUG: A DERIVED LOCAL-ARRAY POINTER COULD REMAIN LIVE ACROSS A GENERAL IF, BE
SPILLED ON ONE ARM ONLY, AND THEN BE RESTORED AT THE COMMON CONTINUATION.  THE
OPTIMIZER NOW REJECTS THAT UNSAFE MERGE SHAPE WHILE RETAINING SAFE TERMINAL
IF/CONTINUE FORMS.  DAS1/DAS2 REMAIN USEFUL KCC CODE-SIZE WORKLOADS, BUT BOTH
NOW FIT THE ESTABLISHED RESIDENT BUDGET WITHOUT RAISING THE LOADER LIMIT.

THE KCC-ONLY TRANSITION EXPOSED A SECOND COMPILER CORRECTNESS BUG IN OBJECT
OPTIMIZATION.  `PNEGREG` COULD PUSH A LATER `MOVN` BACKWARD THROUGH `P_UIDIV`,
ASSUMING NEGATION COMMUTED WITH UNSIGNED QUOTIENT/REMAINDER.  DAS'S PACKED
OPCODE LOOKUP MADE THE FAILURE CONCRETE: `(2U - (MID % 3U)) * 10U` SELECTED
THE ADJACENT JUMPN 0326 FIELD INSTEAD OF MOVEI 0201.  KCC NOW REFUSES TO PUSH
NEGATION THROUGH `P_UIDIV`; THE MINIMIZED SEMANTIC REGRESSION PASSES ON PDP-6,
KA10, KI10, AND KS10, AND THE FULL NATIVE DAS EXECUTION REGRESSION PASSES.

KCC ITSELF IS PART OF THE INCREMENTAL BUILD DEPENDENCY GRAPH.  REPLACING THE
SELECTED COMPILER INVALIDATES KINIT/KCORE STAMPS, KERNEL C-GENERATED ASSEMBLY,
USERLAND C OBJECTS, AND THE PRIVATE NATIVE DAS PHASE ASSEMBLY.  HANDWRITTEN
ASSEMBLER INPUTS ARE NOT INVALIDATED BY A COMPILER-ONLY CHANGE.  THIS PREVENTS
OLD COMPILER OUTPUT FROM SURVIVING AN OTHERWISE INCREMENTAL SELF-HOSTING BUILD.

THE NATIVE NAMESPACE FOLLOWS THE NORMAL OPTIONAL-SOFTWARE SPLIT.  USERS INVOKE
`/OPTION/BASE/EXEC/DAS`, WHICH IS ON THE DEFAULT LOGIN PATH.  PRIVATE PHASES
LIVE AT `/OPTION/BASE/LIBEXEC/DAS/DAS1` AND `.../DAS2`; THE DRIVER USES THOSE
ABSOLUTE PATHS, SO PHASE IMPLEMENTATION NAMES NEVER ENTER THE COMMAND SEARCH
NAMESPACE.

### 'DLINK'

DLINK IS THE NATIVE STATIC LINKER FOR DOBJ INPUT AND PRODUCES FINAL DAIMOS DXR
EXECUTABLE IMAGES.  KEEP LINK-TIME OBJECT COMPLEXITY OUT OF THE RUNTIME DXR
LOADER.

### 'DARC'

'DARC' IS THE NATIVE DAIMOS ARCHIVE AND OBJECT-LIBRARY TOOL.

IT REPLACES THE NEED FOR UNIX-STYLE ARCHIVE TOOLS IN THE NATIVE SYSTEM. IT SHOULD SUPPORT BOTH GENERAL DAIMOS ARCHIVE USE AND STATIC LIBRARY USE FOR THE LINKER.

A 'DARC' ARCHIVE SHOULD PRESERVE DAIMOS-NATIVE METADATA WITHOUT LOSSY TRANSLATION:

- SIXBIT NAMES WHERE APPLICABLE
- DAIMOS FILE CLASS/TYPE
- WORD-EXACT FILE LENGTH
- MEMBER CHECKSUMS
- LIBRARY MEMBER INDEX
- TOOLCHAIN METADATA

EXTERNAL ARCHIVE FORMATS ARE HANDLED BY HOST-SIDE IMPORT/EXPORT TOOLS, NOT BY THE NATIVE SELF-HOSTING SET.

### 'DOBJDUMP'

'DOBJDUMP' INSPECTS DAIMOS OBJECT FILES, EXECUTABLES, KERNEL IMAGES, AND ARCHIVES.

IT SHOULD BE DAIMOS-SPECIFIC RATHER THAN A CLONE OF A UNIX OBJECT DUMPER.

## 6. RUNTIME LIBRARIES

### REQUIRED COMPONENTS

- 'LIBC'
- 'CRT0'
- 'LIBSYS'

THE C RUNTIME MUST PROVIDE ENOUGH SUPPORT FOR THE COMPILER, BUILD TOOLS, SHELL, EDITOR, AND SYSTEM TOOLS.

### IMPORTANT INTERFACES

- 'OPEN'
- 'READ'
- 'WRITE'
- 'CLOSE'
- 'SEEK' (A LIBC LSEEK-COMPATIBILITY WRAPPER MAY EXIST IF A PORT NEEDS IT)
- 'RUN'
- 'EXEC'
- 'WAIT'
- 'EXIT'
- 'MALLOC'
- 'FREE'
- 'STDIO'
- STRING ROUTINES
- DIRECTORY READING
- REAL UTC WALL CLOCK AND FILE MODIFICATION TIMES
- TERMINAL CONTROL

FILE MODIFICATION TIMES ARE REQUIRED BECAUSE 'MAKE' DEPENDS ON THEM.  THE
CLOCK CONTRACT IS FROZEN IN KERNEL/CLOCK.MD: THE 60 HZ APR LINE CLOCK REMAINS
MONOTONIC TIME, WHILE THE STANDARD PHIL PETIT PCLK PROVIDES UTC WALL TIME.
GETTIME RETURNS THE SORTABLE DAIMOS TIME36 VALUE.  VFS STAT MTIME, D6FS MTIME
UPDATES, DATE DISPLAY, AND TOUCH ARE IMPLEMENTED; MAKE MUST CONSUME THIS
CONTRACT CONSERVATIVELY WHEN IT IS PORTED.

THE DAIMOS PROCESS MODEL IS RUN/EXEC/WAIT, NOT FORK/EXEC.  THE DSH PREREQUISITE
PHASE DEFINES THE BOUNDED ARGC/ARGV/ENVIRONMENT STARTUP CONTRACT SHARED BY RUN
AND EXEC.

## 8. DAIMOS STORAGE AND BOOT TOOLS

### REQUIRED TOOLS

- 'INSTALLBOOT'
- 'DSKLABEL'
- 'BADSCAN'
- 'FSCK.D6FS'
- 'MKFS.D6FS'
- 'DD'
- 'OD'
- 'CKSUM'

### 'INSTALLBOOT'

'INSTALLBOOT' WRITES OR UPDATES THE DAIMOS BOOT LAYOUT.

IT MUST UPDATE THE BOOT/MEDIA DESCRIPTOR USED BY STAGE1 AND KINIT. IT IS RESPONSIBLE FOR INSTALLING THE KERNEL IMAGE, BOOT MODULE AREA, BOOT CONFIGURATION, DESCRIPTOR GENERATION DATA, AND CHECKSUMS.

IT MUST NOT REQUIRE STAGE1 TO PARSE AN ORDINARY FILESYSTEM.

### 'DSKLABEL'

'DSKLABEL' INSPECTS AND WRITES THE DAIMOS DISK LAYOUT.

IT SHOULD DESCRIBE BLOCKSET MEMBERSHIP, BOOT/MEMBER LAYOUT, BAD-MEDIA METADATA,
DESCRIPTOR GENERATION, AND CHECKSUM STATE.  CURRENT LEGACY SWAP/LOGSTORE
RESERVATIONS MAY BELONG TO D6FS, BUT NEW AUXILIARY BACKSTORE/LOGSTORE PLACEMENT
IS PLANNED UNDER THE FILESYSTEM-INDEPENDENT AUXSTORE LAYOUT IN
`KERNEL/BSTORE.MD`; BLOCKSET STILL DOES NOT OWN THOSE SEMANTIC REGIONS.

### 'BADSCAN'

'BADSCAN' SCANS DISK OR DRUM MEDIA BEFORE A NEW STORAGE-SET GENERATION IS
LAID OUT AND RECORDS SOURCE->SPARE EXCEPTIONS IN THE COMMON BAD-MEDIA MAP.
THE PDP-6 PROFILE USES ONE 36-BIT WORD PER REMAP; IT DOES NOT REQUIRE A
RESIDENT FULL-MEDIA BITMAP.

THE FILESYSTEM SEES ONLY THE CLEAN LOGICAL REGION EXPORTED BY THE STORAGE-SET
LAYER.  A NEW DEFECT ON A FORMATTED SET IS A MAINTENANCE EVENT UNTIL THE
CRASH-SAFE ONLINE REMAP UPDATE PATH EXISTS; IT IS NOT REPRESENTED BY A D6FS
HIDDEN FILE.

### 'FSCK.D6FS'

'FSCK.D6FS' CHECKS AND REPAIRS THE NATIVE DAIMOS DISK FILESYSTEM.

IT SHOULD UNDERSTAND DAIMOS WORD-ORIENTED STORAGE, FILE METADATA, GENERATION FIELDS, AND CONSISTENCY RULES.

### 'MKFS.D6FS'

'MKFS.D6FS' CREATES A NATIVE DAIMOS DISK FILESYSTEM.

IT FORMATS THE D6FS LOGICAL SPACE HANDED TO IT BY THE LOWER BLOCK/BLOCKSET
LAYER.  FOR LEGACY/COMPATIBILITY MEDIA IT MAY PRESERVE OR CREATE THE EXISTING
D6FS SWAP/LOGSTORE RESERVATION FIELDS.  NEW AUXILIARY BACKSTORE/LOGSTORE MEDIA
SHOULD INSTEAD BE CREATED THROUGH THE AUXSTORE TOOLING PLANNED IN
`KERNEL/BSTORE.MD`.  D6FS FORMAT DOES NOT NEED PHYSICAL MEMBER OR BAD-MEDIA
LOCATIONS.

- 'DEVSTAT'
- 'MEMSTAT'
- 'OD'

### 'DEVSTAT'

'DEVSTAT' SHOWS DEVICE AND DRIVER STATE.

FOR EARLY DAIMOS THIS IS ESPECIALLY USEFUL FOR DISK, CONSOLE, TAPE, CARD READER/PUNCH, AND BOOT-DEVICE DIAGNOSTICS.

### 'MEMSTAT'

'MEMSTAT' SHOWS MEMORY USAGE AND MEMORY MAP INFORMATION.

ON SMALL PDP-6/KA10-CLASS SYSTEMS, THIS IS IMPORTANT FOR KEEPING THE KERNEL AND USERLAND WITHIN REALISTIC MEMORY LIMITS.

## 10. DEPENDENCY-ORDERED SELF-HOSTING PLAN

THE SELF-HOSTING WORK IS NOT ONE FLAT TOOL LIST.  IMPLEMENT IT IN THESE PHASES.

### PHASE A - CURRENT SYSTEM ACCEPTANCE

- PCLK IS AN EXPLICIT GENERATED-BOOT REQUIREMENT: SIMH EXPOSES IT, THE NORMAL
  DAIMOS BUILD ENABLES IT, AND THE REALTIME WALL-CLOCK PATH IS ACCEPTED.
- CLOSE THE COMPLETE CURRENT PRE-USERLAND KERNEL/STORAGE/TESTKIT GATE BEFORE
  SUBSTANTIAL DSH/SELF-HOSTING WORK.  THE 2026-09-30 FULL REGRESSION CURRENTLY
  STOPS ON STALE TESTKIT VFS_SIX6 REFERENCES; THE CURRENT SOURCE INTERFACE IS
  PDP10_SIX6.
- NORMAL CURRENT USERSPACE BUILDS WITH KCC/DAS AND NO LONGER LINKS LIBGCC.
- BOOT-SOURCE, ROOT-CLASS, AUTO-PRIORITY, INDEPENDENT BOOT/ROOT CROSS-MATRIX,
  AND ROOT LOGIN-LIFECYCLE TESTS ARE LANDED.  KEEP CTY INPUT ACCEPTANCE OPEN
  WITHOUT MAKING IT A V0.9 BLOCKER WHILE DCS0/GE0 LOGIN IS GREEN.

### PHASE B - DSH PLATFORM

THIS PHASE IS COMPLETE:

- THE BOUNDED RUN/EXEC ARGC/ARGV/ENVIRONMENT ABI AND CRT0 CONTRACT ARE
  IMPLEMENTED; INIT/LOGIN USE NORMAL ARGV INSTEAD OF THE PRIVATE AC1=TTY PATH.
- THE DUP2-EQUIVALENT DESCRIPTOR OPERATION IS IMPLEMENTED.
- THE MINIMAL CANONICAL/ECHO/SIGNALS TTY LINE DISCIPLINE IS IMPLEMENTED; DSH
  CAN USE RAW/NO-ECHO/NO-SIGNALS FOR ITS OWN EDITOR.
- DESCRIPTOR-LEVEL ISATTY IS IMPLEMENTED AS PROCCTL 030 AND TARGET-PROBED
  THROUGH ATTACH, REDIRECTION, RESTORE, AND DETACH.
- INHERITED PER-PROCESS UMASK IS IMPLEMENTED AS PROCCTL 031; LOGIN INSTALLS
  022, CREATE-TIME MODE FILTERING IS ATOMIC, RUN INHERITS, AND EXEC RETAINS IT.
- LOGIN CONSTRUCTS AND EXPORTS HOME, PATH, USER, LOGNAME, AND SHELL THROUGH
  EXEC V1.
- THE CURRENT D6FS BLOCK CACHE USES RECLAIMABLE CLEAN WRITE-THROUGH
  MANAGED-CORE SLABS AND IS RECLAIMED BEFORE PROCESS SWAP.  THE PLANNED
  BSTORE/BCACHE CONSOLIDATION REPLACES IT WITH ONE GENERIC TWO-BLOCK CLEAN L1
  SHARED WITH DTFS/TSFS; SEE `KERNEL/BSTORE.MD`.

### PHASE C - KERNEL STABILIZATION BEFORE SUBSTANTIAL DSH

THE MM COMPACTOR/RELOCATOR CORRECTNESS FIX IS COMPLETE: MOVES REUSE THE EXISTING
EXTENT, SUPPORT OVERLAP, AND NO LONGER REQUIRE A SECOND FULL ALLOCATION.

- MONITORFS IS CONSOLIDATED: /MONITOR EXPOSES PROCESSES, DOMAINS, AND DEVICES;
  /PROC ALIASES THE PROCESS TREE ONLY; /DEV PROJECTS EACH DEVICE IO ENDPOINT;
  /DEVICE AND /DOMAIN ARE REMOVED.
- KEEP THE MONITORFS, /PROC, AND /DEV TARGET-SIDE REGRESSIONS PASSING.
- SEEK, CHOWN, CORRECT DIRECTORY REMOVAL, AND D6FS MTIME/STAT/DATE/TOUCH
  SUPPORT ARE IMPLEMENTED AND TARGET-VALIDATED.
- DO NOT RECREATE DAIMOSV1 SYSCTL OR DEVIO.  MONITORFS IS THE ADMINISTRATIVE AND
  INTROSPECTION INTERFACE.

### PHASE D - SUBSTANTIAL DSH

PORT/IMPLEMENT DSH USING THE FROZEN USER/DSH_DESIGN.MD CONTRACT.  REUSE THE
DAIMOSV1 FIXED-ARENA PARSER, SIXBIT, ENVIRONMENT, PATH SEARCH, GLOB, REDIRECTION,
ALIAS, AND HOST-TEST MECHANISMS WHERE THEY FIT.  DO NOT PORT ITS PROCESS EXECUTOR
WHOLESALE: ITS SEQUENTIAL PIPELINE MODEL IS NOT THE CURRENT DAIMOS DESIGN.

THE FIRST USEFUL SHELL MUST PROVIDE EXTERNAL COMMANDS, ENVIRONMENT, REDIRECTION,
CONCURRENT PIPELINES, ONE PROCESS GROUP PER JOB, BACKGROUND JOBS, JOB TABLE,
CTRL-Z/JOBS/BG/FG, WHOLE-JOB WAITING, TTY PGRP/MODE HANDOFF, FUNCTIONS/COMPOUND
LANGUAGE, SCRIPT/-C EXECUTION, SOURCE, AND THE BOUNDED INTERACTIVE EDITOR.
SIXMD HELP/GETOPT/COMPLETION FOLLOWS WITHOUT BLOCKING BASIC EXECUTION.

### PHASE E - DAIMOSV1 CORE-UTILITY PORTS

THE DAIMOSV1 SOURCES ARE A USEFUL IMPLEMENTATION BASE, BUT PORT COMMAND
BEHAVIOR/ALGORITHMS RATHER THAN OBSOLETE KERNEL ABIS.

- EXISTING I/O/PROCESS ABIS ARE ENOUGH FOR ECHO, BASENAME, DIRNAME, TRUE, FALSE,
  EXPR, CAT, CP, CMP, GREP, HEAD, WC, TEE, STRINGS, LS, FIND, STAT, MKDIR, RM,
  MV, PWD, CHMOD, AND XARGS.
- TAIL AND DD MAY USE THE IMPLEMENTED SEEK SET/CUR/END ABI.
- CHOWN MAY USE THE IMPLEMENTED CHOWN ABI.
- RMDIR MAY USE THE IMPLEMENTED DIRECTORY-REMOVAL ABI.
- TOUCH IS IMPLEMENTED; MAKE MAY USE THE IMPLEMENTED MTIME CONTRACT BUT MUST
  REJECT OR CONSERVATIVELY HANDLE UNKNOWN/OUT-OF-RANGE TIMES.
- PS/FREE/DEVSTAT/MEMSTAT/DOMAIN/ADMIN TOOLS MUST TARGET MONITORFS RATHER THAN
  DAIMOSV1 SYSCTL/DEVIO.

PORT ONLY THE SUBSETS ACTUALLY NEEDED BY DAIMOS; DO NOT CLONE HOST COREUTILS.

### PHASE F - MAKE AND NATIVE TOOLCHAIN

- PORT/IMPLEMENT 'MAKE'.
- DAS RESIDENT EXECUTION/BOOT INTEGRATION IS FUNCTIONAL; FINISH THE KCC
  CODE-SIZE WORK NEEDED TO REPLACE THE TRANSITIONAL GCC-BUILT DAS1/DAS2.
- BRING UP 'DLINK', 'DARC', AND REQUIRED OBJECT INSPECTION TOOLS.
- BRING UP NATIVE 'KCC'/'CPP', 'LIBC', 'CRT0', AND 'LIBSYS'.
- REBUILD A CONTROLLED USERLAND COMPONENT, THEN THE FULL USERLAND, THEN THE
  KERNEL WITH THE NATIVE TOOLCHAIN.

THE FIRST V0.9 NATIVE SELF-HOSTING MILESTONE IS REACHED WHEN DAIMOS CAN EDIT OR
IMPORT SOURCE, RUN DSH/MAKE, BUILD WITH DAIMOS-RESIDENT KCC+DAS+DLINK+DARC, AND INSTALL A
NEW NATIVE BUILD WITHOUT A HOST COMPILER/ASSEMBLER/LINKER.

### PHASE G - PRACTICAL DEVELOPMENT AND ADMINISTRATION

AFTER THE BUILD PATH WORKS, ADD ELVIS, AWK/FIND/DU/DF AND OTHER USEFUL TOOLS,
THEN COMPLETE V0.9 STORAGE/ADMINISTRATION WORK INCLUDING GENERAL D6FS MOUNTING,
FSCK.D6FS, PACKFS, MKFS.D6FS, MONITORFS DIAGNOSTICS, INSTALLBOOT, DSKLABEL, AND
BADSCAN.  THESE ARE IMPORTANT V0.9 SYSTEM FEATURES BUT MUST NOT BE MISTAKEN FOR
DSH OR NATIVE-COMPILER BLOCKERS.

BOOTABLE RECOVERY DECTAPE REMAINS POST-0.9.
