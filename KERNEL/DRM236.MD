# DAIMOS TYPE-236 DRUM DRIVER

*RAW PDP-6 DRUM I/O BELOW THE COMMON STORAGE-SET LAYER*

## DOCUMENT METADATA

- STATUS: RAW ASYNCHRONOUS DRIVER, RUNTIME WATCHDOG, COMMON BADMAP, D6FS BINDING, AND DIRECT STAGE1 BOOT IMPLEMENTED; ROTATIONAL SCHEDULING OPEN
- DATE: 2026-11-03
- SCOPE: TYPE-167/TYPE-236 TRANSFER, ERROR BOUNDARY, AND SHARED BAD-MEDIA POLICY
- ENCODING: PLAIN ASCII

## 1. CURRENT IMPLEMENTATION

THE LIVE DRM236 DRIVER TRANSFERS ONE 128-WORD PHYSICAL BLOCK.  IT SUPPORTS FOUR
UNITS OF 8192 BLOCKS EACH.  BEFORE THE PROCESS TABLE EXISTS IT USES A POLLED
TRANSFER; AT RUNTIME IT SERIALIZES THE SINGLE DMA ENGINE AND COMPLETES REQUESTS
THROUGH PI2.

THE DRIVER CHECKS TYPE-167 AND TYPE-236 ERROR STATUS AND RETURNS I/O FAILURE.
RUNTIME I/O ALSO HAS A 300-TICK (FIVE-SECOND AT 60 HZ) ACTIVE-REQUEST
WATCHDOG. THE KCORE STORAGE CLOCK CALLS THE DSK WATCHDOG AND THEN THE DRM
WATCHDOG THROUGH TWO PATCHED CALL SITES, NOT A PERMANENT TIMER TABLE. THE
ACTIVE DRM DESCRIPTOR WORD STORES THE DEADLINE IN ITS LEFT HALF AND THE
EXISTING POINTER IN ITS RIGHT HALF. NO NEW PER-REQUEST OR PER-PROCESS
RESIDENT DATA IS NECESSARY.

ON EXPIRATION, THE TYPE-167 AND TYPE-236 CONTROLLERS ARE CLEARED BEFORE
THE SHARED PI2/TIMEOUT COMPLETION ROUTINE PUBLISHES -1 IN THE PRIVATE
THREE-WORD REQUEST'S EVENT AND WAKES THE OWNER. IF THE ONE-SLOT FIFO
CONTAINS A SECOND REQUEST, IT IS PROMOTED WITH ITS OWN FULL 300-TICK
DEADLINE. THIS IS A REAL HARDWARE-I/O ERROR PATH AND DOES NOT RELEASE
OR STEAL A FILESYSTEM PROVIDER LOCK. THE OWNER MUST STILL RETURN
THROUGH NORMAL PROVIDER CLEANUP.

THE 2026-11-03 V1079 PDP-6 TESTS VALIDATE TWO SUCCESSIVE TIMEOUTS,
EXACT COUNTDOWN, FIFO PROMOTION, ERROR ACCOUNTING AND NO DOUBLE
COMPLETION; DISABLING THE WATCHDOG FAILS THE NEGATIVE CONTROL.
NORMAL TYPE-167/236 READ/WRITE AND QUEUED-RUNTIME REGRESSIONS PASS.
AN INDEPENDENT DRM-ROOT STAGE1 SIMH BOOT WITH DSK0 UNATTACHED REACHES
INIT AND LOGIN, AND THE 256K PHYSICAL-OOM/FILE/MM GUEST STILL PASSES.

THE FULL KCC KCORE GROWS ONE WORD (023157 TO 023160 OCTAL). THE
DRM MRES RESIDENT SIZE GROWS FROM 124 TO 141 WORDS, FOR 18 ADDITIONAL
RESIDENT WORDS TOTAL AND ZERO NEW PERMANENT DATA WORDS. THIS WATCHDOG
REQUIRES QUALIFIED APR CLOCK TICKS. A CLOCK-INHIBITED SLOT-0 REQUEST
OR A PROVIDER STUCK OUTSIDE THIS HARDWARE COMPLETION PATH STILL NEEDS
SEPARATE LIVENESS AND OWNERSHIP HANDLING.

IT DOES NOT KEEP A PRIVATE BAD-BLOCK TABLE OR OWN PERSISTENT REMAPS.  THE
COMMON OPTIONAL BADMAP LAYER NOW TRANSLATES STORAGE-SET PHYSICAL LOCATORS BELOW
D6FS, LOGSTORE, AND RAW SWAP-TAIL I/O.  DRM236-SPECIFIC RETRY/RESET POLICY
REMAINS A LEAF-DRIVER CONCERN.

THE PDP-6 STANDALONE DRM STAGE1 USES THE SAME DBOOT METADATA AND 128-WORD
BLOCK CONTRACT AS THE DSK STAGE1.  ONLY THE LEAF I/O DIFFERS: STAGE1 FORMS A
TYPE-236 ADDRESS AS `UNIT<<16 | BLOCK<<3` AND USES THE EARLY POLLED
TYPE-167/236 DMA SEQUENCE.  `ROOT=DRUM` SELECTS THIS LOADER.  REAL SIMH
ACCEPTANCE WITH DSK0 UNATTACHED REACHES INIT AND LOGIN FROM DR0, SO DIRECT DRM
BOOT NO LONGER DEPENDS ON A DSK-LOADED KINIT.

## 2. BAD-MEDIA POLICY

DRM236 USES THE SAME STORAGE-SET EXCEPTION MAPPER AS DSK270; DO NOT ADD A
DRM236-PRIVATE BAD-BLOCK MAP.  THE CURRENT GEOMETRY FITS THE COMMON V1 18-BIT
PHYSICAL LOCATOR (2-BIT MEMBER + 16-BIT BLOCK), SO ONE SOURCE->SPARE REMAP COSTS
EXACTLY ONE 36-BIT WORD IN CORE.  THIS COMMON BADMAP PATH IS IMPLEMENTED.

DEVICE-SPECIFIC RETRY/RESET AND DRUM ROTATIONAL SCHEDULING REMAIN IN DRM236.
THE COMMON LAYER OWNS PERSISTENT SOURCE->SPARE TRANSLATION AND THE SPARE
RESERVATION.  THIS SHARES CODE AND DATA REPRESENTATION WITH DISKS WITHOUT
FORCING DISK CYLINDER/SEEK POLICY INTO THE DRUM DRIVER.

KNOWN DEFECTS SHOULD BE ASSIGNED SPARES WHEN THE STORAGE-SET GENERATION IS
CREATED.  FUTURE ONLINE RETIREMENT MAY MOVE A WRITE OR RECOVERED READ TO A
SPARE AFTER A CRASH-SAFE MAP UPDATE.  AN UNRECOVERABLE READ STILL REPORTS DATA
LOSS.

## 3. MEMORY RULE

NO FULL DRUM BAD-BLOCK BITMAP IS RESIDENT.  KEEP ONLY ACTIVE REMAP EXCEPTIONS
AND THE SMALL PER-SET/PER-MEMBER SPARE STATE NEEDED BY THE ACTIVE MAPPER.
WITH N DEFECTS, THE MAPPING TABLE COST IS N 36-BIT WORDS FOR BOTH DISK AND DRUM
PROFILES.

## 4. D6FS BINDING

D6FS-ON-DRM IS IMPLEMENTED AT THE FILESYSTEM-INDEPENDENT BACKING BOUNDARY.
A SINGLE DRM USES THE NORMAL 17-WORD D6FS HANDOFF WITH THE DRM DEVICE TAG AND
BYPASSES BLOCKSET.  MULTI-DRM USES THE SAME EQUAL-SIZE ONE-BLOCK INTERLEAVE
POLICY AS BLOCKSET, ENCODING A FOUR-UNIT MEMBER MASK PLUS COMMON PHYSICAL BASE
IN THE EXISTING BACKING OPAQUE WORD.  NO D6FS DEVICE BRANCH OR PER-MOUNT
DESCRIPTOR ALLOCATION IS REQUIRED.

THE DIRECT DSK ENCODING REMAINS BINARY COMPATIBLE.  ABSENT DRM SERVICES LEAVE
THE DRM CALLBACK SLOTS POINTING AT A SAFE FAILURE RETURN.  PDP-6 REGRESSIONS
COVER DIRECT DSK, DIRECT DRM, SPARSE MULTI-DRM INTERLEAVE, MULTIMOUNT, AND THE
NO-DRIVER PATH.  REAL SIMH TYPE-167/236 READ/WRITE ACCEPTANCE PASSES ON UNITS
0 AND 3.

## 4A. COMPLETION ACCOUNTING

DRM0 READ/WRITE COUNTERS ARE THE EXISTING `MFSDEV_DRM_READS` AND
`MFSDEV_DRM_WRITES` MONITORFS WORDS IN `DEVICE_STATE.S`.  THE DRIVER COUNTS
ONE SUCCESSFUL 128-WORD TRANSFER AT ITS PHYSICAL COMPLETION: AFTER BOTH
POLLED DONE PHASES DURING BOOT, OR AT THE DRUM DONE PI2 INTERRUPT AT RUNTIME.
THE INTERMEDIATE TYPE-167 DONE, A QUEUED REQUEST, AND A QUEUE HANDOFF DO NOT
COUNT AS COMPLETIONS.  FAILED REQUESTS INCREMENT THE EXISTING DRM STORAGE
ERROR COUNTER INSTEAD OF A READ/WRITE SUCCESS COUNTER.

THIS FIX REUSES EXISTING RESIDENT COUNTER WORDS; NO ADDITIONAL KCORE STATE
IS ALLOCATED.  THE 2026-10-12 REGRESSIONS FOR CAPACITY, TYPE-167/236
INTERRUPT/QUEUED I/O, MRES INITIALIZATION, AND DIRECT DRM STAGE1 BOOT ALL
PASS.  A DRUM-ROOTED PERMANENT-ADDRESS BUILD REMAINS UNDER THE 16K LIMIT.
