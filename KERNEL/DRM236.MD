# DAIMOS TYPE-236 DRUM DRIVER

*RAW PDP-6 DRUM I/O BELOW THE COMMON STORAGE-SET LAYER*

## DOCUMENT METADATA

- STATUS: RAW ASYNCHRONOUS DRIVER, COMMON BADMAP, AND D6FS BINDING IMPLEMENTED; SCHEDULING OPEN
- DATE: 2026-09-24
- SCOPE: TYPE-167/TYPE-236 TRANSFER, ERROR BOUNDARY, AND SHARED BAD-MEDIA POLICY
- ENCODING: PLAIN ASCII

## 1. CURRENT IMPLEMENTATION

THE LIVE DRM236 DRIVER TRANSFERS ONE 128-WORD PHYSICAL BLOCK.  IT SUPPORTS FOUR
UNITS OF 8192 BLOCKS EACH.  BEFORE THE PROCESS TABLE EXISTS IT USES A POLLED
TRANSFER; AT RUNTIME IT SERIALIZES THE SINGLE DMA ENGINE AND COMPLETES REQUESTS
THROUGH PI2.

THE DRIVER CHECKS TYPE-167 AND TYPE-236 ERROR STATUS AND RETURNS I/O FAILURE.
IT DOES NOT KEEP A PRIVATE BAD-BLOCK TABLE OR OWN PERSISTENT REMAPS.  THE
COMMON OPTIONAL BADMAP LAYER NOW TRANSLATES STORAGE-SET PHYSICAL LOCATORS BELOW
D6FS, LOGSTORE, AND RAW SWAP-TAIL I/O.  DRM236-SPECIFIC RETRY/RESET POLICY
REMAINS A LEAF-DRIVER CONCERN.

## 2. BAD-MEDIA POLICY

DRM236 USES THE SAME STORAGE-SET EXCEPTION MAPPER AS DSK270; DO NOT ADD A
DRM236-PRIVATE BAD-BLOCK MAP.  THE CURRENT GEOMETRY FITS THE COMMON V1 18-BIT
PHYSICAL LOCATOR (2-BIT MEMBER + 16-BIT BLOCK), SO ONE SOURCE->SPARE REMAP COSTS
EXACTLY ONE 36-BIT WORD IN CORE.  THIS COMMON BADMAP PATH IS IMPLEMENTED.

DEVICE-SPECIFIC RETRY/RESET AND DRUM ROTATIONAL SCHEDULING REMAIN IN DRM236.
THE COMMON LAYER OWNS PERSISTENT SOURCE->SPARE TRANSLATION AND THE SPARE
RESERVATION.  THIS SHARES CODE AND DATA REPRESENTATION WITH DISKS WITHOUT
FORCING DISK CYLINDER/SEEK POLICY INTO THE DRUM DRIVER.

KNOWN DEFECTS SHOULD BE ASSIGNED SPARES WHEN THE STORAGE-SET GENERATION IS
CREATED.  FUTURE ONLINE RETIREMENT MAY MOVE A WRITE OR RECOVERED READ TO A
SPARE AFTER A CRASH-SAFE MAP UPDATE.  AN UNRECOVERABLE READ STILL REPORTS DATA
LOSS.

## 3. MEMORY RULE

NO FULL DRUM BAD-BLOCK BITMAP IS RESIDENT.  KEEP ONLY ACTIVE REMAP EXCEPTIONS
AND THE SMALL PER-SET/PER-MEMBER SPARE STATE NEEDED BY THE GENERIC MAPPER.
WITH N DEFECTS, THE MAPPING TABLE COST IS N 36-BIT WORDS FOR BOTH DISK AND DRUM
PROFILES.

## 4. D6FS BINDING

D6FS-ON-DRM IS IMPLEMENTED AT THE FILESYSTEM-INDEPENDENT BACKING BOUNDARY.
A SINGLE DRM USES THE NORMAL 17-WORD D6FS HANDOFF WITH THE DRM DEVICE TAG AND
BYPASSES BLOCKSET.  MULTI-DRM USES THE SAME EQUAL-SIZE ONE-BLOCK INTERLEAVE
POLICY AS BLOCKSET, ENCODING A FOUR-UNIT MEMBER MASK PLUS COMMON PHYSICAL BASE
IN THE EXISTING BACKING OPAQUE WORD.  NO D6FS DEVICE BRANCH OR PER-MOUNT
DESCRIPTOR ALLOCATION IS REQUIRED.

THE DIRECT DSK ENCODING REMAINS BINARY COMPATIBLE.  ABSENT DRM SERVICES LEAVE
THE DRM CALLBACK SLOTS POINTING AT A SAFE FAILURE RETURN.  PDP-6 REGRESSIONS
COVER DIRECT DSK, DIRECT DRM, SPARSE MULTI-DRM INTERLEAVE, MULTIMOUNT, AND THE
NO-DRIVER PATH.  REAL SIMH TYPE-167/236 READ/WRITE ACCEPTANCE PASSES ON UNITS
0 AND 3.

## 5. OPEN WORK

- ADD BOUNDED DRM236-SPECIFIC RETRY/RESET ONLY WHERE HARDWARE BEHAVIOR JUSTIFIES IT.
- ADD BADSCAN SUPPORT FOR DRM236 MEDIA.
- ADD FAULT-INJECTION TESTS FOR TRANSIENT ERROR, RECOVERED READ, FAILED WRITE,
  UNRECOVERABLE READ, SPARE EXHAUSTION, AND MAP PERSISTENCE.
- KEEP DRUM ROTATIONAL SCHEDULING SEPARATE FROM BAD-MEDIA TRANSLATION.
