# KA10 RC10/RM10 block provider (v1970)

## Native hardware boundary

The KA10 0.9 ONESEG configuration uses RC10/FHA at octal
0170 with RM10 media. 90 tracks, 60 segments per track,
64 words per segment: 345600 words or 2700 logical blocks.
The common drum service ABI remains unit<<16 | block<<3,
128-word buffer; the RM10 leaf converts to BCD track and
even segment, using two adjacent segments per block.
RD10 and RM10 root boot are outside this milestone.

The new MRES reuses existing DRM service IDs, device
counters, active request word and clock hook. DF10 pair
0150/0151 contains the -128,,buffer-1 IOWD and terminating
word, overwritten by completion. Pair0152/0153 is not
touched. PI2 completion requires DONE, no BUSY/error
status and exact completion word 0151,,buffer+127.
The caller's three-word stack descriptor stays owned until
acknowledged completion. Other callers wait on its event
and retry; there is no new fixed queue or allocator.
PI6 watchdog claims ownership atomically, STOPs the
controller after 300 ticks, confirms BUSY is clear, and
publishes failure only after acknowledgement. If hardware
cannot quiesce, do not release live DMA memory.

KA10 MINIT probes RC10, while PDP-6 keeps the original
Type167/236 implementation. D6FS lowmem KINIT chooses a
validated drum AUXSTORE only after root mount so normal
disk BACKSTORE is preserved when there is no valid drum.
TSFS uses its existing AUXSTORE discovery. No format
change; current mkauxstore requires an unused D6FS region
1+04213 and a 01000-block tail at 04214 in the test drum.
No drum filesystem is mounted. Default boot.ini leaves
FHA disabled; opt in with set fha enabled, set fha0 rm10,
attach -q fha0 IMAGE (instead of set fha disabled).
