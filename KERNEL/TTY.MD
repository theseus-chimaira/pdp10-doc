# DAIMOS MINIMAL TTY LINE DISCIPLINE

DATE: 2026-09-18

## 1. PURPOSE

DAIMOS KEEPS TERMINAL POLICY SMALL, BUT ORDINARY PROGRAMS BENEFIT FROM ONE
SHARED KERNEL IMPLEMENTATION OF BASIC CANONICAL INPUT.  THE KERNEL SHALL
THEREFORE PROVIDE A MINIMAL PER-TTY LINE DISCIPLINE WHILE RETAINING RAW INPUT
FOR DSH INTERACTIVE EDITING, ELVIS, AND OTHER FULL-SCREEN OR PER-KEYSTROKE
PROGRAMS.

THIS IS NOT A FULL POSIX `TERMIOS` IMPLEMENTATION.

## 2. REQUIRED MODES

THE MINIMUM STATE IS THREE INDEPENDENT SEMANTIC FLAGS:

```TEXT
CANONICAL   EDIT/BUFFER INPUT UNTIL A LINE OR EOF EVENT IS READY
ECHO        ECHO ORDINARY INPUT AND KERNEL EDIT OPERATIONS
SIGNALS     CTRL-C/CTRL-Z GENERATE FOREGROUND-PGRP EVENTS
```

THIS ALLOWS AT LEAST:

```TEXT
CANONICAL + ECHO + SIGNALS   NORMAL COOKED TERMINAL
CANONICAL, NO ECHO + SIGNALS   PASSWORD/SECRET LINE INPUT
RAW, NO ECHO, NO SIGNALS       DSH INTERACTIVE EDITOR
RAW, NO ECHO + SIGNALS         ELVIS/CURSES-LIKE JOB AS APPROPRIATE
```

A RAW+ECHO COMBINATION MAY BE SUPPORTED IF IT FALLS OUT CHEAPLY, BUT IS NOT A
REQUIREMENT FOR THE FIRST IMPLEMENTATION.

MODE IS TERMINAL STATE, NOT PROCESS STATE.  A MODE CHANGE APPLIES TO THE
CONTROLLING TTY AND MUST NOT LEAVE A HALF-COOKED LINE VISIBLE AFTER THE CHANGE.

## 3. COOKED INPUT SEMANTICS

THE FIRST IMPLEMENTATION PROVIDES ONLY:

- CR/LF NORMALIZATION AND LINE TERMINATION;
- ECHO OF ACCEPTED PRINTABLE CHARACTERS WHEN ECHO IS ENABLED;
- BS OR DEL ERASE OF ONE BUFFERED CHARACTER;
- CTRL-U LINE KILL;
- CTRL-D EOF/END-OF-RECORD SEMANTICS: ON AN EMPTY RECORD IT RETURNS EOF; AFTER
  BUFFERED CHARACTERS IT TERMINATES THAT RECORD WITHOUT ADDING A CHARACTER;
- BOUNDED LINE LENGTH WITH SAFE REJECTION WHEN FULL.

THE CURRENT FOREGROUND-PROCESS-GROUP CTRL-C AND CTRL-Z HANDLING REMAINS IN THE
KERNEL WHEN SIGNALS IS ENABLED.  WHEN SIGNALS IS DISABLED, THOSE CHARACTERS ARE
ORDINARY RAW INPUT.  DSH REQUIRES THIS SEPARATION: CTRL-C AT THE SHELL'S OWN
RAW EDITOR MUST CANCEL/EDIT SHELL INPUT IN USERSPACE RATHER THAN KILL DSH, WHILE
ORDINARY FOREGROUND JOBS NORMALLY ENABLE TERMINAL-GENERATED EVENTS.

THE KERNEL DOES NOT IMPLEMENT COMMAND HISTORY, TAB COMPLETION, CURSOR MOTION,
WORD ERASE, ANSI/VT ESCAPE PARSING, TERMINAL CAPABILITY DATABASES, UTF-8 POLICY,
OR SHELL-SPECIFIC EDITING.

## 4. BUFFERING AND MEMORY

DO NOT RESERVE A LARGE LINE ARRAY FOR EVERY POSSIBLE TTY.

A TTY NEEDS ONLY SMALL FIXED MODE/STATE BITS.  A CANONICAL READ ACQUIRES ITS
BOUNDED LINE STORAGE FROM MANAGED CORE IN SLEEPABLE READER CONTEXT BEFORE
ENTERING THE HARDWARE INPUT LOOP; INTERRUPT CODE MUST NEVER ALLOCATE OR BLOCK.
COMPLETED CANONICAL INPUT REMAINS MARKED READY UNTIL A CONSUMER TAKES IT:
READ_WORDS COPIES THE WHOLE S6REC RECORD DIRECTLY, WHILE READCHAR DRAINS THE
SAME READY BUFFER ONE CHARACTER AT A TIME.  THE STORAGE IS RELEASED WHEN THE
COMPLETE LINE/EOF RECORD HAS BEEN CONSUMED OR THE MODE IS RESET.  ACTIVE
PARTIAL INPUT IS NOT REGENERABLE AND THEREFORE IS
NOT A RECLAIMABLE CACHE OBJECT; IT IS ORDINARY SHORT-LIVED KERNEL-DYNAMIC
MEMORY.

THE CANONICAL LINE BUFFER REMAINS A COMPACT CHARACTER REPRESENTATION; DO NOT
SPEND ONE 36-BIT WORD PER CHARACTER.  ITS HARDWARE-FACING EDITOR STILL DEALS
IN 7-BIT TERMINAL CHARACTERS, BUT COOKED DESCRIPTOR WORD I/O IS S6REC/SIXBIT.
READ_WORDS RETURNS ONE COMPLETE COOKED S6REC LINE; WRITE_WORDS ACCEPTS ONE
COMPLETE S6REC TEXT RECORD AND THE TTY MRES DECODES IT TO THE SELECTED CTY,
DCS, OR GE BACKEND.  RAW READCHAR/WRITECHAR REMAINS THE LOSSLESS CHARACTER
INTERFACE.  KEEP THE MAXIMUM CANONICAL LINE LENGTH BOUNDED AND MEASURED
AGAINST DSH/LOGIN/UTILITY REQUIREMENTS.

COOKED READ_WORDS REQUIRES AN ATTACHED CANONICAL CONTROLLING TTY.  A PROCESS
WITHOUT A CONTROLLING TTY MAY STILL USE THE RAW CTY BOOTSTRAP CHARACTER PATH
THROUGH READCHAR, BUT THE KERNEL DOES NOT SYNTHESIZE S6REC RECORDS FROM THOSE
UNOWNED RAW BYTES.  THIS KEEPS WORD-TEXT FRAMING TIED TO THE CANONICAL LINE
DISCIPLINE INSTEAD OF MAINTAINING A SECOND COMPATIBILITY ENCODER.

## 5. I/O AND JOB CONTROL INTERACTION

THE EXISTING CONTROLLING-TTY, SESSION, FOREGROUND-PGRP, AND BACKGROUND-READ
CHECKS REMAIN AUTHORITATIVE.  CANONICAL PROCESSING HAPPENS ONLY AFTER INPUT HAS
PASSED THE TTY OWNERSHIP/FOREGROUND CHECKS AND AFTER KERNEL-OWNED JOB-CONTROL
CHARACTERS HAVE BEEN HANDLED.

A COOKED READ MAY SLEEP UNTIL A LINE OR EOF EVENT IS READY.  RAW READS KEEP THE
CURRENT PER-CHARACTER BEHAVIOR.  OUTPUT POLICY SHOULD REMAIN MINIMAL; DO NOT
TURN THE LINE DISCIPLINE INTO A GENERAL OUTPUT POSTPROCESSOR.

MODE CHANGES SHOULD REQUIRE ACCESS TO THE CALLER'S CONTROLLING TTY AND SHOULD
FOLLOW THE SAME SESSION/FOREGROUND AUTHORIZATION MODEL USED BY THE EXISTING
TTY CONTROL OPERATIONS.  THE ABI MUST PROVIDE COMPACT GET-MODE AND SET-MODE
OPERATIONS SO A SHELL CAN SAVE AND RESTORE MODE AROUND JOB CONTROL.  THE IMPLEMENTED ABI USES PROCCTL GETMODE 026 AND SETMODE 027.  UUO-077
SELECTORS 020-024 ARE RESERVED FOR PIPE/MKFIFO/EXEC/GETTIME/DUP2, SO SETGID
MOVED FROM THE COLLIDING 020 VALUE TO PROCCTL 025.  PROCCTL 030 IS ISATTY;
PROCCTL 031 IS THE PROCESS UMASK OPERATION.

THE SAME SMALL TTY CONTROL SURFACE PROVIDES PROCCTL 030 AS THE CHEAP
DESCRIPTOR-IDENTITY QUERY USED BY LIBC `ISATTY`.  IT RETURNS THE LOGICAL
CONTROLLING-TTY ID WHEN THE DESCRIPTOR NAMES CTY0 AND THE CALLER OWNS AN
ATTACHED CONTROLLING TTY, OR -1 FOR REDIRECTED/CLOSED/NON-TERMINAL DESCRIPTORS
AND DETACHED/NO-TTY PROCESS STATE.  DSH CAN THEREFORE TEST FD 0 WITHOUT
GUESSING FROM PROCESS CONTROLLING-TTY STATE.  DO NOT ADD A GENERAL IOCTL
FRAMEWORK SOLELY FOR THIS CHECK.

DSH USES RAW/NO-ECHO/NO-SIGNALS FOR ITS INTERACTIVE EDITOR.  BEFORE A NEW ORDINARY
FOREGROUND JOB IT SELECTS CANONICAL+ECHO+SIGNALS.  WHEN A JOB STOPS, DSH REGAINS THE
FOREGROUND TTY, SAVES THE JOB'S CURRENT MODE IN ITS BOUNDED JOB RECORD, AND
RESTORES THE SHELL MODE.  `FG` RESTORES THE SAVED JOB MODE BEFORE CONTINUING
THE JOB.  A JOB THAT EXITS NEEDS NO SAVED MODE.  THIS SMALL-WORD MODE STATE
IS REQUIRED FOR STOP/RESUME OF RAW FULL-SCREEN PROGRAMS.

### 5.1 DETACHABLE OUTPUT ROUTING

LOGICAL TTY IDENTITY IS THE INPUT SOURCE.  IT DOES NOT CHANGE WHEN OUTPUT IS
REBOUND:

```TEXT
TTY0       CTY KEYBOARD INPUT
TTY1..16   DCS0..15 INPUT
TTY17..20  GE0..3 INPUT
```

EACH LOGICAL TTY HAS AN INDEPENDENT OUTPUT SINK.  THE DEFAULT/NATIVE ROUTE
PRESERVES THE HISTORICAL PAIRING; AN EXPLICIT ROUTE MAY SELECT CTY, ANY DCS
LINE, ANY GE CONSOLE, OR DPY (TYPE 340/342).  THIS MAKES, FOR EXAMPLE,
`TTY0 = CTY INPUT + DPY OUTPUT` POSSIBLE WITHOUT ADDING AN EMULATOR KEYBOARD.
THE SAME MECHANISM WORKS FOR DCS AND GE INPUT LINES.

THE ROUTE IS PACKED INTO FIVE PREVIOUSLY UNUSED BITS (29..33) OF THE EXISTING
ONE-WORD TTY RECORD.  ENCODED ZERO MEANS NATIVE; EXPLICIT SINKS ARE STORED AS
SINK+1.  THERE IS NO NEW PER-TTY TABLE OR FIXED ROUTING RAM.  ROUTING IS A
PROPERTY OF THE TERMINAL ENDPOINT, NOT OF A LOGIN SESSION, SO SESSION DETACH
AND FINAL SESSION RELEASE PRESERVE THESE BITS WHILE CLEARING OWNERSHIP,
FOREGROUND-PGRP, MODE, AND INPUT STATE.

THE UUO-077 TTYCTL EXTENSION PROVIDES GETOUT AND SETOUT.  GETOUT REPORTS THE
EFFECTIVE OUTPUT SINK.  SETOUT IS ROOT-ONLY BECAUSE IT MODIFIES GLOBAL TERMINAL
ROUTING AND PERSISTS ACROSS LOGIN.  DSH EXPOSES THE ADMINISTRATIVE FRONTEND:

```TEXT
TTYOUT 0             SHOW TTY0 OUTPUT SINK
TTYOUT 0 DPY         CTY KEYBOARD -> TYPE 340 OUTPUT
TTYOUT 0 CTY         CTY KEYBOARD -> CTY OUTPUT EXPLICITLY
TTYOUT 0 NATIVE      RESTORE THE NATIVE PAIRING
TTYOUT N M           ROUTE LOGICAL TTY N TO NUMERIC SINK M
```

CANONICAL ECHO USES THE SAME `TTY_PUTCHAR` PATH AS PROCESS OUTPUT, SO ECHO
FOLLOWS THE SELECTED SINK AUTOMATICALLY.  INPUT SCANNING, PENDING-BYTE
HANDLING, CONTROLLING-TTY OWNERSHIP, AND FOREGROUND-PGRP POLICY ARE UNCHANGED.

THE EXISTING STATELESS DPY BYTE SINK IS A BRINGUP IMPLEMENTATION, NOT THE
TARGET INTERACTIVE DESIGN. A LOGIN/DSH DISPLAY TERMINAL MUST NOT PERFORM ONE
SYNCHRONOUS DATAO/DONE WAIT PER CHARACTER.

THE IMPLEMENTED DPY TEXT SERVICE USES AN 84 BY 42 NATIVE TYPE-342 BLOCK STORE
AT HARDWARE SCALE 2. LOWERCASE STREAM BYTES ARE NORMALIZED TO UPPERCASE; MIXED
CASE AND SCALE CHANGES BELONG TO FORMATTED-DISPLAY PROGRAMS SUCH AS MAN/SIXMD.

EACH ROW HAS FOURTEEN SIX-CELL BLOCKS, TWO WORDS PER BLOCK. A ZERO FIRST WORD
MEANS SIX BLANK CELLS; A ZERO SECOND WORD MEANS THE FIRST WORD IS SIX DIRECT
PRIMARY-SET GLYPHS; OTHERWISE BOTH WORDS HOLD SIX FIXED (SI/SO,GLYPH) PAIRS.
THE REPRESENTATION IS BOTH EDITABLE TERMINAL STATE AND NATIVE REFRESH DATA, SO
THE FORMER 588-WORD SIXBIT PLANE, 42-WORD LENGTH TABLE, AND 1218-WORD
COMPILED-ROW CACHE ARE GONE. THE FIRST DPY TEXT OUTPUT LAZILY ALLOCATES ONE
1176-WORD MM_TYPE_KERNEL_DYNAMIC EXTENT, SAVING 672 DYNAMIC WORDS.

SCROLLING STILL ROTATES A 42-ROW RING WITHOUT COPYING THE SCREEN, AND
dpy_text_rows_used STILL OMITS TRAILING BLANK ROWS. PRIMARY-ONLY BLOCKS REPLAY
AS ONE DISPLAY WORD, WHILE A BLOCK WHICH HAS EVER NEEDED THE SHIFTED SET MAY
REMAIN A TWO-WORD FIXED-PAIR BLOCK UNTIL ROW CLEAR/SCROLL.

THE TEXT CONTROL AND NATIVE BLOCK OPERATIONS ARE NOW PDP-6 ASSEMBLY. THE
2026-10-04 NATIVE-BLOCK PASS REDUCED THE LINKED DPY MRES FROM 512 TO 473
PERMANENT WORDS WHILE REDUCING ITS LAZY TEXT WORKING SET FROM 1848 TO 1176
WORDS.

THE 30-HZ REFRESH STREAM USES THE TYPE-344 DATAO/DONE HANDSHAKE. THE SHARED
PI7 PRE-HANDLER FIRST CONFIRMS DPY DONE. IT WALKS NATIVE BLOCKS THROUGH THE
LAST NONBLANK BLOCK OF EACH USED ROW; SIMPLE BLOCKS ARE ONE WORD, COMPLEX
BLOCKS ARE TWO. ONE NONPRINTING SI RESET WORD IS INSERTED ONLY WHEN A COMPLEX
BLOCK LEAVES SHIFTED STATE BEFORE A SIMPLE/BLANK BLOCK. DEVICE 0130 IS NOT FED
WITH BLKO.

BANNER REFRESH AND RETAINED-TEXT REFRESH USE DISTINCT dpy_refresh_row STATES.
THE BANNER USES DPY_TEXT_ROWS AS AN OUT-OF-RANGE SENTINEL; TEXT SETUP USES -1.
THIS PREVENTS A FIRST-USE TEXT ACTIVATION THAT COMPLETES DURING AN IN-FLIGHT
BANNER FROM CONTINUING DIRECTLY INTO TEXT DATA WITHOUT EXECUTING SETUP FIRST.

THE DPY STREAM HOLDS dpy_pending FOR AN ENTIRE RETAINED FRAME. DONE FOR ONE
WORD DOES NOT MAKE THE DISPLAY IDLE; THE NEXT WORD IS CHAINED WHILE THE FRAME
REMAINS OWNED. CLK REMAINS THE REGISTERED PI6 HANDLER, AND DPY ATTACHES THROUGH
A STACKLESS POST-CLK JRST HOOK.

THE SPARSE ROW BOUND IS A CPU/INTERRUPT OPTIMIZATION, NOT A CHANGE TO TTY
GEOMETRY. `LOGIN:` OCCUPIES ONE PRIMARY NATIVE BLOCK PLUS ONE ROW-END WORD, SO
WITH THE TWO-WORD FRAME SETUP ITS 30-HZ REFRESH COST REMAINS FOUR DATAO/DONE
COMPLETIONS PER FRAME.

DPY HAS A ZERO-COST-UNUSED POLICY. AN ABSENT OR BOOT-DISABLED DPY LEAVES NO
DPY MRES OR SCREEN BUFFER AFTER KINIT. AN ENABLED DPY INSTALLS ONLY ITS SMALL
MRES; THE TEXT STORE IS ONE CONTIGUOUS KERNEL-DYNAMIC EXTENT ALLOCATED WHEN
DPY TEXT SERVICE IS FIRST ACTIVATED. NO INTERRUPT OR STEADY PUTCHAR PATH MAY
ALLOCATE MEMORY.

GRAPHICS STORAGE IS A SEPARATE ON-DEMAND EXTENT AND DOES NOT REDUCE THE
BOUNDED TEXT REPRESENTATION. SEE `HARDWARE/TYPE340.MD` FOR THE COMPLETE
DISPLAY STORAGE, REFRESH, SIXMD, AND GRAPHICS DESIGN.

FULL PDP-6 GUI BOOTS MAY SELECT `DPY_LOGIN=1`. THAT IMAGE USES A FOURTH
INITTAB FIELD TO ROUTE TTY0 OUTPUT TO DPY WHILE RETAINING CTY AS TTY0 INPUT,
SO LOGIN AND THE RESULTING DSH SESSION APPEAR ON THE TYPE 340 WITHOUT
INVENTING A TYPE-340 KEYBOARD DEVICE. HEADLESS/DEFAULT IMAGES RETAIN NATIVE
TTY OUTPUT ROUTES.

MONITORFS ALSO EXPOSES `/DEV/TTYDPY0` WHEN BOTH CTY0 AND DPY0 ARE PRESENT.
THIS IS A COMPOSITE LOGICAL TERMINAL, NOT AN ALIAS OF THE PHYSICAL DISPLAY:

```TEXT
/DEV/TTY0       CTY0 INPUT -> CTY0 OUTPUT
/DEV/TTYDPY0    CTY0 INPUT -> DPY0 RETAINED-TEXT OUTPUT
/DEV/DPY0       PHYSICAL TYPE-340 NATIVE-PROGRAM ENDPOINT
```

TTYDPY0 DOES NOT MODIFY THE PERSISTENT TTY0 OUTPUT-ROUTE FIELD. RAW READS
USE THE EXISTING CTY0 BACKEND AND RAW WRITES USE THE EXISTING DPY RETAINED
TEXT BACKEND. IT IS RECOGNIZED AS THE CALLER'S CONTROLLING TTY0 BY ISATTY,
SO REDIRECTED TERMINAL OUTPUT REMAINS CHARACTER-ORIENTED. FOR EXAMPLE:

```TEXT
ECHO TEST > /DEV/TTYDPY0
```

WRITES `TEST` TO THE TYPE-340 TERMINAL WHILE THE CALLER'S ORDINARY TTY0
OUTPUT ROUTE MAY REMAIN CTY. THE NODE IS NOT PUBLISHED ON NO-DPY SYSTEMS.

/DEV/DPY0 IS DELIBERATELY DIFFERENT. CHARACTER WRITES ARE NOT THE GRAPHICS
ABI; A WRITE_WORDS OPERATION SUBMITS ONE COMPLETE NATIVE TYPE-340 DISPLAY
PROGRAM. THE KERNEL EXECUTES THE SUPPLIED 36-BIT WORDS BUT RETAINS NO RAW
GRAPHICS PROGRAM. USERSPACE CLIENTS SUCH AS DPYVIEW OWN THE PROGRAM STORAGE
AND REPLAY IT AT REFRESH RATE. A SHORT DRIVER LEASE SUPPRESSES RETAINED-TEXT
REFRESH WHILE RAW FRAMES CONTINUE TO ARRIVE AND EXPIRES AUTOMATICALLY WHEN
THE RAW CLIENT STOPS.

## 6. WHY THIS BELONGS IN THE KERNEL

THE SMALL COOKED LAYER HAS THREE CONCRETE BENEFITS:

1. ORDINARY PORTED PROGRAMS CAN READ LINES WITHOUT EACH REIMPLEMENTING ECHO,
   ERASE, KILL, EOF, AND NEWLINE HANDLING;
2. THE JOB-CONTROL/CONTROLLING-TTY LAYER ALREADY LIVES IN THE KERNEL, SO INPUT
   DISCIPLINE CAN SHARE THAT AUTHORITY WITHOUT DUPLICATED USERSPACE RACES;
3. PER-KEYSTROKE USER/KERNEL ROUND TRIPS ARE AVOIDED FOR SIMPLE CANONICAL
   READERS ON A SLOW PDP-6/KA10.

THE COST IS RESIDENT CODE AND SMALL TERMINAL STATE.  THAT COST IS ACCEPTABLE
ONLY FOR THE MINIMAL COMMON SEMANTICS ABOVE.  DSH COMPLETION/HISTORY AND ELVIS
EDITING REMAIN USERSPACE FEATURES.

## 7. SIZE POLICY

THE DAIMOSV1 CONSOLE IMPLEMENTATION IS A DESIGN REFERENCE, NOT A CURRENT SIZE
BASELINE.  HISTORICAL OBJECT SIZES AND OLD LINE-DISCIPLINE DELTAS BELONG IN GIT
HISTORY OR BUILD LOGS AND MUST NOT BE COPIED FORWARD AS CURRENT CLAIMS.  THE
IMPLEMENTATION KEEPS MODE BITS IN EXISTING TERMINAL RECORDS, PACKS LINE-BASE
POINTERS, AND ALLOCATES CANONICAL-LINE STORAGE FROM MANAGED CORE ONLY WHILE
NEEDED.  CURRENT ACCEPTANCE IS THE PROJECT-WIDE HARD BELOW-16K FIXED
RESIDENT+IRREDUCIBLE-SCRATCH LIMIT, RE-MEASURED FROM THE CURRENT KCC BUILD.


## 8. IMPLEMENTATION STATE

IMPLEMENTED IN DAIMOS V0.9 DEVELOPMENT: CANONICAL/ECHO/SIGNALS FLAGS, RAW
MODE, CR/LF TERMINATION, PRINTABLE ECHO, BS/DEL ERASE, CTRL-U KILL, CTRL-D EOF,
120-CHARACTER BOUNDED INPUT, MODE-RESET LINE DISCARD, AND FOREGROUND CTRL-C/
CTRL-Z event generation when SIGNALS is enabled.  LOGIN selects cooked mode and
temporarily clears ECHO for password input.  DSH selects raw/no-echo/no-signals
for its own editor and restores cooked mode on exit.

Real scripted Telnet acceptance now passes LOGIN -> DSH -> EXIT -> LOGIN on
both DCS0 and GE0 with CRLF input.  The canonical path suppresses the LF of a
CRLF pair while still accepting bare CR or bare LF.  Permanent target coverage
for erase/kill/EOF/full-line/signal/allocation edge cases remains testkit work;
this does not reopen the ABI/design.

DETACHABLE OUTPUT ROUTING AND THE TYPE-340/342 TERMINAL SINK ARE IMPLEMENTED.
THE ROUTE REGRESSION BUILDS THE FULL PDP-6 IMAGE, VERIFIES THE KCORE/TTY/DPY
EXPORTS AND ZERO-TABLE BIT LAYOUT, AND BOOTS THROUGH `DPY OK`, `TTY LOADED`,
AND `INIT V1`.  AGAINST CLEAN DAIMOS COMMIT 642018F, THE MEASURED PERMANENT
COST IS +45 KCORE WORDS, +16 TTY-MRES WORDS, AND +42 DPY-MRES WORDS, OR +103
WORDS WHEN TTY AND DPY ARE BOTH INSTALLED.  FIXED ROUTING BSS COST IS ZERO.
