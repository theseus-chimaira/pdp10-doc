# KA10 basic compatibility: accepted 0.9 boundary (v1974)

K17 is CLOSED for native 64K KA10 ONESEG, PDP-6-equivalent
operation in the tested SIMH configuration. This is not
full KA10 architecture or physical hardware qualification.
The build selects native machine code at compile time,
not a runtime dispatcher. Same contiguous user ABI and
common MM, process and VFS policy; no additional per-process
state. RAW PURE and mode3 remain OFF by default.

## Boot and storage

Counted paper-tape read-in is the accepted KA10 bootstrap,
with shared 53-word decoder at 062. Trap cells060/061
reserved on KA10, reclaimed on PDP6. Native APR protection,
PI and 060/061 trap paths accepted. Two reserved DF10 pairs
0150/0151 and 0152/0153; RM10 exclusively uses first pair.
The second is isolated but concurrent independent DMA
channels are not qualified. KA10 fixed KCORE11124 words,
RM10 MRES130 words, DCS MRES65 words. No production code,
RAM or simulator changes in v1973/v1974 qualification.

All four native root profiles have usable stock CTY and
DCS0 shells: D6FS without/with RM10 and TSFS without/with
RM10. TSFS without backing serial CTY then DCS shell,
not simultaneous DSH. Other profiles simultaneous.
TSFS tests use validated media-locality repacking only;
full command tree retained and all file/boot words equal.
RM10 geometry, native transfer, NXM, locked/absent media,
bounded timeout and peer recovery accepted v1970.
Actual critical READ/WRITE loss after DATAO accepted
v1973: 300-tick STOP then reason2 fail-stop, original MM/
pins/backing preserved. Not arbitrary mid-sector coverage.

Current native 64K six-child pressure tests, each 8192
words, exact WAIT/canaries and stable MM owners:
- D6FS direct Type270 (v1974): MM9/20/8,
  free43863/1319/43877; bitmap0/64/0, reads50/129/193,
  writes1/65/65, errors0.
- D6FS+RM10 (v1972/v1974): MM9/20/8,
  free43747/1203/43761; bitmap0/64/0, reads2/2/66,
  writes0/64/64, errors0.
- TSFS+RM10 (v1973): MM9/20/8,
  free42661/117/42675; bitmap0/64/0, reads2/2/66,
  writes0/64/64, errors0; tapes unchanged.
All three use actual native backing transfer and restore,
not synthetic allocator state. PID1 success marker then
controlled monitor termination. Original v1959 PDP6
disk swap report retained, v1972 matched PDP6 boot
binaries byte-identical. v1964 native Type270 component
recovery tests retained; no claim that every historical
PDP6 fault was repeated on KA10.

## v1974 process and interrupt qualification

Three native source-linked shared-PI2 cases: actual DCS
RX while RM10 BUSY, both pending, and DMA before RX PASS.
Exact TCP byte, 128 DMA words and two wakes. Test process
event stubs, actual device/handler semantics. Full native
kernel DCS-swapped-reader case additionally verifies
PID2 DISK original DCS wait event, real TCP wake retained
through slot0 RM10 READ and return to original syscall,
then six exact WAITs/canaries and complete cleanup.
See KA10-DCS-V1972.MD and RM10-V1970.MD.

Native KA10 and matched PDP6 lowmem 64K D6FS replay
unchanged user fixtures (byte-identical per case):
process lifecycle, PID/PGRP events and STOP/CONT, five
user timer preemption/private stack and data context,
disk sleep/wakeup, user APR fault termination all PASS.
Additional native faulting child test READ/WRITE outside
APR and KA10 unassigned instruction, exact parent fatal
WAIT0400001, unchanged parent canaries and process/file
accounting, subsequent ordinary child037, then HALT0.
KA10 RWINP, PDP6 RWNP (KA10-specific opcode not executed
on PDP6). Both exit0. Initial PDP6 graphical runs stopped
and replayed headless; no kernel defect inferred.
RUN/EXEC/BRK/EXIT/WAIT and ordinary context accepted
through the combined pressure, stock login/shell, events,
preemption and fault lifecycle tests.

## Deferred boundary

Full dual relocation/high segment, shared TEXT, native
KA10-specific DXR policy, additional controllers (including
RD10 and RM10 root), non-paper-tape direct read-in, all
sixteen terminal lines, simultaneous independent DMA
channels, optional RAW/mode3, size optimization and
broader physical hardware/release qualification remain
separate. No assertion of exhaustive faults at every
transfer word or every hardware state. K01-K09 PDP6 and
K17 basic KA10 functional integration closed; optional
K10-K16 compression remains subject to measured net RAM
benefit and separate qualification.
