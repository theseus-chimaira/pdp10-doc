# DAIMOS LOGSTORE V1

*SMALL RAW-DISK DURABLE LOG QUEUE WITH SEQUENTIAL MAGTAPE DRAIN*

## DOCUMENT METADATA

- STATUS: V1 DISK CORE, MTC516 RAW SERVICE, AND COLD MAGTAPE DRAIN VERIFIED
- DATE: 2026-09-17
- SCOPE: DISK LOGSTORE RECORDS, RECOVERY, FULL-RING POLICY, AND MAGTAPE DRAIN
- ENCODING: PLAIN ASCII; ALL MEDIA WORDS ARE 36-BIT PDP-10 WORDS

## 1. PURPOSE

LOGSTORE IS A BOUNDED PERSISTENT CIRCULAR RECORD QUEUE IN A RAW LOGICAL RANGE
RESERVED BY A FILESYSTEM AND REGISTERED THROUGH VFS.
IT IS THE DURABLE SPOOL FOR KERNEL/SYSTEM LOG RECORDS AND THE SOURCE QUEUE FOR
THE V1 MAGTAPE ARCHIVE PATH.

LOGSTORE IS NOT A D6FS FILE, JOURNAL, FILESYSTEM, OR GENERAL DATABASE.  IT MUST
REMAIN AVAILABLE BEFORE, DURING, AND AFTER D6FS RECOVERY.

THE LAYERING IS:

'''TEXT
RUNTIME LOG PRODUCERS
        |
        V
   LOGSTORE CORE
        |
        V
VFS-REGISTERED RAW LOGICAL RANGE
        |
        +------> DISKSET MRES ------> STORAGE/DSK270
        |
        V
MAGTAPE DRAIN POLICY
        |
        V
RAW MTC516 RECORD PRIMITIVES
'''

THE DISK REGION IS THE FAST DURABLE QUEUE.  MAGTAPE IS THE LONG-TERM SEQUENTIAL
ARCHIVE.

## 2. DESIGN PRIORITIES

1. CORRECT CRASH RECOVERY;
2. RESIDENT RAM SIZE;
3. EXECUTION SPEED;
4. MEDIA SPACE;
5. ABSTRACTION ELEGANCE.

LOGSTORE MUST NOT BLOCK AN ARBITRARY KERNEL PRODUCER WAITING FOR MAGTAPE.

## 3. REGION CONTRACT

LOGSTORE DOES NOT OWN PERSISTENT PLACEMENT METADATA.  A FILESYSTEM MAY RESERVE
A LOGSTORE RANGE; ON MOUNT VFS DISCOVERS THAT RESERVATION AND MAKES IT
AVAILABLE FOR LOGSTORE ACTIVATION.  ACTIVATION CACHES THE BACKING LOGICAL
DEVICE/START/LENGTH, AFTER WHICH LOGSTORE I/O BYPASSES NORMAL VFS/D6FS FILE I/O
AND USES THE LOWER RAW BLOCK/RANGE PATH.

LOGSTORE KNOWS NOTHING ABOUT STORAGE-SET MEMBERS, STRIPING, BAD-MEDIA REMAPS,
PHYSICAL SECTORS/BLOCKS, D6FS FCBS, OR THE FILESYSTEM'S INTERNAL RESERVATION
REPRESENTATION.  THE STORAGE-SET LAYER CHOOSES PHYSICAL DISTRIBUTION AND APPLIES
THE COMMON DISK/DRUM BAD-MEDIA MAP; DEVICE DRIVERS OWN THEIR SCHEDULING.

LOGSTORE SIZE IS FILESYSTEM FORMAT/MAINTENANCE POLICY.  IT IS NOT DERIVED FROM
A FIXED RAM-SIZE MULTIPLIER.  REQUESTED SIZES ARE ROUNDED/VALIDATED TO THE
LOWER DEVICE'S EFFICIENT TRACK/CYLINDER GEOMETRY.  ON MOVING-HEAD DISK, D6FS
POLICY PLACES LOGSTORE AT THE INNER EDGE DIRECTLY AFTER THE BOOT AREA; DRUMSETS
HAVE NO INNER/OUTER RULE.

A REGION SMALLER THAN THE REQUIRED STATE PLUS RECORD AREA IS INVALID.  AN
ABSENT/ZERO-SIZED LOGSTORE MEANS NO DURABLE LOGSTORE IS AVAILABLE.  A
FILESYSTEM PROVIDING AN ACTIVE LOGSTORE CANNOT BE UNMOUNTED UNTIL LOGSTORE IS
DEACTIVATED.

## 4. V1 DISK FORMAT

THE FINAL V1 FORMAT USES PHYSICAL LOGSTORE BLOCKS AS THE CRASH-ATOMIC UNIT OF
REUSE.  IT DOES NOT PACK INDEPENDENT DURABLE RECORDS INTO ONE REWRITTEN SECTOR.
THIS AVOIDS A TORN UPDATE OF ONE NEW RECORD DAMAGING OLDER COMMITTED RECORDS IN
THE SAME PHYSICAL SECTOR.

REGION LAYOUT:

'''TEXT
BLOCK 0   STATE A
BLOCK 1   STATE B
BLOCK 2+  ONE LOGSTORE RECORD PER 128-WORD BLOCK
'''

STATE A/B ARE ALTERNATING RECOVERY CHECKPOINTS.  RECORD BLOCKS ARE A CIRCULAR
ARRAY.

THE HISTORICAL KINIT 'D6LOG2' HEADER-PLUS-8-WORD-PACKED-RECORD FORMAT HAS BEEN
REMOVED FROM THE CURRENT TREE.  THE BOOT RECORD PATH NOW USES THIS V1 FORMAT.

## 5. RECORD BLOCK

A V1 RECORD OCCUPIES ONE 128-WORD BLOCK.

THE CURRENT V1 RECORD LAYOUT IS:

'''TEXT
WORD 0    0546362454321  SIXBIT /LSREC1/
WORD 1    MONOTONIC SEQUENCE, ZERO INVALID
WORD 2    TIMESTAMP, LOW 36 BITS
WORD 3    BITS 35..30 SEVERITY (6 BITS)
          BITS 29..18 SOURCE   (12 BITS)
          BITS 17..0  PAYLOAD WORD COUNT
WORD 4..126  PAYLOAD, MAXIMUM 123 WORDS
WORD 127  COMMIT TRAILER
'''

THE RECORD COMMIT TRAILER IS EXACTLY:

'''TEXT
X = (0546362454321 + SEQUENCE + (PAYLOAD_WORDS << 18)) & 0777777777777
COMMIT = (X ^ 0777777777777) | 1
'''

THE LOW COMMIT BIT IS FORCED TO ONE SO ZERO IS NEVER A VALID COMMIT VALUE.

THE TRAILER IS PHYSICALLY LAST.  THE DSK270/DCT WRITE PATH TRANSFERS A SECTOR IN
WORD ORDER.  A PARTIAL REWRITE THEREFORE EITHER LEAVES THE OLD RECORD VALID OR
LEAVES A NEW HEADER WHOSE OLD/MISSING TRAILER DOES NOT VALIDATE.  A RECORD IS
COMMITTED ONLY WHEN ITS HEADER/LENGTH AND FINAL TRAILER AGREE.

THE RECORD VALIDATOR MUST REJECT ZERO SEQUENCE, IMPOSSIBLE LENGTHS, UNKNOWN
VERSION, AND A BAD TRAILER.  A CHECKSUM OVER THE WHOLE PAYLOAD IS OPTIONAL FOR
V1 ONLY IF MEASUREMENT SHOWS IT IS NEEDED; THE COMMIT TRAILER IS REQUIRED.

V1 DOES NOT NEED A 72-BIT SEQUENCE.  SEQUENCE ZERO IS RESERVED.  EXHAUSTION OF
THE 36-BIT NONZERO SEQUENCE SPACE IS A MAINTENANCE CONDITION RATHER THAN A
COMPLICATED RESIDENT WRAP-EPOCH PROTOCOL.

## 6. STATE BLOCKS

STATE A AND STATE B ARE INDEPENDENT FULL BLOCKS.  THE CURRENT V1 STATE LAYOUT
IS:

'''TEXT
WORD 0    0546363644121  SIXBIT /LSSTA1/
WORD 1    STATE GENERATION, ZERO INVALID
WORD 2    NEXT DRAIN SEQUENCE, ZERO INVALID
WORD 3    LOST/OVERWRITTEN RECORD COUNT
WORD 4    RECORD CAPACITY FOR THIS LOGSTORE REGION
WORD 5..126  ZERO/RESERVED IN V1
WORD 127  STATE COMMIT TRAILER
'''

THE STATE COMMIT TRAILER IS EXACTLY:

'''TEXT
X = (0546363644121 + GENERATION + NEXT_DRAIN + LOST + CAPACITY)
    & 0777777777777
COMMIT = (X ^ 0777777777777) | 1
'''

AN UPDATE WRITES THE OLDER STATE COPY WITH GENERATION+1 AND ITS COMMIT TRAILER
LAST.  RECOVERY CHOOSES THE NEWEST VALID COPY.  A TORN STATE WRITE THEREFORE
LEAVES THE PREVIOUS COPY AVAILABLE.

THE STATE BLOCK IS NOT AUTHORITATIVE FOR APPEND POSITION.  RECORD BLOCKS ARE.
THIS PREVENTS A TORN HEAD-POINTER UPDATE FROM MAKING THE LOG UNRECOVERABLE.

## 7. RECOVERY

RECOVERY IS BOUNDED BY THE REGION SIZE AND MAY SCAN ALL RECORD BLOCKS.  FOR THE
DEFAULT 32-KWORD REGION THIS IS SMALL ENOUGH TO PREFER SIMPLE CORRECT CODE OVER
A RESIDENT INDEX.

RECOVERY:

1. VALIDATES STATE A/B AND SELECTS THE NEWEST VALID STATE;
2. SCANS RECORD BLOCKS AND ACCEPTS ONLY COMMITTED RECORDS;
3. FINDS THE HIGHEST VALID NONZERO SEQUENCE;
4. SETS NEXT APPEND SEQUENCE TO HIGHEST+1, OR 1 FOR AN EMPTY LOG;
5. REMEMBERS THE SLOT OF THE HIGHEST VALID RECORD AND CHOOSES THE NEXT SLOT;
6. RECONCILES DRAIN STATE WITH THE OLDEST RECORD STILL PRESENT;
7. NEVER TREATS A PARTIAL RECORD AS COMMITTED.

BECAUSE V1 TREATS 36-BIT SEQUENCE EXHAUSTION AS MAINTENANCE, SIMPLE NUMERIC
SEQUENCE ORDER IS VALID DURING NORMAL OPERATION.

## 8. APPEND

APPEND BUILDS ONE COMPLETE RECORD BLOCK IN THE SHARED/PROVIDED SCRATCH BUFFER
AND ISSUES ONE LOGSTORE-REGION BLOCK WRITE.  THE COMMIT TRAILER IS THE LAST WORD
OF THAT TRANSFER.

ON SUCCESS THE RECORD IS DURABLE.  NO D6FS SYNC, PATH LOOKUP, FILE ALLOCATION,
OR LOGSTORE HEADER WRITE IS REQUIRED PER APPEND.

NORMAL APPEND MUST NOT UPDATE STATE A/B.  STATE WRITES ARE REQUIRED ONLY FOR
DRAIN ACKNOWLEDGEMENT, FULL-RING LOSS ADVANCE, REEL/ARCHIVE CHECKPOINTS, OR
OTHER INFREQUENT PERSISTENT DRAIN POLICY.

## 9. FULL-RING POLICY

LOGGING MUST NOT DEADLOCK THE KERNEL WHEN MAGTAPE IS ABSENT.

V1 POLICY IS KEEP-THE-NEWEST:

- APPEND NEVER WAITS FOR MAGTAPE;
- IF THE NEXT SLOT STILL CONTAINS AN UNDRAINED RECORD, THAT OLDEST RECORD IS
  DECLARED LOST BEFORE THE SLOT IS REUSED;
- THE PERSISTENT DRAIN FLOOR IS ADVANCED PAST THE LOST RECORD THROUGH THE
  CRASH-SAFE A/B STATE UPDATE;
- LOST_RECORDS IS INCREMENTED;
- THE DRAIN EMITS OR REPORTS A GAP BEFORE CONTINUING WITH THE NEXT AVAILABLE
  SEQUENCE.

THIS PRESERVES RECENT FAILURE CONTEXT WHILE MAKING LOSS EXPLICIT.  DO NOT ADD
SEVERITY-CLASS RESERVATIONS UNTIL MEASUREMENT OR OPERATING EXPERIENCE JUSTIFIES
THE EXTRA POLICY.

## 10. MAGTAPE DRAIN

THE MAGTAPE DRAIN IS A SEQUENTIAL CONSUMER OF COMMITTED, UNDRAINED LOGSTORE
RECORDS.

ORDERING RULE:

'''TEXT
COMMIT RECORD TO DISK
        |
        V
WRITE CORRESPONDING TAPE RECORD
        |
        V
WAIT FOR SUCCESSFUL MTC516 COMPLETION
        |
        V
PERSIST NEXT-DRAIN SEQUENCE IN STATE A/B
'''

THE IMPLEMENTED COLD DRAIN READS THE NEXT COMMITTED RECORD INTO A CALLER-OWNED
128-WORD BUFFER, PERFORMS ONE MTC STATUS/READINESS PREFLIGHT, WRITES THE RECORD,
AND ONLY THEN PERSISTS THE NEXT-DRAIN SEQUENCE.  TAPE ERROR, EOT, DETACH,
UNAVAILABLE MEDIA, OR A FAILED ACK STATE WRITE LEAVES THE RECORD ELIGIBLE FOR
RETRY.  THE CALLER IS TOLD WHEN REEL ATTENTION IS REQUIRED.

THE DRAIN PROVIDES AT-LEAST-ONCE ARCHIVE SEMANTICS.  IF POWER FAILS AFTER A TAPE
WRITE SUCCEEDS BUT BEFORE THE DISK ACKNOWLEDGEMENT COMMITS, THAT LOG RECORD MAY
BE WRITTEN TO TAPE AGAIN AFTER REBOOT.  THIS IS INTENTIONAL.  EXACTLY-ONCE
COORDINATION BETWEEN DISK AND TAPE IS NOT WORTH THE CODE/RAM COST.

EVERY TAPE RECORD THEREFORE CARRIES THE LOGSTORE SEQUENCE NUMBER SO OFFLINE
TOOLS CAN RECOGNIZE DUPLICATES AND GAPS.

## 11. TAPE REPRESENTATION

ONE COMMITTED LOGSTORE RECORD MAPS WORD-FOR-WORD TO ONE 128-WORD MTC516 TAPE
RECORD.  THE EXISTING LSREC1 HEADER, SEQUENCE, LENGTH, PAYLOAD, AND COMMIT
TRAILER ARE THE ARCHIVE FORMAT.  THERE IS NO SECOND ARCHIVE HEADER, FORMAT
CONVERSION, RECORD COPY, OR PERMANENTLY RESIDENT TRANSFER BUFFER.

THE DRAIN DOES NOT ISSUE A POST-WRITE STATUS COMMAND.  A SUCCESSFUL WRITE IS
ACKNOWLEDGED EVEN IF IT REACHES EOT; THE NEXT DRAIN PREFLIGHT OBSERVES EOT AND
REQUESTS A REEL CHANGE.  THIS SAVES ONE CONTROLLER OPERATION PER SUCCESSFUL
RECORD.  IF POWER FAILS OR THE A/B ACK STATE WRITE TEARS AFTER TAPE COMPLETION,
THE SAME LSREC1 RECORD IS WRITTEN AGAIN AFTER RECOVERY.

FILEMARK POLICY:

- WRITE A FILEMARK AT A CLEAN DRAIN STOP OR REEL-CLOSE OPERATION;
- EOT DOES NOT ACKNOWLEDGE A RECORD THAT DID NOT COMPLETE;
- REEL CHANGE STARTS A NEW ARCHIVE FILE/REEL GENERATION AND THEN RESUMES AT THE
  FIRST UNACKNOWLEDGED LOGSTORE SEQUENCE;
- FILEMARKS AND REELS ARE ARCHIVE STRUCTURE, NOT VFS FILES.

THE LOW-LEVEL MTC516 DRIVER OWNS ONLY RAW RECORD READ/WRITE, REWIND, FILEMARK,
SPACING, STATUS, AND ERROR COMPLETION.  ONE COMPACT MTC SERVICE EXPORT CARRIES
READ, WRITE, STATUS, AND CONTROL OPERATIONS.  STATUS SELECTS THE REQUESTED UNIT
AND IS THE READINESS PREFLIGHT; CALLERS START NO RECORD OR CONTROL COMMAND UNLESS
TAPE_RDY IS SET.  RECORD/CONTROL FAILURES RETURN GENERIC EIO, AND EOF/EOT ARE
CLASSIFIED FROM THE RAW STATUS WORD.  THIS SAVES RESIDENT CODE IN RARE ERROR
PATHS.  LOGSTORE OWNS DRAIN POLICY.

## 12. PRODUCER API

THE CORE API REMAINS SMALL, CONCEPTUALLY:

'''TEXT
RECOVER
APPEND RECORD
READ NEXT COMMITTED RECORD FOR DRAIN
REPORT OLDEST/NEWEST/NEXT-DRAIN STATUS
ACK INSIDE THE SUCCESSFUL ONE-RECORD DRAIN OPERATION
REPORT LOST COUNT
'''

DO NOT ADD NAMED STREAMS, FILES, DIRECTORIES, GENERAL TRANSACTIONS, ALLOCATION
TREES, INDEXES, OR FILESYSTEM-STYLE CACHING.

## 13. CONTROL AND TOOLS

V1 NEEDS SMALL NATIVE CONTROLS/TOOLS TO:

- SHOW LOGSTORE CAPACITY, OLDEST/NEWEST SEQUENCE, DRAIN POSITION, AND LOSS COUNT;
- START/STOP THE MAGTAPE DRAIN;
- SHOW CURRENT MTC UNIT/REEL STATE;
- CLOSE A REEL WITH A FILEMARK;
- RESUME AFTER REEL CHANGE;
- DUMP/VERIFY ARCHIVE RECORDS OFFLINE.

TOOLS BELONG IN PDP10-TOOLS.  TESTS BELONG IN PDP10-TESTKIT.

## 14. NON-FEATURES

LOGSTORE V1 HAS NO:

- NORMAL VFS/D6FS FILE-I/O DEPENDENCY AFTER ACTIVATION;
- GENERAL FILE API;
- UNBOUNDED MEMORY QUEUE;
- EXACTLY-ONCE DISK/TAPE TRANSACTION;
- GENERAL DATABASE INDEX;
- PRODUCER BLOCKING ON MAGTAPE;
- SILENT OVERWRITE WITHOUT A PERSISTENT LOSS INDICATION.

## 15. CURRENT IMPLEMENTATION TRANSITION, 2026-09-17

THE LOGSTORE RECORD/RECOVERY FORMAT AND MAGTAPE-DRAIN ORACLES ARE IMPLEMENTED
AND TESTED.  THE CURRENT DAIMOS RUNTIME STILL REACHES LOGSTORE THROUGH THE
OLDER DISKSET-OWNED SEMANTIC REGION INTERFACE.  THAT PLACEMENT INTERFACE IS
TRANSITIONAL.

THE ACCEPTED TARGET IS THE REGION CONTRACT IN SECTION 3: D6FS PERSISTS THE
OPTIONAL LOGSTORE RESERVATION, VFS RESOLVES/REGISTERS IT, AND LOGSTORE CACHES
THE BACKING LOGICAL DEVICE/START/LENGTH.  NORMAL LOGSTORE I/O THEN BYPASSES
D6FS FILE I/O AND USES GENERIC LOWER-LAYER RANGE I/O.  DISKSET DOES NOT OWN
LOGSTORE SEMANTICS.

THE EXISTING FORMAT/RECOVERY TESTS MUST SURVIVE THIS OWNERSHIP MIGRATION.
HISTORICAL KINIT/MRES SIZE NUMBERS ARE AVAILABLE IN GIT HISTORY AND ARE NOT
CURRENT KERNEL-SIZE ACCEPTANCE LIMITS.
