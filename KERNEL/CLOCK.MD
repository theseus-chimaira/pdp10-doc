# DAIMOS MONOTONIC AND WALL CLOCK DESIGN

DATE: 2026-09-18
STATUS: IMPLEMENTATION CONTRACT FOR THE STANDARD PHIL PETIT PCLK

## 1. TWO CLOCKS, TWO JOBS

DAIMOS HAS TWO DISTINCT CLOCKS.

THE PDP-6 APR 60 HZ LINE CLOCK IS THE MONOTONIC CLOCK.  IT REMAINS THE SOURCE
FOR SCHEDULING, SLEEP, TIMEOUTS, DEVICE TIMING, AND ELAPSED-TIME MEASUREMENT.
IT MUST NOT DEPEND ON CIVIL TIME.

THE STANFORD PHIL PETIT CALENDAR CLOCK (PCLK), I/O DEVICE 0730, IS THE STANDARD
DAIMOS WALL CLOCK.  IT PROVIDES UTC FOR D6FS/MEMFS MTIME, DATE DISPLAY, LOGGING, AND
LATER NETWORK/SECURITY SOFTWARE.  DAIMOS DOES NOT USE A SERIAL RTC OR RTCD.
PCLK INTERRUPTS ARE NOT REQUIRED; THE WALL CLOCK IS READ ON DEMAND.

## 2. STANDARD HARDWARE REQUIREMENT

PCLK IS PART OF THE DAIMOS PDP-6 HARDWARE BASELINE.  A DAIMOS PDP-6
CONFIGURATION IS EXPECTED TO PROVIDE THE PETIT CLOCK AT DEVICE 0730.  THERE IS
NO SECOND STANDARD WALL-CLOCK PROVIDER AND NO SERIAL-LINE FALLBACK.

THIS MATCHES THE HISTORICAL STANFORD PDP-6 INSTALLATION WHILE KEEPING THE
RESIDENT DAIMOS CLOCK PATH VERY SMALL.  THE APR LINE CLOCK CONTINUES TO WORK
INDEPENDENTLY OF PCLK AND MUST NEVER BE REPLACED BY PCLK FOR SCHEDULING.

## 3. SUPPORTED CIVIL-TIME RANGE

DAIMOS DOES NOT SUPPORT WALL-CLOCK DATES BEFORE 2026-01-01.

THE PETIT CLOCK CARRIES ONLY TWO DECIMAL YEAR DIGITS.  DAIMOS USES THIS FIXED
CENTURY RULE:

    PCLK 26..99    2026..2099
    PCLK 00..25    2100..2125

THEREFORE THE SUPPORTED PCLK WALL-CLOCK RANGE IS:

    2026-01-01 00:00:00 UTC
    THROUGH
    2125-12-31 23:59:59 UTC

THE RULE IS PART OF THE DAIMOS ABI, NOT A SIMULATOR CONFIGURATION OPTION.
SOFTWARE MUST NOT TRY TO INFER A DIFFERENT CENTURY FROM FILE CONTENTS OR BOOT
HISTORY.

## 4. TIME36 REPRESENTATION

GETTIME RETURNS ONE CHRONOLOGICALLY SORTABLE 36-BIT UTC VALUE.  IT IS NOT UNIX
EPOCH SECONDS.  THE FORMAT IS CHOSEN SO THE PETIT HARDWARE FIELDS CAN BE
NORMALIZED WITH VERY LITTLE PDP-6 CODE AND UNSIGNED NUMERIC COMPARISON PRESERVES
TIME ORDER THROUGH THE SUPPORTED RANGE.

    BIT 35        0
    BIT 34        0 = 20XX, 1 = 21XX
    BITS 33..26   TWO BCD YEAR DIGITS
    BITS 25..22   MONTH, 1..12
    BITS 21..17   DAY, 1..31
    BITS 16..12   HOUR, 0..23
    BITS 11..6    MINUTE, 0..59
    BITS 5..0     SECOND, 0..59

TIME36 VALUE 0 MEANS UNKNOWN/UNINITIALIZED WHEN USED IN A PERSISTENT METADATA
FIELD.  A LIVE STANDARD PCLK READ IS EXPECTED TO RETURN A VALID SUPPORTED DATE.

TIMEZONE, DAYLIGHT-SAVING POLICY, AND HUMAN DATE FORMATTING ARE USERSPACE
POLICY.  THE KERNEL CLOCK ABI IS UTC ONLY.

## 5. PETIT REGISTER ENCODING

THE HISTORICAL/SIMULATED PCLK ENCODING USES:

- DATAI 0730: TWO DECIMAL YEAR DIGITS, MONTH CODE, ZERO-BASED DAY, HOUR, AND
  MINUTE, PLUS THE HISTORICAL 05004 OFFSET;
- CONI 0730: MINUTE/SECOND INFORMATION PLUS THE PETIT/PANOFSKY OFFSET
  02020136700.

MONTHS ARE ENCODED 4,5,6,7,8,9,A,B,C,D,E,F FOR JANUARY THROUGH DECEMBER.
THE TWO YEAR DIGITS ARE DIGIT-ENCODED NIBBLES: 1974 IS ENCODED AS 0X74, NOT AS
THE BINARY NUMBER 74.

THE RESIDENT READER MUST AVOID MIXING FIELDS ACROSS A MINUTE ROLLOVER.  THE
FIRST IMPLEMENTATION READS:

    DATAI
    CONI
    DATAI

AND RETRIES IF THE TWO DATAI VALUES DIFFER.  IT THEN REMOVES THE HISTORICAL
OFFSETS, CONVERTS THE MONTH/DAY ORIGINS, APPLIES THE 2026..2125 CENTURY RULE,
AND RETURNS TIME36.

NO CALENDAR STRING PARSER, DIVISION-HEAVY EPOCH CONVERSION, OR LARGE KERNEL
DATE LIBRARY BELONGS ON THIS FAST PATH.

## 6. KERNEL AND LIBC ABI

THE INITIAL ABI PROVIDES A THIN GETTIME OPERATION RETURNING TIME36.

GETTIME IS A DIRECT, NONBLOCKING PCLK READ.  THERE IS NO KERNEL WALL-CLOCK
ACCUMULATOR, SERIAL-I/O PATH, RTCD, OR GENERAL SETTIME OPERATION.  THIS KEEPS
THE RESIDENT COST SMALL AND AVOIDS DUPLICATING A CLOCK THAT THE HARDWARE ALREADY
MAINTAINS.

THE APR 60 HZ CLOCK REMAINS THE ONLY CLOCK USED BY SCHEDULER/TIMER CODE.

USERSPACE HAS ONE DELIBERATELY SMALL MONOTONIC DELAY PRIMITIVE,
`SYS_EXT_SLEEP` (EXTENSION 036).  ITS ARGUMENT IS A BOUNDED 17-BIT NUMBER OF
APR TICKS; ZERO RETURNS IMMEDIATELY.  THE TOP SCHEDULER-RH BIT TAGS A TIMED
WAIT, LEAVING A MODULO RANGE OF 0377777 TICKS (ABOUT 36 MINUTES AT 60 HZ).
A SLEEPING PROCESS STORES ITS DEADLINE IN
THE EXISTING SCHEDULER RH FIELD, AND ONE GLOBAL NEXT-DEADLINE FRONTIER WORD
PREVENTS AN O(PROCESS-COUNT) SCAN ON EVERY 60 HZ TICK.  THE PROCESS TABLE IS
SCANNED ONLY WHEN THE CURRENT FRONTIER BECOMES DUE, AT WHICH POINT EXPIRED
SLEEPERS ARE MADE RUNNABLE AND THE NEXT FRONTIER IS REBUILT.

THIS IS A BLOCKING SLEEP, NOT A POSIX TIMER FACILITY.  THERE IS NO TIMER
OBJECT TABLE, INTERVAL TIMER, WALL-CLOCK ALARM, OR SECOND TIMER WHEEL.

A USERSPACE DATE UTILITY DECODES TIME36 FOR DISPLAY.  IT NEED NOT SET THE
STANDARD PCLK.  IF A FUTURE PHYSICAL PCLK IMPLEMENTATION PROVIDES A SAFE SET
MECHANISM, THAT IS A SEPARATE HARDWARE/ADMINISTRATIVE FEATURE AND DOES NOT
CHANGE THE TIME36 ABI.

## 7. FILESYSTEM MTIME AND MAKE

DAIMOS EXPOSES ONE 36-BIT MTIME FIELD.  MTIME36 USES THE EXACT TIME36 FORMAT
ABOVE; THERE IS NO ATIME OR CTIME.

D6FS STORES MTIME PERSISTENTLY IN EACH FCB AND UPDATES IT ON RELEVANT CONTENT,
DIRECTORY, AND METADATA MUTATIONS.  MEMFS STORES ONE MTIME36 PER NODE IN ITS
DYNAMIC METADATA AREA, UPDATES FILE AND DIRECTORY MTIME ON MUTATION, AND
PRESERVES IT IN VERSION-2 PERSISTENT MEMFS SNAPSHOTS.  TOUCH/UTIME USES THE
COMMON VFS SETATTR PATH; THE OWNER OR UID 0 MAY SET MTIME.

DTFS, TSFS, AND MONITORFS RETURN MTIME 0.  DTFS FOREIGN/NATIVE MEDIA DO NOT
PROVIDE A COMMON MEANINGFUL FILE MTIME; TSFS IS IMMUTABLE AND DOES NOT SPEND A
PER-FILE WORD ON TIMESTAMPS; MONITORFS IS A LIVE SYNTHETIC VIEW FOR WHICH A
CONVENTIONAL FILE MODIFICATION TIME WOULD BE MISLEADING.  MTIME 0 THEREFORE
MEANS UNKNOWN/NOT-APPLICABLE.

MAKE MAY COMPARE VALID TIME36 VALUES DIRECTLY AS UNSIGNED 36-BIT VALUES BECAUSE
THE FORMAT IS CHRONOLOGICALLY SORTABLE THROUGH THE SUPPORTED 2026..2125 RANGE.
MAKE MUST NOT SILENTLY TREAT MTIME 0 AS VALID DEPENDENCY DATA.

THE PCLK/GETTIME DRIVER AND D6FS STAT/MTIME UPDATE/DATE/TOUCH PLUMBING ARE
IMPLEMENTED AND TARGET-VALIDATED.  MAKE STILL MUST HANDLE MTIME 0 AND
OUT-OF-RANGE VALUES CONSERVATIVELY WHEN IT IS PORTED.

## 8. SIMH CONTRACT

THE PDP-6 SIMULATOR MUST EXPOSE PCLK DEVICE 0730.

FOR PDP-6, PCLK DEFAULTS TO REALTIME MODE.  DAIMOS BOOT CONFIGURATIONS MUST
NOT RELY ONLY ON THAT SIMULATOR DEFAULT; THEY EXPLICITLY ISSUE:

    SET PCLK ENABLED
    SET PCLK REALTIME

THE DAIMOS MAKE VARIABLE `SIMH_PCLK_MODE` MAY BE SET TO `HISTORICAL` FOR THE
HISTORICAL-MODE REGRESSION TEST, BUT NORMAL DAIMOS BOOTS USE `REALTIME`.

REALTIME REPORTS THE HOST UTC DATE AND TIME USING THE HISTORICAL REGISTER
ENCODING.  HOST LOCAL TIME MUST NOT LEAK INTO REALTIME MODE.

THE SIMULATOR ALSO RETAINS:

    SET PCLK HISTORICAL

FOR WAITS/HISTORICAL COMPATIBILITY.  HISTORICAL MODE PRESERVES THE EXISTING
FIXED FRIDAY 1974-07-26 DATE WITH HOST-LOCAL TIME.  IT IS FOR WAITS/HISTORICAL
SIMULATION, NOT DAIMOS.  BECAUSE THE HARDWARE EXPORTS ONLY TWO YEAR DIGITS,
DAIMOS WOULD INTERPRET ITS `74` FIELD ACCORDING TO THE STANDARD CENTURY RULE
AS 2074; THE GUEST CANNOT DISCOVER THE SIMULATOR'S HISTORICAL INTENT.

THE CENTURY RULE IS NOT A SIMH OPTION.  THE GUEST SEES ONLY THE HISTORICAL
PCLK YEAR DIGITS, SO CENTURY INTERPRETATION BELONGS TO DAIMOS.

PCLK INTERRUPT DELIVERY REMAINS DEFERRED.  DAIMOS POLLS THE REGISTERS ONLY
WHEN GETTIME IS REQUESTED AND DOES NOT NEED A PERIODIC PCLK INTERRUPT.

## 9. ACCEPTANCE

CLOCK ACCEPTANCE REQUIRES:

- CLEAN PDP-6 SIMH BUILD WITH PCLK ENABLED;
- CLEAN KA10/WAITS BUILD SO SHARED PCLK SOURCE CHANGES DO NOT REGRESS IT;
- PDP-6 `SHOW PCLK` REPORTING REALTIME BY DEFAULT;
- REALTIME/HISTORICAL MODE SWITCH TESTS;
- A TARGET PDP-6 READ/DECODE TEST CONFIRMING THE RETURNED TIME36 MATCHES HOST
  UTC;
- DAIMOS KCC FULL-BOOT SIZE MEASUREMENT AFTER THE RESIDENT READER IS LINKED;
- LATER, D6FS MTIME/STAT/TOUCH AND MAKE TESTS ACROSS SECOND, MINUTE, DAY, YEAR,
  2099->2100, AND THE 2125 END OF THE SUPPORTED RANGE.
