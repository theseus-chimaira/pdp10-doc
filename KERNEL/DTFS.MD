# DECTAPE FILESYSTEMS V1

STATUS: IMPLEMENTED V1 CONTRACT WITH DEFERRED OPTIMIZATION NOTES
SCOPE: DAIMOS PDP-6/KA10 V1, 32K-WORD PDP-6 BASELINE
FILESYSTEMS: DTFS WITH NATIVE/TENEX/ITS PERSONALITIES, PLUS TSFS

THIS DOCUMENT COLLECTS THE CURRENT IMPLEMENTED DAIMOS DECTAPE FILESYSTEM
CONTRACT AND EXPLICITLY DEFERRED OPTIMIZATION/FORMAT WORK. IT REPLACES
SEPARATE TAPE-FILESYSTEM NOTES. IN V1, "TAPE FILESYSTEM" MEANS DECTAPE
FILESYSTEM. MTC516 MAGTAPE MAY
CARRY A RAW DAIMOS BOOT BLOCK/BOOT STREAM, INSTALL MEDIA, BACKUPS, DOCUMENT
TRANSFER, AND TAR-LIKE SEQUENTIAL ARCHIVE STRUCTURES, BUT IT DOES NOT GET AN
ORDINARY MOUNTED FILESYSTEM.

## 1. PURPOSE

DAIMOS HAS TWO DECTAPE FILESYSTEM ENGINES:

'''TEXT
DTFS    SINGLE-DECTAPE READ/WRITE ENGINE WITH NATIVE, TENEX, AND ITS MEDIA
        PERSONALITIES
TSFS    NATIVE READ-ONLY MULTI-DECTAPE TAPESET FILESYSTEM
'''

DTFS IS THE NORMAL SINGLE-DECTAPE VFS PROVIDER.  IT AUTO-DETECTS THE ON-MEDIA
PERSONALITY AND OPERATES DIRECTLY ON THAT FORMAT.  TENEX AND ITS TAPES ARE NOT
CONVERTED TO A DAIMOS PRIVATE IMAGE WHEN MOUNTED; CREATE/WRITE/RENAME/TRUNCATE
OPERATIONS MUST PRESERVE THE SELECTED NATIVE MEDIA FORMAT.

TSFS IS THE DAIMOS TAPESET FORMAT: IT SPANS 1 TO 7 DECTAPES AND PRESENTS ONE
READ-ONLY FILESYSTEM FOR RESCUE, INSTALL, OR COMPACT DISTRIBUTION SETS.

### VFS OWNERSHIP AND MODE POLICY

DAIMOS USES NINE-BIT UID AND GID VALUES (0..0777).  DTFS DOES NOT WRITE UNIX
OWNERSHIP INTO NATIVE, TENEX, OR ITS MEDIA.  INSTEAD EACH DTFS MOUNT IS OWNED
BY THE PROCESS THAT MOUNTED IT; THE COMPACT UID9,GID9 OWNER IS KEPT ONLY IN
RUNTIME MOUNT STATE AND IS RETURNED BY STAT FOR THE MOUNT ROOT AND EVERY FILE.
A ROOT BOOT/SYSTEM MOUNT THEREFORE NATURALLY APPEARS AS 0:0.  FILE-LEVEL CHOWN
IS NOT REPRESENTABLE ON DTFS MEDIA AND REMAINS UNSUPPORTED.

NATIVE DTFS RETAINS ITS ONE EXECUTABLE PROPERTY: THE VFS MODE IS 0666 PLUS
0111 WHEN THE NATIVE EXECUTE BIT IS SET, AND CHMOD COLLAPSES THE REQUEST TO
THAT EXECUTE PROPERTY.  FOREIGN TENEX/ITS MODES ARE SYNTHETIC (0444 WHEN
READ-ONLY, 0666 WHEN WRITABLE).  NONE OF THESE POLICIES ALTER FOREIGN MEDIA.

DTFS HAS NO MEANINGFUL PER-FILE MTIME IN THE SUPPORTED MEDIA PERSONALITIES,
SO VFS STAT RETURNS MTIME 0.

## 4. BOOT AND SYSTEM ROLE

DECTAPE FILESYSTEMS ARE NOT DAIMOS BOOT MEDIA. DTFS AND TSFS
MUST NOT RESERVE OR INTERPRET A DAIMOS BOOT BLOCK OR BOOTSTREAM. THE KERNEL
NORMALLY COMES FROM DISK, PAPER TAPE CHAIN, OR RAW MAGTAPE BOOT BLOCK/BOOT
STREAM. MAGTAPE CAN ALSO CARRY INSTALL MEDIA, BACKUPS, DOCUMENT-TRANSFER
RECORDS, AND TAR-LIKE SEQUENTIAL ARCHIVES; THOSE ARE STREAM/ARCHIVE FORMATS,
NOT ORDINARY MOUNTED FILESYSTEMS.

DECTAPE FILESYSTEMS CAN STILL BE DAIMOS ROOT FILESYSTEMS. A TSFS TAPESET IS A
VALID READ-ONLY ROOT FILESYSTEM AFTER THE KERNEL AND DTC551 DRIVER ARE RESIDENT.
IN THAT MODE, BOOT LOADS KRES/KINIT FROM NON-DECTAPE MEDIA, THEN ROOT SELECTION
MOUNTS THE TSFS SET.

DESCRIPTOR REPLICAS ARE NOT A BOOT AREA. THEY ARE ONLY MOUNT RELIABILITY DATA.

## 5. CAPACITY AND TAPE COUNT

THERE IS NO TSFS DEFAULT TAPE COUNT.

THE MANIFEST/PROFILE DETERMINES THE NUMBER OF MEMBERS NEEDED, FROM 1 TO 7.
A 6-MEMBER IMAGE MAY BE A COMMON GENERATED PROFILE, BUT IT IS NOT A FILESYSTEM
RULE.

A MISSING MEMBER IS FATAL IN V1 BECAUSE THERE IS NO PARITY/RECONSTRUCTION.

## 6. DECTAPE MODEL

USE THIS MENTAL MODEL:

'''TEXT
DECTAPE = BLOCK-ADDRESSABLE SEQUENTIAL MEDIUM WITH VERY HIGH SEEK COST
'''

DO NOT TREAT IT LIKE A NORMAL DISK FOR LAYOUT. RANDOM ACCESS IS LEGAL, BUT
TSFS IMAGES SHOULD BE PLACED SO COMMON READS ARE MOSTLY SEQUENTIAL OR NEAR EACH
OTHER.

## 7. CONTROLLER PARALLELISM ASSUMPTION

FOR V1, BE CONSERVATIVE:

'''TEXT
SEVERAL DECTAPE UNITS MAY EXIST AND MAY HAVE INDEPENDENT MOTION STATE, BUT THE
CONTROLLER/DATA PATH SHOULD BE TREATED AS ONE ACTIVE TRANSFER STREAM PER
CONTROLLER.
'''

THEREFORE TSFS V1 MUST NOT DEPEND ON TRUE SIMULTANEOUS MULTI-DRIVE DATA READS.
IT MAY STILL BENEFIT FROM SPREADING HOT FILES ACROSS MEMBERS AND FROM LATER
PREPOSITIONING/READ-AHEAD POLICIES.

## 8. PLACEMENT POLICY FOR V1

DO NOT USE MANDATORY BLOCK-LEVEL ROUND-ROBIN STRIPING.

V1 PLACEMENT IS COARSE:

'''TEXT
SMALL FILE          CONTIGUOUS ON ONE MEMBER
NORMAL FILE         ONE OR MORE NORMAL EXTENTS, EACH ON ONE MEMBER
LARGE FILE          MAY HAVE SEVERAL LARGE EXTENTS ON DIFFERENT MEMBERS
METADATA            COMPACT AND EASY TO FIND
'''

ROUND-ROBIN BLOCK PLACEMENT IS DEFERRED. FUTURE LARGE-FILE STRIPING SHOULD BE
PREPARED IN THE EXTENT FORMAT BUT REJECTED BY THE V1 KERNEL.

## 9. FUTURE STRIPING PREPARATION

EXTENT RECORDS MUST INCLUDE AN EXTENT TYPE FIELD.

V1 SUPPORTS ONLY:

'''TEXT
EXT_NORMAL
'''

RESERVE:

'''TEXT
EXT_STRIPED
'''

IF A V1 KERNEL SEES 'EXT_STRIPED', IT MUST REJECT THE FILESYSTEM OR REJECT THE
FILE AS AN UNSUPPORTED TSFS FORMAT. V1 IMAGE BUILDERS MUST EMIT ONLY
'EXT_NORMAL'.

THIS LETS FUTURE 'TSPACK' SPLIT LARGE SEQUENTIAL FILES ACROSS MEMBERS WITHOUT
CHANGING THE BASIC PATHNAME/FILE LAYOUT.

## 10. MEMBER DISCOVERY

TSFS MEMBER PLACEMENT MUST BE DRIVE-INDEPENDENT. OPERATORS SHOULD NOT HAVE TO
INSERT MEMBER 0 INTO A FIXED DRIVE.

MINIT SHOULD SCAN AVAILABLE DECTAPE DRIVES:

'''TEXT
FOR EACH DECTAPE DRIVE:
    READ DESCRIPTOR REPLICAS
    VALIDATE TSFS MAGIC/CHECKSUM/VERSION
    COLLECT TAPESET_ID, GENERATION, MEMBER_COUNT, MEMBER_INDEX

CHOOSE A COMPLETE MATCHING SET:
    SAME TAPESET_ID
    SAME GENERATION
    SAME MEMBER_COUNT
    EXACTLY ONE MEMBER_INDEX IN 0..MEMBER_COUNT-1
'''

MOUNT FAILS ON:

'''TEXT
MISSING MEMBER
DUPLICATE MEMBER_INDEX
WRONG GENERATION
BAD DESCRIPTOR CHECKSUM
UNSUPPORTED FORMAT FLAGS
'''

EXTRA UNRELATED TAPES ARE IGNORED UNLESS THE OPERATOR EXPLICITLY SELECTS THEM.

THE MOUNTED INSTANCE RECORDS:

'''TEXT
TSFS MEMBER INDEX -> PHYSICAL DECTAPE DRIVE
'''

## 11. ON-TAPE STRING AND PATH RULES

USE SIXBIT PATHS AND NAMES, LIKE THE DISK FILESYSTEM.

RULES:

'''TEXT
UPPERCASE ONLY
COUNTED SIXBIT WORDS
NO C STRINGS
NO NUL TERMINATORS
NO VARIABLE IN-CORE POINTER VALUES ON TAPE
'''

EXAMPLE PATHS:

'''TEXT
/SYSTEM/EXEC/SH
/OPTION/BASE/EXEC/LS
/SYSTEM/INIT
/SYSTEM/LIB/RUNTIME
'''

THE SLASH CHARACTER IS STORED AS ITS SIXBIT CODE. PATH VALUES ARE COMPARED AS
PACKED SIXBIT WORD SEQUENCES.

## 12. PATH LOOKUP STRUCTURE

DO NOT USE LINKED LISTS FOR TSFS PATH LOOKUP. TSFS IS READ-ONLY; INSERTION COST
IS IRRELEVANT AND LINKED LISTS WASTE SEEKS.

DO NOT START WITH AN ON-TAPE TREE. IT ADDS CODE AND RECOVERY COMPLEXITY THAT
V1 DOES NOT NEED.

USE:

'''TEXT
SORTED FULL-PATH INDEX
OPTIONAL DIRECTORY RANGE TABLE
'''

LOOKUP:

'''TEXT
BINARY SEARCH COUNTED SIXBIT FULL PATH
'''

DIRECTORY LISTING:

'''TEXT
FIND DIRECTORY RANGE
SCAN IMMEDIATE CHILDREN IN SORTED INDEX
'''

THE DIRECTORY RANGE TABLE IS AN OPTIMIZATION AND SHOULD BE SMALL. IF THE FIRST
IMPLEMENTATION WANTS TO BE EVEN SMALLER, IT CAN DERIVE DIRECTORY LISTINGS BY
PREFIX SCAN AND ADD THE RANGE TABLE LATER.

## 13. MINIMAL FILE FLAGS

TSFS HAS NO BOOT AREA AND NO NORMAL MULTIUSER HIDDEN/SYSTEM VIEW. KEEP FLAGS
MINIMAL.

V1 COMPATIBLE FLAGS:

'''TEXT
TSF_DIR   SYNTHETIC DIRECTORY ENTRY, IF EXPLICIT DIRECTORIES ARE STORED
TSF_EXEC  FILE MAY BE OFFERED TO THE EXEC LOADER
'''

RESERVED OR UNSUPPORTED IN V1:

'''TEXT
TSF_COMPRESSED
TSF_BOOT
TSF_STRIPED_FILE
TSF_SPECIAL
'''

THE OLD 'SYSTEM' AND 'HIDDEN' IDEAS ARE NOT NEEDED FOR V1. THEY CAN REMAIN
RESERVED IF THE FIELD HAS SPARE BITS, BUT THE V1 CODE SHOULD NOT IMPLEMENT
POLICY AROUND THEM.

EXEC RULE:

'''TEXT
TSF_EXEC PERMITS AN EXEC-LOADER ATTEMPT.
THE LOADER MUST STILL VALIDATE THE ACTUAL EXECUTABLE FORMAT.
'''

## 14. DESCRIPTOR CONCEPT

USE A MINIMAL MEMBER DESCRIPTOR, SIMILAR IN SPIRIT TO BLOCKSET/MEDIA
DESCRIPTORS, BUT MUCH SMALLER THAN THE DISK BOOT DESCRIPTOR. IT ONLY IDENTIFIES
THE TAPESET AND POINTS TO THE TABLE DIRECTORY.

DESCRIPTOR REPLICAS SHOULD LIVE AT FIXED BLOCKS ON EVERY MEMBER, FOR EXAMPLE:

'''TEXT
BLOCK 0      PRIMARY DESCRIPTOR
BLOCK 1      BACKUP DESCRIPTOR
LAST BLOCK   OPTIONAL FINAL BACKUP DESCRIPTOR
'''

EXACT REPLICA POSITIONS CAN BE FINALIZED IN THE HEADER, BUT V1 SHOULD USE AT
LEAST TWO DESCRIPTOR COPIES PER MEMBER.

ITS DESCRIPTOR CARRIES THESE FIELDS:

'''TEXT

FORMAT_MAJOR
FORMAT_MINOR
FLAGS
TAPESET_ID_HI
TAPESET_ID_LO
GENERATION
MEMBER_COUNT
MEMBER_INDEX
BLOCK_COUNT

NOTES:

'''TEXT

## 16. TABLE DIRECTORY

THE TABLE DIRECTORY IS THE METADATA ROOT. IT TELLS THE KERNEL WHERE ALL OTHER
STATIC TABLES LIVE.

THE TABLE DIRECTORY SHOULD CONTAIN RECORDS FOR:

'''TEXT
NAME INDEX
SIXBIT PATH POOL
FILE TABLE
EXTENT TABLE
DIRECTORY RANGE TABLE, OPTIONAL
CHECKSUM TABLE OR EXTENT CHECKSUMS
RESERVED FUTURE TABLES
'''

A TABLE DIRECTORY ENTRY SHOULD INCLUDE AT LEAST:

'''TEXT
TABLE_ID
FLAGS
MEMBER_INDEX
START_BLOCK
BLOCK_COUNT
RECORD_WORDS
RECORD_COUNT
CHECKSUM
'''

V1 CAN KEEP ALL MANDATORY METADATA TABLES UNCOMPRESSED AND UNSTRIPED.

## 17. FILE TABLE

TSFS V1.1 KEEPS THE IMPLEMENTED EIGHT-WORD FILE RECORD.  THIS IS DELIBERATE:
EIGHT WORDS GIVE EXACTLY 16 RECORDS PER 0200-WORD DECTAPE BLOCK, SO THE PDP-6
RUNTIME CAN INDEX RECORDS WITH SHIFTS/MASKS INSTEAD OF DIVISION.

THE LOW HALF OF PARENT_FLAGS CARRIES TYPE PLUS MODE: TYPE USES THE LOW TWO
BITS, BITS 2..5 ARE RESERVED ZERO, AND MODE12 OCCUPIES BITS 6..17.  OWNERSHIP
IS ONE COMPACT UID9,GID9 HALFWORD.  DIRECTORY SIZE IS OTHERWISE UNUSED, SO A
DIRECTORY STORES OWNER THERE; REGULAR-FILE AUX IS OTHERWISE UNUSED, SO A
REGULAR FILE STORES OWNER THERE.  DIRECTORY AUX RETAINS FIRST_CHILD,CHILD_COUNT.
THUS PER-FILE MODE/OWNER COSTS NO NINTH RECORD WORD.

MKTSFS MANIFEST ENTRIES MAY SUPPLY THESE IMMUTABLE ATTRIBUTES:

'''TEXT
D /PATH [MODE UID GID]
F /PATH HOST-SOURCE [MODE UID GID]
'''

MODE IS OCTAL; UID/GID ARE DECIMAL 0..511.  OMITTED ATTRIBUTES DEFAULT TO
0555 0 0 FOR DIRECTORIES AND 0444 0 0 FOR REGULAR FILES.  TSFS DOES NOT STORE
PER-FILE MTIME; STAT RETURNS MTIME 0.

'PATH_INDEX' REFERS TO THE SORTED PATH/NAME INDEX ENTRY. THE ACTUAL PATHNAME IS
STORED IN THE SIXBIT PATH POOL.

IF DIRECTORIES ARE EXPLICIT, DIRECTORY RECORDS USE 'TSF_DIR' AND HAVE ZERO
SIZE AND ZERO EXTENTS.

## 18. EXTENT TABLE

A NORMAL V1 EXTENT SHOULD BE ONE CONTIGUOUS RANGE ON ONE MEMBER.

SUGGESTED LOGICAL FIELDS:

'''TEXT
EXTENT_TYPE
FLAGS
FILE_BLOCK_START
FILE_BLOCK_COUNT
MEMBER_INDEX
PHYSICAL_BLOCK
PHYSICAL_COUNT
EXTENT_CHECKSUM
RESERVED
'''

V1 RULES:

'''TEXT
EXTENT_TYPE MUST BE EXT_NORMAL
MEMBER_INDEX MUST BE VALID
PHYSICAL_COUNT MUST MATCH OR COVER FILE_BLOCK_COUNT
RESERVED STRIPING FIELDS MUST BE ZERO
'''

FUTURE STRIPING CAN ADD STRIPE GROUP, CHUNK SIZE, MEMBER MASK, OR AN INDIRECT
STRIPE DESCRIPTOR THROUGH RESERVED FIELDS OR A NEW TABLE TYPE.

## 19. CHECKSUMS

CHECKSUMS ARE MANDATORY FOR TSFS BECAUSE TAPE MEDIA AND DESCRIPTOR MISMATCH
ERRORS MUST BE CAUGHT EARLY.

V1 MUST CHECKSUM:

'''TEXT
MEMBER DESCRIPTORS
TABLE DIRECTORY
METADATA TABLE PAGES
FILE/EXTENT DATA AS DESCRIBED BY EXTENT CHECKSUMS
'''

THE CHECKSUM IS FOR CORRUPTION DETECTION, NOT SECURITY.

RECOMMENDED ALGORITHM FOR FIRST IMPLEMENTATION:

'''TEXT
36-BIT ROTATING ADD/XOR CHECKSUM OVER 36-BIT WORDS
'''

THE EXACT FUNCTION IS SHARED BY THE IMAGE TOOLS AND TRANSIENT METADATA
VALIDATOR.  MEMBER DESCRIPTORS, TABLE DIRECTORY, AND METADATA TABLE PAGES ARE
CHECKED BEFORE THE KERNEL ACCEPTS THE MOUNT HANDOFF.  EXTENT-DATA CHECKSUMS ARE
AUTHORITATIVE OFFLINE-INTEGRITY DATA AND `TSFSCHECK` VALIDATES THEM OVER THE
FULL PHYSICAL EXTENT.  V1 DOES NOT FORCE THE RESIDENT READER TO REREAD AN
ENTIRE TWO-BLOCK STORED RESTART FOR EVERY PARTIAL READ JUST TO RECOMPUTE THAT
WHOLE-EXTENT CHECKSUM; D6LZ STREAM STRUCTURE/LENGTH IS STILL CHECKED during
DECODE.  A FUTURE PER-BLOCK RUNTIME DATA CHECKSUM FORMAT REQUIRES A FORMAT
REVISION RATHER THAN ADDING HIDDEN READ AMPLIFICATION TO V1.

THE CHECKSUM FUNCTION MUST REMAIN SMALL, DETERMINISTIC, AND ENDIAN-INDEPENDENT
AT THE IMAGE LEVEL.

A PRACTICAL RULE:

'''TEXT
CHECKSUM FIELD IS TREATED AS ZERO WHILE CALCULATING ITS CONTAINING OBJECT
'''

XOR/PARITY IS DEFERRED. RESERVE AN INCOMPATIBLE FEATURE FLAG:

'''TEXT
TSFS_F_PARITY
'''

IF SET, V1 REFUSES TO MOUNT.

## 20. COMPRESSION

TSFS REGULAR-FILE PAYLOAD DATA IS COMPRESSED WITH D6LZ36 BY DEFAULT IN NEW
IMAGES.  THIS IS A FILE/EXTENT REPRESENTATION, NOT A TRANSPARENT COMPRESSED
DECTAPE BLOCK DEVICE.

KEEP MEMBER DESCRIPTORS, TABLE DIRECTORY, FILE TABLE, EXTENT TABLE, AND OTHER
MOUNT/PATH METADATA DIRECT AND UNCOMPRESSED.  THIS LETS MEMBER DISCOVERY,
CHECKSUM VALIDATION, LOOKUP, READDIR, AND STAT OPERATE WITHOUT FIRST DECODING A
STREAM AND KEEPS CORRUPTION LOCALITY SIMPLE.

MKTSFS AND TSPACK COMPRESS REGULAR-FILE PAYLOADS OFFLINE.  TSFSCHECK MUST
VALIDATE BOTH STORED EXTENT BOUNDS AND THE D6LZ36 STREAM/EXPECTED LOGICAL WORD
COUNT.  THE FORMAT MUST RECORD ENOUGH PER-FILE/PER-EXTENT INFORMATION TO MAP
LOGICAL FILE OFFSETS TO COMPRESSED EXTENTS WITHOUT SCANNING UNRELATED FILES.

THE KERNEL READ PATH REUSES THE RESIDENT D6LZ36 DECODER.  DECOMPRESSION IS
BOUNDED AND STREAMING: NO WHOLE-FILE INFLATION, NO PER-MOUNT HISTORY COPY, AND
NO SECOND RESIDENT D6LZ IMPLEMENTATION.  RANDOM SEEK MAY RESTART AT A COMPRESSED
EXTENT BOUNDARY; TSPACK SHOULD KEEP RESTARTABLE EXTENTS SMALL ENOUGH FOR
ACCEPTABLE DECTAPE LATENCY WHILE STILL OBTAINING USEFUL COMPRESSION.
MULTI-EXTENT AND CROSS-MEMBER FILES MOVE TO THE NEXT VALIDATED COMPRESSED EXTENT
AND RESTART THE DECODER THERE.

EVERY REGULAR-FILE EXTENT IS EXPLICITLY ENCODED.  `D6LZ` IS USED WHEN IT
REDUCES PHYSICAL DECTAPE BLOCK OCCUPANCY; `STORED` IS THE INCOMPRESSIBLE ESCAPE
REPRESENTATION AND IS NOT A SECOND RAW-FILE ARCHITECTURE.  V1 USES FIXED
0400-WORD RESTART EXTENTS (THE FINAL EXTENT MAY BE SHORTER).  THIS MAKES RANDOM
ACCESS DIRECT: THE RESTART INDEX IS `FILE_WORD_OFFSET / 0400`.

DO NOT IMPLEMENT A TRANSPARENT COMPRESSED DECTAPE BLOCK LAYER FOR TSFS.

## 21. BUFFER AND CACHE POLICY

THE 32K-WORD PDP-6 BASELINE IS AUTHORITATIVE.  THE CURRENT IMPLEMENTATION USES
ONE SHARED 128-WORD FULL-BLOCK WORKSPACE FOR DTFS, D6FS, AND OTHER SERIALIZED
BLOCK-FILESYSTEM OPERATIONS.  THE PLANNED BSTORE/BCACHE CONSOLIDATION IN
`KERNEL/BSTORE.MD` ADDS ONE COMMON CLEAN TWO-BLOCK RAM L1 FOR D6FS AND
DTFS/TSFS WITHOUT A PER-MOUNT PRIVATE DATA CACHE.  DTFS MUST USE THE SMALLEST
COMMON SCRATCH/BUFFER INTERFACE THAT RESULTS RATHER THAN REINTRODUCING A
PERMANENT PRIVATE BLOCK ARRAY.

DTFS PERSONALITIES DO NOT OWN SEPARATE DIRECTORY/DATA BUFFERS.  THEY SHARE THE
COMMON WORKSPACE AND RETAIN ONLY COMPACT PERSONALITY/ALLOCATION STATE THAT
MEASURABLY REDUCES REREADS.

TSFS MUST ALSO START FROM THIS MINIMAL RAM MODEL.  ADDITIONAL METADATA OR
READ-AHEAD BLOCKS ARE OPTIONAL PERFORMANCE FEATURES AND MAY BE ADDED ONLY WHEN
MEASUREMENT DEMONSTRATES THAT THE SPEEDUP JUSTIFIES EACH EXTRA 128-WORD BLOCK.
THE OLD SEVEN-BUFFER/896-WORD DEFAULT IS DELETED.

WHEN AUXSTORE CACHESTORE EXISTS, DTFS/TSFS MAY ALSO USE THE COMMON BCACHE L2.
THE L2 IS DIRECT-MAPPED, CLEAN/DISCARDABLE, AND INTENDED PRIMARILY TO TURN
REPEATED DECTAPE SEEKS INTO DRUM/DISK BLOCK ACCESSES.  IT MUST NOT ALLOCATE A
RESIDENT TAG TABLE OR SHARE PHYSICAL SLOTS WITH AUTHORITATIVE BACKSTORE.

BUFFER OWNERSHIP/INVALIDATION MUST MAKE CROSS-FILESYSTEM REUSE SAFE.  DO NOT
START WITH ONE DATA BUFFER PER MOUNTED TAPE OR MEMBER.

## 22. READ SCHEDULING POLICY

V1 SCHEDULER SHOULD STAY SIMPLE:

'''TEXT
MERGE ADJACENT READS ON THE SAME MEMBER
PREFER CONTINUING A SEQUENTIAL RUN
USE METADATA CACHE BEFORE REREADING TABLES
AVOID COMPLEX ONLINE OPTIMIZATION
'''

DO NOT IMPLEMENT PROFILE-BASED OR TRACE-BASED SCHEDULING IN THE KERNEL.
IMAGE PLACEMENT BELONGS TO 'MKTSFS' FIRST AND LATER TO 'TSPACK'.

## 23. INITIAL IMAGE BUILDER

THE FIRST IMPLEMENTATION DOES NOT REQUIRE 'TSPACK'.

IMPLEMENT 'MKTSFS' FIRST. IT CAN BE A HOST/USERLAND TOOL THAT:

'''TEXT
READS A MANIFEST
PACKS UPPERCASE SIXBIT PATHS
CHOOSES MEMBER COUNT FROM MANIFEST/IMAGE SIZE
PLACES FILES SEQUENTIALLY AS NORMAL EXTENTS
CREATES EXPLICIT DIRECTORY ENTRIES IF NEEDED
BUILDS THE SORTED PATH INDEX
BUILDS FILE AND EXTENT TABLES
BUILDS THE TABLE DIRECTORY
WRITES DESCRIPTOR REPLICAS
WRITES MEMBER IMAGES
CALCULATES CHECKSUMS
'''

NO V1 'MKTSFS' REQUIREMENTS:

'''TEXT
NO TRACE LEARNING
NO ACCESS PROFILE OPTIMIZER
NO COMPRESSION
NO FILE STRIPING
NO PARITY
NO BOOT AREA
'''

'TSPACK' IS DEFERRED. LATER IT MAY ADD OPTIMIZED PLACEMENT, PROFILE SELECTION,
LARGE-FILE STRIPING, COMPRESSION DECISIONS, AND EMULATOR-TRACE-GUIDED LAYOUT.

## 24. EXTERNAL TRACE OPTIMIZER IS DEFERRED

BECAUSE DAIMOS IS EMULATOR-FOCUSED, EXTERNAL DECTAPE ACCESS TRACING COULD BE A
POWERFUL LATER OPTIMIZATION. IT IS NOT REQUIRED FOR THE FILESYSTEM
IMPLEMENTATION.

DEFERRED FUTURE FLOW:

'''TEXT
EMULATOR RECORDS DECTAPE BLOCK ACCESSES
HOST TOOL DECODES ACCESSES AGAINST TSFS MAPS
TSPACK BUILDS BETTER USAGE PROFILES AND MEMBER IMAGES
'''

DO NOT ADD KERNEL TRACING FOR V1 TSFS.

## 25. RUNTIME MOUNT BEHAVIOR

TSFS MINIT OR FILESYSTEM MOUNT CODE SHOULD:

'''TEXT
SCAN DECTAPE DRIVES
READ DESCRIPTOR REPLICAS
VALIDATE DESCRIPTORS
ASSEMBLE A COMPLETE TAPESET
READ AND VALIDATE TABLE DIRECTORY
READ SMALL RESIDENT TABLE INDEXES
REGISTER A READ-ONLY FILESYSTEM INSTANCE
'''

AFTER MOUNT, ORDINARY FILE READS PERFORM:

'''TEXT
PATH LOOKUP IN SORTED SIXBIT PATH INDEX
FILE RECORD LOOKUP
EXTENT LOOKUP
MEMBER/PHYSICAL BLOCK READ
CHECKSUM VERIFICATION AS REQUIRED
RETURN DATA
'''

ALL WRITES MUST FAIL WITH A READ-ONLY ERROR.

## 26. ERROR BEHAVIOR

MOUNT SHOULD FAIL ON:

'''TEXT
NO COMPLETE MATCHING MEMBER SET
BAD DESCRIPTOR CHECKSUM
BAD TABLE DIRECTORY CHECKSUM
UNSUPPORTED INCOMPATIBLE FEATURE FLAG
MISSING REQUIRED TABLE
BAD MEMBER_COUNT OR MEMBER_INDEX
'''

OPEN/READ SHOULD FAIL ON:

'''TEXT
PATH NOT FOUND
UNSUPPORTED FILE/EXTENT FLAG
BAD EXTENT CHECKSUM
OUT-OF-RANGE MEMBER OR BLOCK
UNDERLYING DECTAPE READ ERROR
'''

SINCE THERE IS NO PARITY, TSFS CANNOT RECONSTRUCT MISSING DATA IN V1.

## 27. DTFS MEDIA PERSONALITIES

TSFS IS A SEPARATE READ-ONLY SYSTEM/RESCUE FORMAT.  DTFS IS THE SINGLE-DECTAPE
READ/WRITE ENGINE AND HAS THREE V1 MEDIA PERSONALITIES:

'''TEXT
DAIMOS NATIVE
TENEX
ITS
'''

THE COMMON DTFS LAYER OWNS VFS OPERATIONS, DTC BLOCK I/O, THE SHARED FULL-BLOCK
WORKSPACE, BOUNDS CHECKING, AND GENERIC COPY/WORD OPERATIONS.  A PERSONALITY
CONTAINS ONLY FORMAT-SPECIFIC WORK SUCH AS:

'''TEXT

DIRECTORY LOCATION/LAYOUT
NAME ENCODE/DECODE
ALLOCATION-MAP INTERPRETATION
FILE BLOCK ORDER/CHAIN RULES
SIZE/TAIL METADATA
FORMAT-SPECIFIC MUTATION RULES
'''

TENEX AND DAIMOS NATIVE SHARE THE 128-WORD BLOCK AND CHAINED-DATA-BLOCK
STRUCTURE WHERE THEIR MEDIA RULES MATCH; THAT FUNCTIONALITY MUST NOT BE
DUPLICATED IN TWO FILESYSTEM IMPLEMENTATIONS.  ITS USES ITS OWN DIRECTORY AND
ALLOCATION-MAP INTERPRETATION WHILE REUSING THE SAME DTFS/VFS/DTC MACHINERY.

MOUNTING A TENEX OR ITS TAPE NEVER CONVERTS IT TO DAIMOS NATIVE DTFS.  WRITES
UPDATE THE FOREIGN FORMAT DIRECTLY.

DO NOT NORMALIZE FOREIGN METADATA BY STORING LARGE STRINGS OR POLICY TABLES IN
KRES.  KEEP KRES NUMERIC/PACKED; USERLAND MAY PRESENT HUMAN-READABLE DETAILS.

## 31. FINAL V1 SUMMARY

V1 DECTAPE FILESYSTEM WORK STARTS WITH DTFS READ SUPPORT, THEN DTFS WRITE
SUPPORT, THEN TSFS. TSFS IS A SMALL, READ-ONLY, IMAGE-BUILT, MULTI-DECTAPE
FILESYSTEM. IT USES NATIVE DECTAPE BLOCKS, COUNTED UPPERCASE SIXBIT PATHS,
STATIC TABLES, MANDATORY CHECKSUMS, DRIVE SCANNING, AND SIMPLE NORMAL EXTENTS.
IT DOES NOT IMPLEMENT WRITES, COMPRESSION, PARITY, BOOT AREAS, ONLINE REPAIR,
ONLINE OPTIMIZATION, OR FILE STRIPING. TENEX AND ITS ARE DTFS READ/WRITE MEDIA PERSONALITIES USING THE SAME COMMON ENGINE. NO ORDINARY MTC516 MAGTAPE FILESYSTEM IS
PLANNED; MAGTAPE REMAINS SEQUENTIAL BOOT/INSTALL/BACKUP/TRANSFER/ARCHIVE MEDIA.


## CURRENT TSFS V1.1 IMPLEMENTATION STATE (2026-10-01)

TSFS V1.1 READ SUPPORT IS COMPLETE.  THE TWO-REPLICA MEMBER DESCRIPTOR,
CHECKSUMMED TABLE DIRECTORY, 8-WORD FILE RECORDS, AND 4-WORD EXTENT RECORDS
REMAIN DIRECT/UNCOMPRESSED.  V1.1 ADDS IMMUTABLE MODE12 AND UID9,GID9 WITHOUT
GROWING THE EIGHT-WORD RECORD; MKTSFS MANIFESTS SUPPLY THE ATTRIBUTES AND
TSFSCHECK VALIDATES THE SAME FORMAT.  THE MINOR-VERSION BUMP PREVENTS V1.0
IMAGES FROM BEING SILENTLY INTERPRETED WITH ZERO MODES.
THE TRANSIENT MOUNT.TSFS HELPER SCANS MEMBERS THROUGH THE BOUNDED READ-ONLY
DTC BLOCK ABI, RECONCILES REPLICAS, VALIDATES SET ID/GENERATION/TABLES AND THE
CANONICAL FIXED-RESTART FILE/EXTENT GEOMETRY, THEN PASSES ONLY COMPACT
TABLE-LOCATOR/MEMBER-MAP STATE TO THE KERNEL.  SCANNER/CHECKSUM WORKSPACE IS
NOT RESIDENT.

REGULAR FILES MAY SPAN MULTIPLE EXTENTS AND LOGICAL DECTAPE MEMBERS.  PAYLOAD
EXTENTS HAVE A FIXED 0400-WORD RESTART GEOMETRY; THE FINAL EXTENT MAY BE
SHORTER.  THE KERNEL COMPUTES THE RESTART RECORD DIRECTLY FROM THE FILE OFFSET
INSTEAD OF WALKING EXTENTS.  EVERY EXTENT IS EXPLICITLY `D6LZ` OR `STORED`.
MKTSFS CHOOSES D6LZ ONLY WHEN HEADER+STREAM REDUCES PHYSICAL BLOCK OCCUPANCY;
OTHERWISE IT EMITS STORED.  TSFSCHECK VALIDATES PHYSICAL BOUNDS/OVERLAP, EXTENT
CHECKSUMS, RESTART GEOMETRY, PADDING, AND EXACT D6LZ DECODE LENGTH.

THE RESIDENT D6LZ PATH READS THE ONE-BLOCK COMPRESSED RESTART INTO THE EXISTING
128-WORD FILESYSTEM WORKSPACE, BORROWS AT MOST 0400 WORDS FROM MANAGED CORE FOR
THE DECODED RESTART, AND PASSES THE ALREADY-RESIDENT COMPRESSED BUFFER TO THE
COMMON D6LZ RUNTIME ADAPTER'S DIRECT-BUFFER ENTRY.  THAT ENTRY SHARES DECODER
AC SAVE/RESTORE, STATE INITIALIZATION, EXACT-CONSUMPTION CHECKS, AND ERROR
NORMALIZATION WITH THE COMPRESSED-EXEC VFS FRONTEND, BUT DOES NOT PERFORM VFS
REFILLS OR COPY THE COMPRESSED SOURCE.  BOTH FRONTENDS CALL THE EXISTING FIXED
LOW-CORE D6LZ36 TOKEN ENGINE.  TSFS THEN COPIES THE REQUESTED SLICE AND
IMMEDIATELY FREES THE BORROWED BUFFER.  THERE IS NO WHOLE-FILE INFLATION,
PER-MOUNT DECODE BUFFER, OR SECOND RESIDENT DECODER.

VALIDATION COVERS HOST MIXED D6LZ/STORED MULTI-MEMBER IMAGES, TRANSIENT SCANNER
HANDOFF/GEOMETRY, PDP-6 CROSS-EXTENT/CROSS-MEMBER READS, PDP-6 D6LZ ALLOCATION/
FREE INTEGRATION, HOST-BUILT V1.1 ATTRIBUTE-BEARING MEDIA, AND THE PRODUCTION
TYPE-551 DTC DRIVER.  CURRENT GLOBAL RESIDENT-SIZE FIGURES ARE MAINTAINED IN
DAIMOS `PROJECT-STATE.MD`; THIS FORMAT DOCUMENT DOES NOT DUPLICATE A STALE
KERNEL-WIDE SIZE SNAPSHOT.
