# v1365: real PDP-6 Stage-1 grouped KINIT media boot acceptance

Date: 2026-11-08. Status: verified **test-only** media boot to KINIT
entry. Production boot images and runtime D6LZ36 are unchanged.

The staged grouped format is now tested with a real linked KINIT
image generated by `system/boot/pdp6/image/mkimage.sh`, including
its initialized KCORE load slot. The independent host grouped
reference compresses all 32,670 decoded 36-bit KINIT words into
29,023 grouped words, reconstructs the complete original stream,
and writes a separate test-only three-word DAIMON-framed image.

The KINIT entry is octal 053524, decoded end is 0127636,
and compressed staging end is 0220375. These extents are within
the 256K core profile, with `0400` words of KINIT stack reserve.

Five actual native PDP-6 Stage-0/Stage-1 tests use the real
controller paths, not merely extracted assembler call sites:

| Stage-1 | Image source and virtual controller | Result |
|---|---|---|
| DSK | Four-member DBOOT, DSK270 | PASS |
| DRM | Four-member DBOOT, Type-236 drum | PASS |
| DTC | Real DECtape image via Type-136 | PASS |
| MTC | Seven-track magnetic tape via Type-516 | PASS |
| PTR | Two Type-760 paper tapes, operator `TAPE2` change | PASS |

Every staged Stage-1 is a proper read-in paper tape loaded by the
existing Stage-0 bootstrap at 000060. Each embeds the direct-linked
grouped complete-buffer v053 decoder and the v1364 pre-write
physical-memory geometry guard. All five simulator runs reach the
expected KINIT breakpoint at 053524, and the first decoded word
at 030000 agrees with the linked KINIT image.

Two additional Type-136 failure-media cases are accepted:

- A deliberately oversized decoded-image header is refused by
  the pre-write physical-memory check.
- A malformed grouped control word with zero tokens is refused by
  the native decoder after the compressed stream has been read.

Both halt instead of transferring to KINIT and show unmodified
memory at physical 030000. The host generator also refuses invalid
32K and insufficient-stack configurations without publishing an
output file. All these tests use isolated, versioned files under
`$TMPDIR`, never modifying production disks or source formats.

This result **does not imply a fully booted grouped-format DAIMOS**.
Each successful test stops at KINIT entry. The installed KCORE,
runtime VFS, EXEC, PURE, swap and TSFS consumers still use D6LZ36
and must be migrated with host producers, all Stage-1 images,
filesystem media and failure handling in a single format cutover.
Next validation should verify more reconstructed KINIT words,
truncated or damaged media on every controller, KINIT runtime
behavior, and the resource costs of the resident grouped decoder.
