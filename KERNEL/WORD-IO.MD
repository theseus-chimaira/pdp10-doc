# DAIMOS WORD I/O AND TOKEN ADAPTERS

## 1. CORE RULE

DAIMOS TRANSPORTS NATIVE 36-BIT WORDS.  REGULAR FILES, PIPES, FIFOS, AND THE
GENERIC READ_WORDS/WRITE_WORDS ABI DO NOT DEFINE CHARACTER, BYTE, RECORD, OR
DEVICE-TOKEN SEMANTICS.  INTERPRETATION BELONGS TO THE FORMAT OR DEVICE WHICH
ACTUALLY NEEDS IT.

THIS RULE KEEPS THE PDP-6/PDP-10 NATURAL WORD SIZE ON THE HOT PATH, REMOVES
ENCODING WORK FROM IPC, AND LETS SIMPLE FORWARDERS COPY WORDS WITHOUT DECODE
AND RE-ENCODE.

## 2. FIXED-WIDTH TOKEN CONTRACT

`SYSTEM/KERNEL/CORE/WORDTOKEN.H` DEFINES THE COMMON MSB-FIRST LAYOUT.  THE
CONTRACT HAS FOUR SPECIALIZED WIDTHS ONLY:

| WIDTH | TOKENS/WORD | PADDING | PRIMARY USE |
| --- | ---: | ---: | --- |
| 6 BIT | 6 | 0 | SIXBIT/S6REC |
| 7 BIT | 5 | 1 LOW BIT | TERMINAL/HARDWARE CHARACTER GROUPS |
| 8 BIT | 4 | 4 LOW BITS | PAPER TAPE |
| 12 BIT | 3 | 0 | CARD COLUMNS |

THERE IS DELIBERATELY NO RUNTIME-SELECTABLE ARBITRARY-WIDTH CODEC.  THE C
HELPERS ARE STATIC INLINE; HANDWRITTEN ASSEMBLER MAY IMPLEMENT THE SAME LAYOUT
DIRECTLY WITH FIXED SHIFTS OR BYTE POINTERS.  COMMONALITY IS IN THE FORMAT AND
TEST VECTORS, NOT IN A REQUIRED RESIDENT CALL PATH.

A PARTIALLY FILLED WORD IS LEFT ALIGNED AND UNUSED TOKEN SLOTS/PADDING ARE ZERO
UNLESS A FORMAT BELOW EXPLICITLY USES PADDING FOR FRAMING.

## 3. FRAMING OWNERSHIP

TOKEN PACKING AND RECORD FRAMING ARE SEPARATE.

- S6REC OWNS SIXBIT TEXT TYPE AND CHARACTER COUNT.
- THE TTY LINE DISCIPLINE OWNS CANONICAL/RAW INPUT, EDITING, SIGNALS, AND EOF.
- PAPER TAPE OWNS THE EXACT BYTE COUNT OF ITS FINAL PARTIAL WORD.
- CARD I/O OWNS THE FIXED 80-COLUMN PHYSICAL RECORD.
- PIPES OWN NONE OF THESE.

THIS AVOIDS A GENERIC STREAM STATE MACHINE IN KCORE AND PREVENTS DEVICE-SPECIFIC
POLICY FROM LEAKING INTO IPC.

## 4. PIPES AND FIFOS

AN ANONYMOUS PIPE AND A FILESYSTEM-NAMED FIFO ARE THE SAME NATIVE-WORD QUEUE.
THE LIVE OBJECT IS 14 WORDS:

    WORD 0      ACTIVE-NAMED-FIFO LINK
    WORD 1      BACKING FIFO VNODE, ZERO FOR ANONYMOUS PIPE
    WORD 2      HEAD,,COUNT
    WORD 3      READER-REFS,,WRITER-REFS
    WORD 4      READER EVENT
    WORD 5      WRITER EVENT
    WORDS 6-15  EIGHT OPAQUE 36-BIT PAYLOAD WORDS

READ_WORDS AND WRITE_WORDS RETURN AS MUCH AS IS IMMEDIATELY AVAILABLE/FREE AND
MAY RETURN A SHORT POSITIVE COUNT.  THEY SLEEP ONLY WHEN ZERO PROGRESS IS
POSSIBLE.  EOF AND EPIPE FOLLOW THE EXISTING READER/WRITER REFERENCE MODEL.
MULTIWORD APPLICATION RECORDS ARE NOT MADE ATOMIC BY THE PIPE LAYER.

USERSPACE WHICH REQUIRES COMPLETE OUTPUT MUST LOOP OVER SHORT WRITES.  THE
COMMON `u_write_words_all()` HELPER PROVIDES THIS POLICY WITH A FULL-WRITE FAST
PATH.

## 5. SIXBIT/S6REC TEXT AND TERMINALS

NORMAL DAIMOS TEXT IS S6REC/SIXBIT.  A TEXT PIPE THEREFORE CARRIES THE SAME
S6REC WORDS AS A TEXT FILE; IPC DOES NOT TRANSCODE THEM.

TTY HARDWARE REMAINS CHARACTER-ORIENTED INTERNALLY.  CTY, DCS, AND GE KEEP
THEIR EXISTING CHARACTER DRIVERS AND THE PROCESS LAYER KEEPS THE EXISTING
CANONICAL EDITOR/JOB-CONTROL POLICY.

TTY WORD I/O IS THE FORMAT BOUNDARY:

- WRITE_WORDS ACCEPTS EXACTLY ONE COMPLETE S6REC TEXT RECORD AND THE TTY MRES
  UNPACKS SIXBIT WITH A BYTE POINTER, RESOLVING THE CONTROLLING TTY ONCE PER
  CALL BEFORE THE CHARACTER LOOP.
- COOKED READ_WORDS RETURNS ONE COMPLETE S6REC TEXT RECORD FROM THE EXISTING
  CANONICAL LINE BUFFER.
- RAW READCHAR/WRITECHAR REMAINS THE LOSSLESS 7-BIT CHARACTER INTERFACE.
- RAW READ_WORDS IS REJECTED RATHER THAN GUESSING AN ENCODING.

THE TTY ADAPTER LIVES IN THE TTY MRES, NOT KCORE AND NOT EACH PHYSICAL TERMINAL
DRIVER.

## 6. PAPER TAPE: PT8

PTR/PTP USE WORDTOKEN8.  A FULL WORD HOLDS FOUR BYTES IN BITS 35..4 AND HAS A
ZERO LOW NIBBLE.  A FINAL PARTIAL WORD STORES ONE, TWO, OR THREE VALID BYTES IN
THE SAME LEFT-ALIGNED SLOTS AND STORES THAT COUNT IN THE LOW NIBBLE.  LOW-NIBBLE
VALUES 4..15 ARE INVALID.

PTR BULK READ OWNS THE PHYSICAL READER FOR THE CALL, STARTS IT ONCE, AND
CONSUMES SUCCESSIVE DONE/DATAI BYTES.  THIS MATCHES THE PDP-6 STAGE1 TRANSPORT
AND AVOIDS THE INCORRECT/SLOWER RESTART-PER-BYTE MODEL.  PTP DECODES THE WORDS
DIRECTLY TO PHYSICAL BYTES.  BOTH ADAPTERS LIVE WITH THEIR OPTIONAL MRES
PACKAGES AND ADD NO BSS.

## 7. CARDS: CARD12

CR/CP USE WORDTOKEN12.  ONE PHYSICAL 80-COLUMN CARD IS EXACTLY 27 WORDS:
26 FULL THREE-COLUMN WORDS PLUS A FINAL WORD CONTAINING COLUMNS 78 AND 79; THE
UNUSED THIRD 12-BIT SLOT MUST BE ZERO.

THE BULK ADAPTERS PACK/UNPACK DIRECTLY WHILE THE HARDWARE RUNS.  THEY DO NOT
ALLOCATE OR EXPAND TO AN 80-WORD TEMPORARY BUFFER.  THE FIXED RECORD SIZE ALSO
MEANS NO ADDITIONAL LENGTH TAG IS REQUIRED.

## 8. LINE PRINTER

LPT WORD OUTPUT ACCEPTS ONE COMPLETE S6REC TEXT RECORD.  THE LP10 DATAO FORMAT
CAN CARRY FIVE SEVEN-BIT CHARACTERS, SO THE ADAPTER CONVERTS SIXBIT AND PACKS
UP TO FIVE CHARACTERS PER HARDWARE TRANSFER.  RAW WRITECHAR REMAINS AVAILABLE
FOR SINGLE-CHARACTER DEVICE USE.

THE ENLARGED LPT DRIVER IS AN OPTIONAL MRES.  SYSTEMS WITHOUT LPT DO NOT KEEP
ITS TEXT RESIDENT; KCORE RETAINS ONLY PATCHED SERVICE JUMPS.

## 9. PERFORMANCE AND SIZE POLICY

THE ORDER OF OPTIMIZATION FOR THIS I/O LAYER IS:

1. MINIMIZE INSTRUCTIONS AND HARDWARE WAITS PER TRANSPORTED WORD/TOKEN.
2. AVOID SCHEDULER WAKEUPS WHEN A BULK TRANSFER CAN MAKE PROGRESS.
3. KEEP KCORE SMALL; DEVICE-SPECIFIC DECODERS BELONG IN OPTIONAL MRES PACKAGES.
4. KEEP PER-STREAM RAM SMALL AND BOUNDED.
5. SHARE SEMANTICS/TESTS RATHER THAN FORCE HOT PATHS THROUGH A GENERIC CODEC.

THE FIRST WORD-FIFO CHECKPOINT REDUCED THE FIXED-BASE KCORE MEASUREMENT FROM
9728 TO 9722 WORDS AND REDUCED EACH LIVE PIPE FROM 32 TO 14 WORDS.  DEVICE
ADAPTER COST IS ACCOUNTED TO THE CORRESPONDING MRES.  FULL-KERNEL SIZE MUST BE
MEASURED ONLY AGAINST A STABLE INTEGRATION TREE; CONCURRENT UNRELATED RESIDENT
WORK IS NOT A VALID BEFORE/AFTER MEASUREMENT FOR THIS REDESIGN.

## 10. VALIDATION

THE CURRENT TEST SET COVERS:

- 6/7/8/12-BIT TOKEN BOUNDARIES, PADDING, AND PARTIAL GROUPS ON PDP-6;
- WORD-FIFO WRAP, SHORT TRANSFER, EOF/EPIPE, DUP/RUN REFS, AND WAKEUP;
- TTY S6REC OUTPUT VALIDATION/RENDERING;
- COOKED TTY S6REC INPUT, RETRY, EMPTY/^D, AND RAW REJECTION;
- PHYSICAL PTR/PTP FULL/PARTIAL PT8 ROUND TRIP;
- PHYSICAL 80-COLUMN CR/CP CARD12 ROUND TRIP;
- PHYSICAL S6REC TO PACKED LP10 OUTPUT.
