# PDP-6 HDD DBOOT V1

STATUS: CURRENT IMPLEMENTATION SUMMARY.  SOURCE OF TRUTH:
'../DAIMOS/INCLUDE/DBOOT_V1.H',
'../DAIMOS/INCLUDE/BOOTINFO_HDD_V1.H', AND
'../DAIMOS/TOOLS/MKPDP6_HDD_BOOTSET_V1.PY'.

## BOOT PATH

'''TEXT
STAGE0 PAPER TAPE/RIM PROXY
  -> STAGE1 HDD/DBOOT V1
  -> DAIMON FILE HEADER VALIDATION
  -> KRES PAYLOAD AT 000040
  -> OPAQUE HIGH INIT STREAM: DMANIF + KINIT + MINIT + MRES
  -> BOOTINFO AT 073000
  -> KINIT ENTRY WITH AC1 = BOOTINFO
'''

'000020..000037' IS RESERVED FOR THE DAIMOS PI AC SAVE SLOTS.
PDP-6 EXECUTIVE LOCATIONS '000040..000041' ARE THE UUO TRAP BLOCK, AND
'000042..000057' ARE THE PDP-6 INTERRUPT-LOCATION BLOCK.  THESE LOCATIONS ARE
ARCHITECTURAL LOW MEMORY AND MUST NOT BE REUSED AS ORDINARY KRES STORAGE.
NORMAL CONTIGUOUS RESIDENT KRES BEGINS AT '000060', BUT THE LOADED KRES PAYLOAD
RANGE STARTS AT '000040' BECAUSE THE UUO AND PI BLOCKS ARE PART OF THE RESIDENT
LOW-MEMORY CONTRACT.

STAGE1 TREATS EVERYTHING AFTER KRES AS ONE OPAQUE INIT STREAM.  IT DOES NOT
PARSE KINIT, MINIT, OR MRES.  KINIT PARSES DMANIF, RELOCATES MRES, DISPATCHES
MINIT, LINKS RESIDENT MODULES, AND RECLAIMS INIT MEMORY.

## BOOT FLOW

'''TEXT
POWER/RESET
  -> OPERATOR LOADS STAGE1 FROM PAPER TAPE
  -> STAGE1 INITIALIZES STACK, SCRATCH, CONSOLE, AND DSK/DCT ACCESS
  -> PROBE DSK0..DSK3
  -> READ AND VALIDATE DBOOT DESCRIPTORS
  -> CLASSIFY MEDIA AS COMPLETE DISKSET MEMBERS, STANDALONE BOOT DISKS,
     OR INVALID/STALE/UNREADABLE MEDIA
  -> BUILD BOOT CHOICE TABLE
  -> HALT WITH ?BOOT IF NO BOOTABLE CHOICE EXISTS
  -> DISPLAY THE BOOTABLE MAP AND DEFAULT CHOICE
  -> ACCEPT A VALID OPERATOR OVERRIDE DURING COUNTDOWN, OR USE DEFAULT
  -> LOAD KRES FROM THE RAW BOOT REGION
  -> LOAD THE OPAQUE INIT STREAM BELOW BOOTINFO
  -> BUILD BOOTINFO WITH SELECTED SOURCE, PHYSICAL DISK MAP, LOGICAL MEMBER
     ORDER, DESCRIPTOR GENERATION, KRES RANGE, INIT-STREAM RANGE, ROOT HINTS,
     AND MINIMAL HARDWARE INFORMATION
  -> JUMP TO KINIT WITH AC1 = BOOTINFO POINTER
  -> KINIT VALIDATES BOOTINFO, INITIALIZES KRES STRUCTURES AND BUILT-IN BOOT
     DRIVERS, REOPENS THE BOOT MEDIUM, PARSES THE FULL LAYOUT AND MODULE
     MANIFEST, MOUNTS OR CONSTRUCTS THE INITIAL ROOT, STARTS INIT, AND RECLAIMS
     KINIT/MINIT MEMORY
'''

STAGE1 PRESENTS ONLY BOOTABLE COMPLETE DISKSETS AND STANDALONE DISKS.  DISKSETS
HAVE BOOT PREFERENCE OVER STANDALONE DISKS.  DISPLAY CHARACTERS ARE SIXBIT-SAFE:

'''TEXT
_   NO BOOTABLE DISK IN THAT PHYSICAL SLOT
A-D DISKSET CHOICE / MEMBER DISPLAY
0-3 STANDALONE BOOTABLE DISK
'''

PHYSICAL DSK UNIT NUMBER AND LOGICAL DISKSET MEMBER INDEX MUST NOT BE CONFLATED.
STAGE1 IS NOT A FILESYSTEM READER, MODULE LINKER, OR RESCUE OS.

## MEDIA RECORDS

THE SECTOR SIZE IS 128 PDP-10 WORDS.  STAGE1 SCANS UP TO 128 SECTORS FOR A
VALID DESCRIPTOR.

- 'DBC': COMPACT ONE-SECTOR DESCRIPTOR FOR CLEAN/EMULATOR MEDIA.
- 'DB0': BAD-RUN SECTOR FOR MEDIA WITH BAD SECTORS.
- 'DBX': DESCRIPTOR FOLLOWING DB0 AT THE NEXT GOOD SECTOR.

DBC AND DBX USE DESCRIPTOR VERSION 2.  THE CURRENT DBX/DBC SECTOR CONTAINS:

'''TEXT
000  HEADER: MAGIC ! VERSION=2 ! RESERVED COUNT ! FLAGS
001  CHECKSUM
002  GENERATION
003  DISKSET UUID WORD 0
004  DISKSET UUID WORD 1
005  MEMBER WORD: MASK16 ! INDEX4 ! DISK_COUNT4 ! FLAGS12
006  KICFG0: BOOT MODE, CONSOLE MODULE/UNIT, ROOT POLICY, INITCONF, FLAGS
012  MEMBER-LOCAL BOOTSTREAM PHYSICAL START/COUNT
013..067  KERNEL/MODULE CONFIGURATION RESERVED FOR KINIT POLICY
070..177  RESERVED
'''

THERE IS NO S1CONF IN THE CURRENT BOOT PATH.  COMPATIBILITY OPTIONS THAT TRY TO
EMIT S1CONF OR THE OLD INITFS0 FALLBACK BUNDLE ARE REJECTED BY THE IMAGE
GENERATOR.

## DAIMON HEADER

THE DAIMON FILE HEADER IS FOUR WORDS ON DISK AND IS NOT COPIED INTO RESIDENT
KRES MEMORY:

'''TEXT
0  SIXBIT "DAIMON"
1  VERSION6 ! HEADER_WORDS6(4) ! CPU6(PDP6=1) ! BOOT_ABI6(1) ! RESERVED12
2  KRES PAYLOAD WORDS18 ! INIT STREAM WORDS18
3  KINIT ENTRY OFFSET18 ! HEADER CHECKSUM18
'''

THERE IS NO IMAGE-STREAM CHECKSUM IN V1.  KINIT VALIDATES THE INIT-STREAM
MANIFEST AND COMPONENT CHECKSUMS BEFORE USING OR RELOCATING THE STREAM.

## DISKSETS

EVERY MEMBER RECORDS A DISKSET UUID, GENERATION, MEMBER MASK, MEMBER INDEX, AND
DISK COUNT.  STAGE1 ACCEPTS A DISKSET ONLY WHEN ALL REQUIRED MEMBERS WITH THE
SAME UUID, GENERATION, AND MASK ARE PRESENT.

BOOTSTREAM DATA IS READ FROM CONTIGUOUS MEMBER-LOCAL CONTRIBUTIONS RECORDED IN
DBC OR DBX. THE CURRENT BOOTSET READER INTERLEAVES MEMBERS WITH ONE 128-WORD
SECTOR PER TURN, BUT THIS IS BOOT MEDIA LAYOUT POLICY, NOT GENERAL STRIPING OR
RAW DSK270 DRIVER SCOPE. THE INSTALLER MUST ALLOCATE A CONTIGUOUS PHYSICAL
CONTRIBUTION ON EVERY MEMBER AND RECORD THAT MEMBER-LOCAL START/COUNT IN DBC OR
DBX.

BAD PHYSICAL SECTORS INSIDE FSREGION ARE REPRESENTED BY HIDDEN
'SYSTEM!PINNED!UNLINKED' D6FS FCBS.  THEY ARE NOT SUPERBLOCK ROLES.

## STAGE1 DIAGNOSTICS

STAGE1 HAS NO C-STRING DIAGNOSTICS.  FATAL DIAGNOSTICS ARE PACKED SIXBIT WORDS,
FOR EXAMPLE '?NODSK', '?NOSET', '?KHEAD', '?LAYOT', OR '?READ '.

CRITICAL HALT PATHS:

'''TEXT
NO BOOTABLE DISK/DISKSET         -> ?BOOT    HALT
DESCRIPTOR CHECKSUM FAILURE      -> ?CHECK   HALT
KERNEL IMAGE INVALID/OVERLAP     -> ?KERNEL  HALT
SELECTED DISK READ FAILURE       -> ?DSK     HALT
CLOCK INVALID, IF STAGE1 USES IT -> ?CLOCK   HALT
'''
