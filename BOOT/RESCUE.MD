# DAIMOS HDD/DBOOT V1 - RECOVERY PROCEDURE

STATUS: MEDIA/BOOT RECOVERY REFERENCE.  THE FULL ADMINISTRATIVE SINGLE-USER/RECOVERY
ENVIRONMENT IS POST-0.9; THIS DOCUMENT DOES NOT MAKE IT A CURRENT 0.9 TASK.

RECOVERY IS NEEDED WHEN:
- DBOOT SECTORS ON ALL MEMBERS ARE UNREADABLE OR CORRUPTED
- THE BOOTSTREAM (KRES+KINIT) IS UNREADABLE FROM EVERY MEMBER
- THE DISK SET IS INCOMPLETE AND THE KERNEL CANNOT BE REBUILT FROM THE SURVIVING MEMBERS

RECOVERY IS NOT NEEDED IF ANY MEMBER'S DBOOT IS INTACT AND READABLE: STAGE1 ALREADY
SCANS UP TO 'DBOOT_SCAN_LIMIT_DEFAULT' (0200 = 128) SECTORS LOOKING FOR DB0/DBX/DBC
AND HANDLES BAD SECTORS VIA THE BADMAP IN DB0.  IF EVEN ONE MEMBER STILL HAS A READABLE
DBOOT, STAGE1 WILL FIND IT.

---

## PAPER TAPE (STAGE0 / STAGE1 READ-IN IMAGE)

### WHAT IT IS

THE CURRENT PDP-6 STANDALONE BUILD PRODUCES DEVICE-SPECIFIC READ-IN PAPER-TAPE
IMAGES FROM THE NATIVE DAS/DXR TOOLCHAIN:

    BUILD/SYSTEM/STAND/PDP6/DSK/STAGE1-DSK-V1.PT
    BUILD/SYSTEM/STAND/PDP6/DRM/STAGE1-DRM-V1.PT

THE CORRESPONDING INTERMEDIATE DXR FILES ARE `STAGE1-DSK-V1.DXR` AND
`STAGE1-DRM-V1.DXR`.  `DXRCONVERT --PDP6-READIN` EMITS THE HARDWARE READ-IN
FORMAT; THE BUILD APPENDS THE REQUIRED TRAILING 0252 BYTE.  THE OLD
`BUILD/NATIVE-STAGE1-*/STAGE1-HDD-V1.RIM` NAMES ARE OBSOLETE AND MUST NOT BE
USED AS CURRENT RECOVERY ARTIFACTS.

### BUILDING THE TAPE

    MAKE -C SYSTEM/STAND/PDP6/DSK BUILD
    MAKE -C SYSTEM/STAND/PDP6/DRM BUILD

THE NORMAL ACCEPTANCE TOOLCHAIN IS DAS/KCC-BASED DAIMOS TOOLING UNDER
`$PDP10_PREFIX`; GCC IS NOT A SUBSTITUTE FOR THE KCC ACCEPTANCE BUILD.

### USING IN SIMH

ATTACH THE READ-IN IMAGE TO THE PDP-6 PAPER-TAPE READER AND USE THE NORMAL
PDP-6 READ-IN BOOTSTRAP.  SELECT THE DEVICE-SPECIFIC STAGE1 THAT MATCHES THE
BOOT TRANSPORT:

- `STAGE1-DSK-V1.PT` PROBES DSK270 UNITS 0-3;
- `STAGE1-DRM-V1.PT` PROBES DRM236 UNITS 0-3.

THE CURRENT REGRESSION SUITE PROVES DSK STAGE1 BOOT TO INIT/LOGIN WITH ONLY
DSK0 ATTACHED AND DIRECT DRM STAGE1 BOOT TO INIT/LOGIN WITH DSK DELIBERATELY
UNATTACHED.

### USING ON HARDWARE PDP-6

1. PUNCH THE APPROPRIATE `.PT` READ-IN IMAGE TO PAPER TAPE WITHOUT FORMAT
   CONVERSION.
2. LOAD THE TAPE INTO THE HIGH-SPEED READER.
3. SET THE CONSOLE SWITCHES FOR THE REQUIRED ROOT CLASS/ORDINAL POLICY.
4. PRESS READ IN.  THE PAPER-TAPE BOOTSTRAP LOADS STAGE1 AT ITS LINKED LOW-CORE
   ADDRESS AND TRANSFERS CONTROL TO IT.
5. DSK STAGE1 SCANS DSK270 UNITS 0-3; DRM STAGE1 SCANS DRM236 UNITS 0-3.
   BOTH USE THE SAME DBOOT MEMBER SELECTION, BAD-RUN, DAIMON HEADER, AND
   D6LZ36/RAW KINIT STREAM CONTRACT.

## RECOVERY SCENARIO 1 - DBOOT SECTORS LOST, DISK DATA INTACT

THE KERNEL BOOTSTREAM AND D6FS FILESYSTEM ARE INTACT BUT DBOOT (DB0/DBX OR DBC) IS
UNREADABLE OR OVERWRITTEN.

**CURRENT V1 STATUS:** THERE IS NO AUTOMATED DBOOT RE-WRITER.  RECOVERY REQUIRES
REBUILDING THE DISK IMAGE ON THE HOST AND RE-IMAGING EACH MEMBER DRIVE.

HOST-SIDE REBUILD STEPS:

    # REBUILD A REPLACEMENT BOOTSET WITH THE SAME MEMBER COUNT AND GEOMETRY.
    # REPLACE --MEMBERS N TO MATCH YOUR DISK SET.
    PYTHON3 TOOLS/MKPDP6_HDD_BOOTSET_V1.PY \
        --MEMBERS 4 \
        --OUTPUT-DIR IMAGES/PDP6/RECOVERY/NEW-BOOTSET \
        --PREFIX DSK \
        --KERNEL-WORDS-FILE /PATH/TO/SAVED/KERNEL.WORDS \
        --KERNEL-REGION-SECTORS 64

    # WRITE EACH .DSK IMAGE BACK TO ITS PHYSICAL DRIVE (HARDWARE) OR RE-ATTACH
    # IN SIMH (VIRTUAL).

IF THE ORIGINAL BOOTSTREAM WORDS WERE SAVED (E.G., FROM A 'MAKE PDP6-BOOT-IMAGES' RUN
OR A D6FS BACKUP), PASS THEM VIA '--KERNEL-WORDS-FILE'.  WITHOUT THEM, A NEW DAIMON
KERNEL MUST BE ASSEMBLED SEPARATELY AND THEN SUPPLIED HERE.

---

## RECOVERY SCENARIO 2 - COMPLETE DISK SET LOSS

ALL MEMBERS ARE UNREADABLE OR ALL DBOOT AND BOOTSTREAM SECTORS ARE CORRUPTED.

STEPS:
1. REBUILD A FRESH BOOTSET FROM SOURCE:

       MAKE PDP6-BOOT-IMAGES   # USES CURRENT MACH/PDP6_BOOT_MEMBERS SETTINGS

2. USE THE PAPER TAPE RIM (SEE ABOVE) TO BOOT THE NEW SET.
3. RESTORE D6FS DATA FROM BACKUP (ARCHIVE MEDIUM: DECTAPE OR ANOTHER DISK SET).

## KNOWN V1 LIMITATIONS

- STAGE1 HARDWARE DISK PROBE IS LIMITED TO UNITS 0-3 (ONE DSK270 CONTROLLER).
  A 16-MEMBER DISK SET REQUIRES MULTIPLE CONTROLLERS; V1 STAGE1 CANNOT PROBE BEYOND
  UNIT 3 IN NATIVE PDP-6 MODE.  HOST-SIDE IMAGE GENERATION SUPPORTS 1-16 MEMBERS;
  THE EXTRA MEMBERS ARE PLACED ON A SECOND CONTROLLER (NOT YET PROBED BY NATIVE STAGE1).
- NO DBOOT RE-WRITER TOOL EXISTS YET; RECOVERY REQUIRES FULL DISK RE-IMAGING ON THE HOST.
- THERE IS NO NATIVE DTC STAGE1 YET.  TSFS ROOT BOOT IS IMPLEMENTED THROUGH
  KINIT ROOT DISCOVERY, BUT POST-0.9 BOOTABLE RECOVERY DECTAPE STILL REQUIRES A
  NATIVE DTC STAGE1/RECOVERY TRANSPORT.  NORMAL MAINTENANCE TOOLS, NOT AN
  EMERGENCY INITFS ROOT, REMAIN THE INTENDED RECOVERY MODEL.
