# DXR V1 EXECUTABLE IMAGE

STATUS: NATIVE IMAGE FORMAT WITH OPTIONAL D6LZ36 COMPRESSED LOAD IMAGE
DATE: 2026-09-23

DXR IS THE TINY RELOCATABLE EXECUTABLE IMAGE USED BY DSH TO RUN EXTERNAL
COMMANDS THROUGH 'SYS_RUN'.

IT IS DELIBERATELY NOT A FULL OBJECT FORMAT.  IT HAS NO SYMBOLS, SECTIONS,
IMPORTS, EXPORTS, LIBRARIES, STRING TABLES, DEBUG RECORDS, DYNAMIC LINKING,
ABI WORD, VERSION WORD, CHECKSUM, RELOCATION COUNT, OR EXPLICIT STACK SIZE.
IT IS ONLY:

'''TEXT
FLAT IMAGE WORDS + ADDR18 RELOCATION BITMAP
'''

THE SOURCE FILES STILL USE THE HISTORICAL 'DEX0R_' C FUNCTION PREFIX FOR NOW,
BUT THE ON-DISK/NATIVE STREAM IS THE FINAL-MINIMAL DXR V1 FORMAT.

## 1. CONSTRAINTS

'''TEXT
PDP-6/KA10 FIRST
256K WORDS RAM
NO SWAPPING YET
SMALL EXTERNAL COMMANDS
SMALL LOADER
NO DOBJ/DARC DEPENDENCY
'''

DEX0 REMAINS THE FIXED EARLY '/INIT' IMAGE FORMAT.  DXR IS USED BESIDE IT FOR
THE RUN/WAIT USERLAND PATH.

## 2. WORD STREAM

DXR V1 USES NATIVE 36-BIT WORDS.  WORD 0 IS ALWAYS THE MAGIC AND ENTRY
OFFSET.  WORD 1 CARRIES THE UNCOMPRESSED IMAGE SIZE, BSS SIZE, AND FLAGS.

'''TEXT
WORD 0: SIXBIT("DXR"),,ENTRY_OFFSET
WORD 1: IMAGE_WORDS,,FLAGS|BSS_WORDS
'''

THE RIGHT HALF OF WORD 1 IS:

'''TEXT
BITS 0..14: BSS_WORDS
BIT 15:     COMPRESSED
BIT 16:     PURE
BIT 17:     RT_REQUIRED
'''

FLAG VALUES ARE:

'''TEXT
COMPRESSED = 0100000
PURE       = 0200000
RT_REQUIRED = 0400000
'''

PURE IS A ONE-BIT TEXT POLICY: SET MEANS THE TEXT PREFIX IS CLEAN AND MAY
USE EXECUTABLE BACKING; CLEAR MEANS ORDINARY PRIVATE/WRITABLE IMAGE STATE.
THERE IS NO SEPARATE IMPURE FLAG.  RT_REQUIRED IS INDEPENDENT OF PURE AND
COMPRESSED.


## RT_REQUIRED ADMISSION

`RT_REQUIRED` MARKS AN EXECUTABLE THAT MUST NOT BEGIN USER EXECUTION WITHOUT
THE SYSTEM-WIDE REAL-TIME SLOT.  RUN/EXEC VALIDATES WORD 1 AND RESERVES THE
SLOT BEFORE VM ALLOCATION, DECOMPRESSION, RELOCATION, OR MAKING A NEW CHILD
RUNNABLE.  IF ANOTHER OWNER OR RESERVATION EXISTS, THE LAUNCH FAILS AND THE
NEW IMAGE EXECUTES ZERO USER INSTRUCTIONS.

THE RESERVATION IS RELEASED ON LOAD/STARTUP FAILURE, PROCESS EXIT, FAILED RUN
UNWIND, RT DISABLE/YIELD, OR OPERATOR REVOCATION.  A SUCCESSFUL EXEC OF AN
IMAGE WITHOUT RT_REQUIRED RELEASES A PRIOR RT OWNERSHIP ONLY AFTER THE NEW
IMAGE HAS COMMITTED.  COMPRESSED EXECUTABLES PRESERVE RT_REQUIRED IN THE OUTER
DXR HEADER, SO ADMISSION OCCURS BEFORE D6LZ DECOMPRESSION.

`DLINK --RT-REQUIRED` SETS THE FLAG.  COPYING OR PACKING THE EXECUTABLE DOES
NOT REQUIRE FILESYSTEM METADATA; THE REQUIREMENT TRAVELS WITH THE IMAGE.

AN UNCOMPRESSED DXR1 IMAGE HAS A TWO-WORD HEADER:

'''TEXT
WORD 2..: IMAGE WORDS
THEN:       RELOCATION BITMAP WORDS
'''

DXR2 ADDS A THIRD HEADER WORD:

'''TEXT
WORD 2: TEXT_WORDS,,SIXBIT("TX2")
'''

A COMPRESSED EXECUTABLE IS ALWAYS DXR2.  AFTER WORD 2 IT STORES A
VARIABLE-LENGTH D6LZ36 STREAM THAT EXPANDS TO EXACTLY IMAGE_WORDS WORDS, THEN
THE NORMAL RELOCATION BITMAP.  THE COMPRESSED PAYLOAD LENGTH IS DERIVED FROM
THE FILE SIZE AFTER SUBTRACTING THE THREE HEADER WORDS AND RELOCATION BITMAP.
NO SECOND LENGTH FIELD IS STORED.

THE NUMBER OF RELOCATION BITMAP WORDS IS DERIVED FROM THE UNCOMPRESSED IMAGE
SIZE:

'''TEXT
RELOC_WORDS = CEIL(IMAGE_WORDS / 36)
'''

THE BITMAP IS ALWAYS PRESENT.  FOR IMAGES WITH NO RELOCATED WORDS, ALL BITMAP
BITS ARE ZERO.

## 3. MAGIC

THE MAGIC IS THE 18-BIT LEFT HALF OF WORD 0:

'''TEXT
SIXBIT("DXR")
'''

THE RIGHT HALF OF WORD 0 IS THE IMAGE-RELATIVE ENTRY OFFSET.

## 4. IMAGE AND MEMORY LIMITS

CURRENT PDP-6 LIMITS ARE:

'''TEXT
IMAGE_WORDS        <= 036000
BSS_WORDS          <= 020000
USER_ORIGIN        = 020
DEFAULT_STACK      = 02000 WORDS
'''

THE PROCESS ADDRESS SPACE CONTAINS USER_ORIGIN + IMAGE_WORDS + BSS_WORDS +
DEFAULT_STACK WORDS.  THERE IS NO STACK-SIZE FIELD IN DXR V1.

## 5. RELOCATION BITMAP

DXR V1 HAS ONLY ONE RELOCATION KIND:

'''TEXT
ADDR18 LOW EFFECTIVE-ADDRESS RELOCATION
'''

EACH RELOCATION BITMAP WORD COVERS 36 IMAGE WORDS.  THE LEFTMOST BIT NAMES THE
FIRST IMAGE WORD IN THAT GROUP:

'''TEXT
BITMAP WORD 0 BIT 0  -> IMAGE WORD 0
BITMAP WORD 0 BIT 35 -> IMAGE WORD 35
BITMAP WORD 1 BIT 0  -> IMAGE WORD 36
'''

UNUSED BITS IN THE FINAL BITMAP WORD MUST BE ZERO.

NO FULL-WORD RELOCATION EXISTS IN V1.

## 6. LOADER RULE

THE FILESYSTEM-BACKED PROCESS LOADER:

'''TEXT
VALIDATES MAGIC, FLAGS, SIZES, ENTRY, AND HEADER SHAPE
DERIVES RELOCATION BITMAP SIZE FROM UNCOMPRESSED IMAGE_WORDS
ALLOCATES PROCESS MEMORY FOR THE UNCOMPRESSED IMAGE
IF COMPRESSED:
    REQUIRES DXR2 TEXT METADATA
    D6LZ36-DECOMPRESSES DIRECTLY INTO PROCESS MEMORY
ELSE:
    READS IMAGE WORDS DIRECTLY INTO PROCESS MEMORY
APPLIES THE NORMAL ADDR18 RELOCATION BITMAP
ZEROS BSS/STACK AS REQUIRED BY THE VM PATH
ATTACHES EXECUTABLE BACKING METADATA
'''

COMPRESSION IS SELECTED ONLY BY THE EXPLICIT COMPRESSED FLAG.  THE LOADER
DOES NOT SNIFF OR GUESS THE STREAM FORMAT.  D6LZ36 DECOMPRESSION USES ALREADY
PRODUCED OUTPUT AS ITS HISTORY WINDOW AND ALLOCATES NO DICTIONARY BUFFER.

IMPLEMENTED NOW:

'''TEXT
DXR1 TWO-WORD HEADER
DXR2 TEXT METADATA HEADER
EXPLICIT COMPRESSED/PURE/RT_REQUIRED FLAGS
FILESYSTEM-BACKED EXEC LOADER
D6LZ36 COMPRESSED EXEC LOAD PATH
NORMAL ADDR18 RELOCATION AFTER DECOMPRESSION
RUN/EXEC USERLAND PATHS
HOST AND NATIVE D6LZ COMPRESSORS
TARGET AND END-TO-END COMPRESSED-EXEC REGRESSIONS
DEFAULT SYSTEM-IMAGE COMPRESSION FOR LOGIN AND DSH
'''

CURRENT PRODUCTION D6FS PACKAGING KEEPS THE ORDINARY UNCOMPRESSED LOGIN AND DSH
BUILD PRODUCTS BUT INSTALLS THEIR D6LZ36-COMPRESSED DXR2 FORMS BY DEFAULT.
THE CURRENT MEASURED SIZES ARE LOGIN 2524 -> 2125 WORDS (15.8 PERCENT) AND
DSH 5312 -> 4197 WORDS (21.0 PERCENT), FOR 1514 WORDS SAVED COMBINED.
`SYSTEM_LOGIN_DXR` AND `SYSTEM_DSH_DXR` REMAIN OVERRIDEABLE SO RECOVERY AND
FOCUSED TEST IMAGES CAN SELECT UNCOMPRESSED OR ALTERNATE EXECUTABLES WITHOUT
CHANGING THE PROGRAM BUILD.  DEFAULT-IMAGE SIMH ACCEPTANCE EXECUTES BOTH
COMPRESSED PROGRAMS THROUGH LOGIN/AUTHENTICATION/DSH/RESPAWN.

CURRENT SWAP WRITES AND RESTORES THE COMPLETE PROCESS IMAGE.  PURE-TEXT
METADATA IS RETAINED, BUT COMPRESSED EXECUTION DOES NOT DEPEND ON REREADING
UNCOMPRESSED TEXT FROM THE EXECUTABLE FILE DURING SWAP-IN.

## 8. ARGV STARTUP ABI

DXR V1 STARTS NATIVE PROGRAMS WITH A VERY SMALL REGISTER CONVENTION:

'''TEXT
AC1 = ARGC
AC2 = ARGV POINTER, OR 0 WHEN ARGC IS 0
AC3 = 0, RESERVED
PC  = LOAD_BASE + ENTRY_OFFSET
SP  = STACK POINTER AFTER THE ARGV STARTUP BLOCK
'''

THE ARGV STARTUP BLOCK IS PLACED AT THE BOTTOM OF THE DEFAULT STACK AREA.  THE
STACK POINTER RETURNED BY 'DEX0R_LOAD_MEMORY()' NAMES THE FIRST STACK WORD.  IF
ARGV IS NON-EMPTY, 'DEX0R_BUILD_ARGV()' WRITES THE ARGV BLOCK THERE AND MOVES
SP TO THE LAST WORD CONSUMED BY THAT BLOCK.  ON PDP-10 PUSHDOWN STACKS, THE
NEXT PUSH WILL THEN USE THE FOLLOWING WORD.

THE ARGV BLOCK IS:

'''TEXT
WORD 0..ARGC-1: ABSOLUTE USER ADDRESSES OF COUNTED SIXBIT STRINGS
THEN:           COUNTED PACKED SIXBIT STRINGS
'''

EACH STRING IS:

'''TEXT
WORD 0:    CHARACTER COUNT
WORD 1..N: SIX SIXBIT CHARACTERS PER WORD
'''

THE ARGV VECTOR IS NOT ZERO-TERMINATED.  'ARGC' IN AC1 IS AUTHORITATIVE.
ENVIRONMENT IS NOT PART OF V1.

INITIAL LIMITS:

'''TEXT
ARGC       <= 8
ARG CHARS  <= 36 PER ARGUMENT
'''

THESE MATCH THE CURRENT SMALL DSH COMMAND PROFILE AND AVOID MAKING THE FIRST
RUN/WAIT ABI LARGER THAN NECESSARY.
