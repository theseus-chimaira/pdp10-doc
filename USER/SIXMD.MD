# SIXMD COMMAND MANUAL AND HELP SPECIFICATION

STATUS: DESIGN SPECIFICATION FOR DAIMOS COMMAND MANUALS, HELP, OPTION PARSING,
AND DSH COMPLETION.

## 1. PURPOSE

DAIMOS COMMAND DOCUMENTATION IS A SINGLE SOURCE FOR HUMAN DOCUMENTATION AND
MACHINE-READABLE COMMAND SYNTAX.  A COMMAND MANUAL SHALL NOT DUPLICATE ITS
COMMAND NAME, SYNOPSIS, OPTION TABLE, SHORT HELP, OR COMPLETION DESCRIPTION IN
SEPARATE FILES WHEN THOSE VALUES CAN BE DERIVED FROM THE MANUAL.

THE FORMAT HAS TWO LAYERS:

- SIXMD IS THE SMALL SIXBIT-SAFE PRESENTATION LANGUAGE.
- THE COMMAND-MANUAL PROFILE ASSIGNS MACHINE MEANING TO SELECTED SIXMD HEADINGS.

THE SAME COMMAND MANUAL IS USED TO DERIVE:

- MAN OUTPUT;
- HELP COMMAND SHORT HELP;
- GETOPT/OPTION-DESCRIPTION TABLES;
- DSH COMMAND, OPTION, AND OPERAND COMPLETION;
- SYNOPSIS TEXT;
- WHATIS/APROPOS INDEX DATA;
- BUILD-TIME VALIDATION.

PROGRAM BEHAVIOR SHALL NOT DEPEND ON MAN OR DSH ACCEPTING MALFORMED MANUAL
INPUT.  OPTION PARSING AND SECURITY CHECKS REMAIN PROGRAM RESPONSIBILITIES;
GENERATED TABLES MAY IMPLEMENT THE MECHANICAL OPTION-PARSING PART.

## 2. SIXMD SOURCE FORM

A SIXMD SOURCE CONTAINS ONLY THE PDP-10 SIXBIT PRINTABLE CHARACTER REPERTOIRE
AND RECORD DELIMITERS.  REPOSITORY COPIES MAY USE ASCII LF OR CRLF AS THE
TRANSPORT REPRESENTATION.  NATIVE STORAGE MAY USE S6REC RECORDS.

THE FIRST RECORD IS:

    %SIXMD 1

SIXBIT LETTER CODES ARE UPPERCASE.  NORMAL LETTERS ARE DISPLAYED UPPERCASE.
'@' ESCAPES THE FOLLOWING LETTER TO LOWERCASE.  '@@' REPRESENTS A LITERAL '@'.
LOWERCASE ASCII CHARACTERS ARE NOT VALID SIXMD SOURCE.

EXAMPLE SOURCE:

    C@O@P@Y @F@I@L@E@S

DISPLAYS AS:

    Copy files

A BACKSLASH ESCAPES THE FOLLOWING MARKUP CHARACTER LITERALLY.

SIXMD SUPPORTS:

- '#', '##', AND '###' HEADINGS;
- TEXT RECORDS AND BLANK RECORDS;
- '- ' AND '* ' UNORDERED LIST ITEMS;
- '> ' QUOTATIONS;
- FOUR-SPACE INDENTED LITERAL RECORDS;
- '---' HORIZONTAL RULES;
- '*...*' AND '**...**' PRESENTATION HINTS.

SIXMD DOES NOT REQUIRE GENERAL MARKDOWN COMPATIBILITY.  LINKS, IMAGES, HTML,
TABLES, NESTED LISTS, TASK LISTS, FENCED CODE, INLINE BACKTICK CODE, AND OTHER
MARKDOWN EXTENSIONS ARE OUTSIDE THIS SPECIFICATION.

A SOURCE RECORD MUST NOT EXCEED 255 SIXBIT CHARACTERS.  AUTHORS SHOULD WRAP
PROSE EARLIER FOR TERMINAL READABILITY.

## 3. SEMANTIC HEADING ANCHOR

THE COMMAND-MANUAL PROFILE RESERVES '@?' AS A SEMANTIC ANCHOR ONLY WHEN IT
OCCURS IMMEDIATELY AFTER THE HEADING MARKER AND ITS REQUIRED SPACE:

    # @?...
    ## @?...
    ### @?...

'@?' IN THIS POSITION IS NOT DISPLAY TEXT.  MAN STRIPS THE TWO CHARACTERS AND
RENDERS THE REST OF THE HEADING AS NORMAL SIXMD.  MACHINE READERS USE THE
ANCHOR TO DISTINGUISH STANDARDIZED COMMAND DATA FROM ORDINARY DOCUMENTATION.

OUTSIDE THIS POSITION '@?' HAS NO COMMAND-MANUAL MEANING AND IS INVALID AS AN
UNESCAPED SIXMD CASE SEQUENCE.  THIS MAKES ACCIDENTAL MACHINE METADATA
UNLIKELY AND MAKES OLD STRICT SIXMD VALIDATORS REJECT NEW SEMANTIC INPUT RATHER
THAN SILENTLY MISREAD IT.

UNANCHORED HEADINGS ARE PURE DOCUMENTATION AND SHALL BE IGNORED BY COMMAND
SYNTAX READERS.

## 4. COMMAND IDENTITY

A COMMAND MANUAL HAS EXACTLY ONE ANCHORED LEVEL-ONE HEADING.  IT IS THE
AUTHORITATIVE COMMAND NAME AND ONE-LINE SUMMARY:

    # @?COPY - COPY FILES

THE FIRST WORD IS THE COMMAND NAME.  TEXT AFTER ' - ' IS THE SHORT SUMMARY.
THE COMMAND NAME SHALL MATCH THE INSTALLED COMMAND NAME OR A DECLARED BUILTIN
NAME.  MAN, HELP, WHATIS, APROPOS, AND DSH SHALL DERIVE THE NAME FROM THIS
HEADING.  THERE IS NO SEPARATE COMMAND-NAME RECORD.

THE FILE NAME SHOULD MATCH THE COMMAND NAME FOR DIRECT MAN LOOKUP, BUT THE FILE
NAME IS AN INDEXING CONVENTION, NOT A SECOND AUTHORITATIVE COMMAND NAME.

## 5. STANDARD SEMANTIC SECTIONS

ANCHORED LEVEL-TWO HEADINGS DEFINE STANDARD MACHINE-READABLE SECTIONS.  V1
DEFINES:

    ## @?OPTIONS
    ## @?OPERANDS
    ## @?ENVIRONMENT
    ## @?FILES
    ## @?EXIT STATUS
    ## @?SEE ALSO

THE FOLLOWING MAY BE ADDED WHEN A COMMAND NEEDS THEM WITHOUT CHANGING SIXMD:

    ## @?SUBCOMMANDS
    ## @?DIAGNOSTICS

UNKNOWN ANCHORED LEVEL-TWO SECTION NAMES SHALL BE REJECTED BY A V1 VALIDATOR.
THIS PREVENTS A MISSPELLED STANDARD SECTION FROM QUIETLY DISABLING COMPLETION
OR HELP GENERATION.

ORDINARY SECTIONS SUCH AS DESCRIPTION, EXAMPLES, NOTES, BUGS, IMPLEMENTATION,
AND HISTORY NEED NO ANCHOR UNLESS A LATER PROFILE ASSIGNS MACHINE SEMANTICS TO
THEM.

## 6. OPTIONS

EACH ANCHORED LEVEL-THREE HEADING UNDER OPTIONS DEFINES ONE OPTION.  ITS
HEADING CONTAINS THE COMMAND-LINE SPELLING, OPTIONAL VALUE METAVARIABLE, AND A
SHORT DESCRIPTION:

    ### @?-F - FORCE REPLACEMENT
    ### @?-V - VERBOSE
    ### @?-O FILE - OUTPUT FILE

THE FIRST FIELD IS THE OPTION SPELLING.  A FOLLOWING METAVARIABLE MEANS THAT
THE OPTION REQUIRES A VALUE.  TEXT AFTER ' - ' IS THE SHORT HELP STRING.

THE SIXMD TEXT FOLLOWING THE HEADING, UP TO THE NEXT HEADING OF THE SAME OR
HIGHER LEVEL, IS THE LONG MANUAL DESCRIPTION FOR THAT OPTION.

V1 OPTIONS USE ONE DASH AND ONE SIXBIT OPTION LETTER.  LONG OPTIONS, OPTIONAL
OPTION VALUES, OPTION GROUP CONSTRAINTS, AND ALIASES ARE NOT PART OF V1 UNTIL
A REAL COMMAND REQUIRES THEM.

THE OPTION DECLARATION IS THE SINGLE SOURCE FOR:

- THE OPTION-PARSER DESCRIPTION;
- THE OPTION PART OF THE GENERATED SYNOPSIS;
- DSH OPTION COMPLETION;
- THE HELP COMMAND OPTION LIST;
- THE MAN OPTIONS SECTION.

## 7. OPERANDS AND COMPLETION CLASSES

EACH ANCHORED LEVEL-THREE HEADING UNDER OPERANDS DEFINES ONE POSITIONAL
OPERAND.  THE DECLARATION ITSELF IS COMMAND SYNTAX:

    ### @?SOURCE FILE
    ### @?DEST FILE

V1 ALSO RESERVES BRACKETS FOR AN OPTIONAL OPERAND AND A TRAILING '...' FOR A
REPEATED OPERAND:

    ### @?[FILE]
    ### @?FILE...

THE VALIDATOR SHALL REJECT AMBIGUOUS ORDERINGS SUCH AS A REQUIRED OPERAND AFTER
AN OPTIONAL OR REPEATED OPERAND UNLESS A LATER PROFILE DEFINES THE GRAMMAR.

STANDARD METAVARIABLE NAMES ALSO DEFINE THE DSH COMPLETION CLASS.  V1 SHOULD
START WITH THE SMALLEST USEFUL SET:

    FILE       FILE NAME
    DIR        DIRECTORY NAME
    PATH       FILESYSTEM PATH
    COMMAND    COMMAND NAME
    USER       USER NAME
    DEVICE     DEVICE NAME
    PROCESS    PROCESS OR JOB IDENTIFIER
    NUMBER     NUMERIC VALUE; NO NAME COMPLETION
    STRING     ARBITRARY TEXT; NO NAME COMPLETION

COMMANDS SHALL PREFER THESE STANDARD NAMES WHEN THEY WANT AUTOMATIC
COMPLETION.  SPECIAL SEMANTIC NAMES MAY BE DOCUMENTED IN PROSE, BUT THEY DO NOT
IMPLY A NEW COMPLETION CLASS.

THE SAME METAVARIABLE RULE APPLIES TO OPTION VALUES, SO '-O FILE' REQUESTS FILE
COMPLETION AFTER '-O'.

## 8. GENERATED SYNOPSIS

NORMAL COMMANDS SHALL NOT MAINTAIN AN INDEPENDENT SYNOPSIS.  THE SYNOPSIS IS
GENERATED FROM THE COMMAND NAME, OPTIONS, AND OPERANDS.

FOR:

    # @?COPY - COPY FILES
    ### @?-F - FORCE REPLACEMENT
    ### @?-V - VERBOSE
    ### @?-O FILE - OUTPUT FILE
    ### @?SOURCE FILE
    ### @?DEST FILE

THE GENERATED FORM IS:

    COPY [-F] [-V] [-O FILE] SOURCE DEST

MAN MAY DISPLAY THIS AS A SYNOPSIS SECTION.  HELP COMMAND SHALL USE THE SAME
GENERATED FORM.  A FUTURE EXPLICIT GRAMMAR ESCAPE MAY BE DEFINED FOR COMMANDS THAT CANNOT
BE REPRESENTED BY THE V1 OPTION/OPERAND MODEL; IT SHALL NOT BE ADDED UNTIL SUCH
A COMMAND EXISTS.

## 9. HELP SHORT HELP

DAIMOS DOES NOT RESERVE A PER-COMMAND '-H' HELP OPTION.  SHORT HELP IS
PROVIDED BY THE SEPARATE `HELP COMMAND` INTERFACE.  ITS OUTPUT IS GENERATED
FROM THE MANUAL DESCRIPTION OR FROM THE COMPACT DESCRIPTOR PRODUCED FROM IT.
A COMMAND SHALL NOT CARRY A SECOND HAND-WRITTEN HELP TABLE.

THE SHORT HELP CONTAINS AT LEAST:

- COMMAND NAME AND ONE-LINE SUMMARY;
- GENERATED SYNOPSIS;
- EACH OPTION SPELLING, VALUE METAVARIABLE, AND SHORT DESCRIPTION;
- A POINTER TO MAN FOR THE COMPLETE MANUAL.

`HELP COMMAND` MAY READ THE INSTALLED SIXMD MANUAL DIRECTLY ON SMALL SYSTEMS OR
CONSUME A GENERATED COMPACT DESCRIPTOR.  BASIC COMMAND EXECUTION MUST NOT
DEPEND ON HELP DATA BEING PRESENT.

THE USER-FACING DISTINCTION IS INTENTIONAL:

- `HELP COMMAND` SHOWS THE COMPACT COMMAND-LINE INTERFACE: SUMMARY, SYNOPSIS,
  OPTIONS, AND OPERANDS;
- `MAN COMMAND` SHOWS THE COMPLETE LONG-FORM SIXMD MANUAL;
- `APROPOS WORD` SEARCHES THE ONE-LINE `COMMAND - SUMMARY` RECORDS DERIVED
  FROM THE ANCHORED LEVEL-ONE COMMAND HEADINGS.

THE THREE INTERFACES SHARE SIXMD AS THEIR SOURCE OF TRUTH BUT MUST NOT COLLAPSE
INTO THE SAME OUTPUT MODE.

## 10. GETOPT/OPTION PARSING

THE BUILD TOOLS SHALL BE ABLE TO COMPILE THE ANCHORED OPTION HEADINGS INTO A
SMALL OPTION-DESCRIPTION TABLE.  A COMMON DAIMOS GETOPT-LIKE ROUTINE MAY USE
THAT TABLE TO RECOGNIZE OPTIONS AND DETERMINE WHETHER A VALUE IS REQUIRED.

THE APPLICATION STILL HANDLES THE SEMANTIC EFFECT OF EACH OPTION.  THE MANUAL
FORMAT IS NOT A SUBSTITUTE FOR APPLICATION VALIDATION OR KERNEL SECURITY.

THE NATIVE PROGRAM SHOULD CONSUME THE COMPACT GENERATED TABLE, NOT PARSE THE
FULL MANUAL AT STARTUP.  THIS KEEPS RESIDENT RAM AND EXECUTION COST LOW.

## 11. DSH COMPLETION

DSH COMPLETION SHALL USE THE SAME SEMANTIC MANUAL DATA.  IT SHALL NOT CONTAIN
PER-COMMAND OPTION TABLES.

AT A COMMAND POSITION, DSH COMPLETES COMMAND NAMES FROM THE NORMAL COMMAND
SEARCH PATH AND BUILTIN SET.  AFTER A KNOWN COMMAND NAME IT MAY CONSULT THE
COMPILED COMMAND DESCRIPTION TO COMPLETE:

- OPTION NAMES WHILE OPTIONS ARE LEGAL;
- OPTION VALUES ACCORDING TO THEIR METAVARIABLE CLASS;
- POSITIONAL OPERANDS ACCORDING TO THEIR DECLARED CLASS;
- COMMAND NAMES FOR COMMAND-CLASS OPERANDS;
- FILESYSTEM, USER, DEVICE, PROCESS, AND OTHER STANDARD NAMES THROUGH THE
  CORRESPONDING COMPLETION PROVIDER.

COMPLETION IS ADVISORY.  FAILURE TO FIND, READ, OR PARSE COMPLETION METADATA
MUST NOT CRASH DSH AND MUST NOT PREVENT THE USER FROM ENTERING THE COMMAND.
DSH SHALL FALL BACK TO GENERIC COMPLETION OR NO COMPLETION.

THE INTERACTIVE COMPLETION PATH SHOULD USE A PREVALIDATED COMPACT INDEX RATHER
THAN OPENING AND PARSING FULL SIXMD MANUALS FOR EVERY TAB REQUEST.

## 12. OTHER SEMANTIC SECTIONS

ENVIRONMENT, FILES, EXIT STATUS, AND SEE ALSO USE ANCHORED LEVEL-THREE ENTRIES
SO THEIR IDENTIFIERS CAN BE INDEXED WHILE THEIR FOLLOWING SIXMD TEXT REMAINS
THE LONG DESCRIPTION.

EXAMPLES:

    ## @?ENVIRONMENT
    ### @?PATH
    COMMAND SEARCH PATH.

    ## @?FILES
    ### @?/SYSTEM/CONFIG
    SYSTEM CONFIGURATION AREA.

    ## @?EXIT STATUS
    ### @?0 - SUCCESS
    ### @?1 - OPERATION FAILED

    ## @?SEE ALSO
    ### @?MOVE
    ### @?DELETE

THESE SECTIONS ARE PRIMARILY DOCUMENTATION/INDEX DATA IN V1.  THEY SHALL NOT BE
USED AS A SECURITY OR RESOURCE-ACCESS POLICY.

## 13. MAN RENDERING

MAN IS A SIXMD RENDERER WITH COMMAND-PROFILE AWARENESS.  FOR ANCHORED HEADINGS
IT REMOVES '@?' AND RENDERS THE REMAINDER AS THE CORRESPONDING NORMAL HEADING.
THE ANCHOR SHALL NEVER APPEAR IN DISPLAYED MANUAL TEXT.

ON A TYPE-340/342 DISPLAY, MAN MAY RENDER SIXMD PRESENTATION DIRECTLY WITH
HARDWARE CHARACTER SIZE AND INTENSITY RATHER THAN FLATTENING EVERYTHING TO
AN 80-COLUMN CHARACTER STREAM. THIS IS A FORMATTED-DISPLAY FACILITY, NOT A
TTY SIZE ATTRIBUTE. MAN MAY USE TYPE-342 SCALES 1, 2, AND 4 FOR SMALL,
NORMAL, AND LARGE TEXT PLUS ALL EIGHT INTENSITIES. NORMAL BODY TEXT USES
SCALE 2. HEADINGS MAY USE LARGE TEXT; EMPHASIS AND STRONG
EMPHASIS MAY USE HIGHER INTENSITY, QUOTATIONS MAY USE LOWER INTENSITY, AND A
HORIZONTAL RULE MAY USE A NATIVE VECTOR. FORMATTED SIXMD LAYOUT MAY USE
TYPE-340 DISPLAY COORDINATES; THE 84-BY-42 GRID REMAINS THE CONTRACT ONLY FOR
ORDINARY STREAM TTY PROGRAMS.

THE ORDINARY DPY TTY KEEPS ONLY INTENSITY AS A SPARSE BOUNDED ATTRIBUTE.
FORMATTED SIZE/LAYOUT IS OWNED BY THE SIXMD RENDERER. SEE
`HARDWARE/TYPE340.MD`.

MAN MAY INSERT A GENERATED SYNOPSIS AFTER THE COMMAND TITLE.  IT MAY ALSO
FORMAT OPTIONS AND OTHER STANDARD SECTIONS SPECIALLY, BUT A MINIMAL RENDERER
THAT STRIPS THE ANCHOR AND RENDERS VALID SIXMD REMAINS CORRECT FOR HUMAN
READING.

THIS PROPERTY IS DELIBERATE: THE MACHINE DESCRIPTION REMAINS A READABLE MANUAL
EVEN ON A SMALL RENDERER.

## 13.1 APROPOS INDEX

THE ANCHORED LEVEL-ONE COMMAND HEADING IS ALSO THE AUTHORITATIVE APROPOS
RECORD.  FOR:

    # @?DAS - DAIMOS PDP-6 AND PDP-10 ASSEMBLER

THE INDEX ENTRY IS:

    DAS - DAIMOS PDP-6 AND PDP-10 ASSEMBLER

`APROPOS WORD` SEARCHES THESE ONE-LINE RECORDS AND PRINTS EACH MATCHING RECORD.
IT DOES NOT RENDER THE MANUAL BODY OR THE HELP OPTION/OPERAND SECTIONS.

## 14. VALIDATION

COMMAND MANUALS SHALL BE VALIDATED AT BUILD OR INSTALL TIME.  THE VALIDATOR
SHALL CHECK AT LEAST:

- '%SIXMD 1' IS THE FIRST RECORD;
- SOURCE IS SIXBIT-CLEAN;
- '@' CASE ESCAPES ARE VALID;
- RECORD LENGTH IS WITHIN THE FORMAT LIMIT;
- EXACTLY ONE ANCHORED LEVEL-ONE COMMAND HEADING EXISTS;
- THE COMMAND HEADING HAS A NAME AND SUMMARY;
- ANCHORED SECTION NAMES ARE KNOWN;
- ANCHORED LEVEL-THREE ENTRIES OCCUR ONLY IN A VALID SEMANTIC SECTION;
- OPTION SPELLINGS ARE VALID AND UNIQUE;
- VALUE AND OPERAND METAVARIABLES ARE KNOWN WHERE AUTOMATIC COMPLETION IS
  REQUESTED;
- OPTIONAL/REPEATED OPERAND ORDER IS UNAMBIGUOUS;
- EXIT STATUS VALUES ARE VALID AND UNIQUE;
- SEE ALSO REFERENCES ARE SYNTACTICALLY VALID.

A BAD MANUAL MUST FAIL THE BUILD/INSTALL VALIDATION.  AN INSTALLED BAD OR
MISSING MANUAL MUST DEGRADE HELP/COMPLETION SAFELY; IT MUST NOT CRASH DSH OR A
COMMAND.

THE USER-VISIBLE MISSING-METADATA CONTRACT IS EXPLICIT: `HELP COMMAND` PRINTS
`HELP NOT AVAILABLE`, WHILE `MAN COMMAND` PRINTS `MANUAL NOT AVAILABLE`, AND
RETURNS FAILURE.  THE COMMAND ITSELF REMAINS RUNNABLE.

## 15. COMPILED REPRESENTATION

FULL SIXMD IS AN AUTHORING AND MANUAL-PRESENTATION FORMAT.  PERFORMANCE-SENSITIVE
CONSUMERS SHOULD USE A COMPACT GENERATED REPRESENTATION CONTAINING ONLY THE
FIELDS THEY REQUIRE.

THE BUILD MAY PRODUCE:

- A COMMAND/OPTION/OPERAND INDEX FOR DSH;
- A SMALL PER-COMMAND OPTION/HELP DESCRIPTOR FOR GETOPT AND HELP;
- WHATIS/APROPOS INDEX RECORDS.

THE COMPILED FORM IS DERIVED DATA.  IT SHALL NOT BECOME AN INDEPENDENT SOURCE
OF TRUTH.  REBUILDING IT FROM THE MANUAL MUST REPRODUCE THE SAME SEMANTICS.

## 16. COMPLETE EXAMPLE

    %SIXMD 1
    # @?COPY - COPY FILES

    ## @?OPTIONS

    ### @?-F - FORCE REPLACEMENT
    FORCE REPLACEMENT OF AN EXISTING DESTINATION.

    ### @?-V - VERBOSE
    REPORT EACH FILE COPIED.

    ### @?-O FILE - OUTPUT FILE
    WRITE OUTPUT TO FILE.

    ## @?OPERANDS

    ### @?SOURCE FILE
    FILE TO COPY.

    ### @?DEST FILE
    DESTINATION FILE.

    ## DESCRIPTION

    COPY COPIES SOURCE TO DESTINATION.

    ## EXAMPLES

        COPY OLD.TXT NEW.TXT

    ## @?EXIT STATUS

    ### @?0 - SUCCESS
    ### @?1 - COPY FAILED

    ## @?SEE ALSO

    ### @?MOVE
    ### @?DELETE

FROM THIS ONE SOURCE THE SYSTEM CAN DERIVE THE COMMAND NAME, SUMMARY, SYNOPSIS,
OPTION PARSER TABLE, HELP OUTPUT, DSH COMPLETION CLASSES, MAN OUTPUT, AND INDEX
DATA.

## 17. DESIGN RULES

THE FORMAT SHALL REMAIN SMALL ENOUGH FOR PDP-6/PDP-10 NATIVE TOOLS.

DO NOT ADD A SECOND DECLARATION WHEN EXISTING SIXMD STRUCTURE CAN CARRY THE
MEANING.  DO NOT ADD A COMPLETION-SPECIFIC FIELD WHEN OPTION OR OPERAND SYNTAX
ALREADY DETERMINES COMPLETION.  DO NOT REQUIRE DSH TO PARSE PROSE.  DO NOT ADD
GENERAL MARKDOWN FEATURES TO SOLVE COMMAND-DESCRIPTION PROBLEMS.

NEW SEMANTIC FEATURES SHOULD BE ADDED ONLY WHEN A REAL COMMAND REQUIRES THEM.
