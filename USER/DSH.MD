# DAIMOS DSH CURRENT SUMMARY

DATE: 2026-09-17
STATUS: ACTIVE USERSPACE DESIGN; SEE USER/DSH_DESIGN.MD FOR THE DETAILED HANDOFF.

DSH IS A NATIVE DAIMOS, KSH-INSPIRED SHELL USING BOUNDED SIXBIT-ORIENTED DATA
AND THE DAIMOS RUN/WAIT/DESCRIPTOR PROCESS MODEL.  IT IS NOT A POSIX SH PORT.

## CURRENT KERNEL BASELINE AVAILABLE TO DSH

THE CURRENT KERNEL ALREADY PROVIDES:

- RUN/EXEC/WAIT;
- DESCRIPTOR INHERITANCE/MAPPING AND DUPLICATION;
- CHDIR/GETCWD;
- ANONYMOUS PIPES AND FILESYSTEM FIFOS;
- PROCESS GROUPS AND SESSIONS;
- DOMAINS;
- STOP/CONTINUE AND CHILD STATE REPORTS;
- CONTROLLING TERMINALS AND FOREGROUND PROCESS-GROUP CONTROL;
- NATIVE PROCESS EVENTS.

THESE ARE IMPLEMENTED INPUTS TO DSH, NOT DEFERRED KERNEL FEATURES.  NO SESSIONFS
IS REQUIRED.

## IMMEDIATE BUILD GATE

BEFORE FURTHER DSH FEATURES, THE EXISTING USERSPACE BUILD MUST MOVE FROM
GCC/LIBGCC TO KCC.  DSH MUST BUILD WITH KCC AND PASS THE REAL INIT -> LOGIN ->
DSH ACCEPTANCE PATH.  KCC/DAS DEFECTS EXPOSED BY THIS WORK TAKE PRIORITY.

## NEXT DSH FUNCTIONAL WORK

AFTER THE KCC GATE:

1. USE THE EXISTING PIPE FACILITY FOR PIPELINE EXECUTION;
2. CREATE/JOIN ONE PROCESS GROUP PER JOB/PIPELINE;
3. IMPLEMENT BACKGROUND JOBS AND A SMALL BOUNDED JOB TABLE;
4. IMPLEMENT CTRL-Z, JOBS, BG, FG, AND WHOLE-JOB WAITING;
5. HAND THE CONTROLLING TERMINAL FOREGROUND PROCESS GROUP TO/FROM JOBS;
6. COMPLETE REDIRECTION AND COMMAND SUBSTITUTION ON THE COMMON DESCRIPTOR MODEL;
7. CONTINUE SIXMD-DRIVEN HELP/GETOPT/COMPLETION WORK FROM USER/DSH_DESIGN.MD.

## NAMESPACE DIRECTION

NORMAL SYSTEM PROGRAMS LIVE UNDER /SYSTEM AND OPTIONAL SOFTWARE UNDER /OPTION;
PERSISTENT ADMINISTRATIVE CONFIGURATION LIVES UNDER /CONFIG.

THE CURRENT KERNEL STILL HAS LEGACY SYNTHETIC DEVICE/PROCESS/DOMAIN VIEWS.  THE
ACCEPTED LATER VFS DESIGN IS MONITORFS AT /MONITOR WITH /DEV AS AN I/O-ONLY
ALTERNATE VIEW IMPLEMENTED BY THE SAME CODE.  DSH MUST NOT BAKE THE LEGACY
/DEVICE, /PROC, OR /DOMAIN TREE INTO ITS LANGUAGE OR COMMAND ABI.

## LANGUAGE AND MEMORY RULES

- DSH IS NATIVE DAIMOS SOFTWARE AND USES RUN/WAIT RATHER THAN FORK/EXEC.
- MEMORY USE IS BOUNDED; CORE SHELL DATA STRUCTURES DO NOT REQUIRE UNBOUNDED
  HEAP GROWTH.
- ORDINARY UTILITIES ARE EXTERNAL PROGRAMS; BUILTINS ARE KEPT FOR OPERATIONS
  THAT MUST MODIFY SHELL STATE OR WHERE MEASUREMENT JUSTIFIES RESIDENCY.
- PIPELINE OPERATOR: `!`.
- LOGICAL OPERATORS: `AND`, `OR`, `NOT`.
- BACKGROUND EXECUTION: `COMMAND &`.
- COMPLETION IS ADVISORY AND MUST NEVER PREVENT COMMAND EXECUTION.
- SIXMD MANUAL METADATA IS THE AUTHORITATIVE HELP/GETOPT/COMPLETION DESCRIPTION
  ONCE INSTALLATION TOOLING ENFORCES IT.

THE DETAILED GRAMMAR, FIXED LIMITS, COMMAND POLICY, MANUAL FORMAT, COMPLETION,
AND IMPLEMENTATION PLAN ARE IN USER/DSH_DESIGN.MD AND USER/SIXMD.MD.
