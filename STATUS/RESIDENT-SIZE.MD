# DAIMOS RESIDENT-SIZE STATUS

DATE: 2026-09-17

## CURRENT ACCEPTANCE ACCOUNTING

THE CURRENT SHRINK TARGET IS A 14K TOTAL KERNEL FOOTPRINT.  LOW CORE FROM
000000 THROUGH ABOUT 000060 CONSUMES WORDS OUTSIDE THE KCORE+MRES LINK TOTAL,
SO THE CURRENT MEASURABLE ACCEPTANCE GATE IS:

    KCORE + MRES <= 14288 DECIMAL WORDS

THE CURRENT KCC FULL-BOOT KCORE+MRES OBSERVATION IS ABOUT:

    14525 DECIMAL WORDS

THEREFORE THE CURRENT TREE IS ABOUT 237 WORDS ABOVE THE SHRINK GATE.

THE HARD ARCHITECTURAL LIMIT REMAINS BELOW 16K WORDS INCLUDING ALL RESIDENT AND
SCRATCH KERNEL MEMORY.  THE 14K SHRINK GATE EXISTS TO LEAVE HEADROOM FOR
SYSCALLS AND OTHER KERNEL WORK DURING USERSPACE DEVELOPMENT.

## COMPILER RULE

KCC IS THE ACCEPTANCE COMPILER.  GCC HAS HISTORICALLY GENERATED A SMALLER
KERNEL, AND GCC MEASUREMENTS MAY REMAIN USEFUL COMPILER-QUALITY DATA, BUT A GCC
IMAGE MUST NOT BE USED TO PASS A KCC SIZE GATE.

OLDER 11500-, 11999-, 12288-, 12-KIWORD, 13312-, AND 13-KIWORD TARGETS WERE
EARLIER DEVELOPMENT MILESTONES.  THEY ARE NOT ACTIVE ACCEPTANCE LIMITS.
DETAILED HISTORICAL SIZE SWEEPS REMAIN AVAILABLE IN GIT HISTORY.

## REPORTING REQUIREMENTS

EACH MATERIAL SIZE CHANGE SHOULD RECORD:

- COMPILER AND RELEVANT FLAGS;
- KCORE WORDS;
- EACH NORMAL FULL-BOOT MRES PACKAGE;
- KCORE+MRES TOTAL;
- LOW-CORE OR OTHER RESIDENT/SCRATCH COMPONENTS NEEDED TO INTERPRET THE TOTAL;
- PERFORMANCE CHANGE WHEN SIZE WAS TRADED AGAINST EXECUTION SPEED.

THE TESTKIT SHOULD ENFORCE 14288 FOR THE CURRENT KCC SHRINK PHASE AND SHOULD
KEEP THE BELOW-16K TOTAL ARCHITECTURAL SANITY BOUND DISTINCT FROM THAT TEMPORARY
ENGINEERING TARGET.
