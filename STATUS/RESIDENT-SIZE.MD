# DAIMOS RESIDENT SIZE AND REDUNDANCY REPORT

DATE: 2026-06-28

THIS REPORT RECORDS THE KRES RESIDENT-SIZE FINDINGS FROM THE FIRST KINIT/KRES
AND MINIT/MRES SPLIT WORK, THE COMPACT RESIDENT MODULE TABLE, THE DYNAMIC D6FS
METADATA ALLOCATION, STREAMING '/INIT' EXEC, THE PACKED BOOTDISK BAD-RUN MAP,
AND THE DEFAULT SIMH CLEAN-MEDIA PROFILE THAT COMPILES RESIDENT BAD-RUN STORAGE
OUT OF KRES.

STATUS: HISTORICAL MEASUREMENT NOTES.  THE LIVE SIZE TARGET MUST BE REPAIRED
BEFORE THE NUMERIC BASELINE BELOW IS TREATED AS CURRENT.

THE GOAL IS NOT TO DELETE EVERY LARGE OR CURRENTLY-UNUSED SYMBOL.  SOME CODE IS
INTENTIONAL SCAFFOLDING FOR THE NEXT KERNEL PHASES.  FINDINGS BELOW ARE
THEREFORE CLASSIFIED AS ONE OF:

- **REQUIRED NOW**: NEEDED BY THE CURRENT FULL-STACK BOOT/RUNTIME PATH.
- **LIKELY REMOVABLE NOW**: NO CURRENT KRES CALLER OR RUNTIME NEED FOUND.
- **REDUNDANT REPRESENTATION**: STORES DATA THAT CAN PROBABLY BE DERIVED OR
  REPRESENTED MORE COMPACTLY.
- **FUTURE SCAFFOLDING**: NOT FULLY USED TODAY, BUT PROBABLY BELONGS TO A NEAR
  FUTURE FEATURE AND SHOULD BE GATED OR DOCUMENTED RATHER THAN BLINDLY REMOVED.

## FINDINGS

### BOOTDISK / P6STRIPE

'BOOTDISK_REGION_MAP' IS NO LONGER A LARGE RESIDENT BAD-RUN RESERVATION IN THE
DEFAULT SIMH PROFILE.  IT KEEPS ONLY CLEAN-MEDIA MEMBER/UNIT/START MAPPING.

CLASSIFICATION: **REDUNDANT REPRESENTATION, PARTLY REQUIRED NOW.**

CURRENT REASON:

- KINIT IMPORTS BOOTINFO AND, ON REAL-MEDIA BUILDS, BAD MAPS.
- KRES MUST KEEP ENOUGH ROOT FSREGION MAPPING DATA AFTER KINIT MEMORY IS
  RECLAIMABLE.
- THE OLD DIRECT POINTER INTO KINIT BOOT-SOURCE STATE WAS CORRECTLY REMOVED.

REDUNDANCY:

- THE MAP IS A RESIDENT COPY OF DERIVED BOOTINFO/KINIT BOOT-SOURCE DATA.
- THE DEFAULT BOOT USES CLEAN EMULATOR MEDIA AND SHOULD NOT CARRY BAD-RUN STATE.
- REAL-MEDIA BUILDS MAY STILL NEED COMPACT BAD-RUN OWNERSHIP, BUT THAT SHOULD
  REMAIN COMPILE-TIME GATED UNTIL NEEDED.

ALREADY IMPROVED:

- BAD RUNS ARE PACKED INTO ONE WORD PER '(START,COUNT)' PAIR WHEN REAL-MEDIA
  SUPPORT IS COMPILED IN.

LIKELY NEXT CUTS:

- STORE ONLY ACTIVE MEMBER SLOTS, NOT ALL 16 SLOTS, IF THE REMAINING CLEAN MAP
  BECOMES WORTH SHRINKING.
- KEEP REAL-MEDIA BAD-RUN SUPPORT OUTSIDE THE SIMH PROFILE.
- CONTINUE REPRESENTING FILESYSTEM-LEVEL BAD MEDIA AS HIDDEN PINNED FCBS, NOT
  AS RESIDENT KERNEL TABLES.

RISK:

- DO NOT REINTRODUCE A KRES POINTER INTO KINIT-OWNED BOOTINFO STATE UNLESS
  KINIT LIFETIME IS EXPLICITLY CHANGED.

### PROCESS TABLE

'PROCTAB' IS 400 WORDS.

CLASSIFICATION: **FUTURE SCAFFOLDING / REDUCIBLE FIXED TABLE.**

CURRENT REASON:

- THE CURRENT KERNEL HAS RUDIMENTARY PROCESS STATE FOR PID 1 AND FUTURE PROCESS
  WORK.

REDUNDANCY:

- A FIXED 16-PROCESS RESIDENT TABLE IS LARGER THAN CURRENT FUNCTIONALITY NEEDS.
- CURRENT BOOT ONLY STARTS '/INIT'.

LIKELY NEXT CUTS:

- LOWER THE EARLY PROCESS LIMIT UNTIL FORK/EXEC/PROCESS MANAGEMENT IS REAL.
- ALLOCATE PROCESS RECORDS DYNAMICALLY LATER.
- SPLIT PID 1 BOOTSTRAP STATE FROM THE FUTURE MULTI-PROCESS TABLE.

RISK:

- REMOVING THE TABLE ENTIRELY WOULD FIGHT THE EXPECTED PROCESS MODEL.  THIS IS
  LIKELY NOT DEAD CODE, JUST OVER-PROVISIONED FOR THE CURRENT MILESTONE.

### EXEC BUFFERS AND INTERPRETER

LARGE EXEC RANGES:

'''TEXT
256 WORDS  EXEC_IO_BUF
128 WORDS  EXEC_LOAD_BUF
 95 WORDS  EXEC_USER_SYSCALL
 72 WORDS  EXEC_USER_COPYKPATH
 70 WORDS  EXEC_LOAD_IMAGE
 69 WORDS  EXEC_BYTEPTR_ADDR
'''

CLASSIFICATION: **REQUIRED NOW, WITH REDUNDANT BUFFERING.**

CURRENT REASON:

- '/INIT' IS LOADED FROM D6FS AND ENTERED IN NATIVE PDP-6 USER CONTEXT.
- SYSCALLS NEED COPYIN/COPYOUT AND BYTE-POINTER HANDLING.
- 'EXEC_LOAD_BUF' IS THE BOUNDED WORD BUFFER USED WHILE STREAMING THE DEX IMAGE
  INTO USER MEMORY.
- 'EXEC_IO_BUF' IS THE SYSCALL READ/WRITE BOUNCE BUFFER.
- 'EXEC_RUN_CURRENT_INIT()' IS HOST-TEST-ONLY IN NATIVE SYSCALL BUILDS AND IS
  NOT INCLUDED IN THE PDP-6 RESIDENT IMAGE.

REDUNDANCY:

- TWO STATIC EXEC BUFFERS CONSUME 384 RESIDENT WORDS.
- SOME BYTE-POINTER AND INTERPRETER HELPERS ARE BROADER THAN THE CURRENT TINY
  '/INIT' NEEDS.

LIKELY NEXT CUTS:

- ALLOCATE SYSCALL I/O BUFFER PER PROCESS OR FROM A SMALL TEMPORARY KERNEL
  ALLOCATOR INSTEAD OF KEEPING A GLOBAL 256-WORD STATIC BUFFER.
- CONSIDER SHARING THE LOAD BUFFER AND I/O BUFFER IF THEIR LIFETIMES NEVER
  OVERLAP.
- KEEP STREAMING EXEC; DO NOT RETURN TO WHOLE-IMAGE STAGING.

RISK:

- THIS AREA IS REQUIRED BY THE CURRENT VISIBLE BOOT.  CUTS MUST PRESERVE
  '/INIT' LOADING AND SYSCALL READ/WRITE.

### D6FS

D6FS TOTALS ABOUT 1563 RESIDENT WORDS.

CLASSIFICATION: **REQUIRED NOW, BUT PROBABLY OVER-GENERAL FOR THE FIRST ROOT.**

CURRENT REASON:

- KRES MOUNTS D6FS ROOT.
- '/INIT' AND '/TXT/LOREM.TXT' ARE READ FROM THE D6FS ROOT.
- D6FS NOW ALLOCATES CACHES DYNAMICALLY INSTEAD OF KEEPING STATIC BLOCK CACHE
  STORAGE.

POSSIBLE REDUNDANCIES:

- BOTH BYTE READ AND WORD READ PATHS EXIST.
- LOOKUP, NODE CACHE, LOOKUP CACHE, RUN MAPPING, FCB PARSING, AND STATS ARE
  ALL RESIDENT.
- CURRENT BOOT NEEDS ENOUGH FS TO OPEN AND READ '/INIT'; LATER USERLAND NEEDS
  NORMAL FILE READS.

LIKELY NEXT CUTS:

- AUDIT OVERLAP BETWEEN 'D6FS_FILE_READ' AND 'D6FS_FILE_READ_WORDS'.
- KEEP WORD-READ PATH FOR EXEC ONLY IF IT PROVIDES A REAL SIZE/SIMPLICITY WIN.
- MOVE HUMAN-READABLE FILESYSTEM STATS INTERPRETATION TO USERLAND.

RISK:

- THIS IS NOT FAKE ANYMORE.  D6FS IS PART OF THE CURRENT BOOT PATH.

### MODULE REGISTRY

THE RESIDENT MODULE GROUP IS STILL ABOUT 427 WORDS.

CLASSIFICATION: **PART REQUIRED NOW, PART BOOT-ONLY LEAKAGE.**

ALREADY IMPROVED:

- THE RESIDENT MODULE TABLE IS NOW ONE WORD PER MODULE PLUS SMALL GLOBAL STATE.
- RESIDENT SIXBIT NAME WORDS AND PER-MODULE MRES BASE FIELDS WERE REMOVED.
- KINIT KEEPS DIAGNOSTIC NAMES; KRES STORES NUMERIC IDS AND COMPACT FLAGS.

LIKELY DEAD OR BOOT-ONLY IN KRES:

- 'MODULE_FIND_ID' APPEARS TEST-ONLY IN THE CURRENT RESIDENT PATH.
- 'MODULE_LOAD_*' FUNCTIONS ARE NEEDED DURING KINIT DISPATCH, BUT NOT AFTER
  BOOT.  BECAUSE KINIT CALLS KRES REGISTRATION HELPERS TODAY, THESE FUNCTIONS
  STILL LIVE IN THE RESIDENT IMAGE.
- 'MODULE_MSG_LINE' IS USED BY SOME MINIT/INIT-SIDE MODULE CODE, NOT BY NORMAL
  KRES RUNTIME.

LIKELY NEXT CUTS:

- MOVE SIMPLE MODULE-LOAD REGISTRATION STUBS TO KINIT/MINIT WHERE POSSIBLE.
- KEEP ONLY RESIDENT OPERATIONS NEEDED AFTER BOOT: COUNT/GET BY INDEX, MARK
  ROOT, NUMERIC SYSCTL EXPOSURE, AND PACKED TABLE ACCESS.
- COMPILE-GATE 'MODULE_FIND_ID' OUT OF THE RESIDENT IMAGE IF ONLY TESTS NEED
  IT.

RISK:

- DO NOT LOSE THE RESIDENT MODULE TABLE ITSELF.  IT IS THE RUNTIME SOURCE OF
  MODULE STATE FOR SYSCTL/ADMIN TOOLS.

### SYSCTL

'SYSCTL_READ_WORD' IS 75 WORDS.  '/INIT' NOW PRINTS ALL CURRENT SYSCTL VALUES
AS RAW OCTAL 'SYSCTL OID INDEX VALUE' LINES; THE LARGER PRINTER LIVES IN
USERSPACE INIT, NOT IN KRES.

CLASSIFICATION: **FUTURE SCAFFOLDING / USEFUL ABI.**

CURRENT REASON:

- NUMERIC SYSCTL EXPOSES RAW KERNEL/MODULE/D6FS COUNTERS WITHOUT STRINGS.
- KERNELSPACE STILL DOES NOT CARRY SYSCTL NAMES; USERLAND/ADMIN TOOLING SHOULD
  TRANSLATE NUMERIC OIDS AND FLAGS.
- THIS MATCHES THE DESIGN DECISION THAT FORMATTING BELONGS IN USERLAND TOOLS.

REDUNDANCY:

- IF NO USERLAND ADMIN TOOL CONSUMES IT YET, IT IS RESIDENT FUTURE CODE.

RECOMMENDATION:

- KEEP IT.  IT PREVENTS FUTURE PROCFS/STRING BLOAT AND GIVES A COMPACT ABI FOR
  DIAGNOSTICS.
- AVOID GROWING IT INTO TEXT OUTPUT.

### FILE TABLE AND VFS

'FILETAB' IS 96 WORDS; 'VFS_LOOKUP' IS 126 WORDS.

CLASSIFICATION: **REQUIRED NOW, OVER-PROVISIONED.**

CURRENT REASON:

- '/INIT' NEEDS OPEN/READ/CLOSE.
- SYSCALLS NEED FILE DESCRIPTORS.

REDUNDANCY:

- THE FIXED GLOBAL FILE TABLE IS PROBABLY LARGER THAN THE CURRENT SINGLE-INIT
  WORKLOAD.
- LOOKUP CODE IS GENERAL RELATIVE TO THE TINY CURRENT ROOT USE.

LIKELY NEXT CUTS:

- LOWER EARLY FILE TABLE SIZE OR ALLOCATE DYNAMICALLY ONCE KERNEL ALLOCATION
  POLICY IS SETTLED.
- KEEP VFS IF MULTIPLE FILESYSTEMS REMAIN PLANNED.

RISK:

- THIS IS FOUNDATIONAL FOR REAL USERLAND, NOT DEAD CODE.

### MEMORY MANAGER

MEMORY GROUP IS ABOUT 877 WORDS.

CLASSIFICATION: **REQUIRED NOW, WITH SOME FUTURE STUBS.**

CURRENT REASON:

- KINIT RECLAIM RANGES ARE IMPORTED AT 'MEM_INIT'.
- D6FS METADATA/CACHE ALLOCATIONS USE PERMANENT KERNEL WORD ALLOCATION.
- '/INIT' GETS ITS USER ARENA THROUGH THE MEMORY MANAGER.
- STREAMING EXEC WRITES DIRECTLY INTO USER MEMORY.

LIKELY DEAD OR FUTURE-ONLY TODAY:

- 'MEM_FORK'
- 'MEM_SWITCH'
- 'MEM_GROW'

REQUIRED NOW:

- 'MEM_INIT'
- 'MEM_KALLOC_WORDS'
- 'MEM_TAKE_LARGEST'
- 'MEM_EXEC_BEGIN'
- 'MEM_EXEC_WRITE_WORDS'
- 'MEM_EXEC_COMMIT'
- 'MEM_EXIT'
- STATS/SYSCTL SUPPORT IF SYSCTL IS KEPT

LIKELY NEXT CUTS:

- GATE FUTURE STUBS OUT OF THE RESIDENT BUILD UNTIL CALLERS EXIST.
- AVOID DUPLICATING EXEC-SPECIFIC ARENA STATE IN BOTH PROC AND MEM IF FOUND.

RISK:

- THE ALLOCATOR IS NOW PART OF THE BOOT PATH.  AVOID BROAD REFACTORS UNTIL
  SMALLER DEAD/FUTURE STUBS ARE SEPARATED.

### CONSOLE / DEVICE PROBE MODULES

MANY DRIVER MODULES ARE INTENTIONALLY SIMPLE PROBE/REGISTER CODE TODAY.

CLASSIFICATION: **FUTURE SCAFFOLDING / BOOT DIAGNOSTICS.**

CURRENT BEHAVIOR:

- MOST MODULE MINIT PATHS PROBE AND PRINT 'OK' OR 'REG'.
- SLV IS INTENTIONALLY NODRV AND PRINTS 'NO DRV'.
- REAL DRIVER IMPLEMENTATIONS REMAIN FUTURE WORK.

POTENTIAL REDUNDANCY:

- PROBE-ONLY MRES BODIES MAY NOT BE NEEDED AFTER KINIT RECORDS STATUS.
- SOME FAKE PAYLOADS EXIST ONLY TO MAKE THE SPLIT AND MANIFEST PATH REAL.

RECOMMENDATION:

- DO NOT DELETE THE MODULE STRUCTURE.  INSTEAD CLASSIFY EACH MODULE AS:
  'RESIDENT REQUIRED', 'BOOT PROBE ONLY', 'REGISTERED NO RESIDENT DRIVER', OR
  'NOT PRESENT'.
- RECLAIM OR OMIT BOOT-PROBE-ONLY MRES AFTER KINIT RECORDS THE RESULT.

RISK:

- THIS IS IN-PROGRESS ARCHITECTURE, NOT ACCIDENTAL DEAD CODE.

## RECOMMENDED CUT ORDER

1. ADD OR KEEP 'KRES-SIZE-REPORT' AS THE STANDARD MEASUREMENT BEFORE/AFTER
   EVERY RESIDENT-SIZE CHANGE.
2. COMPILE-GATE TRULY UNUSED RUNTIME STUBS:
   'MEM_FORK', 'MEM_SWITCH', 'MEM_GROW', AND TEST-ONLY MODULE LOOKUP.
3. REMOVE OR GATE 'BOOTDISK_READ_REGION_WORDS' IF NO CURRENT BOOT PATH USES
   REGION WORD READS.
4. KEEP 'DAIMON_BOOT_NO_BAD_RUNS' AS THE DEFAULT EMULATOR PROFILE.  REAL-MEDIA
   BAD-RUN SUPPORT SHOULD BE A SEPARATE BUILD PROFILE AND MUST REJECT MISMATCH
   CASES LOUDLY.
5. COMPACT 'BOOTDISK_REGION_MAP' FURTHER BY STORING ONLY ACTIVE MEMBERS.
6. REDUCE FIXED EARLY TABLES:
   PROCESS TABLE, FILE TABLE, AND EXEC BUFFERS.
7. AUDIT D6FS BYTE/WORD READ OVERLAP.
8. MOVE BOOT-ONLY MODULE REGISTRATION HELPERS OUT OF KRES AFTER THE KINIT/MRES
   BOUNDARY IS STABLE ENOUGH.

## POLICY NOTES

- A LARGE SYMBOL IS NOT AUTOMATICALLY A BUG.
- A CURRENTLY UNUSED SYMBOL IS NOT AUTOMATICALLY DEAD IF IT IS PART OF THE NEXT
  PLANNED SUBSYSTEM.
- PREFER COMPILE-TIME SEPARATION OVER DELETION FOR INTENTIONAL FUTURE ABI.
- DO NOT KEEP HUMAN-READABLE STRINGS IN KRES FOR DIAGNOSTICS; EXPOSE NUMERIC
  FACTS AND LET USERLAND/ADMIN TOOLS TRANSLATE THEM.
- DO NOT REINTRODUCE KRES POINTERS INTO KINIT-OWNED MEMORY MERELY TO SAVE A
  COPY.  IF KRES DEPENDS ON DATA AFTER KINIT, THE DATA MUST EITHER BE RESIDENT,
  COMPACTLY COPIED, OR HAVE A FORMALLY EXTENDED LIFETIME.
