# DAIMOS RESIDENT-SIZE STATUS

DATE: 2026-09-21

## ACTIVE RULE

THE ONLY ACTIVE FIXED-SIZE ACCEPTANCE LIMIT IS THE ARCHITECTURAL REQUIREMENT
THAT FIXED RESIDENT PLUS IRREDUCIBLE SCRATCH KERNEL MEMORY REMAIN BELOW 16K
WORDS.  RECLAIMABLE MANAGED-CORE CACHE DOES NOT COUNT AS FIXED IMAGE MEMORY,
BUT ITS RESIDENT CODE AND NONRECLAIMABLE METADATA DO.

KCC IS THE ACCEPTANCE COMPILER.  GCC RESULTS MAY BE USED FOR CODE-QUALITY
COMPARISON BUT MAY NOT SUBSTITUTE FOR KCC ACCEPTANCE.

## MEASUREMENT POLICY

RUN `MAKE PERMANENT-SIZE` AFTER EVERY MATERIAL KERNEL CHANGE AND RECORD:

- COMPILER AND RELEVANT BUILD OPTIONS;
- KCORE;
- MRES;
- KCORE+MRES;
- PERMANENT_LAST OR EQUIVALENT ADDRESS HIGH-WATER MARK;
- OTHER FIXED RESIDENT/IRREDUCIBLE SCRATCH COMPONENTS NEEDED TO INTERPRET THE
  TOTAL;
- PERFORMANCE CHANGE WHEN MEMORY WAS TRADED AGAINST EXECUTION SPEED.

EXACT PREVIOUS SIZE FIGURES AND FORMER SHRINK TARGETS ARE HISTORICAL DATA.
THEY REMAIN AVAILABLE IN GIT HISTORY AND BUILD LOGS BUT MUST NOT BE COPIED
FORWARD AS CURRENT LIMITS, BASELINES, OR ACCEPTANCE CLAIMS.

## TESTING

THE TESTKIT SHOULD REPORT THE CURRENT KCC ACCOUNTING AND FAIL ON THE HARD
ARCHITECTURAL LIMIT.  THE 32K LOW-MEMORY ACCEPTANCE HARNESS MUST ALSO PROVE THAT
INIT -> LOGIN -> DSH STILL WORKS ON THE MINIMUM MACHINE.


## CURRENT KERNEL/STORAGE MEASUREMENT - 2026-09-21

DEFAULT SINGLE-DISK CONFIGURATION: KCORE+MRES 16242 WORDS, PERMANENT_LAST
037641.  ACTIVE MULTI-MEMBER DSK ROOT: KCORE+MRES 16283 WORDS, PERMANENT_LAST
037712.  THE ROOT BLOCKSET PACKAGE IS 41 WORDS.  A SINGLE D6FS DSK ROOT
BYPASSES BLOCKSET.  THE DISTANCE FROM 037712 TO 040000 IS 54 ADDRESS WORDS,
I.E. 53 UNUSED WORD ADDRESSES FOLLOW THE LAST OCCUPIED WORD.
`MAKE PERMANENT-SIZE` REPORTS BOTH ROOT CONFIGURATIONS AND FAILS IF EITHER
REACHES OR CROSSES 040000.

THE CURRENT STORAGE CHANGES HAVE REMOVED RESIDENT SWAP/LOGSTORE SEMANTICS FROM
BLOCKSET AND REUSE THE ORDINARY ROOT BLOCKSET MAPPER FOR RAW TAIL BLOCKS.
CONTINUE THE HEADROOM SWEEP BEFORE ADDING LARGE NEW RESIDENT STORAGE FEATURES.

## 32K TRANSIENT KINIT IMAGE - 2026-09-21

THE PERMANENT-SIZE LIMIT ABOVE IS NOT THE SAME AS THE TRANSIENT BOOT-IMAGE
LIMIT.  THE FULL KINIT IMAGE CURRENTLY EXTENDS ABOVE A 32K PDP-6 AND IS INTENDED
FOR LARGER CONFIGURATIONS.  `BOOT_PROFILE=LOWMEM` LINKS ONLY THE MRES PACKAGE
SOURCES REQUIRED FOR THE NORMAL CTY/DCS/GE + DSK/D6FS BOOT PATH, GENERATES A
32K SIMH CONFIGURATION, AND BUILDS WITH `BOOT_CORE_WORDS=0100000` AND A
`02000`-WORD KINIT STACK RESERVE.  IMAGE CONSTRUCTION FAILS IF THOSE CANNOT FIT.

THE CURRENT LOWMEM KINIT IMAGE ENDS AT 075762, BELOW THE 076000 IMAGE CEILING.  SWAP ACTIVATION REUSES THE EXISTING FIXED BLOCKSET STATE WORDS; NO DEDICATED RESIDENT SWAP SETTER IS REQUIRED.
A REAL 32K BOOT WITH THE STOCK THREE-LINE INITTAB REACHED INIT AND A DCS ROOT
LOGIN REACHED DSH.  THE OLD AUTOMATED CTY MULTITTY HARNESS IS STALE EVEN ON THE
FULL 256K PROFILE AND MUST BE REPAIRED OR REPLACED; IT MUST NOT BE USED AS A
REASON TO CHANGE WORKING KERNEL BEHAVIOR.
