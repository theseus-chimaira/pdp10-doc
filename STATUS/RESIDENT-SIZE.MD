## COMPILER RULE

KCC IS THE ACCEPTANCE COMPILER.  GCC HAS HISTORICALLY GENERATED A SMALLER
KERNEL, AND GCC MEASUREMENTS MAY REMAIN USEFUL COMPILER-QUALITY DATA, BUT A GCC
IMAGE MUST NOT BE USED TO PASS A KCC SIZE GATE.

OLDER 11500-, 11999-, 12288-, 12-KIWORD, 13312-, AND 13-KIWORD TARGETS WERE
EARLIER DEVELOPMENT MILESTONES.  THEY ARE NOT ACTIVE ACCEPTANCE LIMITS.
DETAILED HISTORICAL SIZE SWEEPS REMAIN AVAILABLE IN GIT HISTORY.

## REPORTING REQUIREMENTS

EACH MATERIAL SIZE CHANGE SHOULD RECORD:

- COMPILER AND RELEVANT FLAGS;
- KCORE WORDS;
- EACH NORMAL FULL-BOOT MRES PACKAGE;
- KCORE+MRES TOTAL;
- LOW-CORE OR OTHER RESIDENT/SCRATCH COMPONENTS NEEDED TO INTERPRET THE TOTAL;
- PERFORMANCE CHANGE WHEN SIZE WAS TRADED AGAINST EXECUTION SPEED.

THE TESTKIT SHOULD CONTINUE TO REPORT THE 14288 SHRINK TARGET, BUT DURING THE
CURRENT EARLY-USERSPACE BRING-UP IT MUST NOT TURN THAT TARGET INTO A STOP
CONDITION WHILE THE SYSTEM BOOTS.  THE BELOW-16K TOTAL RESIDENT+SCRATCH RULE
REMAINS THE HARD LIMIT.  WHEN THE OPTIMIZATION PASS RESUMES, 14288 AGAIN
BECOMES THE ACTIVE SHRINK GOAL.
