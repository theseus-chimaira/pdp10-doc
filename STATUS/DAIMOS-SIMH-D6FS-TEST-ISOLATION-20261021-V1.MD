# SIMH D6FS Root Test Isolation (2026-10-21, V1)

## Observed boot failure

Successive testkit simulator invocations sometimes failed during early
boot, before `/SYSTEM/INIT` could log in.  The console stopped with `?RT`
after loading D6FS.  This marker is deliberately emitted by DAIMOS when
the selected root cannot be mounted or validated; it is not a DSH parser
or HELPER error.

The same test image was reused by independent SIMH harness runs that
modified D6FS and terminated the simulator without a guest filesystem
clean-unmount.  On a reproducible failure, `d6fsck -n 4 -d disk/` reported
selected superblock 704, sequence 2, `DIRTY`.  DAIMOS correctly refused
to mount that filesystem.  Bypassing its dirty-state validation would
weaken crash-consistency guarantees and was not done.

## Testkit fix

`tools/daimos-simh-harness-v4.sh` now accepts the opt-in
`--isolate-media` option.  Its versioned helper
`tools/daimos-simh-isolate-media-20261021-v1.sh` clones the absolute
disk, drum, tape, and ordinary file attachments from the SIMH dofile
into a fresh per-run media directory and writes a temporary boot dofile
that references these private copies.  It preserves TCP port attachments
unchanged.  Sparse media copies use reflinks when supported, but never
hard links, so guest writes cannot change source fixtures.

Nine DSH probe targets opt in.  Other testkit scenarios can retain
intentional cross-session persistence for recovery tests; there is no
kernel change.  The already-dirty root fixture had to be regenerated
once, leaving selected superblock 703, sequence 1, `CLEAN`.

## Verification and limits

The host isolation test modifies a first invocation's disk and drum
copies, then verifies both originals and a subsequent invocation's copies
are unchanged.  Native SIMH packed-name 4/4 and packed-UNALIAS 4/4 suites
pass, as does the full 115/115 DSH conformance suite.  An inspection of
the built source root afterwards still reports `CLEAN` superblock 703,
sequence 1.  This removes the fixture-contamination cause of `?RT` for
these targets; it does not claim all conceivable boot faults are solved.

Only unquoted absolute attachment paths are rewritten.  This matches the
versioned DSH boot.ini generated by the project; a future change to the
SIMH template path syntax must be accompanied by a matching helper test.
