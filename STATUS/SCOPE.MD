# DAIMOS V0.9 CURRENT SCOPE

DATE: 2026-09-24

THIS FILE SUMMARIZES CURRENT V0.9 SCOPE.  DAIMOS/PROJECT-STATE.MD IS THE
AUTHORITATIVE CURRENT PROJECT-STATE SOURCE.

## MACHINE BASELINE

- MINIMUM/INITIAL TARGET: PDP-6 WITH 32K WORDS OF CORE.
- PDP-10 BACKENDS MAY ADD MACHINE-SPECIFIC FACILITIES WITHOUT RAISING THE PDP-6
  BASELINE.
- THE VM/MM INTERFACE MUST REMAIN REPLACEABLE BY A MACHINE-SPECIFIC PAGER
  BACKEND WITHOUT CHANGING GENERIC PROCESS/EXEC SEMANTICS.

## KERNEL MEMORY

- HARD ARCHITECTURAL LIMIT: BELOW 16K WORDS INCLUDING FIXED RESIDENT AND
  IRREDUCIBLE SCRATCH KERNEL MEMORY.
- KCC IS THE ACCEPTANCE BUILD; GCC SIZE IS COMPARISON DATA ONLY.
- EXACT KCORE/MRES AND PERMANENT-LAST VALUES ARE DATED BUILD MEASUREMENTS AND
  MUST BE REGENERATED AFTER MATERIAL KERNEL CHANGES.

## V0.9 PROCESS/IPC MODEL

V0.9 INCLUDES NATIVE:

- PROCESSES AND EXEC IMAGE REPLACEMENT;
- PROCESS GROUPS;
- SESSIONS;
- DOMAINS AS A SEPARATE PROCESS-CONTROL SCOPE;
- CONTROLLING TERMINALS AND FOREGROUND GROUPS;
- STOP/CONTINUE AND THE COMPACT NATIVE EVENT MODEL;
- DESCRIPTOR-BASED I/O;
- ANONYMOUS PIPES AND FILESYSTEM-NAMED FIFOS;
- UID/GID AND OWNER/GROUP/OTHER FILE PERMISSIONS.

NO SESSIONFS IS REQUIRED.

## USERSPACE/SELF-HOSTING SCOPE

THE NORMAL BOOT IS KINIT -> /SYSTEM/INIT -> LOGIN -> CONFIGURED SHELL.
/CONFIG/FSTAB, /CONFIG/INITTAB, AND /CONFIG/PASSWD ARE THE CURRENT USERSPACE
CONFIGURATION BASELINE.  KINIT DISCOVERS AND MOUNTS ONLY THE BOOT ROOT.
OPTIONAL MEMFS SCRATCH STORAGE IS MOUNTED BY INIT FROM FSTAB POLICY.  INIT
WARNS, BUT CONTINUES BOOTING, WHEN MEMFS IS NOT MOUNTED ON /TEMP; THIS IS
EXPECTED ON THE 32K LOWMEM PROFILE.

KCC IS THE REQUIRED NORMAL C COMPILER FOR BOTH KERNEL AND USERSPACE.  CURRENT
NORMAL USERSPACE BUILDS WITH KCC/DAS WITHOUT LIBGCC.  THE CURRENT ORDER IS:

    CLOSE THE COMPLETE PRE-USERLAND KERNEL/STORAGE GATE
    KEEP MONITORFS + /PROC + /DEV AND FILESYSTEM-SYSCALL REGRESSIONS PASSING
    SUBSTANTIAL DSH AGAINST THE STABILIZED NAMESPACE
    USEFUL DAIMOSV1 CORE-UTILITY PORTS
    MAKE
    DAS + DLINK + DARC
    KCC RUNNING UNDER DAIMOS

DO NOT ADD A BROAD SYSCTL/DEVIO COMPATIBILITY ABI.  ADD THIN NATIVE SYSCALLS ONLY
FOR DEMONSTRATED USERSPACE NEEDS; USE MONITORFS FOR INTROSPECTION.

THE STANFORD PHIL PETIT PCLK AT DEVICE 0730 IS THE STANDARD PDP-6 WALL-CLOCK
SOURCE.  DAIMOS SUPPORTS PCLK CIVIL DATES FROM 2026-01-01 THROUGH 2125-12-31.
THE APR 60 HZ LINE CLOCK REMAINS THE MONOTONIC SCHEDULER CLOCK; THERE IS NO
SERIAL RTC/RTCD STANDARD PATH.

## FILESYSTEM/VFS SCOPE

D6FS IS THE NATIVE WRITABLE DISK FILESYSTEM.  DTFS PERSONALITIES SHARE ONE
ENGINE; FOREIGN PERSONALITIES ARE OPTIONAL TEST BUILDS.

THE LANDED PRE-DSH VIRTUAL-FILESYSTEM STATE VIEW IS:

    /MONITOR/PROCESSES       PROCESS STATE
    /MONITOR/DOMAINS     DOMAIN STATE
    /MONITOR/DEVICES    DEVICE STATE/STATISTICS
    /DEV                DIRECT DEVICE I/O ENDPOINTS

PROCESS DIRECTORIES EXPOSE PPID, STATE, WORDS, NAME, CMDLINE, AND ENVIRONMENT.
NAME/CMDLINE/ENVIRONMENT ARE DERIVED ON DEMAND FROM THE LIVE USER IMAGE RATHER
THAN COPIED INTO PER-PROCESS RESIDENT KERNEL STATE.  DOMAIN DIRECTORIES EXPOSE
PROCESSES, WORDS, SWAPPED, SWAPWORDS, STOPPED, AND PIDS; PIDS IS DERIVED BY
SCANNING THE PROCESS TABLE AND HAS NO RESIDENT MEMBERSHIP TABLE.

THE ROOT NAMES /DEVICE AND /DOMAIN ARE NOT EXPOSED.  /PROC IS AN ALIAS OF /MONITOR/PROCESSES.  STATIC MONITORFS
NAMESPACE LOOKUP/READDIR SHARE ONE VFS NAME TABLE, AND SYNTHETIC GETCWD USES
THE NORMAL VFS PARENT-NAME WALK RATHER THAN THREE ABSOLUTE-PATH FORMATTERS.
MONITORFS IS THE SOLE STATE-FILESYSTEM IMPLEMENTATION; ITS COMPACT VIEW PROVIDER
IDS ARE AN INTERNAL BACKEND DETAIL, NOT A SECOND STATE FILESYSTEM.

## STORAGE SCOPE

D6FS MAY OWN ZERO/ONE SWAP RESERVATION AND ZERO/ONE LOGSTORE RESERVATION.
THEY ARE RAW LOGICAL RANGES, NOT FILES.  VFS REGISTERS THEM WITH THE SERVICE;
ACTIVE I/O BYPASSES NORMAL FILE I/O.  THE STORAGE-SET LAYER OWNS PHYSICAL
DISTRIBUTION AND ONE COMMON DISK/DRUM BAD-MEDIA EXCEPTION MAP; DEVICE-SPECIFIC
SCHEDULING AND RETRY REMAIN IN EACH PHYSICAL DRIVER.

ON SPINNING DISK MEDIA, FORMAT/MAINTENANCE POLICY PREFERS SWAP AT THE OUTER
EDGE AND LOGSTORE AT THE INNER EDGE AFTER THE BOOT AREA, WITH GEOMETRY-ALIGNED
SIZES.  DRUMSETS HAVE NO INNER/OUTER PLACEMENT RULE.

## BOOT AND RECOVERY

KINIT MUST REMAIN SMALL AND RECLAIM BOOT-ONLY CODE/DATA.  NORMAL SYSTEM POLICY
MOVES TO PID-1 INIT AS USERSPACE INTERFACES BECOME AVAILABLE.

A RECOVERY/SINGLE-USER ENVIRONMENT IS REQUIRED EVENTUALLY BUT IS EXPLICITLY
POST-0.9.  THE ACCEPTED DIRECTION IS BOOTABLE RECOVERY DECTAPE MEDIA USING THE
NORMAL MAINTENANCE TOOLS, NOT AN EMERGENCY INITFS ROOT.  DO NOT SCHEDULE ITS
IMPLEMENTATION AS CURRENT V0.9 WORK.

## TEST/ACCEPTANCE SCOPE

- REAL LOGIN, NOT A BARE DSH PROMPT, IS THE NORMAL SYSTEM REACHABILITY TEST.
- KEEP A COMPLETE 32K PDP-6 LOGIN/DSH ACCEPTANCE PATH.
- THE TOP-LEVEL REGRESSION GATE MUST COVER NORMAL MULTIUSER BOOT AND KCC-BUILT
  USERSPACE.
- COMPILER/ASSEMBLER BUGS TAKE PRIORITY OVER FEATURE DEVELOPMENT.
