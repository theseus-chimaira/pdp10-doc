DISKSET IS AN INDEPENDENT MRES.  D6FS DOES NOT LINK OR OWN MEMBER, STRIPE,
SWAP, OR LOGSTORE MAPPING.  THE CURRENT PROFILE HAS AT MOST FOUR MEMBERS.
UNEQUAL-MEMBER D6FS MAPPING IS PRESERVED.  SWAP TAILS ARE MEMBER-CONTIGUOUS
AND THE RAW SWAP API ACCEPTS BOUNDED RUNS.

LOGSTORE V1 IS A RAW-DISK PERSISTENT CIRCULAR RECORD QUEUE.  BLOCKS ZERO AND
ONE ARE ALTERNATING LSSTA1 STATE BLOCKS; EVERY LATER BLOCK CONTAINS ONE LSREC1
RECORD.  RECORD AND STATE COMMIT TRAILERS ARE PHYSICALLY LAST.  RECOVERY SCANS
THE BOUNDED REGION, RECORDS ARE AUTHORITATIVE FOR APPEND POSITION, AND THE A/B
STATE HOLDS THE DRAIN FLOOR AND PERSISTENT LOSS COUNT.

THE FULL-RING POLICY KEEPS THE NEWEST RECORDS.  BEFORE AN UNDRAINED RECORD IS
OVERWRITTEN, LOGSTORE DURABLY ADVANCES THE DRAIN FLOOR AND LOSS COUNT.  LOGGING
NEVER WAITS FOR MAGTAPE.

THE MTC516 RAW SERVICE PROVIDES RECORD READ/WRITE, STATUS, REWIND, FILEMARK,
RECORD SPACING, AND FILEMARK SPACING.  EOF, EOT, AND DETACHED-UNIT READINESS
ARE COVERED BY A PRODUCTION ONLINE ORACLE.  REEL AND ARCHIVE POLICY DO NOT LIVE
IN THE DRIVER.

THE COLD ONE-RECORD DRAIN IS IMPLEMENTED AND VERIFIED.  IT:

- USES A CALLER-OWNED 128-WORD BUFFER;
- READS THE NEXT COMMITTED LSREC1 RECORD DIRECTLY FROM THE RAW REGION;
- USES ONE MTC STATUS/READINESS PREFLIGHT;
- WRITES THE SAME 128 WORDS AS ONE TAPE RECORD WITHOUT CONVERSION OR COPY;
- PERSISTS THE ACK ONLY AFTER SUCCESSFUL TAPE COMPLETION;
- ISSUES NO POST-WRITE STATUS COMMAND;
- ACKNOWLEDGES A SUCCESSFUL WRITE THAT REACHES EOT;
- OBSERVES EOT ON THE NEXT PREFLIGHT;
- RETRIES AFTER TAPE FAILURE OR TORN ACK;
- INTENTIONALLY ALLOWS A DUPLICATE AFTER CRASH, PROVIDING AT-LEAST-ONCE
  ARCHIVAL.

## NEXT IMPLEMENTATION PLAN

### PHASE 1: RUNTIME LOGSTORE SERVICE

ADD THE SMALLEST RUNTIME SERVICE/BRIDGE THAT CAN CALL THE EXISTING DISKSET AND
MTC SERVICES.  THE DRAIN BUFFER MUST BE PROVIDED BY THE PROCESS-CONTEXT CALLER
OR BORROWED FROM AN EXISTING MUTUALLY EXCLUSIVE WORKSPACE.  DO NOT RESERVE A
NEW PERMANENT 128-WORD ARRAY.

MEASUREMENT GATE: RECORD TEXT, DATA, BSS, STACK, KCORE, AND CONCURRENT MRES
RESIDENCY.  REJECT A GENERAL QUEUE, GENERAL WORKER FRAMEWORK, OR DUPLICATE I/O
WRAPPER IF A NARROW DISPATCH OPERATION IS SMALLER.

### PHASE 2: DRAIN WORKER AND REEL POLICY

RUN THE DRAIN ONLY IN PROCESS CONTEXT.  ADD START, STOP, STATUS, CLEAN
FILEMARK/REEL CLOSE, REEL CHANGE, AND RESUMPTION.  ADD EXPLICIT GAP REPORTING
FOR PERSISTENTLY LOST RECORDS.  PRODUCERS AND INTERRUPT PATHS MUST NEVER WAIT
FOR TAPE.

MEASUREMENT GATE: ONE SUCCESSFUL RECORD SHOULD REQUIRE ONE RAW-DISK READ, ONE
MTC STATUS PREFLIGHT, ONE MTC WRITE, AND ONE A/B ACK STATE WRITE.  DO NOT ADD A
POST-WRITE STATUS COMMAND.

### PHASE 3: PROCESS SWAPPING

BUILD PROCESS SWAP POLICY ABOVE THE EXISTING RAW SWAP RUN API.  DEFINE IMAGE
ALLOCATION, OWNERSHIP, RETRY, AND PROCESS-STATE TRANSITIONS BEFORE CHANGING
THE DISK DRIVER.  KEEP SWAP OUT OF D6FS AND VFS.

MEASUREMENT GATE: COLLECT REAL RUN LENGTHS, MEMBER-BOUNDARY FREQUENCY, AND TIME
SPENT IN PER-SECTOR SETUP.

### PHASE 4: CONDITIONAL DSK270 STREAMING

REVISIT HARDWARE MULTI-SECTOR STREAMING ONLY IF PHASE 3 MEASUREMENTS SHOW A
MATERIAL SPEED BENEFIT WORTH THE RESIDENT COST.  NEVER STREAM ACROSS THE
DSK270 SECTOR 43 TO ZERO CYLINDER BOUNDARY UNTIL BOTH SIMULATOR AND HARDWARE
BEHAVIOR ARE PROVEN SAFE.
