# IMG2DPIC

IMG2DPIC IS THE HOST-SIDE IMAGE-CONVERSION TOOL FOR DAIMOS TYPE 340 VECTOR
DISPLAY CONTENT.  IT IS SPECIFIC TO THE TYPE 340 FAMILY.  COLORSCOPE OUTPUT
USES A DIFFERENT DISPLAY MODEL AND SHALL USE A DISTINCT FILE FORMAT AND
CONVERTER PATH RATHER THAN SHARING THE TYPE 340 STREAM FORMAT.

## TYPE 340 INPUT CONTRACT

IMG2DPIC ACCEPTS OPAQUE SINGLE-FRAME INPUT IMAGES AND CONVERTS THEM TO 1 BIT
INTERNALLY.

THE CURRENT INPUT RULES ARE:

- BOTH SOURCE DIMENSIONS MUST BE GREATER THAN 1024 PIXELS.
- THE SOURCE MUST BE SQUARE OR NEAR-SQUARE.
- NEAR-SQUARE MEANS THE SIDE LENGTHS MAY DIFFER BY AT MOST 1/64 OF THE LARGER
  SIDE.
- TRANSPARENCY IS NOT ALLOWED.

THE HOST TOOL USES THE IMAGEMAGICK MAGICKWAND API TO READ THE SOURCE, SCALE IT
TO EXACTLY 1024X1024, CONVERT IT TO GRAYSCALE, AND THRESHOLD IT AT 50 PERCENT.
HIGHER-BIT-DEPTH OR COLOR INPUTS ARE THEREFORE ACCEPTED; THEY DO NOT HAVE TO
BE PRECONVERTED TO MONOCHROME.  THE CONVERTER MATERIALIZES ONE 1024X1024
HOST-SIDE BILEVEL RASTER; IT DOES NOT CREATE AN INTERMEDIATE PBM FILE.

## TYPE 340 CONVERSION

TYPE 340 PHYSICAL POLARITY IS BRIGHT-ON-DARK: INTENSIFIED PIXELS ARE BRIGHT
AND UNTOUCHED PIXELS ARE DARK.  IMG2DPIC THEREFORE EMITS WHITE THRESHOLDED
IMAGE PIXELS AS LIT DISPLAY PIXELS AND LEAVES BLACK PIXELS DARK.  IT ALSO
REFLECTS RASTER Y BECAUSE IMAGE ROW ZERO IS THE TOP EDGE WHILE TYPE 340 Y=0
IS THE BOTTOM EDGE.

IMG2DPIC GENERATES TWO EXACT REPRESENTATIONS OF THE SAME THRESHOLDED BITMAP
AND EMITS THE SHORTER ONE.

THE VECTOR-RUN REPRESENTATION FINDS CONTIGUOUS LIT RUNS AND MEASURES FOUR
ENCODINGS: HORIZONTAL AND VERTICAL RUNS, EACH WITH EITHER SERPENTINE START
DIRECTION.  IT USES NON-INTENSIFIED VECTORS TO MOVE BETWEEN RUNS AND
INTENSIFIED VECTORS TO DRAW THEM.

THE INCREMENTAL REPRESENTATION COVERS LIT PIXELS WITH 8-CONNECTED ONE-PIXEL
PATHS.  FOUR PATH STEPS FIT IN ONE 18-BIT TYPE-340 INCREMENTAL INSTRUCTION.
PATH STARTS ARE INTENSIFIED WITH A ZERO-LENGTH VECTOR BEFORE ENTERING
INCREMENTAL MODE.  A FINAL ONE-TO-THREE STEP TAIL IS NOT ZERO-PADDED IN
INCREMENTAL MODE, BECAUSE THAT WOULD RE-INTENSIFY THE LAST PIXEL.  INSTEAD THE
TAIL IS DRAWN AS ONE-PIXEL VECTOR INSTRUCTIONS.  THIS PRESERVES THE PIXEL SET
AND AVOIDS ARTIFICIALLY BRIGHTENING PATH ENDPOINTS ON A REFRESH CRT.

ON THE 2026-10-07 25-PICTURE DAIMOS CORPUS THE FINAL LOSSLESS CHOOSER REDUCED
THE DISPLAY PROGRAM TOTAL FROM 359396 TO 239465 WORDS, ABOUT 33.4 PERCENT.
PICTURE08 FELL FROM 30324 TO 15092 WORDS.  WITH THE CURRENT SIMH TYPE-340
FIXED PER-WORD DELAY THIS CORRESPONDS TO ABOUT 3.03 SECONDS VERSUS 1.51
SECONDS PER PASS.

THE OPTIMIZED PROGRAMS WERE RENDERED BACK TO 1024X1024 BITMAPS AND COMPARED
WITH THE ORIGINAL 25 THRESHOLDED RASTERS; ALL 25 MATCHED BIT FOR BIT.

ONE TYPE 340 VECTOR INSTRUCTION HAS A SEVEN-BIT MAGNITUDE FIELD PER AXIS, SO
THE MAXIMUM VECTOR DELTA IS 127 PIXELS.  LONG MOVES AND HORIZONTAL RUNS ARE
SPLIT INTO MULTIPLE VECTOR SEGMENTS.

THE CURRENT TYPE 340 PROGRAM LIMIT IS 32256 WORDS, MATCHING DPYVIEW.  A
RASTER WHICH CANNOT BE ENCODED WITHIN THAT LIMIT IS REJECTED INSTEAD OF
PRODUCING A FILE THE TARGET VIEWER CANNOT LOAD.

## OUTPUT FORMAT

THE TYPE 340 OUTPUT IS A RAW NATIVE DISPLAY-PROGRAM WORD STREAM.

EACH HOST FILE ELEMENT IS ONE LITTLE-ENDIAN 64-BIT CONTAINER.  THE LOW 36
BITS CONTAIN ONE PDP-6/PDP-10 WORD, AND THAT WORD CONTAINS TWO 18-BIT TYPE 340
INSTRUCTIONS.  THE HIGH 28 BITS OF EACH HOST CONTAINER ARE ZERO.

THIS FILE FORMAT IS NOT A GENERIC PICTURE FORMAT.  IT EXISTS TO MINIMIZE
TARGET-SIDE MEMORY AND CPU COST: DAIMOS CAN PASS THE PRECOMPILED TYPE 340
PROGRAM TO THE DISPLAY PATH WITHOUT IMAGE DECODING, SCALING, OR RASTER
CONVERSION.

## HOST DEPENDENCIES

THE CURRENT IMPLEMENTATION IS A C99 HOST PROGRAM USING IMAGEMAGICK'S MAGICKWAND
API.  BUILDING IMG2DPIC REQUIRES THE IMAGEMAGICK DEVELOPMENT HEADERS AND
LIBRARIES DISCOVERABLE AS `MAGICKWAND` THROUGH `PKG-CONFIG` (FOR EXAMPLE,
`LIBMAGICKWAND-DEV` ON DEBIAN-FAMILY SYSTEMS).  PYTHON IS NOT REQUIRED.

THE COMMAND FORM IS:

    IMG2DPIC -T 340 INPUT OUTPUT

TYPE 340 IS CURRENTLY THE ONLY IMPLEMENTED IMG2DPIC TARGET.
