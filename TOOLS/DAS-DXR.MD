### RECENT PROGRESS: STRICT BASE PROFILE AUDIT SLICE

STRICT DAIMOS V1 BASE MODE NOW REJECTS THE FIRST BROADER NON-BASE GROUP:
XMOVEI, DMOVE-FAMILY FORMS, DOUBLE-PRECISION ARITHMETIC, AND FLOATING-POINT
FORMS.  THIS IS HOST-ONLY CHECKING; IT DOES NOT ADD CODE TO THE COMPACT NATIVE

### RECENT PROGRESS: STRICT BASE PROFILE I/O SPLIT

STRICT DAIMOS V1 BASE MODE NOW KEEPS BYTE-POINTER INSTRUCTIONS SUCH AS
ADJBP, IBP, ILDB, LDB, IDPB, AND DPB AVAILABLE.  DAIMOS REQUIRES BYTE
MANIPULATION, SO THESE REMAIN PART OF THE BASE PROFILE.

PLAIN '--BASE' NOW REJECTS PDP-10 I/O INSTRUCTION MNEMONICS.  KERNEL AND
DRIVER SOURCES CAN USE '--BASE-KERNEL', WHICH KEEPS THE SAME BASE/DEFERRED
OPCODE CHECKS BUT PERMITS BLKI, DATAI, BLKO, DATAO, CONO, CONI, CONSZ, AND
CONSO.  THIS KEEPS USER-MODE BASE BUILDS FROM ACCIDENTALLY ACCEPTING
PRIVILEGED I/O INSTRUCTIONS WHILE PRESERVING A COMPACT PATH FOR KERNEL CODE.

KCC CORPUS CASES SHOULD BE RUN ONE BY ONE, NOT ONLY THROUGH THE FULL WRAPPER.
THIS MAKES TIMEOUTS AND COMPATIBILITY FAILURES ATTRIBUTABLE TO A SPECIFIC
SOURCE FILE. THE CURRENT INDIVIDUAL CASES ARE:

'''TEXT

DATA.C
BRANCH.C
'''

FOR EACH CASE, KCC EMITS ASSEMBLY, 'DAS' ASSEMBLES IT TO DXR,
'DXR-KCC-CORPUS-CHECK.PY' VALIDATES THE EXPECTED DXR SHAPE, AND 'DXRCHECK'
VALIDATES THE CONTAINER.

### RELOCATION HARDENING UPDATE

THE REGRESSION SUITE NOW COVERS RELOCATION BITMAP BOUNDARY OFFSETS 71 AND
72, INCLUDING RELOCATION IN THE FINAL IMAGE WORD. IT ALSO VERIFIES
SYMBOL-MINUS-CONSTANT EXPRESSIONS IN INSTRUCTION EFFECTIVE ADDRESSES AND
RIGHT-HALF DATA WORDS.

THE EXPRESSION EVALUATOR REJECTS MALFORMED OR UNSAFE RELOCATION FORMS SUCH
AS UNARY RELOCATABLE NEGATION AND MIXED MULTI-SYMBOL EXPRESSIONS LIKE
'A-B+C'. DXR V1 STILL SUPPORTS ONLY ADDR18 RELOCATION AND STILL REJECTS
FULL-WORD AND LEFT-HALF RELOCATION.

'DXRCONVERT' IS NOW THE SINGLE HOST-SIDE CONVERTER TOOL FOR DXR OUTPUT. IT

### GCC FLAT-DXR CORPUS STUB

THE GCC PDP-10 BACKEND EMITS A CALL TO '__MAIN' IN ORDINARY C OUTPUT.
DXR V1 DELIBERATELY HAS NO EXTERNAL SYMBOL TABLE OR LINK STEP, SO TESTS THAT
ASSEMBLE STANDALONE GCC OUTPUT APPEND 'TESTS/GCC-MAIN-STUB.S':

'''ASM
        .GLOBL __MAIN
__MAIN:
        POPJ 17,
'''

THIS IS A TEST HARNESS STUB ONLY. IT MUST NOT BE INTERPRETED AS EXTERNAL SYMBOL
SUPPORT IN DXR V1.

## DAS SYNTAX
'DAS' IS THE DAIMOS DXR ASSEMBLER. THE ONLY OUTPUT FORMAT IS DXR V1.
HOST-SPECIFIC CONVERSION TO PAPER TAPE, SIMH SCRIPTS, RIM, BIN, OR OTHER
TRANSFER FORMATS BELONGS IN SEPARATE TOOLS.

### SECTIONS AND ENTRY

'''TEXT
.TEXT
.DATA
.BSS
.ENTRY NAME
.END
'''

COMPATIBILITY DIRECTIVES ACCEPTED WHERE THEY DO NOT AFFECT DXR OUTPUT:

'''TEXT
.GLOBL NAME
.GLOBAL NAME
.EXTERN NAME
'''

IF '.ENTRY' IS ABSENT, 'MAIN' IS USED WHEN PRESENT. OTHERWISE THE ENTRY OFFSET
IS ZERO.

### INCLUDE FILES

LINUX TOOLING BUILDS ACCEPT:

'''TEXT
.INCLUDE "FILE"
'''

RELATIVE INCLUDES ARE RESOLVED FROM THE INCLUDING FILE. INCLUDE HANDLING IS NOT
PART OF THE COMPACT NATIVE PRODUCTION PATH.

### DATA PSEUDO-OPS

CURRENTLY SUPPORTED HOST CONVENIENCE FORMS INCLUDE:

'''TEXT
EXP EXPR
.WORD EXPR
.LONG LEFT,RIGHT
POINT SIZE,ADDR,POS
GIW ADDR
OWGBP SELECTOR,ADDR
OWGBP SELECTOR,GIW ADDR
.BYTE SIZE,VALUE,...
.BYTE SIZE VALUE VALUE
.ASCII /TEXT/
.ASCIZ /TEXT/
SIXBIT /TEXT/
.SIXBIT /TEXT/
'''

'SIXBIT' PACKS SIX 6-BIT CHARACTERS PER DAIMOS WORD, FOLDS LOWER-CASE INPUT TO
UPPER CASE, AND ZERO-PADS THE FINAL WORD.

'.ASCII' AND '.ASCIZ' PACK 7-BIT BYTES, FIVE CHARACTERS PER 36-BIT WORD.
'.ASCIZ' APPENDS A ZERO BYTE.

'.BYTE' ACCEPTS COMMA-SEPARATED OR WHITESPACE-SEPARATED VALUES. A '(N)' SIZE
OVERRIDE PERSISTS UNTIL ANOTHER OVERRIDE APPEARS. RELOCATION INSIDE '.BYTE' IS
REJECTED.

### RELOCATION RULES

ALLOWED RELOCATABLE CONTEXTS:

'''TEXT
INSTRUCTION EFFECTIVE-ADDRESS FIELD
INSTRUCTION EFFECTIVE-ADDRESS FIELD WITH INDEX
INSTRUCTION EFFECTIVE-ADDRESS FIELD WITH INDIRECTION
EXPLICIT RIGHT HALF: 0,,SYMBOL
'''

EXAMPLES:

FULL-WORD RELOCATION
RELOCATION INSIDE .BYTE OR ASCII TEXT PACKING
'''

### STRICT BASE PROFILE

HOST 'DAS' DEFAULTS TO THE BROAD COMPATIBILITY OPCODE TABLE WHILE REPLACEMENT
WORK IS IN PROGRESS. FOR DAIMOS V1 PROFILE CHECKS, USE:

'''TEXT
--BASE
--STRICT-BASE
'''

STRICT BASE MODE REJECTS AUDITED NON-BASE COMPATIBILITY MNEMONICS SUCH AS
'XMOVEI', 'DMOVE*', DOUBLE-PRECISION ARITHMETIC, AND FLOATING-POINT FORMS.
THE STRICT REJECTION TABLE IS HOST-ONLY AND IS NOT CARRIED BY THE DEFAULT
NATIVE PRODUCTION BUILD. FLOATING POINT IS DEFERRED FOR THE DAIMOS V1 BASE
PROFILE, EVEN WHEN THE BROAD HOST COMPATIBILITY TABLE CAN ENCODE THOSE
INSTRUCTIONS.

'--BASE-KERNEL' PERMITS KERNEL I/O MNEMONICS WHILE KEEPING THE SAME NON-BASE
REJECTION RULES.

## DAS NATIVE BUILD POLICY
THE DAIMOS NATIVE ASSEMBLER PATH IS BUILT FOR A 256KW-CLASS MACHINE WHERE THE
OPERATING SYSTEM AND OTHER RESIDENT STATE MUST SHARE MEMORY WITH THE TOOL. THE
NATIVE PATH IS THEREFORE SIZE-FIRST.

### BUILD SPLIT

'''TEXT
DAS_NATIVE
  COMPACT MEMORY-TO-MEMORY ASSEMBLER CORE
  NO LINUX FILE/PARSER/TOOLING PATH
  NO STDIO
  NO STDLIB
  NO STRING.H
  NO CTYPE.H
  NO ARGV
  NO FILE I/O

DAS_NATIVE_SELFTEST
  NATIVE SELF-TEST RECORDS AND EXPECTED-OUTPUT TABLES
  INCLUDED ONLY FOR TESTS

'''

THE DEFAULT 'DAS_NATIVE' PRODUCTION BUILD DOES NOT CARRY THE FULL COMPATIBILITY
OPCODE TABLE AND DOES NOT PERFORM MNEMONIC LOOKUP. NATIVE SOURCE RECORDS CARRY
NUMERIC OPCODES DIRECTLY. HOST TOOLING KEEPS THE FULL TABLE AND STRING-BASED
MNEMONIC COMPATIBILITY.

### NATIVE MEMORY SELF-TEST

THE NATIVE BUILD PATH HAS A MEMORY-TO-MEMORY SELF-TEST. IT DOES NOT USE C
STRING SOURCE RECORDS. THE EMBEDDED SOURCE IS A SMALL NUMERIC RECORD STREAM:

'''TEXT
LABEL MAIN
MOVEI 1,MSG
JRST DONE
LABEL MSG
WORD 0123456
LABEL DONE
HALT
BSS 5
END
'''

THE SELF-TEST ASSEMBLES THAT RECORD STREAM INTO AN IN-MEMORY DXR WORD VECTOR
AND COMPARES EVERY PRODUCED 36-BIT WORD AGAINST THE EXPECTED DXR STREAM:

'''TEXT
WORD 0: DXR,,0
WORD 1: 4,,5
WORD 2: MOVEI 1,MSG
WORD 3: JRST DONE
WORD 4: 0123456
WORD 5: HALT
WORD 6: RELOCATION BITMAP WITH BITS 0 AND 1 SET
'''

THIS IS NOT THE FINAL NATIVE ASSEMBLER FRONTEND. IT PROVES THE NATIVE-SAFE
ENCODER, SYMBOL HANDLING, DXR HEADER WRITER, AND RELOCATION BITMAP BUILDER CAN
RUN WITHOUT THE LINUX TOOLING PATH.

### REDUNDANCY POLICY

THE NATIVE MEMORY-TO-MEMORY ASSEMBLER DOES NOT KEEP SEPARATE IMAGE AND
RELOCATION-MAP WORK BUFFERS. AFTER THE FIRST PASS DETERMINES SYMBOL VALUES AND
IMAGE SIZE, THE SECOND PASS WRITES IMAGE WORDS DIRECTLY INTO THE CALLER-PROVIDED
DXR OUTPUT BUFFER AND SETS RELOCATION BITMAP BITS IN PLACE. NATIVE RECORDS USE
NUMERIC OPCODES, SO THE PRODUCTION NATIVE CORE ALSO AVOIDS MNEMONIC LOOKUP AND
ALL OPCODE-TABLE DATA.

PRODUCTION NATIVE CODE MUST NOT CARRY SELF-TEST DATA. 'DAS_NATIVE_SELFTEST' IS
SEPARATE SO TESTS CAN VERIFY THE NATIVE CORE WITHOUT BLOATING THE INSTALLED
NATIVE ASSEMBLER.

### SIZE GUARDS

THE TEST SUITE CHECKS HOST-BYTE SIZES TO CATCH ACCIDENTAL NATIVE-PATH BLOAT:

'''TEXT
DAS_NATIVE PRODUCTION OBJECT: BELOW 4096 BYTES
DAS_NATIVE SELF-TEST PROGRAM: BELOW 12000 BYTES
'''

CURRENT MEASURED GCC SIZES IN THE LATEST CHECKED STATE WERE ABOUT:

'''TEXT
DAS_NATIVE PRODUCTION OBJECT: 782 BYTES
DAS_NATIVE SELF-TEST PROGRAM: 3136 BYTES
'''

THESE ARE HOST-BYTE MEASUREMENTS, NOT PDP-10 WORD MEASUREMENTS.

## DXR V1 EXECUTABLE STREAM
DXR V1 IS THE DAIMOS BASE-PROFILE FLAT RELOCATABLE EXECUTABLE STREAM. IT IS
NOT AN OBJECT FORMAT AND HAS NO ABI FIELD, VERSION FIELD, FLAGS, CHECKSUM,
SYMBOL TABLE, OR RELOCATION COUNT.

### LOGICAL WORD STREAM

'''TEXT
WORD 0: SIXBIT("DXR"),,ENTRY_OFFSET
WORD 1: IMAGE_WORDS,,BSS_WORDS
WORD 2..2+IMAGE_WORDS-1: IMAGE WORDS
THEN: RELOCATION BITMAP WORDS
'''

ALL FIELDS ARE DAIMOS 36-BIT WORDS OR 18-BIT HALFWORDS.
'ENTRY_OFFSET', 'IMAGE_WORDS', AND 'BSS_WORDS' ARE IMAGE-RELATIVE COUNTS.
THE RELOCATION BITMAP IS ALWAYS PRESENT AND HAS THIS LENGTH:

'''TEXT
RELOC_WORDS = (IMAGE_WORDS + 35) / 36
'''

A SET BIT RELOCATES THE CORRESPONDING IMAGE WORD BY ADDING THE LOAD BASE TO THE
LOW 18-BIT EFFECTIVE-ADDRESS FIELD. NO OTHER RELOCATION KIND EXISTS IN DXR V1.

### LOADER CHECKS

'''TEXT
- WORD 0 LEFT HALF MUST BE SIXBIT("DXR")
- IMAGE_WORDS MUST BE NONZERO
- ENTRY_OFFSET MUST BE LESS THAN IMAGE_WORDS
- FILE MUST CONTAIN EXACTLY 2 + IMAGE_WORDS + RELOC_WORDS LOGICAL WORDS
'''

### RELOCATION OPERATION

'''TEXT
WORD = MEMORY[LOAD_BASE + OFF]
EA   = WORD & 0777777
EA   = EA + LOAD_BASE
WORD = (WORD & 0777777000000) ! (EA & 0777777)
MEMORY[LOAD_BASE + OFF] = WORD
'''

### HOST CONTAINER CONVENTION

'DAS' EMITS ONLY DXR V1. IT DOES NOT EMIT PAPER TAPE, RIM, BIN, SIMH SCRIPTS,
OR ANY OTHER TRANSFER/CONTAINER FORMAT. THOSE BELONG IN SEPARATE CONVERSION
TOOLS.

THE LINUX TOOL WRITES THE SAME LOGICAL DXR WORD STREAM USING THE EXISTING
DAIMOS HOST-CONTAINER CONVENTION: ONE LITTLE-ENDIAN 64-BIT CONTAINER WORD PER
36-BIT DAIMOS WORD, LOW 36 BITS SIGNIFICANT. THIS IS NOT A PAPER-TAPE FORMAT.
'DXRCHECK' REJECTS NONZERO HIGH BITS IN THOSE HOST-CONTAINER WORDS.

## DXR CONVERTER TOOL
'DXRCONVERT' IS A HOST-ONLY CONVERTER FOR DXR V1 FILES. IT IS SEPARATE FROM
'DAS'; THE ASSEMBLER STILL EMITS ONLY DXR.

INPUT IS A DXR V1 LINUX HOST-CONTAINER FILE. OUTPUT IS SELECTED WITH EXACTLY
ONE MODE OPTION.

'''TEXT
DXRCONVERT --SIMH -B BASE INPUT.DXR OUTPUT.SIMH
DXRCONVERT --RIM  -B BASE INPUT.DXR OUTPUT.RIM
DXRCONVERT --PT   -B BASE INPUT.DXR OUTPUT.PT
'''

'BASE' IS OCTAL. THE CONVERTER APPLIES DXR ADDR18 RELOCATION AT THAT BASE
BEFORE WRITING THE OUTPUT.

### MODES

#### SIMH

'--SIMH' WRITES A SIMH DEPOSIT SCRIPT:

'''TEXT
DEPOSIT 001000 201040001003
DEPOSIT 001001 260740001002
GO 001000
'''

THIS IS FOR EMULATOR DEBUGGING AND QUICK INSPECTION.

#### RIM

'--RIM' WRITES A RIM10B PAPER-TAPE IMAGE. THE ENCODING MATCHES THE EXISTING
'MKRIM' CONVENTION:

'''TEXT
- 36-BIT WORDS ARE STORED AS SIX TAPE BYTES
- BIT 7 IS SET IN EVERY TAPE BYTE
- ONE STANDARD RIM10B HEADER WORD IS EMITTED
- FOURTEEN ZERO BOOTSTRAP WORDS FOLLOW
- THE IMAGE IS EMITTED AS ONE CONTIGUOUS IOWD BLOCK
- A CHECKSUM WORD FOLLOWS THE BLOCK
- A JRST START WORD IS EMITTED UNLESS --NO-GO IS USED
'''

DXR V1 IMAGES ARE CONTIGUOUS, SO ONE RIM BLOCK IS ENOUGH.

#### PT

'--PT' CURRENTLY WRITES THE SAME RIM10B PAPER-TAPE BYTE STREAM AS '--RIM'.
THE SEPARATE OPTION EXISTS SO LATER PHYSICAL PAPER-TAPE FRAMING OR DAIMOS TAPE
PACKAGING CAN DIVERGE WITHOUT CHANGING CALLERS.

### GO WORD

BY DEFAULT RIM/PT OUTPUT ENDS WITH A JRST TO 'BASE + ENTRY_OFFSET', AND SIMH
OUTPUT ENDS WITH 'GO BASE+ENTRY_OFFSET'.

USE '--NO-GO' TO SUPPRESS THIS FINAL START COMMAND/WORD.

### NON-GOALS

'DXRCONVERT' DOES NOT ASSEMBLE SOURCE AND DOES NOT CREATE OBJECT FILES. IT ONLY
CONVERTS A VALIDATED DXR IMAGE INTO AN ABSOLUTE HOST/TEST TRANSPORT FORMAT.
