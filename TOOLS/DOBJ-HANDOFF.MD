# DAIMOS DAS/DXR HANDOFF: OBJECT FORMAT SHOWSTOPPER

DATE: 2026-06-30
PROJECT: DAIMOS / DAIMON PDP-6 AND PDP-10 OPERATING SYSTEM
AREA: PDP10-TOOLS, DAS ASSEMBLER, DXR EXECUTABLE FORMAT, FUTURE DOBJ/DLINK PATH

## 1. SUMMARY

THE NEW 'DAS' ASSEMBLER AND MINIMAL DXR V1 EXECUTABLE PATH ARE USEFUL AND
SHOULD BE KEPT. THEY SOLVE THE EARLY FLAT EXECUTABLE PROBLEM:

'''TEXT
SOURCE.S -> DAS -> DXR V1
'''

DXR V1 REMAINS INTENTIONALLY SMALL:

'''TEXT
WORD 0: SIXBIT("DXR"),,ENTRY_OFFSET
WORD 1: IMAGE_WORDS,,BSS_WORDS
WORD 2..: IMAGE WORDS
THEN: RELOCATION BITMAP WORDS
'''

THE LOADER APPLIES ONE RELOCATION KIND ONLY: ADDR18 RELOCATION USING THE
BITMAP. THERE IS NO ABI WORD, VERSION WORD, CHECKSUM WORD, SYMBOL TABLE,
EXTERNAL IMPORT TABLE, ARCHIVE TABLE, OR RUNTIME STRING TABLE.

THIS IS STILL THE CORRECT FORMAT FOR FINAL EXECUTABLE IMAGES LOADED BY
DAIMOS. HOWEVER, BROAD COMPILER-OUTPUT TESTING HAS FOUND THE BOUNDARY WHERE
DXR-ONLY ASSEMBLY IS NO LONGER ENOUGH.

## 2. SHOWSTOPPER

THE BROAD KCC TEST REACHED GENERATED ASSEMBLY FOR 'CC.C'. KCC COMPILED THE
FILE SUCCESSFULLY, BUT 'DAS' STOPPED ON THE GENERATED ASSEMBLY WITH:

'''TEXT
DAS: UNSUPPORTED PSEUDO-OP .LINK
'''

THE RELEVANT TEST FLOW WAS:

'''TEXT
KCC SOURCE FILE -> KCC -> PDP-10 ASSEMBLY -> DAS -> DXR
'''

THE GENERATED KCC ASSEMBLY CONTAINS '.LINK'. THIS IS A LINKER/OBJECT-FILE
CONCEPT, NOT A FLAT FINAL-EXECUTABLE CONCEPT.

THAT IS THE SHOWSTOPPER:

'''TEXT
COMPILER-GENERATED REAL PROGRAMS NEED A LINK STEP.
DXR V1 IS A FINAL EXECUTABLE FORMAT, NOT A RELOCATABLE OBJECT FORMAT.
'''

## 3. WHY IGNORING '.LINK' IS NOT THE RIGHT FIX

FOR TINY TESTS, WE ALREADY USED A LOCAL '__MAIN' STUB TO AVOID PULLING IN A
FULL RUNTIME. THAT IS ACCEPTABLE FOR SMOKE TESTS.

BUT '.LINK' APPEARING IN REAL KCC OUTPUT MEANS KCC EXPECTS MORE THAN A
SINGLE FLAT ASSEMBLY UNIT. IT MAY DESCRIBE RUNTIME REQUIREMENTS, LINKED
MODULES, EXTERNAL SUPPORT ROUTINES, OR OTHER METADATA THAT BELONGS BEFORE
FINAL EXECUTABLE EMISSION.

IGNORING '.LINK' WOULD HIDE THE FIRST REAL LINKER BOUNDARY AND WOULD MAKE
LATER FAILURES MORE CONFUSING.

'DAS' IN DXR MODE SHOULD EITHER REJECT '.LINK' CLEARLY OR ACCEPT IT ONLY IN
AN OBJECT-OUTPUT MODE.

## 4. REQUIRED NEXT LAYER

THE NEXT LAYER SHOULD BE MINIMAL STATIC OBJECT SUPPORT:

'''TEXT
SOURCE.S -> DAS -C -> DOBJ
DOBJ...  -> DLINK -> DXR
'''

DO NOT JUMP TO THE FULL FINAL OBJECT ECOSYSTEM. THE IMMEDIATE NEED IS ONLY A
SMALL STATIC LINK FORMAT THAT CAN COMBINE COMPILER OUTPUT AND RUNTIME STUBS
INTO A FINAL DXR V1 EXECUTABLE.

## 5. MINIMAL DOBJ V1A SCOPE

DOBJ V1A SHOULD CONTAIN ONLY WHAT THE LINKER NEEDS:

'''TEXT
- MAGIC/HEADER
- TEXT WORDS
- DATA WORDS
- BSS WORD COUNT
- DEFINED SYMBOLS
- UNRESOLVED SYMBOLS
- RELOCATION RECORDS
- OPTIONAL ENTRY SYMBOL/OFFSET
'''

IT SHOULD NOT INCLUDE:

'''TEXT
- DYNAMIC LIBRARIES
- SHARED OBJECTS
- RUNTIME SYMBOL LOOKUP
- DARC ARCHIVES, UNLESS LIBRARIES FORCE IT LATER
- DMAP/DDBG DEBUG FILES
- SEG30
- RUNTIME MODULE LOADING
- HUMAN-READABLE RUNTIME STRINGS
'''

SYMBOL NAMES IN DOBJ MAY BE TOOL-SIDE ONLY. RUNTIME DXR SHOULD STILL CONTAIN
NO SYMBOL STRINGS.

## 6. MINIMAL RELOCATION NEEDS

DXR LOADER ONLY NEEDS FINAL ADDR18 BITMAP RELOCATION. DOBJ NEEDS RICHER
PRE-LINK RELOCATION RECORDS SO THE LINKER CAN RESOLVE SYMBOLS BEFORE DXR IS
EMITTED.

INITIAL DOBJ RELOCATION SET SHOULD BE DELIBERATELY SMALL:

'''TEXT
ADDR18  INSTRUCTION EFFECTIVE-ADDRESS RELOCATION
RH18    RIGHT-HALF DATA RELOCATION, E.G. 0,,SYMBOL
LH18    REJECT INITIALLY UNLESS REAL COMPILER OUTPUT REQUIRES IT
FULL36  REJECT INITIALLY UNLESS REAL COMPILER OUTPUT REQUIRES IT
'''

THE LINKER RESOLVES DOBJ SYMBOL REFERENCES, PATCHES WORDS, AND EMITS A FINAL
DXR IMAGE PLUS THE FINAL ADDR18 LOAD-TIME RELOCATION BITMAP.

## 7. '.LINK' POLICY

RECOMMENDED POLICY:

'''TEXT
DXR OUTPUT MODE:
  REJECT .LINK WITH A DIAGNOSTIC SUCH AS:
  ".LINK REQUIRES OBJECT-OUTPUT/LINK MODE"

DOBJ OUTPUT MODE:
  ACCEPT .LINK AND RECORD THE NEEDED LINK/RUNTIME REFERENCE
'''

IF '.LINK' TURNS OUT TO BE ONLY A KCC-SPECIFIC FILE DEPENDENCY DIRECTIVE, THE
DOBJ READER/LINKER CAN INTERPRET IT MINIMALLY. IF IT IS MORE COMPLEX, DOBJ
SHOULD STILL BE THE PLACE TO REPRESENT IT.

## 8. CURRENT TOOL STATE

CURRENT 'PDP10-TOOLS' STATE BEFORE DEFINING DOBJ:

'''TEXT
DAS:
  - EMITS DXR V1 ONLY
  - HAS HOST-SIDE COMPATIBILITY SYNTAX FOR KCC/GCC SMOKE TESTS
  - HAS A TINY DAS_NATIVE MEMORY-TO-MEMORY CORE
  - KEEPS NATIVE CODE SIZE SMALL
  - PASSES GCC AND KCC SMALL CORPUS TESTS

DXRCHECK:
  - VALIDATES DXR V1
  - HAS DUMP AND RELOCATION-SUMMARY MODES
  - REMAINS HOST-ONLY

DXRCONVERT:
  - CONVERTS DXR TO SIMH/RIM/PT TRANSPORT FORMATS
  - REMAINS SEPARATE FROM DAS
'''

THE BROAD COMPILER-OUTPUT TEST STOPPED AT '.LINK', SO REPLACING THE OLD
ASSEMBLER AS THE GENERAL COMPILER ASSEMBLER SHOULD WAIT UNTIL DOBJ/DLINK
EXISTS.

## 9. RELATIONSHIP TO THE EARLIER PLAN

THE EARLIER PLAN DELIBERATELY DEFERRED THE FULL OBJECT FORMAT UNTIL AFTER
KERNEL/DRIVER/FILESYSTEM WORK, WHILE ALLOWING FLAT RELOCATABLE EXECUTABLE
IMAGES BEFORE THAT. THAT WAS SOUND FOR EARLY NATIVE ASSEMBLY AND SIMPLE
SINGLE-FILE TOOLS.

THE TEST RESULT CHANGES THE IMMEDIATE TOOLCHAIN REQUIREMENT BUT NOT THE
RUNTIME DESIGN:

'''TEXT
KEEP DXR V1 AS THE FINAL EXECUTABLE IMAGE.
ADD DOBJ/DLINK AS THE HOST/TOOLCHAIN BUILD STEP BEFORE DXR.
DO NOT ADD OBJECT-FORMAT COMPLEXITY TO THE DAIMOS RUNTIME LOADER.
'''

SO THE REVISED PLAN IS:

'''TEXT
1. FREEZE DXR V1.
2. DEFINE MINIMAL DOBJ V1A.
3. ADD DAS -C DOBJ OUTPUT.
4. ADD DLINK DOBJ... -> DXR.
5. RESUME BROAD KCC/GCC/PDP-C-TESTKIT/DAIMOS TESTS THROUGH DLINK.
6. ONLY EXPAND DOBJ WHEN A REAL FAILING INPUT REQUIRES IT.
'''

## 10. IMMEDIATE NEXT TASKS

'''TEXT
1. FINISH THE PDP10-C-TESTKIT SWEEP AS FAR AS POSSIBLE IN STOP-ON-FIRST-ERROR
   MODE, RECORDING WHETHER FAILURES ARE SETUP, PARSER, RELOCATION, OR LINK
   MODEL FAILURES.
2. INSPECT KCC '.LINK' OUTPUT SYNTAX AND SEMANTICS FROM THE FAILING 'CC.S'.
3. DRAFT DOBJ V1A WORD-LEVEL FORMAT.
4. IMPLEMENT DOBJ WRITER PATH IN DAS.
5. IMPLEMENT TINY DLINK.
6. CONVERT THE KCC/GCC CORPUS TESTS FROM DIRECT DXR ASSEMBLY TO:
   DAS -C -> DLINK -> DXRCHECK.
'''

## 11. RULE FOR FUTURE WORK

DO NOT MAKE DXR BIGGER TO SOLVE LINK-TIME PROBLEMS.

DXR IS THE FINAL LOADED IMAGE. DOBJ/DLINK IS THE BUILD-TIME SOLUTION.
