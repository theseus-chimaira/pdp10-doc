# TYPE 340 DISPLAY DESIGN

STATUS: DAIMOS PDP-6 TYPE-340/342 DISPLAY DESIGN.

## 1. GOALS

THE TYPE 340 SHALL SUPPORT A NORMAL DAIMOS LOGIN/DSH TERMINAL WITHOUT TURNING
THE PDP-6 INTO A CHARACTER-AT-A-TIME DISPLAY SERVER. REFRESH-TIME CPU COST IS
MORE IMPORTANT HERE THAN SAVING A FEW WORDS OF DRIVER CODE, BUT AN UNUSED
DISPLAY MUST NOT CONSUME PERMANENT CORE.

THE DESIGN FOLLOWS THE USEFUL PART OF THE HISTORICAL ITS MODEL: KEEP RETAINED
DISPLAY STATE IN MEMORY AND FEED THE REFRESH DISPLAY ASYNCHRONOUSLY. NORMAL
CHARACTER OUTPUT MODIFIES MEMORY AND RETURNS. IT MUST NOT WAIT FOR TYPE-340
DONE AFTER EACH CHARACTER.

THE TYPE 340/342 HARDWARE PROVIDES:

- A 1024 BY 1024 DISPLAY COORDINATE SPACE;
- A TYPE-342 CHARACTER CELL OF 6 BY 11 DISPLAY UNITS AT SCALE 1 IN THE
  CURRENT HARDWARE MODEL;
- FOUR CHARACTER/VECTOR SCALE SETTINGS: 1, 2, 4, AND 8;
- EIGHT INTENSITY SETTINGS: 0 THROUGH 7;
- NATIVE POINT, VECTOR, INCREMENTAL, AND CHARACTER MODES.

THE FOUR HARDWARE SCALE SETTINGS MUST NOT BE CONFUSED WITH INTENSITY.
INTENSITY IS A THREE-BIT FIELD AND THEREFORE HAS EIGHT LEVELS.

THE ORDINARY TTY INTERFACE DOES NOT EXPOSE CHARACTER SIZE. NORMAL TTY TEXT
USES HARDWARE SCALE 2 THROUGHOUT. CHARACTER SIZE IS A FORMATTED-DISPLAY
PROPERTY OWNED BY PROGRAMS SUCH AS MAN/SIXMD RENDERERS, NOT BY THE STREAM
TERMINAL ABI.

THE ORDINARY DPY TTY CHARACTER PLANE IS SIXBIT AND THEREFORE UPPERCASE-ONLY.
LOWERCASE INPUT OR OUTPUT MUST NOT FORCE A SECOND CASE BITPLANE OR A WIDER
TTY CELL FORMAT. IF AN APPLICATION WRITES LOWERCASE THROUGH THE STREAM-TTY
PATH, THE DPY TTY NORMALIZES IT TO THE CORRESPONDING SIXBIT UPPERCASE FORM.

FORMATTED-TEXT CLIENTS MAY USE HARDWARE SCALES 1, 2, AND 4 AS SMALL, NORMAL,
AND LARGE TEXT. HARDWARE SCALE 8 IS RESERVED FOR GENERAL NATIVE TYPE-340
GRAPHICS RATHER THAN THE STANDARD FORMATTED-TEXT INTERFACE.

## 2. NORMAL TERMINAL GEOMETRY

THE NORMAL STREAM TERMINAL TARGET IS 84 COLUMNS BY 42 ROWS AT HARDWARE SCALE
2. THIS IS A DAIMOS TTY GEOMETRY, NOT A TYPE-340 HARDWARE LIMIT. AT THE
TYPE-342 6-BY-11 SCALE-1 CELL, SCALE 2 PRODUCES A 12-BY-22 CELL, SO 84 BY 42
USES 1008 BY 924 OF THE 1024 BY 1024 RASTER.

THIS LEAVES 16 HORIZONTAL AND 100 VERTICAL DISPLAY UNITS OUTSIDE THE NORMAL
TEXT RECTANGLE, NATURALLY GIVING APPROXIMATELY 8 UNITS OF LEFT/RIGHT MARGIN
AND 50 UNITS OF TOP/BOTTOM MARGIN WHEN CENTERED.

84 COLUMNS IS ALSO A NATURAL TYPE-342 WIDTH: SIX TYPE-342 CHARACTER CODES FIT
ONE 36-BIT DISPLAY WORD, SO A SINGLE-CASE 84-COLUMN ROW IS EXACTLY FOURTEEN
DISPLAY WORDS BEFORE CONTROL/SHIFT CODES. THE LOGICAL TERMINAL STORE ITSELF
USES PACKED SIXBIT. SCROLLING IS O(1) THROUGH THE 42-ROW RING RATHER THAN
THROUGH PHYSICAL ROW COPYING.

THE HARDWARE CAN ADDRESS A MUCH DENSER CHARACTER GRID. DAIMOS SHALL NOT USE
THE MAXIMUM THEORETICAL GRID MERELY TO INCREASE CHARACTER COUNT, BECAUSE
REFRESH WORK AND LEGIBILITY MATTER MORE.

AN 84-BY-42 TTY REMAINS 84 BY 42 SCALE-2 LOGICAL CELLS. FORMATTED-TEXT
PROGRAMS MAY LEAVE THIS GRID AND LAYOUT SCALE-1/2/4 TEXT DIRECTLY IN DISPLAY
COORDINATES.

## 3. TERMINAL STORAGE

THE IMPLEMENTED STREAM-TTY STORE IS PACKED SIXBIT AND UPPERCASE-ONLY. EACH
84-COLUMN ROW USES EXACTLY 14 WORDS WITH SIX CHARACTERS PER WORD. THE 42-ROW
LOGICAL CHARACTER PLANE THEREFORE USES 588 WORDS. LOWERCASE STREAM OUTPUT IS
NORMALIZED TO UPPERCASE BEFORE STORAGE; MIXED-CASE PRESENTATION BELONGS TO THE
FORMATTED-DISPLAY/SIXMD PATH.

TO KEEP THE CONTINUOUS 30-HZ REFRESH PATH CHEAP, EACH PHYSICAL ROW ALSO HAS A
PRECOMPILED TYPE-342 CACHE SLOT. A ROW MAY REQUIRE AT MOST 29 WORDS EVEN IN
THE WORST CASE OF ALTERNATING PRIMARY/SHIFTED SIXBIT PUNCTUATION, INCLUDING
SI/SO STATE CHANGES, CR/LF, AND PACKING PAD. THE 42 CACHE SLOTS USE 1218
WORDS. A 42-WORD LENGTH TABLE SELECTS THE USED PREFIX OF EACH SLOT. ROW
COMPILATION STOPS AFTER THE LAST NONBLANK CELL, SO TRAILING SPACES ARE NEVER
PART OF THE REFRESH STREAM.

THE COMPLETE FIRST-USE ALLOCATION IS:

    588 WORDS   84 BY 42 PACKED SIXBIT CHARACTER PLANE
     42 WORDS   COMPILED-ROW LENGTHS
   1218 WORDS   42 BOUNDED NATIVE TYPE-342 ROW CACHE SLOTS
   ----------
   1848 WORDS   ONE MM_TYPE_KERNEL_DYNAMIC EXTENT

THIS 1848-WORD AREA IS RECLAIMABLE/DYNAMIC WORKING MEMORY AND IS NOT PART OF
KCORE+MRES PERMANENT-SIZE ACCOUNTING. ONLY THE SMALL DPY RESIDENT CODE AND
STATE COUNT TOWARD THE PERMANENT KERNEL LIMIT.

THE FORMER 32-WORD INTENSITY RESERVE WAS NEVER CONSUMED BY THE IMPLEMENTED
TTY PATH AND HAS BEEN REMOVED.  IF AN ORDINARY-TTY INTENSITY FEATURE IS LATER
IMPLEMENTED, ITS BOUNDED METADATA MUST BE ALLOCATED ONLY WHEN THAT FEATURE IS
ACTUALLY USED RATHER THAN CHARGED TO EVERY RETAINED TEXT TERMINAL.

THE NATIVE CACHE IS INTENTIONAL. IT SPENDS ON-DEMAND RAM TO AVOID REDECODING
THE COMPLETE SCREEN ON EVERY REFRESH. ORDINARY CHARACTER OUTPUT RECOMPILES
ONLY THE TOUCHED ROW. SCROLLING ROTATES THE 42-ROW RING AND CLEARS/RECOMPILES
ONLY THE NEW BOTTOM ROW. A RESIDENT dpy_text_rows_used BOUND TRACKS THE LAST
LOGICAL ROW THAT CAN CONTAIN VISIBLE TEXT, SO REFRESH ALSO OMITS ALL TRAILING
BLANK ROWS.

## 4. ZERO-COST UNUSED POLICY

DPY MUST COST NO PERMANENT WORDS WHEN IT IS NOT USED.

THERE ARE THREE DISTINCT CASES:

1. DPY ABSENT:
   KINIT MAY PROBE TRANSIENTLY, BUT NO DPY MRES OR BUFFER IS INSTALLED.
2. DPY PRESENT BUT DISABLED/UNSELECTED:
   KINIT MAY PROBE TRANSIENTLY, BUT SHALL NOT INSTALL THE DPY MRES OR RESERVE
   TEXT/GRAPHICS CORE.
3. DPY ENABLED FOR TEXT OR GRAPHICS:
   KINIT INSTALLS THE SMALL DPY MRES. TEXT AND GRAPHICS STORAGE ARE STILL
   ALLOCATED SEPARATELY AND ONLY WHEN THEIR SERVICE IS ACTIVATED.

CASE 2 DELIBERATELY TRADES LATE ENABLEMENT FOR ZERO RESIDENT COST. UNTIL
GENERAL RUNTIME MODULE LOADING EXISTS, A DPY SKIPPED BY KINIT CANNOT LATER BE
TURNED ON BY TTYOUT WITHOUT REBOOTING INTO A CONFIGURATION THAT ENABLES DPY.
DO NOT KEEP A RESIDENT STUB MERELY TO AVOID THAT REBOOT.

THE BOOT POLICY THAT SELECTS DPY USE MUST BE DECIDED BEFORE KINIT RECLAIMS ITS
TRANSIENT IMAGE. IT SHOULD USE EXISTING BOOT/CONFIGURATION POLICY MECHANISMS
RATHER THAN ADDING A SECOND RUNTIME MODULE SYSTEM.

## 5. TEXT ALLOCATION

EVEN WHEN THE DPY MRES IS INSTALLED, THE 84 BY 42 TEXT STORE IS NOT PART OF
KCORE OR MRES BSS.

ONE CONTIGUOUS MM_TYPE_KERNEL_DYNAMIC EXTENT IS ALLOCATED ON DEMAND BY THE
FIRST ACTUAL TERMINAL BYTE SENT TO DPY. MERELY PROBING THE DISPLAY OR
CONFIGURING A ROUTE DOES NOT ALLOCATE THE 1848-WORD TEXT/CACHE AREA.

ALLOCATION IS A CONTROL-PATH OPERATION. NEITHER THE DPY INTERRUPT PATH NOR
THE ORDINARY CHARACTER-OUTPUT HOT PATH MAY ALLOCATE, COMPACT MEMORY, OR BLOCK
ON MM.

THE TEXT EXTENT MAY REMAIN ALLOCATED WHILE DPY TEXT SERVICE IS ACTIVE. IT MAY
BE RELEASED WHEN THE LAST TEXT USER LEAVES, BUT DO NOT ADD COMPLEX LIFETIME
MACHINERY UNLESS MEASUREMENT SHOWS THAT RECLAIM IS WORTH THE CODE AND CPU.

## 6. REFRESH

APPLICATION OUTPUT UPDATES RETAINED TEXT STATE AND THE TOUCHED NATIVE ROW
CACHE, THEN RETURNS WITHOUT ISSUING A DISPLAY DATAO OR WAITING FOR DONE.

THE LOW-PRIORITY DISPLAY SERVICE REFRESHES THE CRT ASYNCHRONOUSLY. THE
IMPLEMENTED TYPE-344 PATH FEEDS ONE 36-BIT DISPLAY WORD WITH DATAO, THEN USES
THE DPY DONE INTERRUPT ON PI7 TO FEED THE NEXT WORD.  DEVICE 0130 IS NOT A
BLKO DISPLAY-LIST INTERFACE; USING BLKO HERE CAUSED PERIODIC/RETAINED REFRESH
TO GO BLACK EVEN THOUGH THE ONE-SHOT KINIT BANNER STILL APPEARED.  THE PI7
PRE-HANDLER CHECKS DPY DONE BEFORE ADVANCING THE STREAM BECAUSE PI7 IS SHARED
WITH OTHER DEVICES. TYPE-342 CHARACTER MODE IS RETAINED ACROSS SUCCESSIVE
CHARACTERS SO ONE 36-BIT DISPLAY WORD CAN CARRY SIX CHARACTER CODES.

THE CURRENT 30-HZ REFRESH RATE REMAINS THE BASELINE UNTIL A LOWER RATE IS
PROVEN VISUALLY AND BY TARGET ACCEPTANCE. THE PREVIOUS 20-HZ EXPERIMENT WAS
PHASE-SENSITIVE IN HEADLESS TESTING.

THE IMPLEMENTED REFRESH IMAGE BEGINS WITH ONE FRAME SETUP THAT SELECTS SCALE
2, THE DEFAULT INTENSITY, AND THE TOP BEAM POSITION. THE DONE PATH THEN WALKS
THE PRECOMPILED ROW SLOTS IN CURRENT RING ORDER ONLY THROUGH
dpy_text_rows_used. ROW SLOTS ARE POSITION-INDEPENDENT CHARACTER STREAMS
ENDING IN NATIVE CR/LF, AND EACH SLOT CONTAINS ONLY ITS VISIBLE PREFIX. A
RESIDENT IOWD-LIKE CURSOR TRACKS THE CURRENT SPAN; EACH DONE INTERRUPT
ADVANCES THAT CURSOR AND SENDS THE NEXT WORD WITH DATAO. FULL ROW-SELECTION
WORK IS NEEDED ONLY WHEN A SPAN ENDS.

THIS IS THE PRIMARY INTERRUPT-LOAD REDUCTION. A SIX-CHARACTER `LOGIN:` ROW
COMPILES TO TWO TYPE-342 WORDS; WITH THE TWO-WORD FRAME SETUP THAT IS FOUR
DATAO/DONE COMPLETIONS PER 30-HZ FRAME, ABOUT 120 COMPLETIONS/SECOND. A
TWO-LINE `LOGIN:`/`DSH V1` SCREEN IS ABOUT SIX WORDS PER FRAME, OR ABOUT
180 COMPLETIONS/SECOND. THE OLD FIXED-WIDTH 42-ROW STREAM COULD APPROACH 630
WORDS PER FRAME, ABOUT 18,900 COMPLETIONS/SECOND.

THE BOOT-BANNER SPAN AND TEXT-SETUP SPAN MUST NEVER BE CONFUSED. A BANNER
REFRESH TAGS dpy_refresh_row WITH DPY_TEXT_ROWS, WHICH IS OUTSIDE THE VALID
0..41 TEXT ROW RANGE; A TEXT FRAME USES -1 FOR ITS SETUP SPAN. THIS MATTERS
BECAUSE THE FIRST LAZY TEXT ALLOCATION CAN FINISH WHILE A BANNER FRAME IS
STILL IN FLIGHT. WITHOUT THE NON-TEXT SENTINEL, THE FINAL BANNER DONE COULD
BE INTERPRETED AS TEXT-SETUP COMPLETION, CAUSING CHARACTER CACHE WORDS TO BE
EXECUTED IN THE WRONG TYPE-340 MODE AND POTENTIALLY STOPPING THE DISPLAY.

dpy_pending DENOTES OWNERSHIP OF THE COMPLETE TYPE-344 DATAO STREAM. IT MUST
REMAIN SET FROM THE FIRST WORD OF A FRAME UNTIL THE FINAL DONE OF THAT FRAME.
THE PI7 HANDLER MUST NOT CLEAR IT BETWEEN WORDS: PI6 CAN PREEMPT PI7, AND A
30-HZ CLOCK TICK OBSERVING A FALSE IDLE WINDOW COULD ISSUE CONO INIT AND START
A NEW FRAME BEFORE THE OLD PI7 CHAIN HAS FINISHED. THAT MIXES TWO DISPLAY
PROGRAMS, CAN LEAVE THE 340 IN PARAMETER MODE, AND CAUSES AN ORDINARY BLANK
CHARACTER WORD (040404) TO SELECT TYPE-343 SLAVE MODE AND STOP ON A SYSTEM
WITHOUT THAT OPTION.

PI6 SCHEDULING HAS A CORRESPONDING NESTING RULE. CLOCK/TIMER ACCOUNTING MAY
RUN WHILE PI7 IS HELD, BUT A PROCESS CONTEXT SWITCH MUST BE DEFERRED WHILE
CONI PI REPORTS THE PI7 HOLD BIT. OTHERWISE THE PI6 SCHEDULER CAN SAVE THE
NESTED PI7 FRAME AS A PROCESS EXECUTIVE CONTINUATION AND RETURN DIRECTLY TO
USER MODE WITH PI7 STILL HELD, PERMANENTLY MASKING LATER DISPLAY DONE
INTERRUPTS.

SLOT 0 IS ALSO AMBIGUOUS DURING BOOT: IT DENOTES THE PERMANENT EXECUTIVE IDLE
CONTEXT AFTER USERSPACE HAS STARTED, BUT IT ALSO DENOTES KINIT BEFORE ANY USER
PROCESS EXISTS. PI6 MUST TREAT SLOT 0 AS SCHEDULABLE ONLY WHEN THE SAVED PI6
RETURN PC LIES INSIDE proc_idle_loop. SWITCHING AWAY FROM A KINIT CONTINUATION
CAN ABANDON THE CLOCK SERVICE FRAME AND CORRUPT THE COMMON PI RETURN STATE.

THE ORDINARY CLK HANDLER REMAINS THE REGISTERED PI6 OWNER. CLK EXPOSES A
POST-SERVICE JRST WHICH DPY MINIT PATCHES TO A STACKLESS DISPLAY HOOK. THE
HOOK COMPARES THE CLK TICK COUNTER WITH ITS LAST-SEEN VALUE, SO SOFTWARE PI6
SCHEDULER KICKS DO NOT ADVANCE THE DISPLAY DIVIDER. IT USES NO PUSHJ: KINIT
MAY BE INTERRUPTED WHILE AC17 IS ITS BOOTSTRAP PUSHDOWN POINTER, SO ADDING A
SECOND PI6 CALL CHAIN WOULD MAKE DISPLAY REFRESH DEPEND ON BOOT STACK LAYOUT.

CLK PRESERVES THE PI DISPATCHER'S AC2/AC3 IN RESIDENT SAVE WORDS RATHER THAN
ON AC17. THIS KEEPS THE PI RETURN CURSOR VALID EVEN IF SCHEDULER WORK CHANGES
THE ACTIVE KERNEL STACK BEFORE CLK RETURNS.

## 7. TERMINAL DEVICE ENDPOINT

THE PHYSICAL DISPLAY AND THE LOGICAL DISPLAY TERMINAL ARE DISTINCT DEVICES:

    /DEV/DPY0       PHYSICAL TYPE-340 DEVICE IDENTITY
    /DEV/TTYDPY0    CTY0 INPUT + DPY0 RETAINED-TEXT OUTPUT

TTYDPY0 APPEARS ONLY WHEN BOTH CTY0 AND DPY0 ARE INSTALLED. IT DOES NOT
CHANGE TTY0'S GLOBAL OUTPUT ROUTE. WRITING TO TTYDPY0 GOES DIRECTLY TO THE
RETAINED DPY TERMINAL, WHILE READING USES CTY0 INPUT. THE ENDPOINT IS
RECOGNIZED AS LOGICAL TTY0 FOR CONTROLLING-TTY/ISATTY PURPOSES, SO NORMAL
CHARACTER-ORIENTED USERLAND OUTPUT DOES NOT GET WRAPPED AS A REGULAR-FILE
S6REC STREAM.

THIS MAKES THE DISPLAY TERMINAL DIRECTLY TESTABLE WITHOUT ALTERING THE LOGIN
ROUTE:

    ECHO TEST > /DEV/TTYDPY0

THE TYPE-340 GUI WINDOW ITSELF IS NOT A DAIMOS KEYBOARD DEVICE. INPUT FOR
TTYDPY0 COMES FROM THE PDP-6 CTY CONSOLE.

## 8. SIXMD AND FORMATTED TEXT

FORMATTED-DISPLAY PROGRAMS MAY USE SCALES 1, 2, AND 4 PLUS ALL EIGHT
INTENSITIES. THIS ALLOWS A TYPE-340 DISPLAY TO RENDER A LARGE PART OF SIXMD
NATIVELY WITHOUT MAKING CHARACTER SIZE PART OF THE TTY ABI.

FORMATTED SIXMD MAY ALSO USE TYPE-342 SHIFT STATE TO DISPLAY LOWERCASE.
SIXMD'S '@' CASE ESCAPES REMAIN SOURCE-LEVEL SIXBIT; THE RENDERER TRANSLATES
THEM DIRECTLY TO THE TYPE-342 PRIMARY/SHIFTED CHARACTER SETS. THIS DOES NOT
CHANGE THE ORDINARY SIXBIT-ONLY TTY BUFFER.

A SUITABLE PRESENTATION POLICY IS:

- NORMAL TEXT: SCALE 2 AT NORMAL INTENSITY;
- EMPHASIS: SCALE 2 AT A HIGHER INTENSITY;
- STRONG EMPHASIS: SCALE 2 AT THE BRIGHTEST TEXT INTENSITY;
- LEVEL-1/2/3 HEADINGS: SCALE 4 OR SCALE 2 PLUS HIGHER INTENSITY;
- QUOTATIONS: SCALE 1 OR SCALE 2 AT A LOWER INTENSITY;
- LITERAL/INDENTED RECORDS: NORMAL CHARACTER MODE WITH DISTINCT INTENSITY;
- LIST MARKERS: ORDINARY TEXT WITH AN OPTIONAL BRIGHT MARKER;
- HORIZONTAL RULES: A NATIVE VECTOR INSTEAD OF A ROW OF DASH CHARACTERS.

THE EXACT VISUAL MAPPING MAY BE TUNED. THE TTY ABI PRESERVES ALL EIGHT
INTENSITIES BUT HAS NO SIZE ATTRIBUTE. FORMATTED-DISPLAY CLIENTS MAY USE
SCALES 1, 2, AND 4; GENERAL GRAPHICS MAY STILL ISSUE RAW SCALE-8 OPERATIONS.

FORMATTED TEXT IS NOT RESTRICTED TO THE 84 BY 42 STREAM GRID. MAN OR ANOTHER
SIXMD RENDERER MAY LAYOUT TEXT IN TYPE-340 DISPLAY COORDINATES USING THE
SMALL 6-BY-11, NORMAL 12-BY-22, AND LARGE 24-BY-44 CELLS. 84 BY 42 REMAINS
THE CONTRACT FOR ORDINARY TTY PROGRAMS.

TTY AND FORMATTED TEXT MAY REUSE THE SAME ALLOCATED DISPLAY WORKING AREA WHEN
PRACTICAL, BUT THEIR REPRESENTATIONS NEED NOT BE IDENTICAL: TTY STORAGE IS AN
84-BY-42 SCALE-2 CHARACTER PLANE PLUS PRECOMPILED ROWS, WHILE A FORMATTED
CLIENT MAY BUILD A NATIVE POSITIONED TYPE-340/342 PROGRAM USING SCALE 1/2/4.

## 9. GRAPHICS

NATIVE GRAPHICS PROGRAM STORAGE BELONGS TO USERSPACE. THE KERNEL DOES NOT
ALLOCATE A SECOND RETAINED GRAPHICS BUFFER, PARSE DISPLAY PROGRAMS, OR PROVIDE
GRAPHICS OBJECTS.

/DEV/DPY0 ACCEPTS WHOLE-WORD WRITES. ONE WRITE IS ONE COMPLETE NATIVE
TYPE-340 FRAME: THE DRIVER WAITS FOR ANY PREVIOUS DISPLAY STREAM TO FINISH,
RESETS THE TYPE 340 TO A DETERMINISTIC INITIAL STATE, THEN EXECUTES EACH
SUPPLIED 36-BIT WORD SYNCHRONOUSLY THROUGH THE NORMAL TYPE-344 DATAO/DONE
PATH.

THE RAW WRITER ALSO REFRESHES A SHORT FOUR-LINE-CLOCK-TICK LEASE. WHILE THAT
LEASE IS NONZERO, THE ORDINARY RETAINED-TEXT 30-HZ REFRESH DOES NOT START.
USERSPACE THEREFORE OWNS THE DISPLAY AS LONG AS IT KEEPS SUBMITTING COMPLETE
FRAMES. IF THE WRITER EXITS, IS KILLED, OR STOPS SUBMITTING, THE LEASE EXPIRES
WITHOUT A CLEANUP SYSCALL AND NORMAL TEXT REFRESH RESUMES.

/SYSTEM/EXEC/DPYVIEW IS THE INITIAL USERSPACE CLIENT. IT LOADS A RAW NATIVE
DISPLAY-PROGRAM FILE INTO A BOUNDED 1024-WORD USER BUFFER AND REPLAYS THE
COMPLETE PROGRAM EVERY TWO 60-HZ CLOCK TICKS, GIVING A NOMINAL 30-HZ REFRESH.
THE FILE CONTAINS NATIVE 36-BIT DISPLAY WORDS ONLY; DPYVIEW DOES NOT DECODE,
SCALE, TRANSLATE, OR VALIDATE THEM.

THIS DESIGN KEEPS GRAPHICS POLICY AND STORAGE OUT OF THE KERNEL WHILE STILL
PROVIDING THE ONE HARDWARE OPERATION USERSPACE CANNOT PERFORM DIRECTLY:
ORDERED TYPE-344 DATAO/DONE EXECUTION WITHOUT RACING THE RETAINED TTY REFRESH.
MULTI-PROCESS COMPOSITING, WINDOWS, SURFACES, A KERNEL GRAPHICS OBJECT MODEL,
AND IMAGE-FORMAT DECODERS REMAIN OUT OF SCOPE.

## 10. PERFORMANCE RULES

TYPE-340 OPTIMIZATION PRIORITY IS:

1. REDUCE CONTINUOUS REFRESH CPU AND I/O WORK;
2. REDUCE CHARACTER/STYLE UPDATE COST;
3. KEEP INTERACTIVE LATENCY LOW;
4. MINIMIZE RAM;
5. MINIMIZE DRIVER CODE SIZE.

THIS IS AN INTENTIONAL DEVICE-SPECIFIC EXCEPTION TO THE NORMAL DAIMOS
RAM-FIRST OPTIMIZATION ORDER: A REFRESH DISPLAY CAN CONSUME CPU CONTINUOUSLY,
SO A MODEST BOUNDED MEMORY COST IS ACCEPTABLE WHEN IT REMOVES REPEATED WORK.

NO INTERRUPT PATH MAY ALLOCATE MEMORY OR BLOCK. NO ORDINARY CHARACTER OUTPUT
PATH MAY SPIN WAITING FOR DPY DONE.
