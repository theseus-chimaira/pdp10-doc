# TYPE 340 DISPLAY DESIGN

STATUS: DAIMOS PDP-6 TYPE-340/342 DISPLAY DESIGN.

## 1. GOALS

THE TYPE 340 SHALL SUPPORT A NORMAL DAIMOS LOGIN/DSH TERMINAL WITHOUT TURNING
THE PDP-6 INTO A CHARACTER-AT-A-TIME DISPLAY SERVER. REFRESH-TIME CPU COST IS
MORE IMPORTANT HERE THAN SAVING A FEW WORDS OF DRIVER CODE, BUT AN UNUSED
DISPLAY MUST NOT CONSUME PERMANENT CORE.

THE DESIGN FOLLOWS THE USEFUL PART OF THE HISTORICAL ITS MODEL: KEEP RETAINED
DISPLAY STATE IN MEMORY AND FEED THE REFRESH DISPLAY ASYNCHRONOUSLY. NORMAL
CHARACTER OUTPUT MODIFIES MEMORY AND RETURNS. IT MUST NOT WAIT FOR TYPE-340
DONE AFTER EACH CHARACTER.

THE TYPE 340/342 HARDWARE PROVIDES:

- A 1024 BY 1024 DISPLAY COORDINATE SPACE;
- A TYPE-342 CHARACTER CELL OF 6 BY 11 DISPLAY UNITS AT SCALE 1 IN THE
  CURRENT HARDWARE MODEL;
- FOUR CHARACTER/VECTOR SCALE SETTINGS: 1, 2, 4, AND 8;
- EIGHT INTENSITY SETTINGS: 0 THROUGH 7;
- NATIVE POINT, VECTOR, INCREMENTAL, AND CHARACTER MODES.

THE FOUR HARDWARE SCALE SETTINGS MUST NOT BE CONFUSED WITH INTENSITY.
INTENSITY IS A THREE-BIT FIELD AND THEREFORE HAS EIGHT LEVELS.

THE ORDINARY TTY INTERFACE DOES NOT EXPOSE CHARACTER SIZE. NORMAL TTY TEXT
USES HARDWARE SCALE 2 THROUGHOUT. CHARACTER SIZE IS A FORMATTED-DISPLAY
PROPERTY OWNED BY PROGRAMS SUCH AS MAN/SIXMD RENDERERS, NOT BY THE STREAM
TERMINAL ABI.

THE ORDINARY DPY TTY IS UPPERCASE-ONLY. LOWERCASE INPUT OR OUTPUT MUST NOT
FORCE A SECOND CASE BITPLANE OR A WIDER TTY CELL FORMAT. IF AN APPLICATION
WRITES LOWERCASE THROUGH THE STREAM-TTY PATH, THE DPY TTY NORMALIZES IT TO
THE CORRESPONDING TYPE-342 UPPERCASE GLYPH BEFORE STORAGE.

FORMATTED-TEXT CLIENTS MAY USE HARDWARE SCALES 1, 2, AND 4 AS SMALL, NORMAL,
AND LARGE TEXT. HARDWARE SCALE 8 IS RESERVED FOR GENERAL NATIVE TYPE-340
GRAPHICS RATHER THAN THE STANDARD FORMATTED-TEXT INTERFACE.

## 2. NORMAL TERMINAL GEOMETRY

THE NORMAL STREAM TERMINAL TARGET IS 84 COLUMNS BY 46 ROWS AT HARDWARE SCALE
2. THIS IS A DAIMOS TTY GEOMETRY, NOT A TYPE-340 HARDWARE LIMIT. AT THE
TYPE-342 6-BY-11 SCALE-1 CELL, SCALE 2 PRODUCES A 12-BY-22 CELL, SO 84 COLUMNS
USES 1008 HORIZONTAL DISPLAY UNITS. THE 46 ROW BASELINES START AT Y=1010 AND
END AT Y=20; THE TOP-ROW GLYPH EXTENT ENDS AT Y=1022. 46 ROWS ARE THEREFORE
THE MAXIMUM SAFE STREAM-TERMINAL HEIGHT AT SCALE 2 IN THE 0..1023 RASTER.

THE BLKO REFRESH STATE MACHINE MUST USE THE SAME 46-ROW LIMIT AS THE RETAINED
STORE. A 2026-10-05 REGRESSION LEFT ITS LOCAL DPY_TEXT_ROWS VALUE AT OCTAL
052 (42 DECIMAL) AND ALSO USED OCTAL 052 AS THE BANNER SENTINEL. REFRESH
THEREFORE TERMINATED WHEN IT REACHED LOGICAL ROW 42 EVEN THOUGH THE STORE AND
SCROLL PATH HELD 46 ROWS. THE DRIVER NOW USES OCTAL 056 FOR THE ROW COUNT AND
RESERVES OCTAL 056..060 FOR NON-ROW REFRESH STATES.

THIS LEAVES 16 HORIZONTAL DISPLAY UNITS OUTSIDE THE NORMAL TEXT RECTANGLE.

84 COLUMNS IS ALSO A NATURAL TYPE-342 WIDTH: SIX TYPE-342 CHARACTER CODES FIT
ONE 36-BIT DISPLAY WORD, SO A PRIMARY-SET 84-COLUMN ROW IS EXACTLY FOURTEEN
DISPLAY WORDS BEFORE ROW CONTROL. THE RETAINED STORE USES THE SAME SIX-CELL
GROUPING AS ITS NATIVE REPLAY FORMAT. SCROLLING IS O(1) THROUGH THE 46-ROW
RING RATHER THAN THROUGH PHYSICAL ROW COPYING.

THE HARDWARE CAN ADDRESS A MUCH DENSER CHARACTER GRID. DAIMOS SHALL NOT USE
THE MAXIMUM THEORETICAL GRID MERELY TO INCREASE CHARACTER COUNT, BECAUSE
REFRESH WORK AND LEGIBILITY MATTER MORE.

AN 84-BY-46 TTY REMAINS 84 BY 46 SCALE-2 LOGICAL CELLS. FORMATTED-TEXT
PROGRAMS MAY LEAVE THIS GRID AND LAYOUT SCALE-1/2/4 TEXT DIRECTLY IN DISPLAY
COORDINATES.

## 3. TERMINAL STORAGE

THE IMPLEMENTED STREAM-TTY STORE IS A CANONICAL NATIVE TYPE-342 BLOCK IMAGE.
EACH 84-COLUMN ROW HAS FOURTEEN SIX-CELL BLOCKS AND EACH BLOCK OWNS TWO
36-BIT WORDS. THE SAME WORDS ARE EDITED BY THE TTY PATH AND REPLAYED BY THE
REFRESH PATH; THERE IS NO SECOND PACKED-SIXBIT PLANE AND NO COMPILED-ROW
CACHE. LOWERCASE STREAM OUTPUT IS NORMALIZED TO UPPERCASE BEFORE ENCODING;
MIXED-CASE PRESENTATION BELONGS TO THE FORMATTED-DISPLAY/SIXMD PATH.

A BLOCK HAS THREE REPRESENTATIONS:

    WORD 0 == 0      SIX BLANK CELLS; WORD 1 IS IGNORED
    WORD 1 == 0      SIX PRIMARY-SET GLYPHS PACKED DIRECTLY IN WORD 0
    WORD 1 != 0      SIX FIXED (SI/SO,GLYPH) 12-BIT PAIRS, THREE PER WORD

THE FIXED-PAIR COMPLEX FORM MAKES EVERY CELL INDEPENDENTLY EDITABLE WITHOUT
RECOMPILING A ROW. A BLOCK WHICH HAS BECOME COMPLEX MAY REMAIN TWO WORDS UNTIL
THE ROW IS CLEARED OR SCROLLED; THIS SAVES RESIDENT CODE AND DOES NOT EXCEED
THE HISTORICAL TWO-WORD WORST-CASE BLOCK COST. PRIMARY-ONLY BLOCKS STAY ONE
DISPLAY WORD, SO NORMAL LOGIN/SHELL TEXT KEEPS THE OLD REFRESH BANDWIDTH.

THE COMPLETE FIRST-USE ALLOCATION IS THEREFORE:

     28 WORDS   14 TWO-WORD NATIVE BLOCKS PER ROW
     46 ROWS
   ----------
   1288 WORDS   ONE MM_TYPE_KERNEL_DYNAMIC EXTENT

THE PREVIOUS SIXBIT+COMPILED-CACHE DESIGN USED 1848 WORDS, SO THE NATIVE BLOCK
STORE STILL SAVES 560 DYNAMIC WORDS. THIS 1288-WORD AREA IS RECLAIMABLE/DYNAMIC
WORKING MEMORY AND IS NOT PART OF KCORE+MRES PERMANENT-SIZE ACCOUNTING. ONLY
THE DPY RESIDENT CODE AND SMALL FIXED STATE COUNT TOWARD THE PERMANENT LIMIT.

A ZERO FIRST WORD IS AUTHORITATIVE FOR A BLANK BLOCK, SO ROW CLEAR NEEDS ONLY
FOURTEEN STORES AND MAY LEAVE THE SECOND WORD STALE. FIRST REUSE OF A BLANK
BLOCK DISCARDS THAT STALE WORD. SCROLLING ROTATES THE 46-ROW RING AND CLEARS
ONLY THE NEW BOTTOM ROW. dpy_text_rows_used STILL BOUNDS THE LAST LOGICAL ROW
THAT CAN CONTAIN VISIBLE TEXT, SO REFRESH OMITS ALL TRAILING BLANK ROWS.

FORM FEED (ASCII 014) CLEARS THE RETAINED IMAGE AND RESETS THE CURSOR AND
RING ORIGIN. /SYSTEM/EXEC/CLEAR USES THIS EXISTING TERMINAL CONTROL RATHER
THAN A DPY-SPECIFIC SYSTEM CALL.

THE FORMER 32-WORD INTENSITY RESERVE REMAINS REMOVED. IF AN ORDINARY-TTY
INTENSITY FEATURE IS LATER IMPLEMENTED, ITS BOUNDED METADATA MUST BE ALLOCATED
ONLY WHEN THAT FEATURE IS ACTUALLY USED.

## 4. ZERO-COST UNUSED POLICY

DPY MUST COST NO PERMANENT WORDS WHEN IT IS NOT USED.

THERE ARE THREE DISTINCT CASES:

1. DPY ABSENT:
   KINIT MAY PROBE TRANSIENTLY, BUT NO DPY MRES OR BUFFER IS INSTALLED.
2. DPY PRESENT BUT DISABLED/UNSELECTED:
   KINIT MAY PROBE TRANSIENTLY, BUT SHALL NOT INSTALL THE DPY MRES OR RESERVE
   TEXT/GRAPHICS CORE.
3. DPY ENABLED FOR TEXT OR GRAPHICS:
   KINIT INSTALLS THE SMALL DPY MRES. TEXT AND GRAPHICS STORAGE ARE STILL
   ALLOCATED SEPARATELY AND ONLY WHEN THEIR SERVICE IS ACTIVATED.

CASE 2 DELIBERATELY TRADES LATE ENABLEMENT FOR ZERO RESIDENT COST. UNTIL
GENERAL RUNTIME MODULE LOADING EXISTS, A DPY SKIPPED BY KINIT CANNOT LATER BE
TURNED ON BY TTYOUT WITHOUT REBOOTING INTO A CONFIGURATION THAT ENABLES DPY.
DO NOT KEEP A RESIDENT STUB MERELY TO AVOID THAT REBOOT.

THE BOOT POLICY THAT SELECTS DPY USE MUST BE DECIDED BEFORE KINIT RECLAIMS ITS
TRANSIENT IMAGE. IT SHOULD USE EXISTING BOOT/CONFIGURATION POLICY MECHANISMS
RATHER THAN ADDING A SECOND RUNTIME MODULE SYSTEM.

## 5. TEXT ALLOCATION

EVEN WHEN THE DPY MRES IS INSTALLED, THE 84 BY 46 TEXT STORE IS NOT PART OF
KCORE OR MRES BSS.

ONE CONTIGUOUS MM_TYPE_KERNEL_DYNAMIC EXTENT IS ALLOCATED ON DEMAND BY THE
FIRST ACTUAL TERMINAL BYTE SENT TO DPY. MERELY PROBING THE DISPLAY OR
CONFIGURING A ROUTE DOES NOT ALLOCATE THE 1288-WORD NATIVE TEXT AREA.

ALLOCATION IS A CONTROL-PATH OPERATION. NEITHER THE DPY INTERRUPT PATH NOR
THE ORDINARY CHARACTER-OUTPUT HOT PATH MAY ALLOCATE, COMPACT MEMORY, OR BLOCK
ON MM.

THE TEXT EXTENT MAY REMAIN ALLOCATED WHILE DPY TEXT SERVICE IS ACTIVE. IT MAY
BE RELEASED WHEN THE LAST TEXT USER LEAVES, BUT DO NOT ADD COMPLEX LIFETIME
MACHINERY UNLESS MEASUREMENT SHOWS THAT RECLAIM IS WORTH THE CODE AND CPU.

## 6. REFRESH

APPLICATION OUTPUT UPDATES THE TOUCHED RETAINED TYPE-342 BLOCK AND RETURNS
WITHOUT WAITING FOR THE DISPLAY.

THE PDP-6 TYPE-340 DATA PATH NOW FOLLOWS THE ITS DATA-CHANNEL MODEL.  PI7 IS
DEDICATED TO DISPLAY DATA WHILE DPY IS INSTALLED.  LOW-CORE WORD 056 CONTAINS
`BLKO 0130,dpy_refresh_iowd`; BLKO COUNT OVERFLOW SELECTS WORD 057, WHICH JSRs
DIRECTLY TO THE DPY PACKAGE'S PRIVATE STACKLESS COMPLETION ENTRY.  THE GENERIC
PI7 HANDLER TABLE IS NOT PART OF THIS CHANNEL.  THE EARLIER 2026-10-04 BLKO
EXPERIMENT FAILED BECAUSE BLKO WAS ISSUED FROM INSIDE AN ORDINARY INTERRUPT
HANDLER INSTEAD OF BEING THE PI VECTOR INSTRUCTION ITSELF.

SLV NORMALLY USES PI7, BUT WHEN DPY RESERVES THE LEVEL MINIT MOVES SLV TO THE
ORDINARY PI6 DISPATCH PATH.  NO-DPY SYSTEMS KEEP THE NORMAL PI7 VECTORS AND PAY
NO DISPLAY RUNTIME COST.

THE CURRENT RETAINED FORMAT IS DIRECTLY BLKO-EXECUTABLE.  EACH 84-COLUMN ROW
HAS FOURTEEN TWO-WORD SIX-CELL BLOCKS.  A ZERO FIRST WORD MARKS AN UNINITIALIZED
TRAILING BLANK BLOCK.  ON FIRST USE BOTH WORDS ARE INITIALIZED TO SIX FIXED
`(SI/SO,GLYPH)` PAIRS.  IF CURSOR MOTION FIRST TOUCHES A LATER BLOCK, ANY ZERO
PREDECESSORS ARE INITIALIZED TO EXPLICIT BLANK PAIRS SO THE used row prefix is
contiguous.  The refresh path therefore sends one BLKO span for the initialized
prefix of a row, then one CR/LF span.  The completed IOWD address itself is the
row-end phase marker; there is no per-block simple/complex decoder, shift-state
tracker, or resident block cursor.

A FINITE FRAME ENDS WITH ONE NONPRINTING SI TRAILER.  `dpy_pending` remains set
from frame start through completion of that trailer, so a higher-priority PI6
clock tick can never mistake an inter-span boundary for an idle display.

THE 30-HZ REFRESH RATE REMAINS THE BASELINE.  THE ORDINARY CLK HANDLER STAYS THE
registered PI6 owner and exposes a stackless post-service JRST hook to DPY.  The
hook compares the resident clock tick counter with its previous value so
software scheduler kicks do not advance the display divider.  No refresh or PI
path allocates memory or blocks.

## 7. TERMINAL DEVICE ENDPOINT

THE PHYSICAL DISPLAY AND THE LOGICAL DISPLAY TERMINAL ARE DISTINCT DEVICES:

    /DEV/DPY0       PHYSICAL TYPE-340 DEVICE IDENTITY
    /DEV/TTYDPY0    CTY0 INPUT + DPY0 RETAINED-TEXT OUTPUT

TTYDPY0 APPEARS ONLY WHEN BOTH CTY0 AND DPY0 ARE INSTALLED. IT DOES NOT
CHANGE TTY0'S GLOBAL OUTPUT ROUTE. WRITING TO TTYDPY0 GOES DIRECTLY TO THE
RETAINED DPY TERMINAL, WHILE READING USES CTY0 INPUT. THE ENDPOINT IS
RECOGNIZED AS LOGICAL TTY0 FOR CONTROLLING-TTY/ISATTY PURPOSES, SO NORMAL
CHARACTER-ORIENTED USERLAND OUTPUT DOES NOT GET WRAPPED AS A REGULAR-FILE
S6REC STREAM.

THIS MAKES THE DISPLAY TERMINAL DIRECTLY TESTABLE WITHOUT ALTERING THE LOGIN
ROUTE:

    ECHO TEST > /DEV/TTYDPY0

THE TYPE-340 GUI WINDOW ITSELF IS NOT A DAIMOS KEYBOARD DEVICE. INPUT FOR
TTYDPY0 COMES FROM THE PDP-6 CTY CONSOLE.

## 8. SIXMD AND FORMATTED TEXT

FORMATTED-DISPLAY PROGRAMS MAY USE SCALES 1, 2, AND 4 PLUS ALL EIGHT
INTENSITIES. THIS ALLOWS A TYPE-340 DISPLAY TO RENDER A LARGE PART OF SIXMD
NATIVELY WITHOUT MAKING CHARACTER SIZE PART OF THE TTY ABI.

FORMATTED SIXMD MAY ALSO USE TYPE-342 SHIFT STATE TO DISPLAY LOWERCASE.
SIXMD'S '@' CASE ESCAPES REMAIN SOURCE-LEVEL SIXBIT; THE RENDERER TRANSLATES
THEM DIRECTLY TO THE TYPE-342 PRIMARY/SHIFTED CHARACTER SETS. THIS DOES NOT
CHANGE THE ORDINARY SIXBIT-ONLY TTY BUFFER.

A SUITABLE PRESENTATION POLICY IS:

- NORMAL TEXT: SCALE 2 AT NORMAL INTENSITY;
- EMPHASIS: SCALE 2 AT A HIGHER INTENSITY;
- STRONG EMPHASIS: SCALE 2 AT THE BRIGHTEST TEXT INTENSITY;
- LEVEL-1/2/3 HEADINGS: SCALE 4 OR SCALE 2 PLUS HIGHER INTENSITY;
- QUOTATIONS: SCALE 1 OR SCALE 2 AT A LOWER INTENSITY;
- LITERAL/INDENTED RECORDS: NORMAL CHARACTER MODE WITH DISTINCT INTENSITY;
- LIST MARKERS: ORDINARY TEXT WITH AN OPTIONAL BRIGHT MARKER;
- HORIZONTAL RULES: A NATIVE VECTOR INSTEAD OF A ROW OF DASH CHARACTERS.

THE EXACT VISUAL MAPPING MAY BE TUNED. THE TTY ABI PRESERVES ALL EIGHT
INTENSITIES BUT HAS NO SIZE ATTRIBUTE. FORMATTED-DISPLAY CLIENTS MAY USE
SCALES 1, 2, AND 4; GENERAL GRAPHICS MAY STILL ISSUE RAW SCALE-8 OPERATIONS.

FORMATTED TEXT IS NOT RESTRICTED TO THE 84 BY 46 STREAM GRID. MAN OR ANOTHER
SIXMD RENDERER MAY LAYOUT TEXT IN TYPE-340 DISPLAY COORDINATES USING THE
SMALL 6-BY-11, NORMAL 12-BY-22, AND LARGE 24-BY-44 CELLS. 84 BY 46 REMAINS
THE CONTRACT FOR ORDINARY TTY PROGRAMS.

TTY AND FORMATTED TEXT MAY REUSE ALLOCATED DISPLAY WORKING AREA WHEN
PRACTICAL, BUT THEIR REPRESENTATIONS NEED NOT BE IDENTICAL: TTY STORAGE IS THE
FIXED 84-BY-46 SCALE-2 NATIVE BLOCK IMAGE, WHILE A FORMATTED CLIENT MAY BUILD
A POSITIONED TYPE-340/342 PROGRAM USING SCALE 1/2/4.

## 9. GRAPHICS

NATIVE GRAPHICS PROGRAM STORAGE BELONGS TO USERSPACE. THE KERNEL DOES NOT
ALLOCATE A SECOND RETAINED GRAPHICS BUFFER, PARSE DISPLAY PROGRAMS, OR PROVIDE
GRAPHICS OBJECTS.

/DEV/DPY0 ACCEPTS WHOLE-WORD WRITES AS A PERSISTENT NATIVE TYPE-340 DISPLAY
PROGRAM.  THE DRIVER COPIES THE PROGRAM INTO ONE DYNAMIC EXTENT, PUBLISHES AN
IMMUTABLE BLKO IOWD WITH PI7 DISABLED, THEN STARTS THE LIST.  BLKO COUNT
OVERFLOW RELOADS THAT INITIAL IOWD SO THE hardware continuously recycles the
list without one KCORE entry per display word.  A zero-length write or close
stops the list and releases the extent.  While the raw list owns the controller,
retained-text refresh remains idle; the next 30-Hz tick resumes it after release.

/SYSTEM/EXEC/DPYVIEW REMAINS THE INITIAL USERSPACE CLIENT.  THE KERNEL DOES NOT
DECODE IMAGE FORMATS OR CREATE GRAPHICS OBJECTS; IT ONLY RETAINS AND REPLAYs the
supplied native 36-bit program.  Multi-process compositing, windows, surfaces,
and image-format decoding remain outside the kernel.

## 10. PERFORMANCE RULES

TYPE-340 OPTIMIZATION PRIORITY IS:

1. REDUCE CONTINUOUS REFRESH CPU AND I/O WORK;
2. REDUCE CHARACTER/STYLE UPDATE COST;
3. KEEP INTERACTIVE LATENCY LOW;
4. MINIMIZE RAM;
5. MINIMIZE DRIVER CODE SIZE.

THIS IS AN INTENTIONAL DEVICE-SPECIFIC EXCEPTION TO THE NORMAL DAIMOS
RAM-FIRST OPTIMIZATION ORDER: A REFRESH DISPLAY CAN CONSUME CPU CONTINUOUSLY,
SO A MODEST BOUNDED MEMORY COST IS ACCEPTABLE WHEN IT REMOVES REPEATED WORK.

NO INTERRUPT PATH MAY ALLOCATE MEMORY OR BLOCK. NO ORDINARY CHARACTER OUTPUT
PATH MAY SPIN WAITING FOR DPY DONE.
