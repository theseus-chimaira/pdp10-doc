# TYPE 340 DISPLAY DESIGN

STATUS: DAIMOS PDP-6 TYPE-340/342 DISPLAY DESIGN.

## 1. GOALS

THE TYPE 340 SHALL SUPPORT A NORMAL DAIMOS LOGIN/DSH TERMINAL WITHOUT TURNING
THE PDP-6 INTO A CHARACTER-AT-A-TIME DISPLAY SERVER. REFRESH-TIME CPU COST IS
MORE IMPORTANT HERE THAN SAVING A FEW WORDS OF DRIVER CODE, BUT AN UNUSED
DISPLAY MUST NOT CONSUME PERMANENT CORE.

THE DESIGN FOLLOWS THE USEFUL PART OF THE HISTORICAL ITS MODEL: KEEP RETAINED
DISPLAY STATE IN MEMORY AND FEED THE REFRESH DISPLAY ASYNCHRONOUSLY. NORMAL
CHARACTER OUTPUT MODIFIES MEMORY AND RETURNS. IT MUST NOT WAIT FOR TYPE-340
DONE AFTER EACH CHARACTER.

THE TYPE 340/342 PROVIDES:

- A 1024 BY 1024 DISPLAY COORDINATE SPACE;
- A TYPE-342 CHARACTER CELL OF 6 BY 11 DISPLAY UNITS AT SCALE 1 IN THE
  CURRENT HARDWARE MODEL;
- FOUR CHARACTER/VECTOR SCALE SETTINGS: 1, 2, 4, AND 8;
- EIGHT INTENSITY SETTINGS: 0 THROUGH 7;
- NATIVE POINT, VECTOR, INCREMENTAL, AND CHARACTER MODES.

THE FOUR SCALE SETTINGS MUST NOT BE CONFUSED WITH INTENSITY. INTENSITY IS A
THREE-BIT FIELD AND THEREFORE HAS EIGHT LEVELS.

## 2. NORMAL TERMINAL GEOMETRY

THE NORMAL STREAM TERMINAL TARGET IS 80 COLUMNS BY 24 ROWS. THIS IS A DAIMOS
TTY GEOMETRY, NOT A TYPE-340 HARDWARE LIMIT.

AT SCALE 1, 80 COLUMNS REQUIRE 480 OF 1024 HORIZONTAL DISPLAY UNITS AND 24
ROWS REQUIRE 264 VERTICAL UNITS. THE UNUSED DISPLAY AREA IS INTENTIONAL: IT
IMPROVES READABILITY AND LEAVES ROOM FOR LARGER FORMATTED HEADINGS, STATUS
MATERIAL, AND GRAPHICS.

THE HARDWARE CAN ADDRESS A MUCH DENSER CHARACTER GRID. DAIMOS SHALL NOT USE
THE MAXIMUM THEORETICAL GRID MERELY TO INCREASE CHARACTER COUNT, BECAUSE
REFRESH WORK AND LEGIBILITY MATTER MORE.

## 3. TERMINAL STORAGE

THE NORMAL CHARACTER PLANE IS PACKED SIXBIT. AN 80 BY 24 SCREEN HAS 1920
CELLS, SO THE CHARACTER PLANE REQUIRES 320 36-BIT WORDS.

SCALE AND INTENSITY ARE SPARSE ATTRIBUTES. THEY SHALL NOT BE STORED AS A
PER-CELL ATTRIBUTE FIELD. INSTEAD, THE TEXT STORE HAS A SMALL BOUNDED POOL OF
STYLE-RUN TRANSITIONS. A TRANSITION IDENTIFIES A SCREEN POSITION AND THE NEW
TWO-BIT SCALE PLUS THREE-BIT INTENSITY.

A 64-TRANSITION POOL NEEDS ABOUT 32 WORDS WHEN TWO TRANSITIONS ARE PACKED PER
WORD. THE EXACT BOUND MAY BE TUNED AFTER TARGET MEASUREMENT, BUT IT MUST
REMAIN FIXED. EXHAUSTION MUST DEGRADE PRESENTATION SAFELY BY COALESCING STYLE
RUNS OR USING THE CURRENT/DEFAULT STYLE; CHARACTER OUTPUT MUST NOT START
ALLOCATING MEMORY.

THE INITIAL STORAGE BUDGET IS THEREFORE APPROXIMATELY:

    320 WORDS   80 BY 24 PACKED-SIXBIT CHARACTER PLANE
     32 WORDS   64 SPARSE STYLE TRANSITIONS
     SMALL      CURSOR, REFRESH, AND BOUNDED CONVERSION STATE

THIS IS A BUDGET, NOT A 512-WORD RESERVATION. THE IMPLEMENTATION SHALL
ALLOCATE THE EXACT BOUNDED SIZE REQUIRED BY THE FINAL REPRESENTATION.

## 4. ZERO-COST UNUSED POLICY

DPY MUST COST NO PERMANENT WORDS WHEN IT IS NOT USED.

THERE ARE THREE DISTINCT CASES:

1. DPY ABSENT:
   KINIT MAY PROBE TRANSIENTLY, BUT NO DPY MRES OR BUFFER IS INSTALLED.
2. DPY PRESENT BUT DISABLED/UNSELECTED:
   KINIT MAY PROBE TRANSIENTLY, BUT SHALL NOT INSTALL THE DPY MRES OR RESERVE
   TEXT/GRAPHICS CORE.
3. DPY ENABLED FOR TEXT OR GRAPHICS:
   KINIT INSTALLS THE SMALL DPY MRES. TEXT AND GRAPHICS STORAGE ARE STILL
   ALLOCATED SEPARATELY AND ONLY WHEN THEIR SERVICE IS ACTIVATED.

CASE 2 DELIBERATELY TRADES LATE ENABLEMENT FOR ZERO RESIDENT COST. UNTIL
GENERAL RUNTIME MODULE LOADING EXISTS, A DPY SKIPPED BY KINIT CANNOT LATER BE
TURNED ON BY TTYOUT WITHOUT REBOOTING INTO A CONFIGURATION THAT ENABLES DPY.
DO NOT KEEP A RESIDENT STUB MERELY TO AVOID THAT REBOOT.

THE BOOT POLICY THAT SELECTS DPY USE MUST BE DECIDED BEFORE KINIT RECLAIMS ITS
TRANSIENT IMAGE. IT SHOULD USE EXISTING BOOT/CONFIGURATION POLICY MECHANISMS
RATHER THAN ADDING A SECOND RUNTIME MODULE SYSTEM.

## 5. TEXT ALLOCATION

EVEN WHEN THE DPY MRES IS INSTALLED, THE 80 BY 24 TEXT STORE IS NOT PART OF
KCORE OR MRES BSS.

ONE CONTIGUOUS MM_TYPE_KERNEL_DYNAMIC EXTENT IS ALLOCATED ON DEMAND WHEN DPY
TEXT SERVICE IS FIRST ACTIVATED, PREFERABLY WHEN THE FIRST LOGICAL TTY IS
ROUTED TO DPY OR A FORMATTED-TEXT CLIENT TAKES THE DISPLAY.

ALLOCATION IS A CONTROL-PATH OPERATION. NEITHER THE DPY INTERRUPT PATH NOR
THE ORDINARY CHARACTER-OUTPUT HOT PATH MAY ALLOCATE, COMPACT MEMORY, OR BLOCK
ON MM.

THE TEXT EXTENT MAY REMAIN ALLOCATED WHILE DPY TEXT SERVICE IS ACTIVE. IT MAY
BE RELEASED WHEN THE LAST TEXT USER LEAVES, BUT DO NOT ADD COMPLEX LIFETIME
MACHINERY UNLESS MEASUREMENT SHOWS THAT RECLAIM IS WORTH THE CODE AND CPU.

## 6. REFRESH

APPLICATION OUTPUT UPDATES RETAINED TEXT STATE AND RETURNS IMMEDIATELY.

THE LOW-PRIORITY DISPLAY SERVICE REFRESHES THE CRT ASYNCHRONOUSLY. THE
PREFERRED TYPE-344 PATH USES BLOCK OUTPUT SEMANTICS WHERE PRACTICAL, FOLLOWING
THE HISTORICAL ITS APPROACH. TYPE-342 CHARACTER MODE IS RETAINED ACROSS
SUCCESSIVE CHARACTERS SO ONE 36-BIT DISPLAY WORD CAN CARRY SIX CHARACTER
CODES. SCALE OR INTENSITY CHANGES INSERT PARAMETER OPERATIONS ONLY AT STYLE
RUN BOUNDARIES.

THE CURRENT 30-HZ REFRESH RATE REMAINS THE BASELINE UNTIL A LOWER RATE IS
PROVEN VISUALLY AND BY TARGET ACCEPTANCE. THE PREVIOUS 20-HZ EXPERIMENT WAS
PHASE-SENSITIVE IN HEADLESS TESTING.

## 7. SIXMD AND FORMATTED TEXT

THE FOUR SCALE SETTINGS AND EIGHT INTENSITIES ARE FIRST-CLASS TEXT
PRESENTATION ATTRIBUTES. THIS ALLOWS A TYPE-340 DISPLAY TO RENDER A LARGE
PART OF SIXMD NATIVELY WITHOUT A BITMAP FONT OR GENERAL GRAPHICS COMPOSITOR.

A SUITABLE PRESENTATION POLICY IS:

- NORMAL TEXT: SCALE 1 AT NORMAL INTENSITY;
- EMPHASIS: SCALE 1 AT A HIGHER INTENSITY;
- STRONG EMPHASIS: SCALE 1 AT THE BRIGHTEST TEXT INTENSITY;
- LEVEL-1/2/3 HEADINGS: LARGER SCALE AND/OR HIGHER INTENSITY;
- QUOTATIONS: SCALE 1 AT A LOWER INTENSITY;
- LITERAL/INDENTED RECORDS: NORMAL CHARACTER MODE WITH DISTINCT INTENSITY;
- LIST MARKERS: ORDINARY TEXT WITH AN OPTIONAL BRIGHT MARKER;
- HORIZONTAL RULES: A NATIVE VECTOR INSTEAD OF A ROW OF DASH CHARACTERS.

THE EXACT VISUAL MAPPING MAY BE TUNED. THE DISPLAY ABI MUST PRESERVE ALL FOUR
SCALE VALUES AND ALL EIGHT INTENSITIES.

FORMATTED TEXT IS NOT RESTRICTED TO THE 80 BY 24 STREAM GRID. MAN OR ANOTHER
SIXMD RENDERER MAY LAYOUT TEXT IN TYPE-340 DISPLAY COORDINATES USING THE
6-BY-11 SCALE-1 CELL AND THE LARGER HARDWARE SCALE VALUES. 80 BY 24 REMAINS
THE CONTRACT FOR ORDINARY TTY PROGRAMS.

TTY AND FORMATTED TEXT SHOULD SHARE THE SAME BOUNDED TEXT STORAGE WHEN
PRACTICAL. THEY DO NOT REQUIRE TWO RETAINED SCREEN BUFFERS WHEN ONLY ONE
PRESENTATION IS VISIBLE.

## 8. GRAPHICS

GENERAL GRAPHICS STORAGE IS SEPARATE FROM THE TERMINAL TEXT STORE.

GRAPHICS USES ZERO BUFFER CORE UNTIL A GRAPHICS OWNER REQUESTS IT. THE KERNEL
THEN ALLOCATES ONE CONTIGUOUS MANAGED-CORE EXTENT FOR THAT OWNER'S NATIVE
TYPE-340 DISPLAY PROGRAM. INDIVIDUAL VECTORS, POINTS, GLYPHS, OR OBJECTS MUST
NOT CAUSE KERNEL ALLOCATIONS. DRAWING OPERATIONS EDIT THE ALREADY-ALLOCATED
PROGRAM.

THE GRAPHICS OWNER PUBLISHES A BASE AND USED LENGTH. REFRESH CAN STREAM TEXT,
GRAPHICS, OR BOTH WITHOUT COPYING THEM INTO A THIRD PER-FRAME BUFFER.

INITIAL DISPLAY MODES ARE:

    TEXT
    GRAPHICS
    TEXT+GRAPHICS

ONLY ONE GENERAL GRAPHICS OWNER IS REQUIRED INITIALLY. MULTI-PROCESS
COMPOSITING, WINDOWS, SURFACES, AND A KERNEL GRAPHICS OBJECT MODEL ARE OUT OF
SCOPE.

## 9. PERFORMANCE RULES

TYPE-340 OPTIMIZATION PRIORITY IS:

1. REDUCE CONTINUOUS REFRESH CPU AND I/O WORK;
2. REDUCE CHARACTER/STYLE UPDATE COST;
3. KEEP INTERACTIVE LATENCY LOW;
4. MINIMIZE RAM;
5. MINIMIZE DRIVER CODE SIZE.

THIS IS AN INTENTIONAL DEVICE-SPECIFIC EXCEPTION TO THE NORMAL DAIMOS
RAM-FIRST OPTIMIZATION ORDER: A REFRESH DISPLAY CAN CONSUME CPU CONTINUOUSLY,
SO A MODEST BOUNDED MEMORY COST IS ACCEPTABLE WHEN IT REMOVES REPEATED WORK.

NO INTERRUPT PATH MAY ALLOCATE MEMORY OR BLOCK. NO ORDINARY CHARACTER OUTPUT
PATH MAY SPIN WAITING FOR DPY DONE.
