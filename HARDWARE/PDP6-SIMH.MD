# PDP-6 SIMH HARDWARE INTEGRATION NOTES

DATE: 2026-09-18
STATUS: CURRENT VERIFIED HARDWARE CONTRACT AND DEFERRED ITEMS

## 1. PHIL PETIT PCLK

THE SIMH TREE CONTAINS AN IMPLEMENTATION OF THE STANFORD A.I. LAB PHIL PETIT
CALENDAR CLOCK IN `PDP10/KA10_PCLK.C`.  THE SOURCE ITSELF RECORDS THAT THE
ORIGINAL DEVICE WAS INSTALLED ON THE PDP-6 I/O BUS AT SAIL IN 1967.

THE IMPLEMENTATION WAS PREVIOUSLY WIRED ONLY INTO THE KA/WAITS CONFIGURATION
AND ITS CALENDAR DATE WAS FIXED TO 1974-07-26.  PDP-6 DAIMOS REQUIRES PCLK AS
STANDARD HARDWARE.

THE PDP-6 SIMULATOR CONTRACT IS NOW:

- COMPILE/LINK THE EXISTING PCLK SOURCE INTO PDP-6;
- EXPOSE DEVICE 0730;
- ENABLE IT BY DEFAULT FOR PDP-6;
- DEFAULT TO `REALTIME`, WHICH REPORTS HOST UTC DATE/TIME;
- HAVE DAIMOS GENERATED SIMH CONFIGURATIONS EXPLICITLY `SET PCLK ENABLED` AND
  SELECT `SIMH_PCLK_MODE` (`REALTIME` BY DEFAULT), RATHER THAN RELYING ON THE
  SIMULATOR DEFAULT;
- RETAIN `HISTORICAL` FOR THE OLD WAITS RE-ENACTMENT;
- PRESERVE THE HISTORICAL PETIT REGISTER ENCODING;
- DO NOT ENABLE THE COMMENTED PCLK INTERRUPT PATH FOR DAIMOS.

THE TWO-DIGIT YEAR IS DIGIT-ENCODED.  FOR EXAMPLE, YEAR 74 USES NIBBLES 7 AND
4.  DAIMOS DEFINES THE 2026..2125 CENTURY INTERPRETATION; SIMH DOES NOT.

## 2. PDP-6 LINE PRINTER

`KX10_LP.C` WAS ALREADY PART OF THE PDP-6 SOURCE LIST, BUT `NUM_DEVS_LP` WAS
DEFINED ONLY WHEN NEITHER PDP6 NOR KS WAS SELECTED.  THE RESULT WAS AN
IMPLEMENTED/COMPILED LINE-PRINTER SOURCE THAT WAS NOT EXPOSED AS A PDP-6
DEVICE.

PDP-6 SHALL DEFINE ONE LPT DEVICE.  THE EXISTING IMPLEMENTATION PROVIDES THE
NEEDED PDP-6-STYLE DEVICE AT I/O DEVICE 0124 AND DOES NOT REQUIRE A SEPARATE
DAIMOS-SPECIFIC SIMULATOR IMPLEMENTATION.

DAIMOS NOW HAS A POLLED MRES DRIVER FOR THIS DEVICE.  THE GENERATED SIMH
CONFIGURATION ENABLES LPT AND ATTACHES IT TO `media/lpt.out`; THE I/O STREAM IS
EXPOSED AS `/DEV/LPT0` AND ITS STATE UNDER `/MONITOR/DEVICES/LPT0`.  RAW
WRITECHAR SENDS ONE SEVEN-BIT CHARACTER.  WORD OUTPUT accepts one complete
S6REC TEXT record and exploits the LP10 DATAO format by packing up to five
seven-bit characters per hardware transfer, reducing waits by up to 5x.  The
MRES is installed only when LPT probes successfully; systems without a printer
pay only the fixed patched service stub.  Physical-output validation produces
the expected S6REC text plus CR/LF in the SIMH printer file.

## 3. TYPE 516 MTC SELECT STATUS BIT

THE SIMULATOR PREVIOUSLY NAMED MTC/MTS CONO BIT 0000002 `ENB_JNU`, DERIVED AN
`IRQ_JNU` STATUS MASK FROM IT, AND CARRIED A DISABLED SPECULATIVE INTERRUPT
BRANCH.

HISTORICAL PDP-6 TS SOFTWARE RESOLVES THE AMBIGUITY: BIT 0000002 IS `SEL`, THE
OPERATION THAT SELECTS THE UNIT NAMED IN THE COMMAND BUFFER SO ITS STATUS CAN
BE OBSERVED.  SOFTWARE ISSUES THE SELECT AND THEN TESTS THE SAME STATUS BIT; IT
IS NOT AN INTERRUPT-ENABLE OPERATION.

THE SIMULATOR THEREFORE SHALL:

- MODEL BIT 0000002 AS SELECT-UNIT STATUS CONTROL;
- NOT COPY IT INTO THE INTERRUPT-ENABLE STATUS MASK;
- NOT ENABLE A JNU INTERRUPT PATH;
- RESET THE SELECTED UNIT TO UNIT 0, NOT TO A VALUE COMPOSED FROM TAPE-STATUS
  FLAG CONSTANTS.

THIS IS A CORRECTNESS FIX, NOT AN OPTIONAL DAIMOS QUIRK.

## 4. MULTI-WINDOW VIDEO EVENT HANDLING

DAIMOS `MAKE BOOT` ENABLES THE PDP-6 DISPLAY AND SPACEWAR CONSOLE DEVICES AT
THE SAME TIME, SO SIMH MAY HAVE MORE THAN ONE SDL VIDEO WINDOW ACTIVE.  THE
SIMH VIDEO THREAD MUST CORRECTLY REPROCESS A COALESCED `EVENT_REDRAW` THAT
BELONGS TO A DIFFERENT WINDOW.  THE PREVIOUS EVENT LOOP LEFT THAT SECOND
REDRAW AS USER EVENT CODE 1 AND THEN FELL THROUGH TO:

    VID_THREAD(): UNEXPECTED USER EVENT CODE: 1

IN DIRECT GUI BOOTS THIS ALSO INTERFERED WITH THE CTY INTERACTIVE PATH AFTER
LOGIN.  THE FIX IS IN SIMH `SIM_VIDEO.C`: WHEN REDRAW COALESCING DEQUEUES A
REDRAW FOR ANOTHER WINDOW, LOOP BACK AND PROCESS IT AS A FRESH REDRAW INSTEAD
OF TREATING IT AS AN UNKNOWN EVENT.

THE ACCEPTANCE CONTRACT IS A GUI-ENABLED FULL BOOT THROUGH CTY `LOGIN -> DSH`
FOLLOWED BY VISIBLE RAW-EDITOR INPUT AND COMMAND OUTPUT, WITH NO UNEXPECTED
VIDEO USER-EVENT DIAGNOSTIC.  DCS0 AND GE0 LOGIN ACCEPTANCE REMAINS REQUIRED
IN PARALLEL.

## 5. TYPE 340 REFRESH AND INTERRUPT POLICY

THE TYPE 340 ON THE PDP-6 USES THE TYPE 344 CPU-FED INTERFACE, NOT THE TYPE
347 MEMORY/SUBROUTINE OPTION.  THE DISPLAY THEREFORE CANNOT LOOP OVER A
DISPLAY LIST BY ITSELF: EACH 36-BIT WORD IS SUPPLIED BY THE CPU AND COMPLETION
OF THAT WORD IS REPORTED THROUGH DONE.

DAIMOS RETAINS THE FIVE-WORD GENERATED BOOT BANNER IN THE OPTIONAL DPY MRES
AND REPLAYS IT AT 30 HZ.  THE START OF EACH FRAME REINITIALIZES THE TYPE 340
STATE AND PRESERVES THE DATA PIA, SO THE GENERATED LIST ALWAYS BEGINS FROM THE
SAME MODE/BEAM STATE.  THE FIRST WORD IS STARTED BY THE CLOCK WRAPPER; THE
REMAINING WORDS ARE CHAINED FROM DONE INTERRUPTS WITHOUT POLLING.

INTERRUPT POLICY IS:

- APR LINE CLOCK AND SOFTWARE SCHEDULER KICKS REMAIN ON PI6;
- TYPE-340 DATA/DONE USES PI7, THE LOWEST PDP-6 PRIORITY;
- DPY IS A PI7 PRE-HANDLER AND THEN REJOINS THE ORDINARY PI7 HANDLER SPAN, SO
  SLV AND OTHER PI7 USERS KEEP THEIR NORMAL TABLE DISPATCH;
- DPY DOES NOT CONSUME A NINTH ENTRY IN THE EIGHT-WORD RESIDENT PI HANDLER
  TABLE;
- WHEN DPY IS ABSENT, KINIT DOES NOT INSTALL THE DPY MRES, DOES NOT REPLACE
  THE CLOCK HANDLER, AND DOES NOT PATCH THE PI7 SPAN-LOAD WORD.  THE NO-DPY
  RUNTIME PATH IS THEREFORE IDENTICAL TO THE ORDINARY CLK/PI7 PATH WITH ZERO
  PERIODIC DISPLAY WORK.

THE 20-HZ EXPERIMENT WAS REJECTED: HEADLESS FRAMEBUFFER DUMPS WERE
PHASE-SENSITIVE AND COULD BE COMPLETELY DARK.  AT 30 HZ, INDEPENDENT KINIT
BREAKPOINT DUMPS CONSISTENTLY RETAINED THE SAME 147 LIT PIXELS AND THE SAME
BANNER BOUNDING BOX, WHILE HALVING THE REFRESH RATE RELATIVE TO 60 HZ.

THE GUI BOOT ACCEPTANCE MUST STILL REACH `DPY OK`, CTY LOGIN -> DSH, AND THE
DCS0/GE0 LOGIN PATHS WITHOUT THE OLD MULTI-WINDOW VIDEO EVENT DIAGNOSTIC.

THE FIVE-WORD BANNER IS THE CURRENT BRINGUP/ACCEPTANCE IMPLEMENTATION, NOT THE
FINAL INTERACTIVE TERMINAL MODEL. THE TARGET DPY DESIGN USES RETAINED,
ASYNCHRONOUSLY REFRESHED TYPE-342 TEXT WITH 84-BY-42 STREAM-TERMINAL
SEMANTICS, NORMAL TEXT AT HARDWARE SCALE 2, SMALL/LARGE TEXT AT SCALES 1/4,
ALL EIGHT INTENSITIES, AND
SEPARATE ON-DEMAND GRAPHICS STORAGE. AN ABSENT OR BOOT-DISABLED DPY MUST
LEAVE ZERO DPY RESIDENT WORDS AFTER KINIT. SEE `HARDWARE/TYPE340.MD`.
