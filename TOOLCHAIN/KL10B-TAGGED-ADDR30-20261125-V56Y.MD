# Host tagged ADDR30 words and exact-width pointer model (v56y)

DAS eca12aa, testkit 5c80d9b. The completed work is a host assembler
extension and independently tested software pointer representation
experiment. GCC remains at 47178f0; no exact-width C pointer lowering
or new GCC/KCC ABI has been installed.

## Tagged relocation syntax

```
.long %GADDR(44,object+1)
move 1,[%GADDR(45,object)]
```

The tag and address expressions are octal by default. The tag must
be an absolute integer in 0..077 octal. The low 30 bits use the
existing GIW/ADDR30 address evaluation, including signed relocatable
addends, strict-base rejection and DOBJ2 relocation requirements.
No additional relocation type or object format. Unlike OWGBP or
EXIND, GADDR does not assign hardware meaning to the six tag bits.
It is not safe to use an arbitrary tagged word as a hardware byte
pointer or effective address. The host assembler recognizes the
parenthesized pseudo-operator in literal sizing even when no space
precedes the opening parenthesis; this also corrects the host
EXIND operator recognition. No new resident assembler code or table
entries; both native phase preprocessed sources are equivalent to
the baseline modulo the while-body braces and line-number diagnostics.
Actual resident binary sizes have not been measured.

## Verified candidate software representation

All 30 virtual address bits can be retained in a single 36-bit word.
The test model uses the high six bits as follows (octal):

- 00: native exact32 word slot, right-justified value.
- 01..44: packed physical bit position 0..35, left-to-right.
- 45/54: native exact16 array slots, starts at bits 0/16.
- Remaining ordinary hardware OWGBP selectors are not changed.

45 and 54 are hardware before-first-byte selectors, not canonical
C byte addresses. The experiment reserves them for typed exact16
software pointers. A standalone right-justified exact16 value can
use the packed position 20 (tag 25 octal). The same tag encoding
is used by the packed exact16 and exact32 types; the source type
provides element width. Null remains a zero word. The tested model
requires valid typed pointer arithmetic, not arbitrary integer
forgeries. Interoperability through void*, mixed-width casts,
relational comparison, native scalar address formation and the
compiler-generated by-value ABI have not been established. These
conditions must be checked before freezing a common ABI.

For continuous exact16/32 advancement, divide the signed element
count by nine: each nine elements spans width/4 words. The remainder
and starting bit position have a bounded magnitude. Normalize the
residual bit position to 0..35, with floor correction for negative
remainders. Same-array subtraction uses 9*(word difference) plus
(bit position difference)/4, divided by width/4. All valid
intermediates fit a signed 36-bit word even at the extremes of the
30-bit coordinate range. Native exact16 slots use two elements per
word with floor correction; native exact32 slots use word arithmetic.
Field access decodes the address and bit position, accessing a second
word only for a crossing field. The test C implementation is an
independent feasibility model, not a selected compiler runtime helper
or a measurement of the eventual code footprint or execution cost.

## Acceptance evidence

The dedicated `gcc-global-exact-model-v56y` test verifies all 64 tags
at maximum absolute address, all 128 local/external symbolic tag
relocations through actual extended linking, tag 077 and signed
addends, range/overflow/underflow and malformed syntax guards.
It executes 3398 host-oracled arithmetic rows (four forward/reverse
checks per row) and 75 unsigned field read/write rows per run.
Arithmetic includes all 36 positions at both widths, native slots,
section carries and almost full-range signed offsets. High virtual
addresses outside the actual emulator mappings are arithmetic-only.
Memory tests cover every bit position at both widths, native slots,
cross-word access and preservation of adjacent bits/words. All eight
O0/O1/O2/Os SIMH/KLH10 runs pass. No signed exact-width C dereference,
actual typed pointer lowering, or cross-compiler ABI pass is claimed.

DAS fast suite, prior DOBJ2 suite, byte-identical representative
DOBJ1 objects and local DXR linking, ten previous extended runtime
observations and four static-pointer object profiles pass again.
Inventory: 2400 matrix sources, 436 special entries, no unowned
sources. Evidence manifest:
`pdp10-testkit/manifests/PDP10-GLOBAL-EXACT-POINTER-MODEL-20261125-v56y.tsv`.
Host DAS staging directory: TMPDIR/pdp10-das-tagged-address-v56y.
No changes to DAIMOS, the compiler matrix, production binaries, or
historical failure counts.
