# GCC PDP-10 PACKED 9-BIT STRING BUILTIN CORRECTION (2026-11-20, V1)

## VERIFIED DEFECT AND CORRECTION

THE GCC 3.2 PDP-10 FRONT END STORES NARROW 9-BIT STRING
CONSTANTS AS TWO HOST BYTES PER TARGET CHARACTER.  THIS
PRESERVES VALUES 0400..0777, WHICH CANNOT FIT INTO A HOST
8-BIT CHARACTER.  HOWEVER, THE GENERIC `gcc/builtins.c`
`c_strlen()` PREVIOUSLY USED THE HOST `strlen()` ON THOSE
STORAGE BYTES.  THE FIRST HOST BYTE OF A NORMAL ASCII
CHARACTER IS ZERO, SO GCC INCORRECTLY TREATED `" a b"` AS
AN EMPTY STRING.  OPTIMIZED `strcpy` EMITTED ONLY THE FIRST
TARGET BYTE, OMITTING THE REMAINING CHARACTERS AND NUL.

GCC NOW USES THE `PDP10_STRING_CST_9BIT_P` REPRESENTATION
FLAG TO COMPUTE LOGICAL TARGET LENGTHS AND SCAN COMPLETE
9-BIT UNITS FOR THE NUL TERMINATOR.  GENERIC `c_getstr`
DOES NOT PASS THE TWO-HOST-BYTE FORM TO HOST `strcmp` OR
OTHER HOST CHARACTER SEARCHES.  SAFE INLINE LITERAL COPIES
RETAIN THE EXISTING PDP-10-AWARE MEMCPY STORE CALLBACK.
THIS IS A COMPILER-SIDE REPRESENTATION FIX, NOT A TEST
WORKAROUND, HOSTED LIBC EMULATION OR NEW TARGET MEMORY
ALLOCATION.

THE CORRECTION IS COMMITTED IN THE OWNING GCC REPOSITORY
AS `507f2e7` (`pdp10-gcc`, MASTER).  THE CORRECTED
`gcc/builtins.c` SOURCE SHA256 IS
`32d2e6d1c375d8d313ecfb59fb0455f03aebc0338efeecb409d4a5c718e13513`.
THE HOST GCC 3.2 COMPILER WAS REBUILT WITH ITS REQUIRED
GNU89 FLAGS AND THE RESULTING `cc1` WAS INSTALLED INTO
`$PDP10_PREFIX/lib/gcc-lib/pdp10-dec-none/3.2/cc1`.
THE OLD EXECUTABLE WAS RETAINED AS A VERSIONED `$TMPDIR`
BACKUP.  OLD `cc1` SHA256:
`d43034a6151e57787514ff6293b6d8da846de34a6192766d701505dab1eb6cc8`.
CORRECTED INSTALLED `cc1` SHA256:
`0c33d1e7e93dd372e8b503aabf167c3299acdd830b289199c679ca07a7529b8a`.
