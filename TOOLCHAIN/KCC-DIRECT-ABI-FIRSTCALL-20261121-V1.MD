# KCC DIRECT-ABI FIRST-CALL PARAMETER LIVENESS (2026-11-21, V1)

## COMPLETED COMPILER CORRECTION

KCC COMMIT `551f406` REPAIRS A DIRECT-ABI ARGUMENT-LIVENESS BUG
IN `ccdecl.c:promote_abi_params()`. A PARAMETER REFERENCED
AFTER A NESTED CALL COULD REMAIN IN ITS CALL-VOLATILE INCOMING
REGISTER AND BE FALSELY CLASSIFIED AS DEAD AT THE FIRST CALL.

THE RESULT WAS A REAL PDP-6 COMPILER ERROR: AFTER CALLING AN
INDIRECT `void *` IDENTITY FUNCTION, A FOLLOWING S=9 BYTE-
POINTER COMPARISON SAW THE ORIGINAL RETURNED POINTER WORD
`001100002503` VERSUS THE TRANSIENT STACK ADDRESS
`000000001511`. THE COMPLETE COMPANION ABORTED AT DECIMAL
ID 10. THE PDP-6 SIMULATOR PRINTS THIS ID IN **OCTAL** AS
`000000000012`; IT IS NOT DECIMAL ID 12. A MINIMAL TWO-CALL
DIAGNOSTIC CONFIRMED THE FAILURE WAS IN THE FIRST 9-BIT
CHECK, BEFORE THE SECOND S=18 CHECKER WAS EVER ENTERED.

THE OWNING FRONT END NOW PERMITS FIRST-CALL PARAMETER DROP
ONLY WHEN THE COMPLETED FUNCTION BODY CONTAINS EXACTLY ONE
REFERENCE TO THAT PARAMETER. MULTI-USE PARAMETERS TAKE THE
EXISTING CALL-PRESERVED AC PATH. THE PROVEN SINGLE-USE
ZERO-COPY FAST PATH REMAINS ENABLED. THE REPAIR ADDS NO
PERMANENT RAM, NO OS SERVICE AND NO NEW RUNTIME LIBRARY.

THE EARLIER INDEPENDENT KCC FIXES ARE ALSO PRESERVED:
`46d0181` (SELF-DESCRIBING POINTER WIDTH THROUGH `void *`)
AND `4a61c53` (CANONICAL POINTER COMPARISON REGISTER LIVENESS).
THE INSTALLED POST-REPAIR KCC COMPILER SHA256 IS
`fbe85b127e2004fac0538b338101a5bca9b155bdf7aad3cd06d0917671ba538b`.
