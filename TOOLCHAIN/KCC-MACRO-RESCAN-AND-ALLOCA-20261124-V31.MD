# KCC v30/v31: correct macro expansion and caller-frame alloca

Status: repaired, installed and independently accepted for the specified
source and CPU profiles on 2026-11-24. The remaining static-inline and
console linker dependencies are separate open work.

## Origin and scope

The v29 testkit census recorded 50 exact `link_fail` cells. Thirty-four
belong to KCC: 22 `alloca`, four incorrect C99 macro rescan, four unused
internal inline-function dependencies and four unavailable hosted
`puts` references. This change repairs the first 26 KCC cells. It does
not rewrite any original source assertion, supply fake linker symbols,
or change a DLINK relocation rule. The GCC-specific 16 `puts` cells are
not part of the compiler fix.

## v30: function-like macro expansion at replacement boundaries

`ccpp.c:mexpand()` previously preserved a temporary hideset after a
function-like macro had consumed its `(` and arguments from an outer
token stream. With `#define c(x) d` and `#define d(x) c(2)`, the original
historical `macro3.c` consequently produced `c(2)` from `c(c)(c)` and
assembled a call to the undefined external `c`.

The repair reduces only the exhausted inner replacement's hideset
after an *actual function-like* macro invocation crosses that boundary.
The remaining enclosing macro hides are retained. This distinction is
essential: an earlier experiment applied the rule to object-like macros
and overexpanded original `strp1.c`. The final code leaves its expected
`"1+h(2)"` string intact, and also fixes the separately reviewed
upstream `macro6.c`. No global macro pool or persistent RAM metadata
was added.

## v31: GNU alloca using the existing KCC dynamic VLA frame

Previously KCC treated an undeclared `alloca(16)` as a plain external
function call with an integer result converted to a pointer. That was
neither linkable nor a valid implementation of caller-frame lifetime.

`ccstmt.c` now recognizes undeclared direct `alloca(size)` and
`__builtin_alloca(size)` in the same bounded way as its existing GNU
memory builtin support. The result type is `void *` and the argument
type is `size_t`. An explicit user definition is not intercepted.
`ccdecl.c` marks the enclosing function as having a dynamic VLA frame,
which uses AC14 as the fixed-frame anchor and reserves that register
from ordinary allocation. The symbol flag `SF_ALLOCA` selects codegen.

`ccgen2.c` emits the actual caller-side allocation: round 9-bit byte
count up to 36-bit words, form the first free stack word address,
advance AC17/SP in the current function and produce an S=9 byte
pointer. The VLA return epilogue restores SP from AC14 even when
the function made further calls or allocations. No artificial
`PUSHJ alloca` helper is used. `ccout.c` also omits the leftover
`EXTERN alloca` generated by the earlier provisional parser stage;
the linker remains strict for all genuinely used external symbols.

This is a compiler builtin for undeclared *direct* invocations; making
an explicit source-level external function declaration work as a
builtin, or guaranteeing allocations beyond the addressable stack,
was not part of this verified correction. The existing freestanding
`libp10c-v2.a` remains byte-for-byte identical and does not grow.

## Outstanding boundaries

Four KCC `20011115-1.c` link cells still contain a real relocation
from an unused static-inline function to `undefined_reference`.
KCC currently emits function bodies as they are parsed. Folding
`foo == foo` alone was experimentally shown to eliminate its dead
call edge but **not** the unused function body. A complete fix needs
reachability-aware function emission, not filtering required linker
relocations. That experiment was reverted and is not described as a
repair.

The other four KCC cells are original `macro1.c` tests that use
hosted `puts` on real error paths. They cannot link against the bare
freestanding runtime without an actual selected console. The existing
GCC DAIMOS console adapter is explicitly OS-dependent; it must not be
silently inserted into KCC's bare-metal test configuration.

Separately, the new KCC-targeted macro regression exposed 33
optimized GCC guest failures (return value seven in the string test),
while all 11 GCC O0 profiles pass. This requires separate GCC codegen
triage; the test assertion has not been modified to hide the result.
