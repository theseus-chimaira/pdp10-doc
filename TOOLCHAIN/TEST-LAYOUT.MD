# PDP-10 TOOLCHAIN TEST LAYOUT

## CURRENT CENTRAL LAYOUT (2026-11-16, V1)

THE SEPARATE PDP10-TESTKIT REPOSITORY HAS TWO AUTHORITATIVE REGISTRIES:

- 'COMPILER_MATRIX.TSV': COMPILER, CPU, FAMILY AND OPTIMIZATION CELLS.
- 'SPECIAL_TESTS.TSV': STANDALONE COMPATIBILITY, ASSEMBLER, LINKER, TOOL,
  VALIDATION AND HOST-REGRESSION SCRIPTS.

THE MATRIX CONTAINS C SOURCE REGISTRATIONS UNDER 'TESTS/SEMANTIC/',
'TESTS/CODEGEN/', 'TESTS/NEGATIVE/', AND 'TESTS/ISA/', WITH SUPPORT
UNDER 'SUPPORT/'. THE CENTRAL COMPILER RUNNER IS 'RUN-TESTS.SH' WITH
'TOOLS/RUN-TESTS.PY'. SPECIALIZED SUITES USE 'RUN-MISC-TESTS.SH' WITH
'TOOLS/RUN-MISC-SUITES.PY'. THE LATTER IS NOT A SECOND MATRIX RUNNER.

THE FIVE MANUAL SPECIAL REGISTRATIONS ARE NOT INCLUDED IN AN AUTOMATIC
SUITE RUN. THE DEFAULT VERIFY SUITE SELECTS VERIFY, COMPAT AND VALIDATION
GROUPS, NOT EVERY ENABLED SPECIAL REGISTRATION.

## CROSS-REPOSITORY CENSUS

STATIC INVENTORY TOOL: 'TOOLS/CENSUS-CROSS-REPO-V1.PY' IN PDP10-TESTKIT.
SOURCE-LEVEL REPORT AND 334-ROW MANIFEST:
'DOCS/CROSS-REPO-TEST-CENSUS-20261116-V1.MD' AND THE MATCHING '.TSV'.

THE CENSUS COMPARES KCC, GCC-PDP10, DAS, INDEPENDENT PDP10-TOOLS,
AND DAIMOS HOST TOOLS AGAINST THE TESTKIT REGISTRIES. IT DOES NOT BUILD
OR EXECUTE TESTS. IDENTICAL SOURCES AND STATIC SCRIPT REFERENCES ARE NOT
EVIDENCE OF PASSING COMPILER OR CPU TESTS.

AT THIS BASELINE THE CENTRAL MATRIX HAS 1986 SOURCES AND THE SPECIAL
REGISTRY HAS 211 ENTRIES. NINETEEN ORIGINAL GCC PDP-10 TARGET-SPECIFIC
FILES REQUIRE AN ASSERTION-LEVEL CROSSWALK. ALL NINETEEN REGISTERED DAS
SCRIPTS STILL RUN THROUGH HARDCODED AGGREGATES RATHER THAN PER-REGISTRY
DISPATCH. THE TOOLS AGGREGATE DEFAULTS TO DAIMOS HOST TOOLS; THIRTEEN
COMMON C OR HEADER FILES DIFFER FROM THE INDEPENDENT PDP10-TOOLS TREE.

THESE COUNTS ARE STATIC AND ARE NOT A COMPILER OR ASSEMBLER EXECUTION
ACCEPTANCE. THE FULL CROSS-CPU AND OPTIMIZATION SWEEP REMAINS OPEN.

PATH NAMES HERE USE SIXBIT UPPERCASE SPELLING. ON A CASE-SENSITIVE HOST,
THE LOWERCASE SCRIPT AND DIRECTORY NAMES IN THE PDP10-TESTKIT CHECKOUT
MUST BE USED AS PRESENT ON DISK.

GENERATED WORKDIR OUTPUT IS DISPOSABLE AND DOES NOT REPLACE THE COMMITTED
MATRIX OR SPECIAL REGISTRY.
