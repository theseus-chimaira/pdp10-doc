# PDP-10 NATIVE C-LOCALE CHARACTER CLASSIFICATION (2026-11-20, V1)

## IMPLEMENTED AND VERIFIED

THE REAL COMPILER-OWNED PDP-6-COMPATIBLE `isprint` AND
`isspace` IMPLEMENTATIONS LIVE IN
`kcc/runtime/libc/kcc-libc-ctype-c-locale-v1.s`, KCC COMMIT
`5264ccc`.  THESE TWO ROUTINES USE NO STACK, HEAP,
WRITABLE GLOBAL DATA OR OPERATING-SYSTEM ENTRY POINTS.
THEY USE THE STANDARD C LOCALE OVER THE ENTIRE PDP-10
9-BIT UNSIGNED-CHAR ARGUMENT DOMAIN (0000..0777) AND EOF:

* `isprint`: OCTAL 040..0176.
* `isspace`: OCTAL 011..015 AND 040.

THEY ARE NOT COMPLETE UTF-9 OR UNICODE CHARACTER PROPERTY
IMPLEMENTATIONS AND DO NOT IMPLEMENT EVERY CTYPE FUNCTION.
HIGH 9-BIT BYTES ARE NONPRINTABLE IN THIS SPECIFIC LOCALE.
THE CORRECT C-LOCALE SCOPE MUST BE PRESERVED WHEN FUTURE
UTF-9 CLASSIFICATION IS ADDED.

## REPRODUCED NATIVE EXECUTION

THE UNCHANGED HISTORICAL `991112-1.c` INVOKES
`rl_character_len` THROUGH A FUNCTION POINTER, CHECKING
PRINTABLE `'a'` AND NONPRINTABLE OCTAL 002.  BOTH ITS
ORIGINAL ASSERTIONS ARE PRESERVED.  BEFORE THE CLASSIFIER
WAS INSTALLED, KCC NOOPT AND GCC O0 GENUINELY FAILED
LINKING ON MISSING `isprint`.  AFTER INSTALLATION, ALL
SIX KCC/GCC PDP-6 COMPILER PROFILES PASS THE UNCHANGED
SOURCE.  AN INDEPENDENT FUNCTION-POINTER ORACLE TESTING
ALL 512 CHARACTER VALUES AND EOF PASSES THE SAME SIX
PROFILES, AND THE UNCHANGED HISTORICAL `980707-1.c`
ALSO PASSES ALL SIX USING THE REAL `isspace`.

THE TESTKIT CORRECTLY RESOLVES THE GCC ASSEMBLY DATA
RELOCATIONS `.long isprint` AND `.long isspace` AS
FUNCTION-POINTER REFERENCES TO REAL INSTALLED LIBRARY
MEMBERS, NOT AS TEST-LOCAL SUBSTITUTES.  THE INSTALLED
FREESTANDING AUDITOR CONFIRMS THE TWO COMPILER LIBRARY
COPIES MATCH AND DOES NOT SILENTLY ADOPT DAIMOS LIBC.

TESTKIT ACCEPTANCE COMMIT: `bd94b2e`.
ITS EVIDENCE HAS 20 SOURCE/PROFILE OUTCOMES (TWO
HISTORICAL LINK FAILURES AND 18 ACTUAL NATIVE PASS),
102 SHA256-PINNED RAW ARTIFACTS, AND 11 FAIL-CLOSED

`pdp10-testkit/docs/PDP10-P1-991112-C-LOCALE-CLOSURE-20261120-v1.md`.
