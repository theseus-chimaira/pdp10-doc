# GCC PDP-10 D-Format Constant Reinterpretation in CSE

Status: fixed in the staged compiler and target-execution verified
on 2026-11-23.

## Defect

PDP-10 D-format floating-point values occupy two 36-bit target words.
The target real encoder exports these 72 bits as three 32-bit host
chunks. GCC 3.2's generic `gen_lowpart_common` in `gcc/emit-rtl.c`
handled floating `CONST_DOUBLE` to integer reinterpretation as though
the value occupied only 64 bits. For a big-endian PDP-10 this omitted
the high eight target bits and could access beyond the four-chunk
buffer. CSE consequently propagated truncated integer comparison
constants.

The original `libgcc_helper_ownership_fp.c` validation source
observed the defect at the final `__negdf2` check. The helper returned
the correct high word (octal 0576200000000) and low word
(0400000000000) for -1.5, while CSE had replaced the expected
high-word comparison with an incorrectly truncated constant. The
failure was in the compiler's raw-bit interpretation, not the
freestanding floating-point arithmetic helper.

## Correction

On 64-bit hosts compiling PDP-10 72-bit `CONST_DOUBLE` values,
`gen_lowpart_common` now reconstructs both 36-bit target words from
all three unsigned 32-bit chunks, preserving their order and bits.
It then returns the correct raw integer-mode representation. This
operation is a bit reinterpretation, not a floating-to-integer
numeric conversion. Other targets and float modes retain the prior
generic path; no DAIMOS resident memory or runtime helper is added.

## Target verification

With rebuilt staged GCC, all 44 profiles of the existing complete
`tests/semantic/validation-gcc/runtime-helper/libgcc_helper_ownership_fp.c`
pass, including 33 formerly failing optimized profiles.

The exact 414 previously crashing GCC cells were also rerun, with
all keys checked against the previous checkpoint. The resulting
counts are **238 pass, 176 diagnosed compile_fail, zero run_fail,
zero compiler_ice**. The only changes are the 33 newly passing
floating-point helper cells.

A new 44-profile testkit regression,
`tests/semantic/regression/pdp10-gcc-df-raw72-cse-v1.c`, covers both
raw 36-bit words of positive and negative D-format constants.
All 44 pass using the repaired compiler. Against the previously
installed compiler, 11 pass and 33 optimized profiles crash,
demonstrating the regression detects old-compiler defects. The
installed compiler is older than the immediately preceding staged
build, so its crashes alone do not isolate this specific CSE cause.

Evidence and limitations:
`pdp10-testkit/history/GCC-DF-RAW72-CSE-RETEST-20261123-v12.md`.

a full compiler test-suite acceptance or a separately built TOPS-20

unchanged.
