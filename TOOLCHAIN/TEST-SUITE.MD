## KCC DIVISION/MODULO CSE REGRESSION

KCC'S PDP-10 IDIV PRODUCES A QUOTIENT/REMAINDER REGISTER PAIR.  WHEN NEARBY
EXPRESSIONS REQUIRE BOTH `X / Y` AND `X % Y`, OPTIMIZED CODE SHOULD REUSE THAT
PAIR WHEN THE OPERANDS AND REQUIRED RESULT HALF ARE PROVEN UNCHANGED.

HISTORICAL SPR-9774 DISABLED THIS CSE FOR CSI BUILDS AFTER A MIXED `/` AND `%`
REGISTER-PAIR MISOPTIMIZATION.  THE ROOT CAUSE WAS THAT `FINDCSE()` INVALIDATED
THE IDIV REMAINDER REGISTER BEFORE `MATCH()` COULD CONSUME ITS `ISMOD[]` STATE.
THE REPAIRED PATH LEAVES THAT PAIR-AWARE INVALIDATION TO `MATCH()` ITSELF.

VARIABLE DIVISORS ALSO NEED A CONSERVATIVE REGISTER-COPY CASE BECAUSE THE CODE
GENERATOR MAY COPY IDENTICAL INPUTS INTO DIFFERENT TEMPORARY ACS FOR THE SECOND
OPERATION.  KCC REUSES THE EARLIER IDIV PAIR ONLY WITHIN THE NORMAL CSE WINDOW,
ONLY FOR REGISTER OPERANDS, AND ONLY WHEN THE SOURCE ACS AND WANTED RESULT HALF
ARE UNCHANGED AND NO CONTROL-FLOW BOUNDARY INTERVENES.

`TESTS/KCC-REGRESSION/SIDIV-DIVMOD-CSE-V2.SH` COVERS SIGNED AND UNSIGNED
VARIABLE-OPERAND `/`/`%` PAIRS IN BOTH ORDERS AND EXECUTES THEM ON PDP-6, KA10,
KI10, AND KS10.  `SIDIV-IDIV-PAIR-CSE-V3.SH` COVERS CONSTANT-DIVISOR AND THE
HISTORICAL ARRAY-INDEX SHAPES, INCLUDING VARIABLE-DIVISOR INDEXING.  EACH
REQUIRES A SINGLE SHARED IDIV FOR THE RELEVANT FUNCTION AND EXECUTES THE RESULT.

## GCC scalar move order regression

`tests/compat/test-gcc-scalar-move-order-v39.sh` protects a PDP-10 backend
correctness case where two adjacent, independent SImode moves must not be
reordered as though they were the halves of an overlapping DImode move.  The
unsafe peephole could transform:

```asm
MOVE 2,1
MOVE 3,1
```

into:

```asm
MOVE 3,2
MOVE 2,1
```

after a call returning its scalar result in AC1.  The first instruction then
reads stale AC2 and changes program semantics.  Overlapping DImode register
pairs are instead ordered by `pdp10_output_movdi()`, while the move mode and
pair relationship are still known.

The regression checks both `-O2` and `-Os`; verification also checked PDP-6,
KA10, KI10, and KS10 code generation.

## GCC -Os callee-save PUSH/POP regression

On PDP-6 and KA10, GCC has no doubleword MOVE for saving a pair of
callee-saved ACs.  A pure callee-save frame containing two or three words is
therefore smaller when emitted as one PUSH per saved AC and one reverse-order
POP per restored AC.  The old sequence allocated the whole frame first and
used MOVE/MOVEM pairs, costing two extra stack-adjust instructions.

The backend uses the compact form only when optimizing for size, only when the
frame contains no locals, outgoing arguments, or pretend arguments, and only
when MOVE_MAX is one word.  One-word frames retain their existing PUSH/POP
behavior at other optimization levels.  KI10 and later targets retain their
DMOVE-based save/restore sequences.

`tests/compat/test-gcc-callee-save-pushpop-v41.sh` checks two- and three-AC
save frames on PDP-6 and KA10.  It requires the `-Os` output to use matching
PUSH/POP sequences, forbids a separate stack adjustment, requires the `-Os`
function to contain fewer instructions than its `-O1` counterpart, and runs
the generated `-Os` program on both simulators.

The 2026-09-17 validation also ran the complete GCC base/`-Os` matrix slices
for PDP-6 and KA10: each selected 402 cells, with 344 semantic passes, 58
compile-only code-generation passes, and zero failures.

The combined 2026-09-17 PDP-6/base verification for GCC `-O2` and `-Os`
selected 648 cells: 532 execution passes, 116 compile-only passes, and zero
failures.
