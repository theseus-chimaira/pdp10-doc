# KCC PDP-6 VOID-POINTER PRESERVATION AND EQUALITY (2026-11-21, V1)

## SOURCE-LEVEL REPAIRS

KCC COMMIT `46d0181` FIXES A REAL COMPILER BUG IN `ccgen2.c`:
COPYING A `void *` THROUGH A VOLATILE LOCAL MUST PRESERVE THE
WHOLE SELF-DESCRIBING PDP-10 POINTER WORD. THE OLD LOWERING
COULD RECODE AN NATIVE S=18 HALFWORD POINTER AS S=9 WHEN THE
POINTED-TO TYPE WAS ERASED. `void *` TO `void *` IS NOW AN
ACTUAL NO-OP, WITH NO CODE, STACK, HEAP OR GLOBAL RAM COST.

KCC COMMIT `4a61c53` FIXES A SECOND, INDEPENDENT COMPILER
DEFECT IN POLYMORPHIC POINTER `==`/`!=` GENERATION. TWO
SUCCESSIVE `gptrcanoncmp()` CALLS COULD REUSE THE FIRST
CANONICAL POINTER'S PHYSICAL REGISTER AS SCRATCH FOR THE
SECOND POINTER. A NATIVE PDP-6 OPTIMIZED TEST RECORDED
THE IDENTICAL ORIGINAL POINTER WORD `002200002402` (OCTAL)
ON BOTH SIDES OF THE `void *` CALL, YET THE GENERATED `CAME`
COMPARED A CLOBBERED S-FIELD SCRATCH REGISTER TO THE OTHER
POINTER AND FALSELY REPORTED UNEQUAL.

THE REPAIRED `gboolop()` STORES THE FIRST CANONICAL OPERAND
IN ONE TEMPORARY STACK WORD, EVALUATES THE SECOND OPERAND,
RELOADS THE FIRST AS A LIVE VREG, AND CLEANS UP THE STACK
*BEFORE* THE CONDITIONALLY SKIPPING COMPARE INSTRUCTION.
THIS IS BOUNDED TRANSIENT STACK USE, NOT A PERMANENT RAM
TABLE OR A RUNTIME WORKAROUND.

THE INSTALLED POST-REPAIR KCC COMPILER SHA256 IS
`b189271f7a43496eaa60dcdfa540ce0a363dae72f8d833273f022eb85ac7a19a`.
