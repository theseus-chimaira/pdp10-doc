# PDP-10 AND DAIMOS DOCUMENTATION

THIS REPOSITORY HOLDS CURRENT DESIGN DOCUMENTATION FOR DAIMOS AND THE SIBLING
PDP-10 TOOLCHAIN/UTILITY TREES.  SOURCE TREES REMAIN AUTHORITATIVE FOR WHAT IS
ACTUALLY IMPLEMENTED; DAIMOS/PROJECT-STATE.MD IS AUTHORITATIVE FOR CURRENT
DAIMOS ARCHITECTURAL STATE AND DEVELOPMENT ORDER.

## LAYOUT

- 'BOOT/' - PDP-6 BOOT, DBOOT, STAGE1/KINIT HANDOFF, AND DEFERRED RECOVERY DESIGN.
- 'KERNEL/' - MEMORY/VM, CLOCKS, STORAGE, FILESYSTEM, LOGSTORE, MODULE, AND
  SELF-HOSTING DESIGN.
- 'HARDWARE/' - PDP-6 HARDWARE, SIMH/AAP EMULATOR INTEGRATION, AND VERIFIED DEVICE SEMANTICS.
- 'STATUS/' - CURRENT SCOPE/SIZE SUMMARIES.  TRANSIENT IMPLEMENTATION HANDOFF
  DOCUMENTS BELONG IN GIT/WORK HISTORY, NOT IN THIS REPOSITORY.
- 'TOOLCHAIN/' - GCC/KCC AND C/TESTKIT DESIGN NOTES.
- 'TOOLS/' - DAS, DOBJ, DISPLAY/CONVERSION, AND SUPPORT-TOOL DOCUMENTATION.
- 'USER/' - DSH, SIXMD, USER COMMAND, AND USERLAND DESIGN.
- 'JOSS-LESSONS.md' - JOSS II-DERIVED INTERACTIVE/WORKSTATION SCHEDULING,
  SWAP, BACKPRESSURE, AND RESPONSE-TIME DESIGN GUIDANCE.
- 'ITS-LESSONS.md' - ITS-138-DERIVED INTERACTIVE PROCESS-CONTROL, TTY,
  I/O-BUFFER, CORE-PRESSURE, AND WORKSTATION DESIGN GUIDANCE.

ROOT-LEVEL OPEN DOCUMENTATION WORK IS IN TODO.MD.  HISTORICAL MATERIAL THAT IS
NO LONGER PART OF THE ACTIVE DESIGN SHOULD BE RECOVERED FROM GIT HISTORY RATHER
THAN KEPT AS A CONTRADICTORY SECOND AUTHORITY.

## CURRENT DAIMOS BOUNDARIES

THE INITIAL/MINIMUM MACHINE IS A 32K-WORD PDP-6.  THE HARD ARCHITECTURAL KERNEL
LIMIT REMAINS BELOW 16K WORDS INCLUDING FIXED RESIDENT AND IRREDUCIBLE SCRATCH
KERNEL MEMORY.  EXACT KCORE/MRES FIGURES ARE DATED BUILD MEASUREMENTS AND MUST
BE REGENERATED AFTER MATERIAL KERNEL CHANGES RATHER THAN COPIED FORWARD AS
CURRENT LIMITS OR BASELINES.

KCC IS THE REQUIRED NORMAL COMPILER FOR BOTH KERNEL AND USERSPACE.  USERSPACE
BUILDS WITH KCC/DAS WITHOUT LIBGCC.  THE PROGRAM-STARTUP ABI, MINIMAL TTY LINE
DISCIPLINE, ISATTY, UMASK, LOGIN INITIAL ENVIRONMENT, RECLAIMABLE D6FS BLOCK
CACHE, AND THE DIRECT-SLIDE MM COMPACTOR/RELOCATOR ARE COMPLETE.  THE EXTERNAL
MONITORFS NAMESPACE IS LIVE AT /MONITOR; /PROC ALIASES /MONITOR/PROCESSES AND
CONTAINS PROCESS OBJECTS ONLY; /DEV PROJECTS /MONITOR/DEVICES/NAME/IO AS
/DEV/NAME; AND /DEVICE + /DOMAIN ARE REMOVED.  MONITORFS CONSOLIDATION AND THE DSH-SPECIFIC FILESYSTEM/SYSCALL PREREQUISITES
ARE COMPLETE.  SEEK, CHOWN, CORRECT RMDIR SEMANTICS, AND D6FS
MTIME/STAT/DATE/TOUCH SUPPORT ARE IMPLEMENTED.  SUBSTANTIAL DSH IS PAUSED UNTIL
THE FULL PRE-USERLAND KERNEL/STORAGE GATE IS CLOSED: STORAGE MECHANICAL
SCHEDULING, RUNTIME MOVABLE MODULES, LOGSTORE RUNTIME INTEGRATION, AND
REMAINING INIT/CONFIG POLICY MIGRATION.  FULL TSFS V1 READ SUPPORT IS ALREADY
COMPLETE.  AFTER THAT, CONTINUE DSH AND THE NATIVE USERSPACE PATH.

THE CURRENT DESIGN RECORDS THESE KERNEL/FILESYSTEM DIRECTIONS:

- D6FS CURRENTLY OWNS OPTIONAL SWAP/LOGSTORE LOGICAL RESERVATIONS; VFS
  REGISTERS THE RAW RANGES; THE STORAGE-SET LAYER OWNS PHYSICAL DISTRIBUTION
  AND ONE COMMON DISK/DRUM BAD-MEDIA EXCEPTION MAP, WHILE DEVICE RETRY/
  SCHEDULING STAYS IN THE PHYSICAL DRIVER.  THE PLANNED BSTORE/AUXSTORE
  MIGRATION MOVES NEW AUXILIARY BACKSTORE/LOGSTORE PLACEMENT OUT OF D6FS;
  SEE `KERNEL/BSTORE.MD`.
- THE LANDED EXTERNAL STATE VIEW IS /MONITOR/PROCESSES, /MONITOR/DOMAINS, AND
  /MONITOR/DEVICES; /DEV IS THE DIRECT I/O-ONLY DEVICE VIEW.  THE OLD INTERNAL
  MONITORFS USES COMPACT INTERNAL VIEW SELECTORS; NO SEPARATE STATE FILESYSTEM IMPLEMENTATIONS REMAIN.
- D6FS CURRENTLY USES A RECLAIMABLE CLEAN BLOCK CACHE.  THE PLANNED COMMON
  BCACHE REPLACES IT WITH ONE TWO-BLOCK L1 SHARED WITH DTFS/TSFS; CLEAN CACHE
  IS RECLAIMED BEFORE BACKED EVICTION/SWAP AND DOES NOT BECOME A LARGE
  FIXED RESIDENT BUFFER POOL.
- THE KERNEL PROVIDES ONLY A MINIMAL COOKED TTY LINE DISCIPLINE; DSH/ELVIS KEEP
  RICH INTERACTIVE EDITING IN USERSPACE AND USE RAW MODE WHEN NEEDED.
